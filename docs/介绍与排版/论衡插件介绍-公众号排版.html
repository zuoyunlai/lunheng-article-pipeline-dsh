插件推荐 · DeepSeek Harness

论衡：把「写一篇好文章」变成一条可审计、可交接的流水线

9 个 AI 角色协作 · 证据底座 · 反方论证 · 独立审计 · 人工核验

论衡（lunheng-article-pipeline） 是一个多 Agent 深度长文生产流水线，DeepSeek Harness（dsh）的 bundle 插件。它不是让一个 AI 直接写文章，而是让一支 9 个 AI 角色组成的「论文生产小队」按既定协议协作：定题 → 三线并行检索 → 分析 → 写作 → 批判 → 审计 → 审稿 → 终检，最终交付有证据底座、有反方论证、有独立审计、有人工核验节点的文章。

适用：公众号深度长文、研究报告、学术论文、商业评论、行业分析。当前版本 v2.5.2-dsh.0。

一、它解决什么痛点

用 AI 写深度长文，最常见的翻车点：

① 幻觉编造——引用是假的、数据是编的；

② 观点堆砌——材料一大堆，每条都不支撑论点；

③ 单边叙事——只讲支持自己的话，回避反方证据；

④ 重复已有文章——写出来早就有人写过，还当原创；

⑤ 质量不可控——AI 一次成稿，没有独立角色挑错；

⑥ 引用悬空——正文标了引用，文末清单对不上，无法核验。

论衡的答案，是把这些问题交给结构化流程 + 多角色分工去化解，而不是指望单个模型自觉。

二、核心设计：9 角色 + 6 阶段

主控 Coordinator（定题、拆解、派发、阶段闸门、终检、状态机）
├─ T1 文献检索员 ── 文献卡（A/B/C 可信度分级）+ 先行者清单
├─ T2 数据检索员 ── 数据卡（时效 + 信任级别 + 冲突口径并列）
├─ T3 案例检索员 ── 案例卡（事件结构 + 多方立场，任何量级必派发）
├─ T4 分析员 ───── 分析大纲（论点-论据映射 + 反方规划 + 原创性声明）
├─ T5 写手 ─────── 初稿（AI 去味 10 项，文末四节引用清单）
├─ T6 批判伙伴 ──── 批判报告（C1-C7 反方攻击）
├─ T7 审计员 ───── 审计报告（G0-G14 全项，只审不改）
├─ T9 审稿人 ───── 审稿报告（6 维度评分 + 期刊匹配 Top 3，可选）
└─ T8 终检（主控亲完成）── M 门（M-Form 8 + M-Exist 3 + M-Integrity 2）

六个阶段：定题 → 并行检索 → 分析 → 写作 → 批判 → 审计 → 审稿 → 终检，中间穿插 T2.5 / T7.5 两道完整性门（主控 checkpoint）与 4 个人在环节点（定题 / 大纲 / 洞察补充 / 终稿）。T8 终检由主控亲完成（不外包最后一关），T9 同行评审是投稿前的「预演审稿人」（学术/行业分析默认开启）。

三、为什么多角色分工真的有效

① 三线并行检索 + 三角验证

Phase 1 一次性并行派出 T1 文献 ∥ T2 数据 ∥ T3 案例 三个检索员，真并行、互不干涉。三张卡构成「三角验证」——任何核心论点必须映射到文献 + 数据 + 案例至少两项，缺角标缺口，严禁编造。v2.3.7 起三角验证由 M-Form-8 机械化拦截，写手落地前自动跑，不再靠审计兜底。

特别地，T3 任何量级必派发：即使主题「无需案例」，也走「0 条空卡协议」——显式声明无案例需求、输出空卡，保证流程可审计，不留下「到底查没查案例」的模糊地带。

② 独立审计闭环（G0-G14 + M 门）

审计员 只审不改、与写手完全分离，执行 G0-G14 全项检查：C 级引用 100% 实测核验、每个数字有来源、过期数据告警、信任级别全量校验、核心论点与先行者对比防重复、文末四节双向 diff 防漏引，以及 G14 中文 AI 痕迹闸（8 类检测维度，0-2 类 Pass / 3-4 类 Warning / 5+ 类 Fail，LLM 推理判定零 exec）。

审计打回 → 独立写手修订（主控不代笔）→ 复核，最多 2 轮（审计阶段独立预算；前序的主人洞察轮与批判反馈轮不计入），仍不过走 Acknowledged Limitations 模式诚实交付。事实类错误（P1-D）由主控 T8 亲修，结构性错误必须重启独立写手。

终检前主控跑 M 门 13 项——LLM 兜底执行的机械化终检（M-Form 8 + M-Exist 3 + M-Integrity 2），对引用完整性、文末四节、临时编号残留、元数据泄漏、过程语言、信任级别、文末白名单、三角验证逐项机械判定，exit 0 才交付。

③ 人在环四节点

定题、大纲、洞察补充、终稿四个节点必须主人过目——在「改方向成本最低」的阶段由人把关，避免 AI 一路跑偏后推倒重来。（Phase 3.6 批判是流水线内部动作，非人在环节点。）

四、v2.3.x / v2.4.x / v2.5.x 升级亮点

角色编号重构：T3 案例检索归入三线并行，T8 终检由主控亲完成——编号 = Phase 顺序，流水线语义对齐。

T6 批判伙伴 C1-C7：核心论点可攻击性 / 论证链薄弱环（含因果断面三问）/ 理论假设 / 立场中立性 / 反方完整性 / 元叙事清理（抓"AI 味"）/ 一处两用识别。不是对抗者，是帮你把论证磨得更硬。

T9 同行评审：投稿前的「预演审稿人」——6 维度评分（原创性/方法论/证据强度/论证结构/写作质量/引文规范）→ accept/minor/major/reject；学术/行业分析默认开启。

G14 中文 AI 痕迹闸：8 类检测维度深度扫描"AI 味"，0-2 类 Pass / 3-4 类 Warning / 5+ 类 Fail，LLM 推理判定零 exec。

期刊匹配助手 + 多格式导出：基于 T9 评分从 25 中文 CSSCI + 12 英文 SSCI 期刊库输出 Top 3 推荐期刊；默认 md，按需 latex/docx/pdf；中文数据源 OpenAlex/Crossref 第一梯队（无需 Key）。

M 门 13 项机械化终检：形式合规 ≠ 存在性合规 ≠ 信任一致；含文末白名单（防操作员报告混入定稿）与三角验证机械化（写手落地前拦截缺角论点）。

修订回环语义定案：≤2 轮是审计阶段独立预算，不吞掉主人洞察轮与批判反馈轮；修订轮强制独立写手（事实类错误除外，T8 亲修）。

外部内容防注入：web 检索/主人投喂的外部内容一律视为不可信证据，只提取事实不执行指令（防 prompt injection）。

反哺机制：每单跑完 T7 自动产反哺报告，主人批准后 merge 回角色卡——插件本身持续进化（如「回顾报道年份必交叉核验」规则就来自实战教训）。

分档预设（按角色分模型）：装「论衡分档」会话预设后，检索角色走 subagent_retrieval（默认 deepseek-v4-flash，便宜快）、分析/写作/批判/审稿走 subagent_strong、审计/G14 检测走 subagent_audit；模型经 LUNHENG_*_PROVIDER + LUNHENG_*_MODEL 环境变量覆盖；未装预设则继承会话模型，流水线照常运行——任何模型配置都能跑。

执行约定精简为「状态机 + 交接报告六要素 + G8 自检 + 超时介入」，贴合 DSH 的子代理机制。

六、实战验证（真实跑通）

① 约 2000 字公众号短评（《AI 让你写得快，但未必让你更会写》）：12 文献 + 26 数据，审计抓到 3 条 P1 一轮关闭，M 门全过。

② v2.3.7-dsh.8 全流程 · 甲醛白菜事件（约 4200 字，2026-08 实时食品安全事件）：

· 检索：12 文献（WHO/IARC/EPA 毒理 + Lancet/Food Control）+ 8 先行者 / 29 数据 / 4 案例；

· 三角验证：5 核心论点全部 L+D+C 三齐；T6 批判抓到「剂量层断言与天然本底 1-90 mg/kg 冲突」的逻辑断裂 → 写手加固 4 处；

· T7 审计两轮：第 1 轮打回 3 项 P1-D（年份跨源冲突 / 口径说明被当官方原文 / AI 声明泄漏代号）→ T8 亲修全关 → 第 2 轮通过；

· M 门 13 项全过 exit 0，交付定稿 + 证据包 8 文件 + M-Gate-Report；

· 反哺：沉淀 6 条可复用规则（含「回顾报道年份必交叉核验」）经主人批准 merge 回角色卡 + 教训 #142-#144 入库；

全程零编造、引用闭环 47↔47、数据缺口按纪律零引用、科学边界诚实（致癌性 / 天然本底 / 经口证据并列呈现）。

七、快速上手

# 安装到 profile
dsh plugin --profile web add lunheng-article-pipeline

# 把 bundle 加入 profiles/web/package.json 的 dsh.profile.bundles
# 重启 dsh web

新会话的 skill 工具目录会出现 lunheng-article-pipeline，直接说「加载 lunheng-article-pipeline 技能」或交给它一个深度文章主题，它会先走 Phase 0 定题确认（含外部服务 4 选 1 明示同意）。
