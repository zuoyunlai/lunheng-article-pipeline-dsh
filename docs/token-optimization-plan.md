# Token 优化计划（token-optimization-plan）

> 状态：**草案 / 待 token 实测确认优先级**｜创建：2026-09-08｜仓库：lunheng-article-pipeline-dsh
> 说明：以下收益为量级判断；正式动手前先跑 `node scripts/token-cost.mjs` 取各 Phase/角色的实测分布，再按数据落地。

## 目标
在保持论衡“证据底座 + 三角验证 + 独立审计”质量的前提下，降低每次会话/子代理的 cacheRead 与 token 成本（仓库记录基线：191M → 80-90M，本轮目标再降 30-50%）。

## 实测步骤（先做）
1. 用一篇 3000-5000 字论文全跑一轮，逐 Phase 记录 `token-cost.mjs --sessions <主会话>,<子代理…>`；
2. 产出各 Phase/角色 token 分布表 → 更新本计划“实测数据”节；
3. 按分布从下表中取 Top 3 立项。

## 优化清单（按性价比）

### 🔴 P1 高性价比
1. **技能本体瘦身**
   - 现状：SKILL.md ≈33KB 每次加载注入；frontmatter description 冗长（每次列技能目录都占 token）；00-主控-扩展职责 41KB 等大文档常被整读。
   - 动作：SKILL.md 拆「入口版（速查+目录+引用）」，机制大段移入 `references/*` 按需 read；description 压缩至 ~120 字；重复段落以“单一真源 + 引用链接”替代。
   - 落点：SKILL.md / AGENTS.md / 相关 references；consistency-check 保证不漂移。
2. **子代理开工卡（prompt 瘦身）**
   - 现状：每次 spawn 携带长自包含 prompt + 子代理先整读角色卡（20-40KB）。
   - 动作：T1-T9 各产 1-2KB「开工卡」（任务/输出路径/必守铁律索引/格式样例链接）；全文按需 read 小节。
3. **共享审计视图（消除重复全读）**
   - 现状：T4/T5/T6/T7/T9/G14 各自重复读 稿+三卡+报告。
   - 动作：闸门处生成共享精简视图（build-evidence-bundle --summary 已有雏形），角色只读视图 + 编号定位原文；派发模板写明“禁全文通读”，T8 复核。

### 🟡 P2 中性价比
4. **交接回报精简**：交接只回「摘要 ≤10 行 + 产物路径 + 关闭状态表」，报告全文落盘不粘贴。
5. **修订轮一律段级 diff**：v1 后默认 T5 段级 diff（≤25 步），主控机械编辑；T5 只读 §11 精简段写为硬约束。
6. **检索上下文累积控制**：每 ~10 次搜索本地小结替换原文；候选 URL 批量化（先清单再一次 read_page）。
7. **判定脚本化前移**：M-Form-8 等三角验证改为结构化清单供脚本/主控 JSON 判定，T8 不整读 46KB 算法文档。

### 🟢 P3 锦上添花
8. **token 可观测**：Phase 结尾自动记 token-cost 到 status.md/memory，设每角色预算、超限告警/拆任务。
9. **断线重派零重读**：中断重派只喂「状态文件 + 产物路径」，禁止重读全套素材（dsh.10 交接状态四要素已就位，落地为强制约定）。

**解读与结论**：
1. **T5 是最大成本源**（cacheRead ≈28.9M，占子代理合计 76%）——且其 3 个会话含一次整稿重写与一次停滞尝试；强支持「v1 后默认段级 diff + 写手只读 §11 精简段」方向。
2. 检索 T1-T3 各 2 会话含首轮后台停滞/重跑，说明「后台子代理停滞→重派」带来 ~30-40% 检索侧冗余成本（韧性重派应更早触发）。
3. 主会话另行累计 input≈3.0M / cacheRead≈117.6M——主体为本超长会话的轮次/工具往返，与论文单次运行关系弱，未计入论文口径。
4. 瘦身后 SKILL（33→16.9KB）与「读取纪律」已在本轮实际执行；精确的“同题对照降幅”需在 dsh.10 优化与旧版间做同题 A/B（待后续轮）。

**工具问题（新增 P2 待修）**：
