# 架构说明

## 角色

| 角色 | 编号 | 职责 |
|---|---|---|
| 主控 | — | 定题、拆解、派发、终检、状态机 |
| 文献检索员 | T1 | 文献卡 [Lxx]（可信度 A/B/C + GB/T 7714） |
| 数据检索员 | T2 | 数据卡 [Dxx]（🟢🟡🔴 时效 + 冲突口径并列） |
| 案例检索员 | T6 | 案例卡 [Cxx]（事件结构 + 多方立场 + ≥2 来源） |
| 分析员 | T3 | 分析大纲（论点-论据映射 + 反方论证规划） |
| 写手 | T4 | 初稿（引用/数据/案例全标编号） |
| 审计员 | T5 | 审计报告（G0-G11，只审不改） |

## 三角验证

任何核心论点必须能映射到三类证据至少两项：

- [Lxx] 学术依据 + [Dxx] 量级数据 + [Cxx] 具体事件

缺角就标缺口，严禁编造。

## 审计 G0-G11

G0 覆盖度 / G0.5 视角一致性 / G1 分级核验（C 级 100% web_search 实测）/ G2 数据溯源 / G2.5 案例核验 / G3 逻辑 / G4 格式 / G4-2 文末四节 / G5 规范 / G6 论据自标 / G7 原创性 / G8 成品度 / G9 时序 / G10 一致性 / G11 时效。

## 原创性保证

T1 先行者检索 → T3 差异点声明 → T5 G7 原创性审计，防止「重复/改写已公开文章」。

## DSH 适配

技能以「bundle patch」形态发布：`package.json` 声明 `dsh.bundle.patch` 指向 `cordis.patch.yml`，后者通过 `skill-filesystem` 的 `customSkillDirs` 把包内 `skills/` 目录注册为技能根。工具集由 DSH Agent 预设决定，模型路由由 `settings.yaml` 配置。
