### 3. 数据考古（脚本内如实声明的关键发现）
`run/` 横跨 4 个版本代际，M-Gate 报告**位置与格式不一致**，脚本据此做三位置回退 + 三桶分类：
- **位置**：`final/M-Gate-Report.json` → `audits/M-Gate-Report-vN.json`（取最大 N）→ `audits/M-Gate-final.json`。
- **格式**：① machine（有 `results[]`，v18.x 机器报告，含/不含 exit、可能带 BOM、gate 总数 12 或 22）；
  ② llm-legacy（v2.5.2-dsh.x 的 LLM 兜底，形态有 `M-Form_形式合规门` 嵌套 / `m_checks` / `exit_code`+`M-Form`，共同点无 `results[]`）；
  ③ none（无报告）。只对 machine 做机械聚合。

### 4. 白名单

## 四、② 裁剪 / 补齐分析结论

**拦到过问题的门（12 个）**：M-Form-4/8/9/11、M-Exist-1/2/4/5/6/8/10、M-Integrity-1——
其中 M-Form-8、M-Exist-1、M-Form-4 是「质量类」，证明机制拦的是真问题而非空转。

**没拦到过的门（10 个）**：M-Form-1/2/3/5/6/7/10、M-Exist-3/7/9。

三条结论：

1. **「没拦到」≠「该裁剪」**。其中 M-Form-2（文末五节存在性）/ M-Form-3（占位符残留）/ M-Form-7（白名单）
   本质是**绊线**——流水线正常时本应常年 0 命中，一旦命中就是真事故；裁绊线等于拆安全网。
   基于「5 个机器报告」的样本，任何裁剪都鲁莽。

2. **裁剪的真实信号是「假阳性率」，不是「拦截率」**。要回答「哪个门该裁」，得看每个 P0/P1 是
   **真拦住问题**还是**误伤**——该信号在 `M-Gate-Report.json` 的 `_t8_conclusion.true_p0/true_p1`
   （T8 裁定段），当前只有 5 个项目有，样本不足。

3. **「补齐」比「裁剪」优先，且方向明确**：
   - 未来项目：当前流水线已默认 `--report` 落机器报告 → 自动补齐，无需动作。
   - 历史 14 个项目（7 LLM 兜底 + 7 无证据）：跨 4 个版本代际、布局/格式已变，**不回填**——
     重跑会改写历史项目数据、老项目可能缺定稿/证据包；作为「旧代际」保留、看板如实标注即可。
