## 3. 阻断项（Blocker）

### 🔴 B-1 `md2html.mjs` 的同文件守卫可绕过 → **销毁用户正文**（P0，数据丢失）

**事实**：`md2html.mjs:36` 的守卫比较**字符串**（`mdPath === htmlPath`），不做路径归一；`:203` 直接 `writeFileSync(htmlPath, page)`。

**实测**（本报告亲验，夹具在 TEMP）：

```
md2html.mjs a.md a.md    → exit 10，报「输入输出不能是同一文件（会覆盖源文件）」   ✅守卫生效
md2html.mjs a.md ./a.md  → exit 0，"HTML written: ./a.md (1029 bytes…)"
                          源文件 a.md 内容变成 <!DOCTYPE html> ← 正文永久丢失
```

同一手法 `A.md`（Windows 大小写）、`final/../final/定稿.md` 同样可绕过。

**为什么严重**：论衡的交付主链正是「Markdown 定稿 → `md2html` 导出」，而**用户自己的文章源文件就坐在被覆盖的位置**。且同库 `apply-diff.mjs` 对同类风险**默认是原地覆盖**（见 B-4）——即脚本层整体缺少「破坏性写」的统一策略。

**修复**：`resolve(mdPath) === resolve(htmlPath)`（必要时叠加 `realpath`）；建议同时在 `_lib/` 加统一的 `assertNotSameFile(in, out)` 并被 `md2html` / `apply-diff` / `normalize-trust-level` / `final-check` 共用。

### 🔴 B-2 `build-evidence-bundle.mjs` 对「不是项目」的目录判成功 → 闸门留痕可伪造（P0，fail-open）

**事实**：`:38-42` 只校验路径存在且是目录，**从不校验是不是项目**；`:90-99` 缺失源一律「跳过（不存在）」；`:145` 仍打印「证据包生成完成：复制 0 个文件，跳过 14 个缺失源」；**全脚本无 exitCode 赋值**。

**实测**（本报告亲验）：

```
build-evidence-bundle.mjs <任意空目录> --summary  → exit 0
   并在该目录内新建：final/证据包/、audits/审计视图-v0.md
（传不存在的路径 → exit 10，正确）
```

**为什么严重**：本包的核心纪律是「闸门必须留机械证据：**脚本 exit code + 产物路径**」。路径敲错时得到的是一份漂亮的 exit 0 报告，主控会把「证据包已刷新」写进闸门记录，而 M 门随后校验的是**旧副本**。这与 `m-gate-check.mjs:57` 当年修掉的「路径错撞 1」是同一类，此处未修。
**附带风险**：参数指向仓库内目录时**直接污染仓库**（本次审计期间就观察到技能包目录内被写入过 `audits/final-check-v0.json`；同族脚本 `final-check.mjs:149` 亦按参数目录写入）。

**修复**：`:42` 后加项目形态校验（存在 `01-任务简报.md` 或 `final/` 之一，否则 exit 10）；`:145` 后加 `copied===0 && missing>0 → exit 10`。

### 🔴 B-3 `m-gate-check.mjs` 非标准编号正则制造**假 P0**，阻断交付（P0）

**事实**：`:827 NONSTD_RE = /\[(?!D-基-)([A-Za-z\u4e00-\u9fff][^\][\s]{0,11}?)-(\d+)\]/g`；`:844 mExist1Hard = leaked + orphan2 + nonStd > 0`；`:854-855 nonStd.length >= 3 → P0`。

**正则反事实实测**（本报告亲验，直接 eval 该正则）：

| 输入 | 判定 |
|---|---|
| `[COVID-19]` `[SARS-CoV-2]` `[GPT-4]` `[AI-2]` `[B2B-2]` | **被判「非标准编号」** |
| `[D-基-R-01]` `[C-主01]` `[L01-v2]` `[D01]` | 正确豁免 |

**为什么严重**：本包支持「行业分析 / AI 产业评论」这类文章类型，正文里出现 `[GPT-4]`、`[COVID-19]` 是**正常且必然**的 → M-Form-1 直接转 P0 → 整体 exit 2 → 按 `AGENTS.md`「M 门 exit 0 才返回」只能走 Acknowledged Limitations，等于**对一整类选题硬性阻断**。

**修复**：收窄为「必须像编号」（序号部分要求 ≥2 位或含 `-` 的规范形态），并把「≥3 条即 P0」降为 P2，同时复用既有的显式申报通道（脚注类编号）。

### 🔴 B-4 `apply-diff.mjs`：参数校验过松 + 默认原地覆盖（P0）

**事实**：`:31-34 optVal` 不校验 `--` 前缀、缺值返回 `null`；`:47 const outPath = optVal('--out') || targetPath`（**默认 = 输入正文**）；`:174 writeFileSync(outPath, text)`（**无 .bak**）；`:189 process.exit(skipped===0 && unparsed===0 ? 0 : 1)`；`:177-186` 恒 `ok:true` + hint「全部条目已机械应用」。

**实测**（本报告亲验）：

```
apply-diff <draft> <空清单>        → exit 0，JSON: {"ok":true, "applied":0, hint:"全部条目已机械应用…"}
apply-diff <draft> <清单> --out    → exit 0（缺值被静默接受；代码路径回落 targetPath）
apply-diff <draft> <清单> --dry-rnu → exit 0（拼错的 flag 被静默忽略 → 本以为是试运行，实际会落盘）
```

「空清单」与「真的全应用了」在输出上**不可区分**——而 apply-diff 正是本包 `SKILL.md:44` 指定的修订轮**唯一机械应用器**。
**附带**：`:85 text.replace(locateStr, head+newPart+tail)` 用字符串替换串，`$&` / `` $` `` / `$'` / `$$` 会被展开（B 报告实测 `$$`→`$` 使行间公式降级）——学术论文是支持类型，应改函数式 `replace(locateStr, () => head+newPart+tail)`。

**修复**：未知参数即 exit 10；`--out` 缺值即 10（对齐 `build-evidence-bundle.mjs:28`）；同文件时强制显式 `--in-place` + 自动 `.bak`；`items.length === 0` → exit 1；`replace` 改函数式。

### 🔴 B-5 写保护可用相对路径绕过（P0）

**事实**：`lib/guard.js:60` 用 `resolve(raw)`（基准 = 宿主进程 `process.cwd()`）；而真正的写工具把相对路径解析到**会话工作区** `exec.agent.session.header.cwd`。

**宿主证据**：`dsh-tool-fs/lib/index.js:225-242, 655, 804` —— 注释原文「so each session's `read`/`write`/`edit` act on its workspace, not the server's launch directory」。

**实测**（本报告亲验，宿主 cwd = `C:\Users\Zuoyunlai\.dsh`）：

```
会话工作区        = E:/HERNESS/lunheng-article-pipeline-dsh
传入相对路径      = skills/lunheng-article-pipeline/SKILL.md
  fs 工具实际写入 : E:\HERNESS\…\skills\lunheng-article-pipeline\SKILL.md  ← 受保护文件
  guard 检查的是  : C:\Users\Zuoyunlai\.dsh\skills\lunheng-article-pipeline\SKILL.md
判定              : ALLOW ← 绕过
```

只要宿主进程 cwd ≠ 会话工作区（DSH Desktop / `dsh web` 的常态），**相对路径即可穿过「机制文件写保护」**。

**修复**：基准改取 `execution.agent?.session?.header?.cwd`（与 fs 工具同源），拿不到时**拒绝而非放行**；`write`/`edit` 只取 `file_path` 键。

### 🔴 B-6 路径拼写绕过 + 保护错对象（P0/P1）

**实测**（9 个变体喂真实 guard）：

| 变体 | 结果 |
|---|---|
| 绝对路径（正/反斜杠）、`str_replace_editor` 的 `path` 键、数组多文件编辑 | DENY ✅ |
| **`e:/…`（小写盘符）** | **ALLOW ✗** |
| **`\\?\E:\…`（长路径前缀）** | **ALLOW ✗** |
| **`{ edits: { file: { file_path: … } } }`（二层嵌套对象）** | **ALLOW ✗** |

**并且（比绕过更值得注意）**：受保护根是**包自身的技能目录**（`lib/index.js:157`），而本包文档反复强调「项目级副本（rank 100）会**静默顶替** bundle（rank 250）」。本次审计工作区**正同时存在**两份：

```

E:\HERNESS\.dsh\skills\lunheng-article-pipeline\                          ← 实际生效（rank 100），无保护
```

## 6. 根因：一个这么认真的项目为什么会漏掉这些

1. **机械门覆盖的是「文本引用」，不是「数字合约」**。`consistency-check` 能查路径、工具名、版本点位，却查不出「M 门到底几项」「随包脚本几个」——于是**它反复宣称「已收敛/已去重/单一真源」的那些点，恰恰是继续漂移的点**（C-1…C-6 全是同一类）。
2. **「改文档以匹配实现」只执行了一半**（`M-Gate-Algorithm.md:766` 声明了，下游 15+ 处没改）。单点改名 = 制造新的名实分离，比不改更危险。
3. **两个真源并存、只有一个被保护**。项目自己写过「镜像不含 tests，在镜像上改 = 跳过契约验证」的教训，却没把这个洞察用到 guard 的作用域上。
4. **辅助脚本被当成「辅助」而免于输入校验**。核心两门（`m-gate-check` / `consistency-check`）**任何缺失输入都不产生 exit 0**（B 已验证），但**非门脚本**（build-evidence-bundle / apply-diff / md2html）大面积 fail-open 或原地破坏——而它们恰恰是主控最常敲的。
5. **环境依赖被登记为「环境限制」而没有转成「可用性矩阵」**。§九 记录了 `pwsh` 整段失效，但没回答「三条路径全废时闸门怎么办」。
6. **CLI 门的外部依赖被排除在供应链考虑之外**。Action 固定 SHA、拒绝缓存、OIDC+provenance 都做了，唯独 gate 2 每次从 registry 拉 `dsh-plugin-guide@0.3.7` 到**持有 `id-token: write` + `NPM_TOKEN` 的发布作业**里执行（`publish.yml:40` vs `:81`）；且该 pin 已落后（本机装的是 0.3.10，实测 `check` = 9 pass / **1 warn** / 4 skip，`--strict` **exit 1**，与仓库文档「14 项：11 通过 / 3 跳过、0 fail / 0 warn」不符；唯一 warn 是 CLI 期望 `README-zh.md` 而仓库用 `README.zh.md`）。
