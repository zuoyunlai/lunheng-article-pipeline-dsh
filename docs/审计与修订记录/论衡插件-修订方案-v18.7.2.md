### P0-1 修 apply-diff tail 切片索引错（致命）

- **文件**：`skills/lunheng-article-pipeline/scripts/apply-diff.mjs:126`
- **改动**：`const tail = locateStr.slice(L - from + oldPart.length)` → `const tail = locateStr.slice(L + oldPart.length)`
  - 推导（写入行内注释）：`from = i - L`，旧偏移 `L - from + oldPart.length = 2L - i + oldPart.length`，当公共前缀 `i > CTX ≥ L` 时为负 → tail 多取 `i - 2L` 个字符，把前缀字符 + oldPart 尾部重复注入。正确偏移 = 定位串内 `head(L) + oldPart` 之后的起点 = `L + oldPart.length`。
- **回归用例**（加进 `tests/scripts.test.mjs` 的 apply-diff 段，标题带「公共前缀>CTX」后缀防同名）：
  1. 现况/修改共享 >8 前导字符（如同一长句只改中段一词）、目标文件中该上下文唯一 → 断言替换后文本 == 期望文本逐字节相等，且不出现 oldPart 残留片段；
  2. 遍历 CTX ∈ {8,16,32,64} 各构造一例（前缀长度分别取 9/17/33/65）；
  3. 纯插入场景（oldPart 为空）回归不破（v18.2.5 修复过的形态，防修一漏一）。
- **验证**：`node --check` + 新用例红→绿（先写用例确认在旧实现上红，再改实现变绿，即 test-first）。

### P0-2 修 consistency-check `--fix --write` 不可达（严重）

- **文件**：`skills/lunheng-article-pipeline/scripts/consistency-check.mjs:53-58`
- **改动**：守卫条件 `a !== '--fix'` → `a !== '--fix' && a !== '--write'`；用法串同步为 `[--fix] [--write]`。
- **回归用例**：① `--write` 单独出现不再 exit 1；② `--fix --write` 在注入了可自动修复缺陷的临时仓库 fixture 上真实落盘且备份存在；③ `--nope` 仍被拒（守住 v18.0.5 的初衷不回退）。
- **连带核查**：`--fix` 分支内 `applyFix = process.argv.includes('--write')` 与完成文案（:277-298 一带）逻辑无需再改，仅确认可达。
