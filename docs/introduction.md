# 论衡：把「写一篇好文章」变成一条可审计、可交接的流水线

> **论衡（lunheng-article-pipeline）** 是一个多 Agent 深度长文生产流水线，DeepSeek Harness（dsh）bundle 插件。它不是让一个 AI 直接写文章，而是让一支 **8 个 AI 角色组成的"论文生产小队"** 按既定协议协作：定题 → 三线并行检索 → 分析 → 写作 → 批判 → 审计 → 终检。每一步都有明确产出物、交接报告与质量闸门，最终交付**有证据底座、有反方论证、有独立审计、有人工核验节点**的文章。

> 适用：公众号深度长文、研究报告、学术论文、商业评论、行业分析——任何"要站得住脚"的长内容。当前版本 **v2.3.7-dsh.2**（对应 OpenClaw 正典 v2.3.7）。

---

## 它解决什么痛点

用 AI 写深度长文，最常见的翻车点：

1. **幻觉编造**——引用是假的、数据是编的；
2. **观点堆砌**——材料一大堆，每条都不支撑论点；
3. **单边叙事**——只讲支持自己的话，回避反方证据；
4. **重复已有文章**——写出来早就有人写过，还当原创；
5. **质量不可控**——AI 一次成稿，没有独立角色挑错；
6. **引用悬空**——正文标了引用，文末清单对不上，无法核验。

论衡的答案，是把这些问题**交给结构化流程 + 多角色分工**去化解，而不是指望单个模型自觉。

## 核心设计：8 张角色卡 + 6 个阶段

```
主控 Coordinator（定题、拆解、派发、阶段闸门、终检、状态机）
  │
  ├─ T1 文献检索员 ── 文献卡 [Lxx]（A/B/C 可信度分级）+ 先行者清单（防重复）
  ├─ T2 数据检索员 ── 数据卡 [Dxx]（🟢🟡🔴 时效 + 信任级别 + 冲突口径并列）
  ├─ T3 案例检索员 ── 案例卡 [Cxx]（事件结构 + 多方立场 + ≥2 来源，任何量级必 spawn）
  ├─ T4 分析员     ── 分析大纲（论点-论据映射 + 反方论证规划 + 三角验证 + 原创性声明）
  ├─ T5 写手       ── 初稿（内联/编号引用，AI 去味 10 项，文末四节引用清单）
  ├─ T6 批判伙伴   ── 批判报告（C1-C5 反方攻击）
  ├─ T7 审计员     ── 审计报告（G0-G13 全项，只审不改）
  └─ T8 终检       ── 主控亲完成（M 门 + 定稿 + 证据包 + 交付说明，无角色卡）
```

编号 = 阶段顺序（T1-T3 检索 / T4-T5 加工 / T6-T8 防御）。六个阶段：**Phase 0 定题 → Phase 1 并行检索 → Phase 2 分析 → Phase 3 写作 → Phase 4 审计 → Phase 5 终检**，中间穿插 **T2.5 / T7.5 两道完整性门**（主控 checkpoint，不绕过交接直接派发）与 **4 个人在环节点**（定题 / 大纲 / 洞察补充 / 终稿）。

---

## 为什么多角色分工真的有效

### ① 三线并行检索 + 三角验证

Phase 1 一次性并行派出 **T1 文献 ∥ T2 数据 ∥ T3 案例** 三个检索员，真并行、互不干涉，各自只写自己的目录：

- 三张卡构成「三角验证」——任何核心论点必须映射到 [Lxx]（学术依据）+ [Dxx]（量级数据）+ [Cxx]（具体事件）至少两项，缺角标缺口，**严禁编造**；
- **T3 任何量级必 spawn**：即使主题"无需案例"，也走「0 条空卡协议」——显式声明无案例需求、输出空卡，保证流程可审计，不留下"到底查没查案例"的模糊地带；
- **强相关性铁律**：每条材料必答「它支撑哪个论点」，答不出不收；数量封顶（50-70 条），宁缺毋滥。

### ② 独立审计闭环（G0-G13 + M 门）

审计员 **只审不改**、与写手完全分离，执行 **G0-G13** 全项检查：

- **G1 分级核验**：C 级引用 100%、B 级 ≥50%、A 级 ≥10% 用 web_search 实测，抓到假引用升级 P0 并全量核验——实战中曾抓到「文献作者名未核」的真实问题；
- **G2 数据溯源 / G11 时效 / G12 信任级别**：每个数字有来源、过期数据告警、已发布/主人投喂/二手转引三档信任级别全量校验；
- **G7 原创性**：对照先行者清单，核心论点与他人重复且未声明 → P0；
- **G4-2 文末四节双向 diff**：正文引用 ↔ 文末「数据来源/案例来源/参考文献/先行者文献」四节双向核验，漏引/孤儿 → P1。

审计打回 → **独立写手**修订（强制 spawn 独立写手，主控不代笔）→ 复核，**最多 2 轮**，仍不过走 Acknowledged Limitations 模式诚实交付。

终检前主控跑 **M 门**——LLM 兜底执行的机械化终检（M-Form 6+7 + M-Exist 3 + M-Integrity 2），对引用完整性、文末四节存在性、临时编号残留、角色元数据泄漏、过程语言残留、信任级别标注做逐项机械判定，**exit 0 才交付**，产出 `M-Gate-Report.json`。

### ③ 人在环四节点

定题、大纲、洞察补充、终稿四个节点必须主人过目——在"改方向成本最低"的阶段由人把关，避免 AI 一路跑偏后推倒重来。

## v2.3.x 升级亮点

- **角色重编号（v2.3.0）**：编号 = 阶段顺序，T1-T3 检索 / T4-T5 加工 / T6-T8 防御——原 T6 案例 → T3、原 T3 分析 → T4、原 T4 写手 → T5、原 T8 批判 → T6、原 T5 审计 → T7，T8 终检由主控亲完成（不再单设角色卡）。
- **M 门机械化终检**：从"靠自觉"到"靠机械门"——形式合规 ≠ 存在性合规 ≠ 信任一致，三层验证，LLM 兜底执行、零脚本依赖。
- **T2.5 / T7.5 阶段闸门**（v2.3.0 将 T5.5 改为 T7.5）：T2→T4、T7→终检之间的主控 checkpoint，数据完整性、信任级别、审计关闭情况逐项核对，不通过不派发。
- **字数分层**：≥5000 全量流水线 / 3000-5000 标准 / 2000-3000 轻量档（跳 T6）/ <2000 简化直写——按需选档，不浪费。
- **文档分层**：SKILL.md 瘦身为索引，机制详情沉淀到 `references/`（设计文档 / deliverables / operations / case-studies / `_shared/`），单一维护不漂移。

## DSH 适配（开箱即用）

| 原 OpenClaw 工具 | DSH 对应 |
|---|---|
| `sessions_spawn` | `subagent`（后台、可续接） |
| `tavily_search` / `tavily_extract` | `web_search` / `read_page` |
| `update_plan` | `todo_write` |
| `sessions_history/list` | `list_agents` |
| `image_generate`（封面） | 无内置 → SVG 矢量风 / 主人投喂 |
| `exec` / `apply_patch` | `pwsh`/`bash` / `edit` |

DSH 下的三个关键适配：

1. **执行约定精简**：OpenClaw 的心跳/分阶段 ack/8 分钟硬卡在 DSH 下移除，改为「状态机 + 交接报告六要素 + G8 自检 + 超时介入（`list_agents`）」——贴合 DSH 的子代理机制，不空转轮询。
2. **分档预设（按角色分模型）**：装「论衡分档」会话预设后，检索角色（T1/T2/T3）走 `subagent_retrieval`（默认 `deepseek-v4-flash`，便宜快）、分析/写作/批判（T4/T5/T6）走 `subagent_strong`、审计（T7）走 `subagent_audit`，模型经 `LUNHENG_*_MODEL` 环境变量覆盖；未装预设则全部继承会话模型，流水线照常运行。
3. **子代理异常兜底**：failed 通知时主控按「验产物 → 验 status → 验口径」三步处理，不默认重跑（实跑沉淀）。

## 实战验证（真实跑通）

v2.2.8-dsh.2/3 在真实环境完整跑通一篇 **~2000 字公众号短评《AI 让你写得快，但未必让你更会写》**（主题：生成式 AI 对学生写作能力的影响）：

- T1 产出 12 条文献（A7/B2/C3）+ 9 条先行者；T2 产出 26 条数据（含信任级别/时效/口径）；案例走 0 条空卡协议；
- 审计抓到 3 条 P1（文献作者名未核、原创性维度缺数据、正面证据单边化）→ 独立写手 1 轮修订全部关闭 → 复核通过；
- M 门全项过 exit 0，产出 M-Gate-Report；
- 全程零编造、文末四节双向 diff 闭环、AI 使用披露三段齐全。

这次实跑还暴露并修复了 10 个流程问题（T2.5 门逻辑、子代理异常兜底、数据卡计数自检、文献作者必核等），已全部沉淀进 v2.2.8-dsh.3。v2.3.0 角色重编号为纯结构改动，流程机制与实跑沉淀保持一致。

## 快速上手

```sh
# 1) 安装到 profile
dsh plugin --profile web add lunheng-article-pipeline

# 2) 加入 bundles 清单
#    $DSH_HOME/profiles/web/package.json 的 dsh.profile.bundles 追加 "lunheng-article-pipeline"

# 3) 重启 dsh web
```

新会话的 `skill` 工具目录会出现 `lunheng-article-pipeline`，直接说「加载 lunheng-article-pipeline 技能」或交给它一个深度文章主题，它会先走 Phase 0 定题确认（含外部服务 4 选 1 明示同意）。

> **安装注意**：① 目标机器需有 pnpm（`dsh plugin` 内部转 pnpm）；② `dsh plugin add` 只装包、**不会**自动把 bundle 加进 `dsh.profile.bundles`——第 2 步必须手动做；③ 依赖版本如被精确锁定（如 `2.3.7-dsh.1`），升级需手动改 `package.json` 依赖后 `pnpm install`；④ 用 dshmarket 市场的用户会看到「校验失败」误报（它只认 JS 入口，不认 `dsh.bundle.patch`），不影响实际使用。

## 结语

论衡把「写一篇好文章」这件看似靠才华的事，拆解成了一套**可复制、可审计、可交接**的工程流程：证据底座防幻觉，三角验证防堆砌，反方论证防单边，先行者检索防重复，批判伙伴磨论证，独立审计防质量漂移，M 门机械终检防侥幸，人在环防跑偏。

它尤其适合：公众号深度文章、研究报告、学术论文、长文评论——以及任何"要站得住脚"的长内容生产场景。
