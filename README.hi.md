# लुन्हेंग (lunheng-article-pipeline) — बहु-एजेंट दीर्घ-लेख पाइपलाइन

> 版本：v18.0.3（DSH bundle：package.json + cordis.patch.yml + lib/index.js）

> एक DeepSeek Harness (DSH) बंडल जो माँग पर एक एजेंट स्किल पंजीकृत करता है। यह स्किल दीर्घ लेखन — शोध-पत्र, उद्योग विश्लेषण, व्यावसायिक समीक्षा और लंबे लेख — को **मानव-सहभागिता वाली 9-भूमिका पाइपलाइन** में बदल देती है।

## What this is

लुन्हेंग एक लेखन पाइपलाइन है, पाठ जनरेटर नहीं। यह दीर्घ लेख के उत्पादन को 6 चरणों में 9 स्वतंत्र भूमिकाओं (T1–T9) में बाँटती है, उन्हें DSH के `subagent` कॉल से संचालित करती है, और प्रमाण-आधार, प्रति-तर्क समीक्षा, स्वतंत्र लेखा-परीक्षण तथा मानव जाँच-बिंदुओं सहित परिणाम देती है।

नौ भूमिकाएँ स्वतंत्र और अप्रतिस्थाप्य हैं: T1 साहित्य खोज, T2 आँकड़ा खोज, T3 प्रकरण खोज, T4 विश्लेषण, T5 लेखन, T6 समालोचक साथी, T7 लेखा-परीक्षक, T8 अंतिम जाँच (समन्वयक स्वयं करता है), T9 सहकर्मी समीक्षा।

## When to use it

- आपको ऐसा दीर्घ लेख चाहिए (2000 अक्षरों से अधिक) जो परीक्षण में टिके, और आप 1–3 घंटे प्रतीक्षा कर सकते हैं।
- विषय में तथ्य, आँकड़े या अनेक दृष्टिकोण हैं, अतः मत-मात्र नहीं बल्कि प्रमाण-आधार चाहिए।
- आप मानव जाँच-बिंदु चाहते हैं: लिखने से पहले रूपरेखा की पुष्टि, और अंतिम प्रारूप की समीक्षा।

## When not to use it

लुन्हेंग **प्रकाशित** प्रमाण जुटाती है और आपके दिए प्रमाण को समाहित करती है। निम्नलिखित स्वयं नहीं कर सकती; सामग्री पहले दें या दूसरा साधन चुनें:

- **प्रथम-हस्त आँकड़ा संग्रह** — प्रयोग, सर्वेक्षण, साक्षात्कार, क्षेत्र-कार्य।
- **सांख्यिकीय विश्लेषण** — परिणाम उद्धृत कर सकती है, पर SPSS/R/Python नहीं चलाती।
- **चार्ट हेतु कच्चा आँकड़ा संग्रह** — दृश्यांकन बनाती है; स्क्रैपिंग, OCR और वाक्-लेखन हेतु अलग साधन चाहिए।
- **मौलिक चित्र या वीडियो** — DSH में चित्र-जनन अंतर्निहित नहीं; आवरण स्थानीय SVG या आपकी दी फ़ाइल से बनते हैं।
- **कोड निष्पादन** — पाइपलाइन केवल अनुमत स्क्रिप्ट चलाती है; शेष हेतु आपकी स्पष्ट अनुमति आवश्यक है।

सरल नियम: पूछें कि प्रमाण पहले से **प्रकाशित** है या नहीं। हाँ हो तो लुन्हेंग जुटाएगी; न हो तो पहले दें।

## What you get

| मद | विवरण |
|---|---|
| साहित्य कार्ड `[Lxx]` | प्रकाशित स्रोत, A/B/C विश्वसनीयता श्रेणी और पूर्ववर्ती सूची |
| आँकड़ा कार्ड `[Dxx]` | मान, स्रोत, वर्ष, ताज़गी श्रेणी, विश्वास स्तर और परस्पर विरोधी मान साथ-साथ |
| प्रकरण कार्ड `[Cxx]` | घटना-संरचना (कौन/कब/क्या/प्रत्येक पक्ष), या स्पष्ट `[C-空]` रिक्त चिह्न |
| विश्लेषण रूपरेखा | तर्क-धारा, दावा-प्रमाण मानचित्रण, प्रति-तर्क योजना, भार-वाहक प्रमाण |
| प्रारूप | क्रमिक संस्करण, AI-चिह्न सफ़ाई सहित, प्रत्येक स्वतंत्र लेखक से |
| रिपोर्ट | समालोचना (C1–C7), लेखा-परीक्षा (G0–G14), सहकर्मी समीक्षा (6 आयाम + पत्रिकाएँ) |
| अंतिम उपज | `final/定稿.md`, चित्र, प्रमाण-पुंज, वितरण टिप्पणियाँ, M-द्वार रिपोर्ट |

## Pipeline overview

```text
चरण 0  विषय          विषय, लंबाई, उद्धरण-प्रारूप तय; बाह्य सेवाओं की सहमति
चरण 1  खोज           T1 साहित्य ∥ T2 आँकड़े ∥ T3 प्रकरण (वास्तविक समानांतर, स्वतंत्र)
द्वार T2.5            आँकड़ा प्रविष्टियाँ ≥ ब्रीफ़ की माँग; विश्वास स्तर पूर्ण
चरण 2  विश्लेषण       T4 विश्लेषक → विश्लेषण रूपरेखा
चरण 2.5 रूपरेखा       मानव समीक्षा (चक्र में)
चरण 3  लेखन          T5 लेखक → प्रारूप v1
चरण 3.5 दृष्टि        मानव प्रथम-हस्त संदर्भ देता है (चक्र में) → प्रारूप v2
चरण 3.6 समालोचना     T6 समालोचक साथी → C1–C7 रिपोर्ट
चरण 4  लेखा-परीक्षा   T7 परीक्षक → G0–G14 रिपोर्ट और संशोधन सूची
चरण 4.2 संशोधन        लेखक + संशोधन टिप्पणियाँ (≤2 चक्र, स्वतंत्र लेखक)
चरण 4.5 समीक्षा       T9 सहकर्मी समीक्षा + G14 AI-चिह्न द्वार (समानांतर); चित्र
द्वार T7.5            नवीनतम परीक्षा + P0/P1 सूची + M-द्वार exit 0 + पृथक्करण
चरण 5  अंतिम जाँच     T8 (समन्वयक द्वारा) → अंतिम पाठ, प्रमाण-पुंज, वितरण टिप्पणियाँ
```

**त्रिकोणीय प्रमाण-आधार** (`[L]` + `[D]` + `[C]`) — प्रत्येक दावा साहित्य, आँकड़ों और घटना-दावों हेतु प्रकरणों से जुड़ना चाहिए। **स्वतंत्र लेखा-परीक्षा** — परीक्षक कभी संपादन नहीं करता। **चार मानव बिंदु** — चरण 0, 2.5, 3.5 और 5।

## Install

**बंडल के रूप में** (अनुशंसित; प्रवेश स्किल पंजीकृत करता है और patch परत स्तर सक्रिय करती है):

```sh
dsh plugin --profile web add lunheng-article-pipeline
dsh --profile web --dump-config   # "# == lunheng-article-pipeline" परत दिखती है
```

नया `dsh` `dsh.bundle` घोषणा देखते ही निर्भरता को `dsh.profile.bundles` में जोड़ देता है — स्थापित करें और `dsh web` पुनः आरंभ करें। केवल शुद्ध npm/pnpm स्थापना या पुराने संस्करणों में मैनुअल प्रविष्टि चाहिए।

**सादे स्किल निर्देशिका के रूप में** (स्थापना नहीं, तत्काल पुनःलोड):

```sh
# स्किल निर्देशिका (रिपॉज़िटरी रूट नहीं) को किसी भी DSH स्किल-मूल में प्रतिलिपि करें:
#   $DSH_HOME/skills/lunheng-article-pipeline        (उपयोगकर्ता, rank 400)
#   <प्रोजेक्ट>/.dsh/skills/lunheng-article-pipeline (प्रोजेक्ट, rank 100)
```

सादी निर्देशिका में `dsh.bundle` घोषणा नहीं होती, अतः `dsh plugin add` उसे केवल निर्भरता मानकर स्थापित करता है और **कोई परत सक्रिय नहीं होती**। स्किल निर्देशिका की प्रतिलिपि ही समर्थित मार्ग है।

### Uninstall

```sh
dsh plugin --profile <profile> remove lunheng-article-pipeline
```

विस्थापन पर `cordis.patch.yml` की 3 `- insert:` पंक्तियाँ और प्रवेश द्वारा पंजीकृत स्किल — दोनों हट जाती हैं, कोई अवशेष नहीं। यदि आपने स्किल निर्देशिका किसी स्किल-मूल में भी प्रतिलिपि की थी, तो उसे अलग से हटाएँ।

## Model routing

DSH में मॉडल मार्ग `settings.yaml` तय करता है; `subagent` सत्र-मॉडल विरासत में लेता है, अतः एकल-मॉडल विन्यास बिना सेटिंग चलता है। भूमिका-अनुसार स्तरीकरण हेतु बंडल तीन स्तरीय साधन स्थापित करता है:

| साधन | भूमिकाएँ | क्षमता |
|---|---|---|
| `subagent_retrieval` | T1 साहित्य / T2 आँकड़े / T3 प्रकरण | सस्ता और तेज़ |
| `subagent_strong` | T4 विश्लेषण / T5 लेखन | प्रबल तर्कण |
| `subagent_audit` | T6 समालोचना / T7 लेखा-परीक्षा / T9 समीक्षा / G14 संसूचक | शीर्ष स्तर, लागत घटाकर नहीं |

`LUNHENG_{RETRIEVAL,STRONG,AUDIT}_PROVIDER` और `LUNHENG_{RETRIEVAL,STRONG,AUDIT}_MODEL` से अधिलेखन करें: प्रदाता और मॉडल स्वतंत्र क्षेत्र हैं (प्रदाता बदलने पर दोनों आवश्यक), और `LUNHENG_TIERING=off` तीनों स्तरों को विरासत पर लौटा देता है। स्तर-साधन अनुपलब्ध हो तो प्रेषण `subagent` पर लौटता है। देखें `examples/preset/README.md` और `docs/installation.md`।

## Known limitations

- **चीनी प्राथमिकता।** भूमिका-प्रॉम्प्ट, उपज, फ़ाइल-नाम और प्रवाह डिफ़ॉल्ट रूप से चीनी में हैं।
- **डिफ़ॉल्ट रूप से जाल-सत्यापन नहीं।** भुगतान-आधारित स्रोत न मिलने से संख्यात्मक जाँच प्रायः «मानव समीक्षा हेतु लंबित» रहती है।
- **स्वतंत्र परीक्षा की लागत है।** पूर्ण चक्र में 15+ उप-एजेंट भेजे जाते हैं; व्यय मुख्यतः संदर्भ-पठन में होता है।
- **M-द्वार में असत्य-धनात्मक संभव।** अंतिम जाँच को `script_exit_raw` अंकित करके `exit` निर्णय का कारण देना चाहिए, न कि exit 0 हेतु दस्तावेज़ बदलना।
- **वास्तविक समीक्षा का विकल्प नहीं।** T9 रिपोर्ट केवल प्रस्तुति-पूर्व अनुकरण है।
