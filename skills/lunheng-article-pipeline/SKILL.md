# 多 Agent 深度长文流水线（论文/深度文章生产）

> 把一篇深度文章/论文的生产拆成 **7 个角色 + 5 个阶段**（Phase 1 为 T1 文献∥T2 数据∥T6 案例 三检索员**三方真并行、互不干涉**，T6 **任何量级必 spawn** 含 0 条场景空卡协议，v2.1.8），用 DSH `subagent` 子代理编排。产出有证据底座（文献卡+数据卡+案例卡）、有反方论证、有独立审计、有人工核验节点的交付物。
> 适用：公众号深度文章、研究报告、论文、长文评论。经验证：一篇 7650 字/8 节/2 图/52 文献/60 数据点的深度文，全流程约 2 小时完成。

## 🔧 DSH 适配说明（v2.1.8-dsh.1 — 从 OpenClaw 移植到 DeepSeek Harness）

本技能原为 OpenClaw 编写。在 DeepSeek Harness（dsh web，standard 预设）环境下，工具映射如下：

| OpenClaw 工具 | DSH 对应 | 说明 |
|---|---|---|
| `sessions_spawn` | `subagent` | 派发子代理（后台、可续接）；`subagent_fork` 可继承本会话上下文 |
| `sessions_yield` | `subagent` 默认后台 + 完成通知 | 并行派发后等待各子代理的完成通知，不要空转轮询 |
| `sessions_history` / `sessions_list` | `list_agents` | 查看/续接子代理 |
| `update_plan` | `todo_write` | 计划与任务跟踪 |
| `web_search` | `web_search` | 已内置；搜索提供方按 DSH 配置 |
| `web_fetch` | （默认关闭） | standard 预设 `fetch: false`；需抓取时经主人开启，或改用 `pwsh`/`bash` |
| `tavily_search` / `tavily_extract` | 无内置 → 用 `web_search` | 如需 Tavily 可另配 Tavily MCP（`dsh-mcp-client`） |
| `memory_get` / `memory_search` / `memory_store` / `memory_recall` | 无内置记忆工具 → 用文件 | 沿用本技能 `memory/*.md` 约定，读写文件即可 |
| `image_generate`（封面/插图） | 无内置图像生成工具 | 降级：SVG 矢量风（程序化，本地）或主人投喂图片 |
| `exec` / `process` | `bash`（Linux）/ `pwsh`（Windows） | 本机为 Windows，用 `pwsh` |
| `apply_patch` | `edit` / `str_replace_editor` | |
| `browser` / `cron` / `skill_workshop` / `tts` 等 | 无对应 | 不适用 |

**结构性差异（重要，覆盖正文中所有残留的 OpenClaw 表述）**：
1. **技能级工具白名单/denied 在 DSH 无效**：工具集由 Agent 预设决定，技能声明不了也禁不了工具；正文中「15 项白名单」「不要试图调用 exec」等段落仅为原 OpenClaw 环境的残留说明，DSH 下模型可用工具以当前会话预设为准。
2. **模型分配无法在技能内强制**：DSH 的模型路由由 `settings.yaml` / LLM 适配器配置决定，`subagent` 默认继承会话模型；正文中的模型建议（deepseek-v4-flash / minimax-m3 等）仅供参考。
3. **运行时目录约定**：`run/<项目名>/` 工作树、`memory/*.md`、`final/` 等由本技能在项目启动时创建；机制文档在本技能目录的 `references/`（原 OpenClaw 部署的 `pipeline/` 对应 `references/`）。

## 何时使用
- 主人要一篇「有深度、要站得住脚」的长文（>3000 字），且愿意等 1-3 小时
- 主题涉及事实/数据/多方观点，需要证据底座而非纯观点输出
- 需要「人在环」把关：大纲确认后再写，终稿人工审

## 🚫 不适用场景（边界明示 — v2.1.5 新增，v2.1.5.1 修正表述）

论衡是「论文/深度文章」**写作流水线**，**擅长主动检索已发布证据 + 整合主人投喂的证据**。

**论衡能主动采集**（T1 文献检索 / T2 数据检索 / T6 案例检索 sub-agent）：
- ✅ 已发布的学术文献（PubMed / CNKI / Web of Science 等数据库）
- ✅ 已发布的统计数据（教育部 / 统计局 / 行业协会等公开数据）
- ✅ 已发布的案例与报道（媒体 / 法院判决 / 行业报告等公开案例）
- ✅ 政府发布的统计 / 报告 / 调查 / 政策文件

**论衡不能主动采集**（需要主人提前准备素材投喂）：
- ❌ **一手原始数据采集**：实验设计 / 调查问卷投放 / 用户访谈 / 田野调查 → 需要主人亲自调研，原始数据投喂为「数据源」
- ❌ **统计分析**（SPSS/R/Python 跑模型）：论衡可以引用统计结果，但**不执行统计计算**。如需跑回归/聚类/因子分析，请主人用专门工具，结论以「数据 + 方法描述 + 结果」形式投喂
- ❌ **图表原始数据采集**：论衡生成的是**数据可视化**（matplotlib/SVG），数据本身需主人提供。如需爬虫/OCR/语音转文字，请主人用专门工具，原始数据投喂后论衡制作图表
- ❌ **原创图片 / 视频生成**：DSH 无内置图像生成工具（原 OpenClaw 的 `image_generate` 不可用）——封面/插图降级为 SVG 矢量风（程序化）或主人投喂图片；**不能拍摄实物照片 / 录制视频**。如需实物素材，请主人拍摄后投喂文件路径，论衡可在文末引用
- ❌ **代码执行**：本技能不主动跑代码（原 OpenClaw 环境 `exec` 被 deny）。DSH 下如需跑代码验证论据，可经主人同意后用 `pwsh`/`bash` 执行，结果投喂为证据

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」——是，论衡主动采集；不是（是一手原始数据 / 自己拍的素材 / 自己跑的计算），主人投喂后再用。

## ⚠️ 执行前安全须知（v2.0.2 起强制）
- **写入范围明示**：本流水线会创建 `run/<项目名>/` 文件树（含 01-任务简报 / status / 文献卡 / 数据卡 / 大纲 / 草稿 / 审计报告 / 定稿 / 图件 / 证据包 / 交付说明），共约 15-25 个文件，仅写入到**当前 workspace 根目录**下，不会写到 workspace 外
- **<项目名> 由主人 Phase 0 显式确认**（不接受 LLM 自动命名），且必须满足：`[\w\-一-鿿]{1,32}`（无路径分隔符，无 `..`，无绝对路径前缀）
- **Phase 0 必须先列出将创建的全部文件清单**让主人确认，再开始 Phase 1（dry-run）
- **审计反哺不自动 commit**：T5 审计员的反哺报告默认只产出 `audits/反哺报告-vN.md`，**不会**自动修改论衡 workspace 下的角色卡；任何对角色卡的改动必须由主人人工 review 后手动 merge
- **失败回滚**：任一 Phase 失败，已写入的文件保留在 `run/<项目名>/` 供人工清理，不会自动删除

## ⚠️ 外部服务与数据流声明（v2.1.2 新增；v2.1.8-dsh.1 按 DSH 工具集修订）

使用本流水线时，以下内容**可能发送到第三方服务商**（用于检索/审计）：

| 操作 | 发送内容 | 第三方服务商 | 适用阶段 |
|------|---------|------------|---------|
| `web_search` | 研究主题关键词、子问题短语 | DSH 的 web_search 提供方（按 DSH 配置，可能含 Google/Bing 等） | T1/T2/T3/T6 |
| ~~`tavily_search` / `tavily_extract`~~（DSH 无） | —— | 改用 `web_search`；如需 Tavily 请另配 Tavily MCP | T1/T2/T6 |
| ~~`image_generate`~~（DSH 无内置） | —— | 封面降级：SVG 矢量风（程序化，本地，无外发）或主人投喂图片 | Phase 4.5 |
| 大模型推理（写作/分析/审计/反哺） | 文献卡/数据卡/案例卡/草稿/大纲等全文 | **当前 DSH 配置的模型 provider**（按 DSH `settings.yaml` / LLM 适配器） | T3/T4/T5 + 主控 |
| ~~`memory_get` / `memory_search`~~（DSH 无） | —— | 用文件记忆（`memory/*.md`），本地不外发 | 全程辅助 |

**主控必须在 Phase 0 主人确认时同步告知**：
1. 研究主题、子问题、检索关键词会发到 `web_search` 的搜索提供方（外部，按 DSH 配置）
2. 封面：DSH 无内置图像生成，默认 SVG 矢量风（本地）或主人投喂，**不外发**
3. 文章全文会发到当前模型 provider 用于推理/写作/审计
4. 涉及未公开主题 / 客户内部信息 / 商业机密的研究，建议：
   - 改用匿名化的子问题措辞（脱敏）
   - 封面一律用 SVG 矢量风（纯本地，无外发）
   - 主控推理改用本地模型（按 DSH 配置，如本地 Ollama 端点，零成本）

**主人拒绝任一外发项** → 主控调整方案并重做 Phase 0 确认。

## 流水线全景（Phase 0-5）

```
Phase 0 定题        与主人确认主题/篇幅/受众/配图需求 → 01-任务简报.md + status.md
Phase 1 并行检索    T1 文献检索员 ∥ T2 数据检索员 ∥ T6 案例检索员（**任何量级必 spawn**，含 0 条空卡协议；subagent 三方真并行后台派发，等完成通知）
Phase 2 分析        T3 分析员 → analysis/分析大纲.md（论点-论据映射 + 反方论证规划）
Phase 2.5 大纲确认  主人过目大纲 → 确认/修改（人在环！改方向成本最低，不可跳过）
Phase 3 写作        T4 写手 → drafts/初稿-v1.md（铁律：引用标[Lxx]、数字标[Dxx]、AI去味10项）
Phase 4 审计        T5 审计员 → audits/审计报告-vN.md（G0覆盖度/G1引用核验/G2数据溯源/G3逻辑/G4格式/G5规范）
Phase 4.2 修订      审计打回 → 写手交修订说明+修订稿 → 审计复核 ≤2 轮 → 仍不过升级主控
Phase 4.5 配图      （可选）写手标 [图N：标题] 图位 → 主控程序化生成图表（数字与数据卡一致）；**封面生成降级方案（DSH 无内置图像工具）**——默认 SVG 矢量风（程序化生成，本地无外发）或主人投喂图片；首次封面需送主人确认风格
Phase 5 终检        主控终检 → final/定稿.md + 图件/ + 证据包/ + 交付说明.md
```

## 核心原则

1. **证据底座先行 + 三角验证**：任何论点必须能映射到文献卡[Lxx]+数据卡[Dxx]+案例卡[Cxx]（涉企业行为/事件者必须配案例卡，至少两项齐全）；检索不到就标缺口，严禁编造
2. **人在环四节点**：Phase 0（定题）、Phase 2.5（大纲）、Phase 3.5（洞察补充）、Phase 5（终稿）必须让主人过目
3. **反方论证强制**：每个核心论点配「可能的反驳+回应策略」，避免单边叙事
4. **独立审计**：审计员只审不改，与写手分离；引用分级抽验（C级100%/B级≥50%/A级≥10%）；案例卡新增「G2.5 案例核验」项（多源交叉、时间锚点、立场并列）
5. **模型分工**：检索用便宜快模型（如 deepseek-v4-flash），分析/写作用推理强模型（如 deepseek-v4-pro / MiniMax-M3），审计用顶配（如 MiniMax-M3 / Claude），主控负责判断路由（具体按本机可用模型调整）
6. **时间锚点显式化**：所有卡片（文献/数据/案例）写作时引用必带年份；案例卡额外要求填「检索截止日期」+「事件时间窗口」
7. **强相关性原则（防材料堆砌，2026-08-13 教训 #34）**：
   - **每条材料必答「它支撑哪个论点」**——卡片「与本文的关联」字段必填，答不出不收
   - **数量封顶**：[Lxx] 8-12 / [Dxx] 30-50 / [Cxx] 0-8（0 条走空卡协议），加一起 50-70 条封顶，宁缺毋滥
   - **反向淘汰自查**（交付前必走）：逐条问「删掉它哪条论点会塌」，无影响→砍
   - **相关性 vs 时效性冲突**：相关性优先；时效新鲜但相关性弱的材料不要
   - **案例卡特别警惕**：是「示例」还是「证据」？示例降级为正文引用，不进案例卡
8. **原创性保证（防「重复/改写已公开文章」，2026-08-13）**：
   - **先行者检索**（T1）：检索支持文献同时，主动搜「该主题是否已有公开深度文/论文写过类似核心论点」，产出先行者清单
   - **差异点声明**（T3）：分析大纲必须声明「本文核心论点与已公开文章的差异点」
   - **G7 原创性审计**（T5）：核心论点与他人重复且未声明 → P0；差异点声明模糊 → P1

## 派发话术（主控复制即用，完整版见 references/agents/）

### T1 文献检索员（并行①）
```
你是「文献检索员」。任务编号 T1。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search 检索主题相关文献（中英文；知网/万方/Google Scholar/期刊官网/SSRN）
2. 产出 literature/文献卡.md：8-12 条核心文献，按子问题分组
3. 每条必须真实存在：作者、年份、标题、期刊/来源、DOI 或 URL、与本文的关联
4. 每条标可信度等级：A（核心期刊/权威机构）/ B（一般期刊/预印本）/ C（网络/二手转引）——C 级必须诚实标注
5. 参考文献条目按任务简报指定格式输出（默认 GB/T 7714），写手可直接粘贴
6. 严禁编造引用；检索不到就写「未检索到」，不许凑数
7. 交接报告六要素（含 status.md 更新）
8. **先行者检索（原创性保证）**：主动搜「该主题是否已有公开深度文/论文写过类似核心论点」，产出 `literature/先行者清单.md`（每条含：文章标题/作者/来源/年份/URL + 核心论点 + 与本文的差异点）
```

### T2 数据检索员（并行②）
```
你是「数据检索员」。任务编号 T2。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search 检索主题相关统计数据（国家统计局/世界银行/CEIC/皮书/权威数据库）

3. 每条标时效评级：🟢 ≤2年 / 🟡 2-5年 / 🔴 >5年（红级显著标注）
```


### T3 分析员

## 审计必查项（G0-G5 详解）

| 检查项 | 内容 | 违规级别 |
|--------|------|---------|
| G0 覆盖度 | 对照简报逐项核对研究问题是否回答、有无跑题 | 缺失→P0 |
| G1 引用核验 | C级100%/B级≥50%/A级≥10% 抽验 + 上下文匹配 | 假→P0 |
| G2 数据溯源 | 每个数字查数据卡来源；关键论点用🔴数据未说明 | 无源→P0 / 红级→P1 |
| **G2.5 案例核验** | **每条 ≥2 来源；时间锚点（检索截止+事件窗口）齐备；多方立场并列；C级诚实标注** | **单源/缺期/单方→P1，C 伪装 A→P0** |
| G3 逻辑 | 论点有无论据、论据是否支撑、有无稻草人；涉企业行为/事件的论点是否有 [Cxx] | 断裂→P0 / 缺角→P1 |
| G4 格式 | 结构完整、引用格式、参考文献对应、篇幅 | 不统一→P1 |
| G5 规范 | 查重意识、AI 痕迹（禁做10项逐项查） | 套话→P1 |

## 修订回环
```

```

## 配图生成规范（Phase 4.5）

- **数据图表**：程序化生成（matplotlib/SVG 脚本），**禁止文生图**（数字不可控）。图位来自写手标注的 [图N]，图上数字必须与数据卡/正文 [Dxx]/案例卡 [Cxx] 一致，生成后抽查核对
- **封面视觉（DSH 适配：无内置图像生成工具）**：默认 **SVG 矢量风**（程序化生成，本地、无外发）或主人投喂图片。prompt/设计严格遵循主人「极简自然」调性 + 主题关键词 + 文字排版位置预留。**首次封面需主人确认风格**（人在环）后再定稿；如主人需要更高质量封面，可自行用外部工具生成后投喂文件路径
- **中文字体**：matplotlib 需显式注册 Noto Sans CJK SC，否则中文乱码
- **图件入 final/图件/**，交付说明列清单；数值标签与来源注释避免同侧重叠（来源统一放底部）
- **案例示意图**（可选）：复杂事件链可用 SVG 画时间线/关系图，不画文生图

## 写作禁做清单（AI 去味 10 项，审计员逐项查）

1. 排比堆砌（连续 3 组以上同构排比 → 拆掉）
2. 金句密度过高（每千字不超过 1 句"点睛句"）
3. 无第一人称（要有"我认为/本文认为"的主体声音）
4. 缺具体细节（论证必须有具体案例/数字/场景支撑）
5. 过度防御性表述（"值得注意的是""不可否认"滥用）
6. 抽象概念密度过高（一段超 2 个抽象大词 → 拆解+举例）
7. 段落结构过度对称（避免每段"总-分-总"机械对称）
8. 学术过渡词过多（"综上所述""进而""由此可见"克制使用）
9. 表格过多（非必要不列表）
10. 缺研究者个人观察（正文要有自己的判断和发现）

## 实战验证案例

- **商业热点深度文**（2026-08）：8节/7650字/2数据图/52文献/60数据点，全流程约2小时。关键产出：事件时间线修正（"三次炮轰"实为"两年五次"）、监管规则逐条对照、行业案例对比。实战教训：除非作者明确要求，文章受众按普通人写，不硬贴作者职业视角。
- **品牌一致性深度文**（2026-08）：~7900字，证据包 15 文献 + 54 数据点，审计复核 8 项 P0/P1 全部修复。实战教训：修订后复核环节在主控会话外无人值守时易卡住；当时已有「失败案例」（JCPenney/MUJI/宜家）作为数据点存在但缺独立案例卡格式——本次 v2.1 优化为案例卡单独立档。
- **原创性悖论深度文**（2026-08-13，v2.2+v2.3 首次实战）：~9500字，证据包 12 文献 + 34 数据 + 6 案例，全文 4 轮修订（v1 主控精修 → v2 主人亲调 P5/P6 → v3 二次审计修 1P1+3P2）。实战暴露 3 类 v2.3 修复的问题：① T3 三连超时（→ 加调度模型健康度预检 + 超时硬卡 8 分钟）② 主人亲历「我接触过」+「10-50 万/SKU」无源（→ 加写手视角一致性铁律 + 审计 G0.5）③ 图注「维权前后 9 年」精度不足（→ 加图注时间三要素铁律）。另加：主人深度洞察融合协议（3 档处理）+ 反哺报告机制（v2.3 设，**v2.0.2 起强制默认只产出**，不自动 commit 角色卡）+ 论据类型自标 G6。
