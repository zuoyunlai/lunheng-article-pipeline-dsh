# 论衡（lunheng-article-pipeline）— 多 Agent 深度长文流水线

> **DSH 适配版（v2.1.8-dsh.1）**：本仓库为 DSH bundle 插件（技能包）；工具映射与结构性差异见 `SKILL.md` 的「🔧 DSH 适配说明」章节。

把一篇深度文章 / 论文的生产拆成 **7 个角色 + 5 个阶段**（Phase 1 为 T1∥T2∥T6 三检索员三方真并行互不干涉，T6 任何量级必 spawn 含 0 条空卡协议），用 DSH 的 `subagent` 子代理编排，产出有**证据底座、反方论证、独立审计、人工核验节点**的交付物。

> 适用：公众号深度文章、研究报告、论文、长文评论。经验证：一篇 ~9500 字的深度文，全流程约 2 小时完成。

---

## 何时使用 + 🌐 语言与定位声明（v2.1.1 新增）

**何时使用**：
- 主人要一篇「有深度、要站得住脚」的长文（>3000 字），且愿意等 1-3 小时
- 主题涉及事实/数据/多方观点，需要证据底座而非纯观点输出
- 需要「人在环」把关：大纲确认后再写，终稿人工审

**🌐 语言与定位（v2.1.1 新增）**：
> 本技能面向**中文研究场景**——人文社科论文/公众号深度文/中文行业评论。角色 prompt/交付物/文件名/操作流程均默认中文。

- **如需要非中文（英文/其他）研究产出**：主人可修改 prompts 为目标语言（所有 prompt 在 `references/agents/` 和 `references/templates/` 目录），但**默认不提供多语言**（保持简洁）
- **如需要多 locale 数据源**：主人可调整 `references/agents/02-数据检索-data-scout.md` 的新闻源列表（当前默认中文新闻源 + 国际英文媒体 Reuters/Bloomberg/FT/WSJ/HBR）
- **设计取舍**：中文研究是论衡的核心定位，强加多语言会稀释质量

## 🚫 不适用场景（边界明示 — v2.1.5 新增，v2.1.5.1 修正表述）

**论衡是「论文/深度文章」写作流水线**，擅长**主动检索已发布证据 + 整合主人投喂的证据**。下列场景**不能**主动完成，需主人投喂素材后再用：

- ❌ **一手原始数据采集** —— 实验 / 调查 / 访谈 / 田野调查 → 主人调研后投喂
- ❌ **统计分析**（SPSS / R / Python）—— 论衡可引用结果，**不执行计算**
- ❌ **图表原始数据采集** —— 论衡做**数据可视化**，爬虫 / OCR / 语音转文字需主人用专门工具
- ❌ **原创图片 / 视频生成** —— DSH 无内置图像生成工具（原 OpenClaw `image_generate` 不可用）：封面/插图降级为 SVG 矢量风或主人投喂，不**拍摄实物 / 录制视频**
- ❌ **代码执行** —— 本技能不主动跑代码（原 OpenClaw 环境 `exec` 不在白名单内）；DSH 下可经主人同意后用 `pwsh`/`bash` 执行

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」—— 是，论衡主动采集；不是，主人投喂后再用。详见 `references/pipeline-readme.md` 的「🚫 不适用场景」段。

## ⚠️ 数据流与第三方服务（v2.1.2 新增）

使用本技能时，以下内容会**发送到第三方服务商**：

| 操作 | 发送内容 | 第三方服务商 | 适用阶段 |
|------|---------|------------|---------|
| `web_search` | 检索关键词 | DSH 的 web_search 提供方（按 DSH 配置，路由可能含 Google/Bing） | T1/T2/T3/T6 |
| ~~`tavily_search` / `tavily_extract`~~（DSH 无） | —— | 改用 `web_search`；如需 Tavily 请另配 Tavily MCP | T1/T2/T6 |
| ~~`image_generate`~~（DSH 无内置） | —— | 封面降级：SVG 矢量风（程序化，本地）或主人投喂图片 | Phase 4.5 |
| 大模型推理 | 文献/数据/案例/草稿/大纲全文 | 当前模型 provider（按 DSH `settings.yaml` / LLM 适配器） | T3/T4/T5 + 主控 |
| ~~`memory_get` / `memory_search`~~（DSH 无） | —— | 用文件记忆（`memory/*.md`），本地不外发 | 全程辅助 |

**主控必须在 Phase 0 主人确认时同步告知上述外发项**。涉及未公开主题/客户内部信息/商业机密的研究：
- 改用匿名化措辞（脱敏）
- 封面一律用 SVG 矢量风（本地零外发，DSH 默认即此）
- 主控推理改用本地模型（按 DSH 配置，如本地 Ollama 端点，零成本）

**主人拒绝任一外发项** → 主控调整方案并重做 Phase 0 确认。详见 SKILL.md 「⚠️ 外部服务与数据流声明」章节。

### ⚠️ v2.1.7 升级 — Phase 0 强同意关卡

上面「数据流与第三方服务」表的工具都会外发——**项目名/主题/论文纲要可能含未公开信息**（客户内部 / 商业机密 / 个人隐私）。主控 Phase 0 必须给主人「4 选 1」明示同意：

| 选项 | 适用 | 零外发项 |
|------|------|---------|
| ① 全部同意（默认）| 公开主题 / 不介意外发 | 无 |
| ② 脱敏+SVG 封面+本地推理 | 未公开主题 / 客户内部 / 商业机密 | web_search / 当前模型 provider |
| ③ 部分同意 | 主人指定具体外发项 | 主人未勾选的项 |
| ④ 全部拒绝 | 极端敏感 | 全部 → 改纯本地（Ollama + SVG）|

**主控必须**把主人选项 + 同意时间写入 `01-任务简报.md` 头部作为审计可追溯依据。详见 `references/pipeline-readme.md` 的「Phase 0 强同意关卡」段。

## 核心特点

### 三不原则（质量底线）

| 原则 | 机制 | 防什么 |
|------|------|--------|
| **不编造** | 引用带 URL/DOI + 数据带来源年份 + 审计分级抽验 | 幻觉 / 假引用 / 假数据 |
| **不堆砌** | 强相关性铁律（每条材料必答「它支撑哪个论点」+ 反向淘汰自查）| 材料凑数 / 观点堆砌 |
| **不重复** | 先行者检索 + 差异点声明 + 原创性审计 | 重复 / 改写已公开文章 |

### 七角色流水线（Phase 1 三检索员并行）

> **v2.1.4 补强**：添加 G8 成品度 + G9 时序合理性 + G10 核心模型一致性三项审计；定稿采用「数据来源 / 案例来源 / 参考文献 / 先行者文献」四节引用清单 + 双向 diff 机械化校验（教训 #47）；查看 `references/pipeline-readme.md` 包含 v2.0.2 → v2.1.4 完整版本日志。

```
主控（Coordinator）——定题、拆解、派发、终检、状态机
  │
  ├─ T1 文献检索员（Literature Scout）── 文献卡 [Lxx]（A/B/C 可信度分级）
  ├─ T2 数据检索员（Data Scout）────── 数据卡 [Dxx]（🟢🟡🔴 时效评级 + 冲突并列）
  ├─ T6 案例检索员（Case Scout）────── 案例卡 [Cxx]（事件结构证据，三角验证第三块，**任何量级必 spawn** 含 0 条空卡）
  ├─ T3 分析员（Analyst）───────────── 分析大纲（论证主线 + 论点-论据映射 + 反方论证）
  ├─ T4 写手（Writer）───────────────── 初稿（引用标 [Lxx] / 数字标 [Dxx] / 案例标 [Cxx]）
  └─ T5 审计员（Auditor）───────────── 审计报告（G0-G11 全项检查，只审不改）
```

### 三角验证（证据底座）

任何论点必须能映射到三类证据，涉企业行为 / 事件必须有案例卡：

| 卡片 | 给的是 | 适用论点 |
|------|--------|---------|
| 文献卡 [Lxx] | 理论 / 学术依据 | 「这事有没有人研究过」 |
| 数据卡 [Dxx] | 量级 / 趋势 | 「这事多大、占比多少」 |
| 案例卡 [Cxx] | 事件结构（who/when/what/各方说法）| 「这事具体怎么发生的」 |

### 人在环四节点

- **Phase 0 定题** —— 人工确认主题
- **Phase 2.5 大纲** —— 人工确认论证方向（改方向成本最低）
- **Phase 3.5 洞察补充** —— 人工补充一线经验/具体场景（v2.1.3 新增，审计前进入正文）
- **Phase 5 终稿** —— 人工终审

### 独立审计（G0-G11）

审计员与写手分离，全项检查：G0 覆盖度 · G0.5 视角一致性 · G1 引用核验 · G2 数据溯源 · G2.5 案例核验 · G3 逻辑 · G4 格式 · G4-2 文末四节 · G5 规范 · G6 论据自标 · G7 原创性审计 · G8 成品度 · G9 时序合理性 · G10 一致性 · G11 数据时效。

## 流水线全景

```
Phase 0 定题        确认主题/篇幅/引用格式 → 任务简报 + 状态机
Phase 1 并行检索    T1 文献 ∥ T2 数据 ∥ T6 案例（任何量级必 spawn，含 0 条空卡），先行者检索
Phase 2 分析        T3 分析员 → 分析大纲（三角验证 + 原创性声明）
Phase 2.5 大纲确认   主人过目（人在环）
Phase 3 写作        T4 写手 → 初稿（AI 去味 10 项 + 反方论证）
Phase 3.5 洞察补充   主人补充一线经验（人在环，v2.1.3）→ 写手 v2 融入
Phase 4 审计        T5 审计员 → 审计报告（G0-G11）
Phase 4.2 修订       写手交修订说明 + 修订稿（≤2 轮）
Phase 4.5 配图       （可选）程序化生成数据图表（数字与数据卡一致）
Phase 5 终检        终稿 + 证据包（文献+数据+案例+审计）+ 交付说明
```

## 怎么用

### 方式一：DSH 插件（bundle）安装

```sh
# 1) 装进 profile 的 node_modules
dsh plugin --profile web add lunheng-article-pipeline

# 2) 把 bundle 加入 profile 清单 dsh.profile.bundles
#    "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "lunheng-article-pipeline"] } }

# 3) 重启 dsh web
```

装好后，新会话的 `skill` 工具目录会出现 `lunheng-article-pipeline`；主控 Agent 按 `references/pipeline-readme.md` 里的派发话术 spawn 各角色。

### 方式二：直接使用技能目录（不发布）

把本仓库的 `skills/lunheng-article-pipeline/` 目录复制到任一 DSH 技能根（`$DSH_HOME/skills/` 或项目 `.dsh/skills/`）即可，无需安装、热加载生效。

### 模型更换

DSH 的模型路由由 `settings.yaml` 配置决定，`subagent` 默认继承会话模型。本技能内的「成本与模型建议」表只作能力分层参考，不构成硬性配置（详见 `references/pipeline-readme.md`）。

要**按角色分模型**，装本包的「分档预设」`examples/preset/`（复制到 `$DSH_HOME/.agent-presets/lunheng/`，新会话选「论衡分档」），主控会改用三档工具按角色分派：

| 工具 | 角色 | 默认模型 | 环境变量 |
|---|---|---|---|
| `subagent_retrieval` | T1 文献 / T2 数据 / T6 案例 | `deepseek-v4-flash` | `LUNHENG_RETRIEVAL_MODEL` |
| `subagent_strong` | T3 分析 / T4 写作 | `deepseek-v4-pro` | `LUNHENG_STRONG_MODEL` |
| `subagent_audit` | T5 审计 | `deepseek-v4-pro` | `LUNHENG_AUDIT_MODEL` |

模型挂载期求值一次，改环境变量后须重启 dsh；未挂载对应工具时自动回退 `subagent`。
