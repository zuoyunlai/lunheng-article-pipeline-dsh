## ⚠️ 重要警告（v2.2.17 加重，回应 安全审计 scanner F09 91%）

使用论衡技能会触发以下副作用，请使用前确认你已理解并同意：

- **文件创建/修改**：`run/<项目名>/`、`drafts/`、`final/` 等目录会创建/修改多个文件
- **Web 检索外发**：检索关键词会发送到 DSH 配置的 web provider（外部服务）
- **可选手动 sha256 验证**：主控会发占位符 `[SHA256-PENDING:HOST-VERIFY]`，如需真实 hash 需主人在 host shell 手动计算后回填
- **可选的封面/配图**（**默认关闭**）：DSH 无内置文生图——默认 SVG 矢量风（本地）或主人投喂；如另配图像 MCP 才会外发
- **本地记忆系统**：`记忆读写` 仅访问本地 DSH 本地记忆（不外发）

**v2.2.17 明确**：以上副作用会在 Phase 0 同意关卡（4 选 1）中由你主动选择。如不愿接受任何外发，选 ④全部拒绝（改纯本地 Ollama 推理）。

## 📋 5 分钟上手

### Step 1：写任务简报（2 分钟）

新建文件 `<项目名>/01-任务简报.md`：

```markdown
# 任务简报：[你的题目]

## 研究问题
1. 本文回答：[核心问题 1]
2. 本文回答：[核心问题 2]
3. 本文不回答：[边界说明]

## 论文类型与篇幅
- 类型：[学术论文 / 商业评论 / 行业分析 / 公众号深度长文]
- 篇幅：[2000-4000 字轻量 / 4000-8000 字中段 / 8000+ 字重量]
- 引用格式：[学术编号 / 内联引用（机构，年份）]

## 期望的数据/文献/案例
- 数据：[需要什么数据，如"2023 年 XX 行业数据"]
- 文献：[需要什么文献，如"近 5 年同行评审文献 ≥3 篇"]
- 案例：[需要什么案例，如"≥3 个具体企业/事件案例"]

## 主人深度洞察（如有）
- [C-主01] 类型：[观点来源 / 理论贡献]
  - 内容：[一句话说明]

## 防哪些 F 模式（选 3-5 个核心）
- F1 幻觉引用 / F2 幻觉数据 / F3 早期框架锁定 / F5 拼凑式断裂 / F7 主人风格失真
```

**模板**：详见 `references/templates/任务简报-template.md`

---

### Step 2：主控自动派发（无需人工）

主控读简报后：

1. **Phase 0 同意关卡**：向你确认 4 选 1（直接开工 / 补充信息 / 暂停 / 拒绝）
2. **Phase 1 检索派发**：自动 spawn **T1∥T2∥T3**（v2.3.0 改 T6→T3）三个独立检索员，三方真并行
3. **Phase 2 分析派发**：自动派 **T4** 分析员（v2.3.0 改 T3→T4）生成大纲
4. **Phase 2.5 主人确认**：主人过目大纲
5. **Phase 3 写作派发**：自动派 **T5** 写手（v2.3.0 改 T4→T5）写 v1
6. **Phase 3.5 主人洞察补充**（人在环，可选）：主人提供深度洞察 → T5 写手 v2 融入
7. **Phase 3.6 批判派发**（v2.3.0 新增独立节点）：自动派 **T6** 批判伙伴（v2.3.0 改 T8→T6）攻击 v2（含主人洞察）
8. **Phase 4 审计派发**：自动派 **T7** 审计员（v2.3.0 改 T5→T7）
9. **Phase 5 终检**：主控 **T8** 主控终检（v2.3.0 改 T7→T8，T8 终检 = 主控亲完成）交付

**主人在 4 个节点介入**：Phase 0 / Phase 2.5 / Phase 3.5 / Phase 5（v2.3.3 纠偏：Phase 3.6 T6 批判是内部流水线动作，非主人介入，教训 #138）

### Step 3：等待交付

预计时间（典型项目）：
- 轻量档（≤4000 字）：约 30-60 分钟
- 中段档（4000-8000 字）：约 1-2 小时
- 重量档（8000+ 字）：约 2-4 小时

## 🚫 5 类不适用场景

**不要用论衡**：

1. **理工科论文**（需数学推导/代码实现/实验设计）
2. **文学创作**（小说/诗歌/剧本）
3. **新闻快讯**（时效性要求 <24 小时）
4. **营销软文**（非客观分析）
5. **需要主人一手数据但主人未提供**（田野调查/问卷/实验数据）

**如需短文（<2000 字）或即时问答，请直接用主控 LLM，不要走论衡流水线。**

## 💡 4 个使用技巧

### 技巧 1：用「我要」而不是「应该是」

- ✅ 写：「我要一篇 6000 字的商业评论，公众号风格」
- ❌ 写：「应该是 6000 字左右」

主控需要明确的意图，不是有条件的推测。

---

### 技巧 2：数据缺口要明说

- ✅ 写：「如果找不到 XX 数据，请标注为'数据缺口'，不要编造」
- ❌ 期望主控自动推断

---

### 技巧 3：主人洞察标类型

- ✅ 写：「[C-主01] 类型：理论贡献，内容：XX 框架」
- ❌ 写：「我有个想法」

类型决定后续如何处理（观点来源 vs 理论贡献，详见 glossary.md § 一 T4 分析员 / T5 写手）。

---

### 技巧 4：失败时用「Acknowledged Limitations」模式

如修订超 2 轮仍有 P0/P1：
- 主控不再死磕
- 改为在文末列「未关闭项」清单
- 搬入 `final/局限性.md`
- 论文正常交付（不假装完美）

> ⚠️ **v2.3.0 注意**：修订回环 ≤2 轮硬约束（v2.2.0 P0-D，教训 #67）+ Phase 3.5 主人洞察 + Phase 3.6 批判 = 共 2 轮修订（v1→v2 / v2→v3），用满 ≤2 约束。审计无修订空间。教训 #117 待立项（v2.3.1 单独处理）。

## ❓ 常见问题

### Q1：论衡能不能执行 shell 命令？

**答：DSH 下取决于会话预设。** 论衡是 LLM 推理 + 文件读写 + Web 检索的流水线；DSH standard 预设含 `pwsh`/`bash`，如需跑代码验证论据，经主人同意后主控/子代理可执行。算法文档中的 `sha256sum`/`grep`/`awk`/`comm` 等命令**仅供人类主人手动验证**，论衡 agent 用 LLM 推理模拟，不实际执行。

---

### Q2：数据来源可以是二手转引吗？

**答：可以但严格限制。** 详见 [`glossary.md § 三 数据信任级别`](references/glossary.md#三数据信任级别v221-核心机制)：
- 🟢 已发布公开数据（最高信任）
- 🟡 主人投喂数据（中信任）
- 🔴 二手转引（低信任，必须回溯一次文献 + 顶部标注）

---

### Q3：论文可以被 安全审计 安全扫描拒绝吗？

**答：可能。** 论衡 v2.2.12 起所有 user-facing 警告已放文件顶部，Phase 0 同意关卡是金标准。详见教训 #51。

---

### Q4：如何处理 AI 安全审计发现的问题？

**答：迭代发布。** 详见论衡发布历史：
- v2.0.5 → v2.1.7：连续 6 轮 安全审计 scanner findings 闭环
- v2.1.8 → v2.2.12：P0+P1+P2 持续改进
- v2.3.0：角色编号重构（教训 #116）+ README 内部冲突修复（教训 #116 + #118）

论衡设计哲学：**安全是持续回应反馈的过程，不是发布前的完美**。
