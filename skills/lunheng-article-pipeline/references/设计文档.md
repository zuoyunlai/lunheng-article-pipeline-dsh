## 四、工作流程（Phase 0-5，含 2.5/3.5/3.6 子节点）

### Phase 0 定题（主控 × 人类）
确认：主题、论文类型、篇幅、引用格式、**目标期刊模板**、deadline、可用数据源、**cases 需求量（含 0 条场景的显式声明，v2.1.8 取消「轻/中/重量」三档决策，教训 #56）**。产出 `01-任务简报.md` + `status.md`（含案例决策行）。

### Phase 1 拆解 + 并行检索（v2.1.8 修订，教训 #56 + #58）

主控把主题拆成 3-5 个可检索的子问题 → 记录 cases 需求量（含 0 条场景显式声明）→ **三方真并行 spawn T1 + T2 + T6**：

- **任何量级（含 0 条）必 spawn T6 案例检索员**（v2.1.8 取消 v2.1.7 三档决策）
- cases = 0 场景走「0 条空卡协议」：T6 prompt 显式声明「无需案例」，输出 [C-空] 卡，不阻塞主流程
- cases ≥ 1 场景按主题相关性筛选产出 [C01]–[Cxx] 卡
- T1/T2/T6 三方 subagent 独立，**互不干涉**（独立上下文 + 独立写路径 + 失败降级隔离）

→ 等子代理完成通知（三方全 Done 才进 Phase 2）。
检索员产出带分级的卡片：文献 A/B/C 可信度、数据 🟢🟡🔴 时效、案例事件结构 + 多方立场。

### Phase 2 分析
分析员产出：研究问题界定、文献缺口、论证主线、**论点-论据映射表**（v2.2 三角验证 [L]+[D]+[C] 标注）、**反方论证规划**、分析框架、章节字数预算。任一核心论点缺角 → 退回主控补检索或降级为「观点」不可写入分析。

### Phase 2.5 大纲确认（人在环，v2 新增）
分析大纲送主人过目。主人确认或提出修改后才放行写手——**大纲阶段改方向成本最低**。

### Phase 3 写作
写手按大纲成文。每处引用标 [Lxx]、每个数字标 [Dxx]、每条案例标 [Cxx]；遵守 **AI 去味禁做清单 10 项**（v2.1.1 改 #3 为「主体声音 ≠ 第一人称经历」）；每核心论点写「反驳 + 回应」；写不出的标 `[待补]`；**「据行业经验估算」使用须满足 5 条限定**（v2.1.1 新增）。

### Phase 3.5 主人深度洞察补充（人在环，v2.1.3 新增）
T4 写手产出 v1 后、T5 审计前，主控主动问主人「有没有一线经验/具体场景/行业惯例要补充」，让主人的深度洞察在审计前进入正文而非终稿后补救。主人补充的洞察按「主人深度洞察融合协议」客观化处理后，由写手 v2 融入。

### Phase 3.6 批判伙伴（T8，v2.2.2 新增，教训 #86）
T4 写手产出 v1（含主人洞察 v2）后、T5 审计前，主控 spawn T8 批判伙伴，从反方角度攻击论证 C1-C5（核心论点可攻击性/论证链薄弱环/理论假设审查/立场中立性/反方完整性），产出 `analysis/批判报告-vN.md`。**轻量档（≤3000 字）可跳过 T8**。批判报告指导 T4 修订（逐条回应）+ T5 审计参考。「不是 adversarial，是 critical companion」—— 批判伙伴帮你把论证磨得更硬。

### Phase 4 审计 + 修订回环
审计员独立检查，产出问题清单（P0/P1/P2）：
- **G0 覆盖度**（v2）：对照任务简报逐项核对研究问题是否被回答、有无跑题（防选题漂移）
- **G1 引用分级核验**（v2）：C 级 100% / B 级 ≥50% / A 级 ≥10% 抽验 + 上下文匹配抽查（防张冠李戴）
- **G2 数据溯源**：每个数字有来源；红级数据用于关键论点未说明 → P1
- **G2.5 案例核验**（v2.2，仅当存在案例卡）：每条 ≥2 来源不达标 → P1；缺检索截止日期 → P1；多方立场未并列 → P1；C 级案例当 A 级用 → P0
- **G3 逻辑**：论点-论据对应、论证链断裂
- **G4 结构与格式**：结构完整、期刊模板、引用格式统一
- **G5 学术规范**：查重意识 + 禁做清单 10 项 + AI 痕迹
- **G0.5/G6**（v2.3）：反方论证覆盖 + 论据类型自标
- **G7 原创性**（v2.4）：核心论点是否与先行者清单中已发表文章重复
- **G8 成品度**（v2.1.0）：8 项必查——过程语言 / 角色元数据 / 临时编号 / 元话语 / 修订文件 / 占位符 / 结构对称 / 字数偏差
- **G9 时序合理性**（v2.1.0）：总耗时 / 文件时间戳（DSH 下无心跳/分阶段 ack，该项只查总耗时与时间戳）
- **G10 核心模型一致性**（v2.1.3）：核心概念/模型全文一致性（如五方主体各方括注、关键术语定义首引 vs 后引）
- **G11 数据时效告警**（v2.1.5）：数据 >5 年 → P1 重检索；3-5 年 → P2 加截至标注
- **G12 信任级别一致性**（v2.2.1）：数据卡信任级别（已发布/主人投喂/二手转引）与正文引用一致
- **G13 AI 使用披露**（v2.2.2）：交付说明必加三段披露（AI 生成/主人洞察/真实检索）
- **G4-2 文末「引用来源」四节完整性**（v2.1.4，教训 #47）：终稿交付前用 `grep -oE "\[D[0-9]+\]|\[C[0-9]+\]|\[C-主[0-9]+\]|\[L[0-9]+\]|\[先[0-9]+\]" final/定稿.md` 拿正文全部编号 → 与文末「数据来源/案例来源/参考文献/先行者文献」四节条目做双向 diff（漏引/孤儿 → P1 必补/必删）；测算值/综合判断条目需如实标注，不伪称来源

P0/P1 → 写手交**修订说明**（逐条回应）+ 修订稿 → 审计复核 → 最多 2 轮 → 仍不过升级主控。

### Phase 5 终检交付（T7，主控自己执行）
主控汇总审计报告，通读全文，交付：定稿 + **图件**（若简报「配图需求」非无：按写手 [图N] 图位程序化生成的数据图表 + 封面视觉）+ **证据包**（文献卡+数据卡+案例卡+审计报告+核验记录）+ 交付说明（图件清单、遗留风险 + 建议人工核验项）。每单结束将高频问题产出**反哺报告**（v2.0.2 起默认只产出，不自动 commit 角色卡，等主人人工 merge）。

## 五、交接协议（Handoff）

每个角色完成任务时必须交「交接报告」，六要素：
1. **做了什么** 2. **产物在哪** 3. **怎么验证** 4. **已知问题** 5. **下一步** 6. **状态机更新**
写手修订时另附「修订说明」：问题编号 → 修改内容逐条对照。

## 七、关键防坑（人文社科特有）

1. **引用幻觉是头号风险** — 三层防御：检索员只写真实检索到的 + 强制带 URL + 审计员分级抽验（C 级 100%）。
2. **张冠李戴**（v2.0）— 文献真实但用错语境：审计抽验时做上下文匹配检查。
3. **数据编造/过时**（v2.0）— 所有数字强制「来源+年份+时效评级」，冲突强制并列口径。
4. **选题漂移**（v2.0）— G0 覆盖度检查：审计员对照任务简报查跑题（08-10 教训 #13 机制化）。
5. **AI 痕迹**（v2.0）— 禁做清单 10 项（排比堆砌/金句密度/模板腔等）写进写手硬约束 + 审计逐项查（08-10 教训 #26 落地）。
6. **创新性不保证** — 机制保证流程严谨、论证有据；人在环四节点：定题、大纲、洞察补充、终稿。
7. **成本控制** — 检索用 flash 级，审计顶配；单篇全流程约 1-3 小时（视篇幅与检索量）。
8. **案例卡 vs 数据卡边界**（v2.2 新增）— 纯量级（占比/规模/趋势）入数据卡；具体事件/人物/企业行为/各方说法入案例卡；同一事实可互引编号但不重复录入。**失败案例（JCPenney/MUJI/宜家）实操中常被错误塞进数据卡**，08-13 优化后单独立档。
9. **执行层脆弱**（v2.1.0 教训 #43）— 子代理静默超时、模型掉线都可能拖垮整条流水线；DSH 执行约定（状态机 + 交接报告六要素 + G8 自检 + 超时介入 `list_agents`）必须全员就位（完整韧化协议见 `references/_shared/执行韧化协议-v2.1.0.md`，仅作参考）。
10. **成品度盲区**（v2.1.0 教训 #43）— G8 成品度 8 项 + G9 时序合理性 4 项，专门查「过程语言残留」「临时编号」「文件时间戳异常」等只在最终交付时才暴露的问题。
11. **数据信任缺失**（v2.2.1 教训 #77）— 已发布/主人投喂/二手转引三档信任级别必填（F8 数据信任失败 4 子项）；M-Form-6 信任级别标注完整性 + M-Exist-3 信任级别一致性 diff + G12 扫描；阶段闸门 T2.5（T2 → T3）+ T5.5（T5 → T7）不绕过交接直接派发。
12. **论证强度不足**（v2.2.2 教训 #86）— 论据单一/因果倒置/以偏概全/回避反方/反方走过场（F9 五子项）；T8 批判伙伴 C1-C5 独立反方攻击，不依赖写手/审计员自我认知；AI 使用披露（G13）三段披露诚实透明。

## 八、和"直接让一个 AI 写论文"的区别

| 维度 | 单 Agent 直写 | 本机制 |
|------|--------------|--------|
| 引用真实性 | 高幻觉风险，无法自检 | 检索-写作-审计三环 + 分级抽验 |
| 论证严谨性 | 依赖单次生成运气 | 独立分析员建框架 + 反方论证强制 |
