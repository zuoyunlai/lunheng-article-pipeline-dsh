## 配图生成规范（Phase 4.5）

- **数据图表**：主控从 [`templates/图表-SVG-template.md`](templates/图表-SVG-template.md) **复制对应图型的整块 SVG**（5 类 copy-ready：条形 / 折线 / 占比条 / 矩阵 / 流程；用 `node scripts/ref-get.mjs references/templates/图表-SVG-template.md '#4x-…'` 只取一节，别整读 19 KB），**只填 `【…】` 槽位与几何量**后落盘，**禁止文生图**（数字不可控）。模板的 `<text>` 里**没有任何数字**（`tests/figure-template.test.mjs` 机械保证）——图上的每个数都必须从数据卡／案例卡来，**不许照抄注释里的示例算术**。图位来自写手标注的 [图N]，与正文 [Dxx]/案例卡 [Cxx] 一致。SVG 是文本，主控 LLM 可直接生成，符合论衡「零 exec」哲学。
  - **良构硬要求**：必须含 `<svg xmlns="http://www.w3.org/2000/svg">` 根 + `viewBox`（或 width/height），标签必须闭合；**禁止** DTD/ENTITY、`<script>`、`on*` 事件、`<foreignObject>`、`javascript:`、**`<style>` 块**（可经 `@import url(...)` 外发样式表）与外部资源引用。判定真源 `scripts/_lib/svg.mjs`；结构不合格 → 导出被拒（`md2html.mjs` **exit 40**）、M-Form-9 判硬问题。三项判定均为**根标签级**（根标签既无 viewBox 也无宽高的塌缩形态判不合格）。
- **图件命名与对账**：唯一口径 `final/图件/图N_标题.svg`（N 与正文 `[图N]` 对应，**图位须独占一行**）。**M-Form-9 图件闭环**机械对账：缺图/图位不足 → P1·P0；孤儿图件、图上数字无出处、SVG 安全告警 → P2 提示。导出多图用 `node scripts/md2html.mjs <定稿.md> <out.html> --fig-dir final/图件`（旧版单 SVG 参数会把同一份图嵌进每个图位）。
- **封面视觉（DSH）**：DSH 无内置文生图（无内置文生图能力）——封面默认 **SVG 矢量风（程序化生成，本地零外发）** 或主人投喂图片；如需文生图，另配图像生成 MCP（如 MiniMax `image-01`），**首次调用需主人显式同意**——主控必须在调用前询问「是否同意调用外部图像生成服务」，主人确认后再调用（防未授权调用 + 成本/数据外发）。出图先送主人确认风格再定稿；MCP 失败则 fallback 到 SVG 矢量风或主人人工上传。
- **中文字体**：matplotlib 需显式注册 Noto Sans CJK SC，否则中文乱码
- **图件入 final/图件/**（命名 `图N_标题.svg`），交付说明列清单；证据包自动收进 `证据包/图件/`（v2.5.2-dsh.16 起，T7/T8 从审计视图即可看到图件对账）；数值标签与来源注释避免同侧重叠（来源统一放底部）
- **案例示意图**（可选）：复杂事件链可用 SVG 画时间线/关系图，不画文生图

## SVG → PNG 导出（v18.73.0 · 反哺报告-v7 F-18）

> **需求真实存在**：本项目交付时主人要 PNG（`final/图件/png/`，3 张 2100×1500）。**论衡 `scripts/` 内没有任何 svg→png 通道**（只有 `md2html.mjs`）。以下三条路**本项目实测过**，按推荐度排序。

**① 浏览器无头截图（推荐·零安装）**

```sh
# Windows（Edge）—— --force-device-scale-factor=3 即 3× 分辨率
msedge --headless=new --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=3 --window-size=2100,1500 \
  --screenshot="<out.png>" "file:///<svg-绝对路径>"
```

- **实测**：3× 缩放 → 2100×1500，与项目要求一致。
- **⚠️ 必须轮询等文件落盘**（实测 Edge 约需 **2 秒**，`Start-Sleep -Milliseconds 700` 不够）——不要写完就断言"生成失败"。
- Chrome 同法（`chrome` 换 `msedge`）。

**② `cairosvg`（⚠️ Windows 常不可用）**

- 本项目实测：**pip 装得上，但缺 cairo 原生 DLL → 不可用**（Windows 经典问题）。**不要因为"装成功"就以为能用**——必须实际跑一次。

**③ 论衡内建通道**：**不存在**。若将来新增，须同时更新本节与 `SECURITY.md` 的执行面计数（`repo-hygiene-check` 规则 ⑧c 双向对账）。

## 图件字体栈：**命名字体不保证存在，通用族兜底才是实际生效项**（v18.73.0 · 反哺报告-v7 F-19 ／ **v18.75.1 定案**）

> **本项目实测（2026-10-04，本机 829 个字体文件）**：旧栈写作
> `-apple-system, 'PingFang SC', 'Noto Serif CJK SC', 'Source Han Serif SC', serif`
> —— **前四个命名字体里，前三个一个都没有**（`-apple-system`／`PingFang SC` 是苹果专有，Windows 恒无；`Noto Serif CJK SC` 未安装），第四个**只有 `Source Han Serif SC Heavy` 一个字重**（无常规字重）→ **实际一路落到通用 `serif`**。

**两条判据**：

1. **模板声明的字体栈 ≠ 实际渲染字体。** 命名字体**不保证存在**；**通用族（`serif` / `sans-serif`）兜底才是实际生效的那一项**。检查"字体合规"时，**不能只读 SVG 源码里的 `font-family`**，要确认**兜底族**是什么。
2. **靠兜底碰巧满足视觉规范是脆弱的。** 本项目「品牌调性 = 衬线」曾在 Windows 上**靠 `serif` 兜底碰巧满足**；**若兜底是 sans（如某些 Linux 发行版的默认），视觉规范会静默失效**——且**没有任何门会报**（`M-Form-9` 只核图位/图件/图上数字，不核字体；`tests/figure-template.test.mjs` 钉的是结构 / 零可见数字 / 数据来源 / 槽位 / 根标签，**同样不核字体**）。

> **⚠️ 与「模板声明的字体栈」的核对义务（v18.75.1 定案时新增）**：改字体栈后，须回到 [`templates/图表-SVG-template.md`](templates/图表-SVG-template.md) 的品牌视觉规范表核对——**两处必须逐字一致**（栈本体写在模板，本节只记录判据与实况，**不复述栈全文**，避免第三个宿主）。

### ✅ v18.75.1 定案（主人 2026-10-04 裁决：**A 单开小批**）

**新栈**（模板 5 块 SVG 与 `md2html.mjs` 正文**同一族链**，逐字一致）：

```
'Source Han Serif SC', 'Noto Serif CJK SC', STZhongsong, STSong, SimSun, serif
```

**为什么这样定**：

- **不改品牌调性**：品牌调性 = 衬线（主人「极简自然」）。新栈**全是衬线族**——`STSong`（华文宋体）/ `STZhongsong`（其粗家族）/ `SimSun`（宋体）都是宋体系，**落点仍是宋体，观感与旧实况同族**；只把「声明」落到**实际存在**的名字上。
- **本机实测可得**（`%WINDIR%\Fonts`）：`STSONG.TTF`（STSong）／`SimSun`（`simsun.ttc`）／`Source Han Serif SC Heavy` ✓；`STZhongsong` 与 `'Noto Serif CJK SC'` 为**跨机/跨平台候选**（本机前者待确认、后者未装）→ 保留在栈里只为别的机器能命中，**不存在的名字无害**：浏览器逐名尝试，全部落空才走 `serif`。
- **`serif` 仍是最后一项**（不是它优先）——**通用族兜底始终是实际生效的保险**，这条判据不因换栈而失效。
- **正文同批对齐**：`md2html.mjs` 原栈 `'Microsoft YaHei','SimSun',serif` 的首选 **`Microsoft YaHei` 是无衬线** → **同一份交付物「图件衬线、正文无衬线」**。v18.76.0 把正文栈改为与图件同一族链 → **实际生效族一致**。

**如实声明的边界**：

- **字体没有门**：本次改动**不新增门**（无法机械判定「某字体在目标读者机上是否存在」）——**新栈是否被正确复制，靠人读，不靠门**。故本节把新栈写在文档里，并请后续维护者按上条「核对义务」履行。
- **弃用 `-apple-system` / `'PingFang SC'` 的代价**：macOS 上将不再由系统 UI 字打头（它们本是无衬线，且中文会回落到 `Songti SC`）。**当前栈在 macOS 上的实际生效 = 系统 `serif` → `Songti SC`（衬线）**；若将来要显式钉 macOS，在栈首补 `'Songti SC'`（**本次未加**，因为已定案的栈是主人在三项里选定的那一串，不擅自扩写）。
- **未验证项**：`STZhongsong` 在本机是否存在（`STSONG.TTF` 已确证，同族的 Zhongsong 未单独验）；`'Noto Serif CJK SC'` 本机确证**未装**。
