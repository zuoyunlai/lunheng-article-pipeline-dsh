## <a id="golden"></a>golden 项目（**合规回归基线** · v18.24.0 QLT-1）

> **用途**：把「文章**合规**能否维持」从**个案感觉**变成**可比数字**。机制改动**前后各跑一次**
> `node scripts/quality-score.mjs run/<项目>`，把 **score / coverage / 逐分量差异**写进反哺报告——
> 没有它，任何合规类改动的收益都不可验证（QLT-2~5 的判据都建立在它之上）。
> **⚠️ 效度边界（v18.52.0 反哺 F-BC 正名）：QLT-1 = 合规分（compliance score），不是质量分**——
> 它的每个分量都是**门计数代理**（门通过率 / 档位 / 是否过门 / 阈值区间 / 单据形态），故**只支撑「合规与成本」的结论**，
> **不得**用来支撑任何「论证质量更好/更差」的主张（实测：某项目关掉 10 条实质论证条件后，**一个分量都没动**；
> 详见 `CHANGELOG.md` §18.52.0 与反哺报告 F-BC）。要测论证强度须另建**独立于门**的量尺（QLT-6），**不得复用门计数**。
> **✅ QLT-6 已落地并标定（v18.53.0）**：`quality-score.mjs` 的 JSON 里 `qlt6` 是**独立块**（不与 `score` 相加）——
> 口径 = 50% 审稿判断（T9 整合报告 总评分/30 归一化） + 50% 论证缺陷闭合率（批判报告条件 ↔ **指纹绑定**的复核裁定）；
> 阳性对照（`AB-共锁-B` v3 → v4：10 条条件 0 → 10 关闭）实测 **Δ = +50.0**，而同一对 QLT-1 **Δ = 0.0**。
> **读法三条**：① ② 分量的条件集来源与 `closureBasis` 决定它可不可横比（无绑定裁定时**保守计 0**，属低估方向）；
> ② 标定样本 = 1 个阳性对照，**未给阈值、未声称跨项目可比**；③ 与 QLT-1 **不得相加**。标定报告见
> `run/_AB-QLT5/QLT6-标定.md`。
> **⚠️ ① 分量的跨体例边界（v18.80.4 跨体例盲评实测，n=6 稿 × 2 判者）**：三体例 ① 均值 **0.036 / 0.197 / 0.518** ⇒ **① 不得跨体例横比**；且**判者噪声与改稿位移同量级**（同稿换人分差均值 1.5、最大 3；改稿位移 +0.5 ~ −3.5）⇒ ① 在此粒度分不清「改稿」与「换判者」；另：`clamp` 下界 = reject 上界 16 ⇒ **总评分 ≤16 一律 ①=0，低分段完全不可区分**（实测 3/12 件）。结论＝**不切换**① 的输入源（仍读知情审稿报告）。判据冻结与结果见 `audits/预注册-QLT6-跨体例盲评-v1.md` + `audits/QLT6-跨体例盲评-结果-v1.md`。
> **⚠️ `handoff` 分量的语义（v18.52.0 反哺 F-S ②）**：它衡量**留痕形态**（四门单据 `阶段确认-Phase*.md` + 闸门记录 +
> 交接门判据），**不衡量论文质量**。受控实验里两臂**同为 0**（实验级批量授权下无四门单据）时属**同口径扣分**
> → **臂间可比、跨本仓金样本基线不可比**（金样本该分量为 0.5；本条已随 `quality-score.mjs` 的
> `componentSemantics` 字段落盘）。

**golden 三例（覆盖三种体例）**——基线实测日 **2026-09-27**（论衡 v18.23.0 机制 + v18.24.0 评分脚本）：

**怎么读这个分数（三条口径，缺一会误读）**：

1. **分数只反映硬失败**：P0/P1 与结构缺项扣分；**P2 软提示单列不扣分**（如 C-Redundancy 的「同句并列引 4 篇」
   候选、G8 字数越限候选）。故 85 分不等于「没有待看项」，只等于「没有硬失败」。
2. **必须连着 `coverage` 读**：`coverage` = 适用分量权重占比；**N/A 分量不进分母**，但覆盖率低时分数
   只覆盖部分判据（`coverage < 0.8` 时 JSON 会给 `coverageWarning`）。例：`甲醛白菜事件` 的 G14 无报告
   → 该 10 分权重不参与，分数含义随之变窄。
3. **体例不适用项如实标 N/A，不给 0 分**：理论/评论型论文没有 IMRaD 节 → `structure` 判 N/A（用实证论文的
   结构门给理论文章判负是**体例差异**而非质量缺陷）；无方法节 → `methodology` 判 N/A。

**已知的历史项目偏差（读旧项目时先看这条）**：`handoff`（交付完整性，权重 10）对**早期项目普遍为 0**——
`handoff-check --role T8 --require-gates` 要求四门确认单与 `阶段确认-*.md` 留痕，而「四门必须」是 v18.13.0
（L-08）才定的，早期项目在制度上不可能满足。**故跨项目比较分数时要先看该项**，或对早期项目只比较
「M 门 / structure / cite-coverage / g-audit / G14」五项。

**可复现性**：同一份产物重复跑分数必须一致（分量输入只有产物本身，无时间/环境依赖）——用例见
`tests/quality-score.test.mjs`。**基线更新时机**：只在**机制改动被接受之后**更新本表，并写明改动版本与日期。
