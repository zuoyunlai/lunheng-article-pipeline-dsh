# 论衡错误信息友好化指南（v2.2.13 新增）

> **目标**：把论衡所有错误信息从「技术黑话」转为「主人能直接行动的人话」
> 适用对象：论衡技能维护者 + 实战中遇到错误的主人

---

## 一、错误信息三段式原则

每条错误信息包含三段：

1. **发生了什么**（一行说人话）
2. **为什么发生**（一句简短解释）
3. **怎么解决**（1-3 条具体行动）

**示例对比**：

❌ **不友好（v2.2.12 之前）**：
```
M-Form-3 failed: temp_id pattern detected in output
```

✅ **友好（v2.2.13）**：
```
❌ 临时编号未清理

【发生了什么】初稿 v2 中残留了 [L_TBD-001] 等占位编号
【为什么】 写手直接覆盖原文件而不是用 cp vN→v{N+1} 修订
【怎么解决】1) 运行版本号同步脚本（DSH 版手动维护版本号五处一致） 看哪些编号需要替换  2) 修订稿必须先 cp 新版本再改  3) 写手铁律 #10 已要求 grep 自检

相关教训：#96（SKILL.md 引用路径必须验证）+ #103（M-Integrity-1 时序）
```

## 三、错误信息实施 SOP

### 3.1 主控/审计员错误信息生成规范

**每条错误信息必须包含**：

```markdown
❌ [错误简称]

【发生了什么】[一行说人话]
【为什么】 [一句简短解释，含教训编号]
【怎么解决】[1-3 条具体行动]

[相关教训/链接]
```

### 3.2 错误信息分级

| 级别 | Emoji | 触发条件 | 主控动作 |
|------|-------|---------|---------|
| **致命** | ❌ | P0 错误 / 阻塞流水线下一步 | 必须解决后才继续 |
| **严重** | ⚠️ | P1 错误 / 不阻塞但必须告知 | 告知主人 + 继续 |
| **建议** | 💡 | P2 优化 / 最佳实践建议 | 记录但不阻塞 |

### 3.3 错误信息禁用清单

**不要**使用以下表述：
- ❌ 「执行失败」（没说原因和行动）
- ❌ 「异常」/「error」（技术黑话）
- ❌ 「请检查」（没说检查什么）
- ❌ 错误代码如 `E001`（除非有明确文档对照）
- ❌ 「internal error」（主人无法行动）

**应该**使用：
- ✅ 「发生了什么 + 为什么 + 怎么解决」
- ✅ 引用具体文件路径和行号
- ✅ 引用相关教训编号（#103, #115 等）
- ✅ 提供 1-3 条具体行动
- ✅ 用 emoji 分级（❌ ⚠️ 💡）

## 四、与 glossary.md / failure-modes.md 的关系

| 文档 | 职责 |
|------|------|
| `glossary.md § 五 工具能力边界` | 工具能做/不能做 |
| `failure-modes.md` | 失败模式定义（F1-F9） |
| `本文` | 错误信息友好化（12 类） |

**主控实战时**：
- 看到错误 → 查 `failure-modes.md` 找定义
- 找不到 → 查 `本文` 找友好版
- 仍找不到 → 主控自由发挥，但遵循「三段式原则」

## 五、实战示例

### 5.1 主控实战输出（v2.2.13 友好版）

```
❌ 数据卡 D05 缺少信任级别

【发生了什么】D05 没有标注「🟢/🟡/🔴」数据来源
【为什么】v2.2.1 起所有数据必须标信任级别（防 F8.4 教训 #77）

【怎么解决】
   ✅ 确认 D05 是「已发布/主人投喂/二手转引」哪类
   ✅ 在 D05 头部加 🟢/🟡/🔴 标注
   ✅ 详见 glossary.md § 三 数据信任级别

需要我帮你自动修复吗？
```

### 5.2 主人视角

主人读到这条信息，**不需要懂 M 门是什么**，直接知道：
1. 哪里出了问题（D05）
2. 为什么是问题（v2.2.1 起的规则）
3. 怎么解决（3 步行动）

**这是 v2.2.13 的核心目标**——让论衡对主人透明、可行动。

## 六、维护规则

1. **新增错误**：必须同时更新 `本文`（友好版）+ `failure-modes.md`（定义）
2. **废弃错误**：保留在 `archive/` 子目录，标注「已废弃 + 替代方案」
3. **跨语言**：本文档为中文版，英文版（如需）单建 `errors.md`
4. **定期审计**：每月一次扫描所有错误信息，确保仍「友好」
