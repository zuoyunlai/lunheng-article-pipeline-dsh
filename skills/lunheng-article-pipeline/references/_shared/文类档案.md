# 文类档案（Genre Profile）

> **定位**：文类（Genre）到 11 个既有开关取值的**单一真源**。Phase 0 定题时，主控让主人**选一份档案**（code），再把派生值展开写进任务简报的**既有字段**（不新增字段名、不加闸门）。
> **为什么需要**（反哺方案「文类档案与 Phase 0 可选项」）：文类此前无集中定义——词表散落 5 处且两两不同（`任务简报-template.md:38` / `-lite.md:26` / `glossary.md` §八 / `期刊匹配算法.md` / `deliverables.md`），新文类无登记处、漏配即假 P0。本表是「登记处 + 预置映射」，不是新机制。
> **受控取值纪律（P5）**：每列取值必须落在既有档位内，**不得引入新档位**（如「文献下限=0」「结构门=跳过」）——那是把配置变成绕过闸门的后门；要豁免走既有 `WAIVER=on` 与 Acknowledged Limitations。
> **消费点（P1）**：11 列每列都有既有消费点（脚本或角色卡真读它）；唯一例外是「文献下限」列——批 2（v18.72.0）以 `--genre` CLI 旗标接上 `m-gate-check.mjs` 的 M-Form-1，缺省仍 3（向后兼容）。
>
> **GB/T 7713.2-2022 合规登记（v18.80.0 · 全量审计-v18.79.1 §八；主人「全修掉」批）**：
> 本档案此前只登记**著录规则**（`GB/T 7714`，管参考文献怎么写）。而**学术论文本体的编写规则**——GB/T 7713.2-2022《学术论文编写规则》（2023-07-01 实施，部分代替 GB/T 7713—1987）——**从未被登记**。后果不是「违规」而是**无从判定**：v18.79.1 全量审计实测，本仓对「题名 ≤25 字 / 摘要分型字数 / 关键词」这三件国标明文的**必备项**既无登记也无门。
> 本版补齐三件（见 §GB/T 7713.2-2022 合规面），并把「引用格式」列语义**澄清为只管著录**（7714）；本体编写另有 7713.2——两者不是一件事，混在同一格里会被读成「已覆盖国标」。

### 「T9 后处置」列（v18.75.0 新增；主人 2026-10-04 裁定口径）

> **取值只有两个**（受控取值纪律同 P5：**不得引入第三档**）：
>
> | 取值 | 含义 | 谁开 |
> |---|---|---|
> | **B 轨** | T9 的实质建议**可开 B 轨**（主控触发轮，**至多 +1**；与「主人洞察 / T6 批判」共享该额度。**与 G14 无关**——G14 终闸的修订走 v18.75.0 新立的 **G 环**，独立记账、**不占 B 轨**） | **主控**判定，**主人可变更** |
> | **只出建议件** | T9 **只产出** `audits/审稿报告-vN.md`，**不自动开轮**；主人认为要改 → **由主控在交付后另行修订**（**不一定再派 T5**），属**流水线走完之后**的动作 | **主人** |
>
> **为什么分档**：三视角（学术类）面向**期刊投稿**，其建议是「投稿前最后一道模拟审稿」，值得一次结构性修订；单视角（非学术类）面向**发布/交付**，其建议多为表述与侧重，**默认不占修订轮次**，由主人按需处置。
>
> **⚠️ 与 §6.6.1「B 轨三类来源」的关系**：T9 **仍是**该三类之一，**但本列决定它在哪一文类下"有资格"充当来源**——标「只出建议件」的文类，T9 建议**不计入** §6.6.1 的条件 ②。
> **⚠️ 口径更正（v18.80.1+v · 独立审计批 5）**：本行原写「**四类**来源」，与真源 `pipeline-readme.md` §6.6.1 的「**三类 B 轨来源**（Phase 3.5 主人洞察 / Phase 3.6 T6 批判 / Phase 4.7 T9 审稿）」**不一致**。成因：v18.75.0 把 **G14 终闸**从 B 轨拆出、另立 **G 环**（其修订**不占 B 轨额度**），而本行的「四类」是拆分前的措辞、未同批更新。**按四类读会让读者以为 G14 也算 B 轨来源**，从而在「B 轨开与不开」的判定里多算一类——这正是 §6.6.1 明文排除的（「**G14 终闸不在其列**」）。

## 四类刻意不进档案（写「不适用」而非给配置）

**理工科论文**（需数学推导/实验设计）、**文学创作**（小说/诗歌/剧本）、**抢时效新闻快讯**（<24h）、**营销软文**、**需一手数据而主人未提供**——`glossary.md` §八官方明列的 5 类不适用。档案表是**准入清单**，不是万能表：把不适用项写进表里等于给它们开准入通道。

## 派生展开（主控 Phase 0 动作，不改字段名）

1. **提问**：`ask_user_question` 一问「本文文类？」，选项 ≤5（学术三档 + 非学术二级 + 其他）。
2. **回填**：code 写进任务简报「论文类型」既有字段，加括号标注，如 `- **论文类型**：期刊投稿（academic-hum）`。
3. **展开**：按本表把 11 列派生值写进既有位置（引用模式行、字数口径、`--humanities` 使用、`QLT=`、`BUF=`、文风档、T9 视角、期刊匹配开关、补扫开关）。
4. **可见化**：`阶段确认-Phase0.md` §8 加一行「文类档案」读数（主人可当场改任一项，变更即留痕）。
5. **留痕**：§6 照旧逐字记录主人原话，无需新字段。

## GB/T 7713.2-2022 合规面（v18.80.0 新增；仅 `academic-*` / `course` / `lit-review` 适用）

> **为什么单列一节而不是加表列**：上表是「code → **开关取值**」映射，每列都有**脚本消费点**；国标合规面是「**稿件本体必须有什么**」的检查项，消费点是**角色卡 + 机检**，量纲不同。故本节是**登记面**，不是新档位（`GENRE_MIN_L` 仍是唯一按 code 分档的映射）。

| 国标要件 | 要求（GB/T 7713.2-2022） | 本仓落点 | 门 |
|---|---|---|---|
| **题名** | 简明，**一般不宜超过 25 字**（推荐型「不宜」） | `templates/任务简报-template.md` 题名格 + T5 卡 | 无（人工：T5 自检 + T7 核） |
| **摘要** | 报道性 **~400 字** / 报道·指示性 **~300** / 指示性 **~150**；须有独立性与自明性 | 任务简报「摘要类型与字数」格 + `字数判定表.md` §五 | 无（人工：T5 + T7） |
| **关键词** | 必备项；有检索意义；**不应**用「方法/理论/评价/性能」等泛指词 | 任务简报「关键词」格 + T5 卡 | 无（人工：T5 + T7） |
| 参考文献著录 | 标注法 + 著录格式**应符合 GB/T 7714**；编号制与著者-出版年制**全文统一** | 本表「引用格式」列 + `cite-format.mjs` | **有**（`cite-format` + M-Exist-1 对账） |
| 正文构成 | 引言 / 主体 / 结论等；**主体占主要篇幅**、宜独立成章 | 本表「结构门」列（IMRaD 族） | **有**（`structure-check.mjs`） |
| 附录/致谢/基金/收稿日期 | 附录有则必备；基金**应**标注、收稿日期**宜**标注 | **不覆盖**（本仓面向投稿前初稿，该类元信息由作者按目标期刊补） | 无（如实声明） |

> **⚠️ 三条「无门」项的性质（不要读成「已合规」）**：它们是**人工责任点**（T5 写手自检 + T7 审计核），与本仓对「M-Form-8 承重墙质量 / M-Integrity-2 跨文件判断」的处置同族——刻意不做机械门，但**必须在登记面可见**。判据：**登记 ≠ 已合规**；本节的用途是把「无从判定」变成「有登记、有人核」。
>
> **⚠️ 与 `glossary.md` §12.3 的既有仲裁无关**：§12.3 处理「文末五节 vs **GB/T 7714-2015** 不重复著录」，与 7713.2 是两件事；本节登记**不改变** §12.3 的仲裁，也**未**被它覆盖。
>
> **一处易误读字面**：GB/T 7713.2-2022 正文写「应符合 GB/T 7711」，而其参考文献表与引用注释（`[来源:GB/T 7714—2015,3.1]`）均指向 **GB/T 7714**——按后者判，**7711 是印刷笔误**。
