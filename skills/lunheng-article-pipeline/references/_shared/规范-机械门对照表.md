## 勾稽方法（两问）

| 问 | 含义 | 不合格表现 |
|---|---|---|
| **① 有无门** | 该规范是否已有机械化检查项？（M 门 / 脚本 / 固定命令） | 规范只写在文档里，无人执行 → **断链**（违规到 T8 或主人处才被发现） |
| **② 覆盖全要件** | 门是否覆盖该规范的**全部要件**，而非只覆盖最容易实现的那一项？ | 「规范 5 个要件、门只核 1 个」→ **隐形断链**（门判通过但不合规） |

## 四、维护规则

1. **新增规范时必须同步本表**：在「一」「二」「三」中择一登记；未登记的规范视为**未定义执行路径**。
2. **修一门须核其所在行**：改脚本判据时，回查本表该规范行的「覆盖要件」是否仍完整。
3. **本表本身不是权威真源**：真源是各规范所在文档（`deliverables.md` / `glossary.md` / 各角色卡）+ `M-Gate-Algorithm.md`；本表是**勾稽视图**，漂移时以真源为准。
4. **每轮实战后 review 第三节**：把「已可用脚本化」的项上移到第一节，把新发现的断链加入第二节。
5. **本表只留现行口径（v18.40.0）**：**不要再往行内写逐轮沿革叙述**（「vX.Y.Z 补…」这类），沿革归 `CHANGELOG.md` / `audits/机制文件修订记录-*`。理由：本表是视图，读者需要的是**现在是什么**。
6. **表体完整性由测试守**：`tests/docs-facts.test.mjs` 断言 **① M 门项 ID 全覆盖**（代码 `gate:` 标签里的机械项全部能在 §一/§二 找到——本批即抓到 `M-Fact-1` 漏登）+ **② handoff 判据码全覆盖**（`handoff-check.mjs` 的 `addHard/addSoft` 码，v18.43.0 扩面——抓到 7 条漏登：A0/A3/A4/A5/B2/B3/B4）+ **③ 引用可解析**（「行 `X`」的 `X` 必须是已登记门 ID，或在表内逐字存在）+ **④ 作废门号不复活**（`M-Form-2 v2` 这类号不得在表外以「机检」身份出现）。收敛/重构**不得丢映射**。
   · **覆盖面边界（如实）**：①② 只覆盖「**有编号的判据族**」。**脚本门族**（`structure-check` / `methodology-check` / `quality-score` / `readability` / `g-audit-check` 各项）与 ①②③… 规则号族**刻意不设**完整性断言——实测 28 个随包脚本（v18.60.1 起；当时为 27）里 22 个是工具类（`count-chars` / `md2html` / `model-routing` / `token-budget` …），本就不是勾稽对象；覆盖它们只能靠一份无意义的豁免清单。
   · **方向只断言「代码 ⇒ 表」**：反向（表 ⊆ 代码）刻意不做——表内**合法**保留人工项（`M-Integrity-2`）、作废号留档、撞号登记，以及**否定的更正说明**（如「本脚本**没有** B5」这句就含 `B5`）。
7. **引用本表用「门 ID」锚，不要只写行名（v18.40.0）**：实测三处只写行名而该行名不存在（本批修）——行名会随收敛改写，**门 ID 才是稳定的**。确要带行名时写成「§X 行 **门 ID**（行名）」。本条的 ②③ 两半由 `tests/docs-facts.test.mjs` 守。
