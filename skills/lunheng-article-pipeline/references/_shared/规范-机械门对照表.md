# 文档层规范 ↔ 机械门覆盖 对照表

> 版本：v18.18.0（读者口径）/ v18.0.2（新增）
> **用途**：逐条勾稽「规范写了什么」与「机械门是否覆盖」，根治教训 **#139「规范从文档层到执行层断链」**——该教训在《观念与理念的关系》实战中**复现 3 次**（文末五节顺序 / 案例来源内容 / 基线编号误判）。
> **用法**：每次新增或修改规范时，在本表中加一行；每次版本 review 时逐行勾稽两问。
> **读者与时机（v18.0.5 补，冗余审计 §二.7）**：**论衡维护者文档**——改规范 / 加机检门 / 版本 review 时读；**运行期角色不加载本文件**（它刻意不在任何角色卡的「读」清单里：主控与 T1-T9 都不需要它）。入口 = `AGENTS.md` §文件修改操作约束 的验证步 + `references/_shared/M-Gate-Algorithm.md` 的「名实对齐」注。

## 勾稽方法（两问）

| 问 | 含义 | 不合格表现 |
|---|---|---|
| **① 有无门** | 该规范是否已有机械化检查项？（M 门 / 脚本 / 固定命令） | 规范只写在文档里，无人执行 → **断链**（违规到 T8 或主人处才被发现） |
| **② 覆盖全要件** | 门是否覆盖该规范的**全部要件**，而非只覆盖最容易实现的那一项？ | 「规范 5 个要件、门只核 1 个」→ **隐形断链**（门判通过但不合规） |

3. **本表本身不是权威真源**：真源是各规范所在文档（`deliverables.md` / `glossary.md` / 各角色卡）+ `M-Gate-Algorithm.md`；本表是**勾稽视图**，漂移时以真源为准。
