# 文档层规范 ↔ 机械门覆盖 对照表

> **版本**：v18.0.5（读者口径）/ v18.0.2（新增）
> **用途**：逐条勾稽「规范写了什么」与「机械门是否覆盖」，根治教训 **#139「规范从文档层到执行层断链」**——该教训在《观念与理念的关系》实战中**复现 3 次**（文末五节顺序 / 案例来源内容 / 基线编号误判）。
> **用法**：每次新增或修改规范时，在本表中加一行；每次版本 review 时逐行勾稽两问。
> **读者与时机（v18.0.5 补，冗余审计 §二.7）**：**论衡维护者文档**——改规范 / 加机检门 / 版本 review 时读；**运行期角色不加载本文件**（它刻意不在任何角色卡的「读」清单里：主控与 T1-T9 都不需要它）。入口 = `AGENTS.md` §文件修改操作约束 的验证步 + `references/_shared/M-Gate-Algorithm.md` 的「名实对齐」注。

---

## 勾稽方法（两问）

| 问 | 含义 | 不合格表现 |
|---|---|---|
| **① 有无门** | 该规范是否已有机械化检查项？（M 门 / 脚本 / 固定命令） | 规范只写在文档里，无人执行 → **断链**（违规到 T8 或主人处才被发现） |
| **② 覆盖全要件** | 门是否覆盖该规范的**全部要件**，而非只覆盖最容易实现的那一项？ | 「规范 5 个要件、门只核 1 个」→ **隐形断链**（门判通过但不合规） |

## 三、**仍无机械门**的规范（人工兜底，登记备查）

> 本表如实列出「暂无门」的项——它们**不是设计缺陷**（部分本质上不可脚本化），但需明确「由谁在哪个阶段人工核」，避免「以为机器会管」。

| 规范 | 为何难机械化 | 人工责任点 |
|---|---|---|
| **逐章字数偏差**（05 卡 ±15%） | 需按章节切分 + 与大纲预算逐章比对，口径易争议 | T5 自检说明 + T7 G8 抽查 |
| **引用越界「量化精化」**（07 卡首判据） | 需比对「正文表述」与「卡片记载」的语义精细度 | T7 G1 上下文匹配抽查（本轮即由此命中 2 处） |
| **`[EB/OL]` 三件套齐备**（05 卡） | 正则可做，但「发布日期不详」等合法例外需判断 | T7 G1 + T9 引文规范维度 |
| **索引行与正文条目「事实」一致**（02 卡） | M-Form-10 只核**编号**对应，不核**事实**一致（本轮 [D10] 索引行把「思想」写成「观念」） | T2 交付前逐行核对 + T7 抽查 |
| **留痕自报计数 = 表行数**（05 卡） | 需理解语义（哪些行算「条目」） | T5 自检 + T7 M-Form-11 复核 |
| **案例多方立场并列**（03 卡 G2.5） | 需读多方文本判断是否「并列」而非「单一转述」 | T7 G2.5 + T6 C4/C5 |
| **数字级核验**（07 卡 G1 两档） | 需订阅环境 / 原文（付费墙、PDF） | 主人 host shell + 交付说明 §4 登记 |
| **查重** | 需 CNKI 学术不端检测（订阅） | 主人投稿前自跑 |
| **AI 痕迹深度判定**（G14-G 个人辨识度） | 属 LLM 自评类判断，无客观阈值 | G14 检测器 + 主人裁定（本轮 G14 已如实登记 3 项口径分歧） |
| **论证实质质量**（F9） | 属语义判断，非形式合规 | T6 批判 + T7 G3 + T9 论证结构维度 |

## 四、维护规则

1. **新增规范时必须同步本表**：在「一」「二」「三」中择一登记；未登记的规范视为**未定义执行路径**。
2. **修一门须核其所在行**：改脚本判据时，回查本表该规范行的「覆盖要件」是否仍完整。
3. **本表本身不是权威真源**：真源是各规范所在文档（`deliverables.md` / `glossary.md` / 各角色卡）+ `M-Gate-Algorithm.md`；本表是**勾稽视图**，漂移时以真源为准。
4. **每轮实战后 review 第三节**：把「已可用脚本化」的项上移到第一节，把新发现的断链加入第二节。
