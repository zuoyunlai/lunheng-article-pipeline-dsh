# 退化场景规范（主人跳过 Phase 3.5 时）

> **用途**：定义主人跳过 Phase 3.5（不投喂深度洞察）时的退化流程，避免主控靠实战推断。
> **教训来源**：2026-08-24 实战——主人跳过 Phase 3.5，T6 攻击对象从 v2 退化为 v1、T5 v2 整合规范、T8 触发 v3 逻辑都未明确文档化，主控现场推断。

## 一、场景定义

| 场景 | Phase 3.5 | T5 v2 | T6 攻击对象 |
|------|----------|-------|-----------|
| **正常** | 主人投喂洞察 | v2（含主人洞察） | v2（含洞察） |
| **退化** | 主人说「没有要补的」 | v2（实质 = v1，无新增洞察） | **退化为 v1 实质内容** |

## 二、退化条款（主人跳过 Phase 3.5 时必走）

1. **攻击对象退化为 v1**：主人跳过 Phase 3.5 时，T5 的 v2 实质 = v1（无新增洞察），T6 攻击对象 = v1 实质内容。T6 不因「v2 无洞察」而空转——照样按 C1-C7 攻击 v1 的论证。
2. **T5 v2 显式标注**：T5 出 v2 时，修订说明头部显式标注「**主人未投喂洞察（Phase 3.5 跳过）**」，避免 T6/T7 误以为 v2 含主人洞察。
3. **§6 显式声明**：写手在正文 §6（如有「机制框架」章节）显式声明「机制框架 + 头部经验外推」——主人未投喂洞察时，写手按既有框架 + 公开经验外推，**不虚构主人观点**。
4. **修订回环计算（v2.5.2-dsh 双轨制统一；版本链于 v18.0.2 裁决对齐 `pipeline-readme.md`）**：主人跳过 Phase 3.5 时，**不产出「无变更的 v2」**——T6 的批判对象 = v1 实质，批判后由 T5 产出的修订版即 **v2**；后续 T9/G14 触发的修订为 **v3**。v1→v2、v2→v3 均属**主控触发轮**，**不计入审计打回轮 ≤2 硬约束，但计入版本号**；T7 打回后的版本（自下一个号起）才计审计打回轮 1/2。
   > ⚠️ **v18.0.2 裁决记录**：本条此前写「v1→v2（无变更）→ v3（T6 批判）→ v4（T9/G14）」，与 `pipeline-readme.md` §「退化路径版本规则」（明确「批判后修订版命名为 **v2**（**不跳号到 v3**）」，且该规则源自 `test-paper-01` 的真实编号错位教训）**互相矛盾**。现按 `pipeline-readme.md` 统一：**跳过 Phase 3.5 时不写空 v2**（写一份与 v1 实质相同的副本既无信息量、又会让「v2」同时指两种东西）。`pipeline-readme.md:277` 为准，本条自此为指针视图。

## 三、关键边界

- **主人跳过 Phase 3.5 是合法选择**（本任务无一线经验可补充），不是错误，不卡流水线。
- **主控不强制主人投喂洞察**；主人跳过时走退化流程，T6/T7/T8 照常跑。
- **退化 ≠ 降级**：T6 批判、T7 审计、T8 终检的深度不减——只是攻击/审计对象的「洞察含量」减少。
