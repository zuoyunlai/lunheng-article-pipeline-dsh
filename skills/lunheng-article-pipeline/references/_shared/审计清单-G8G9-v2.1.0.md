## G8 成品度审计（v2.1.0 必查）

成品度 ≠ 字数 / ≠ 章节完整，**是"这份稿件能不能直接发布"**。

### 8 项必查清单

1. **过程语言残留 grep**
   ```bash
   grep -nE "v2 稿|v3 稿|新增段|新增镜像|新增段|修订说明|上一版|下一版|初稿|定稿|草稿" final/定稿.md
   ```
   命中任何一处 → P0

2. **角色元数据泄露**
   ```bash
   grep -nE "T1|T2|T3|T4|T5|交接报告|六要素|论衡主控|主控已|子代理" final/定稿.md
   ```
   命中任何一处 → P0

3. **临时编号未转内联**
   ```bash
   grep -nE "\[L[0-9]+\]|\[D[0-9]+\]|\[C[0-9]+\]|\[图[0-9]+：" final/定稿.md
   ```
   命中 → P1（要么转内联"（机构, 年份）"，要么保留但确保不是混用）

4. **元话语残留**
   ```bash
   grep -nE "主人结构性观察|据行业经验估算|从业者观察|业内常识|业内共识|反方论证|论据类型|数据基础|学术依据|案例支撑" final/定稿.md
   ```
   命中 → P1（论据类型自标 G6 是大纲/分析阶段的元话语，**不应**出现在最终成品里）

5. **修订文件未分离**
   ```bash
   ls final/ | grep -E "\.bak|修订说明|v[2-9]\.|草稿|backup"
   ```
   final/ 下不应有任何过程文件 → P0

6. **占位符 / 兜底词**
   ```bash
   grep -nE "\[待补\]|TODO|FIXME|XXX|占位|待人工" final/定稿.md
   ```
   命中 → P0（这是"没写完"的标志）

7. **段落结构过度对称 / 模板腔**
   ```bash
   grep -nE "^(首先|其次|再次|最后|第一|第二|第三|综上|总之|那么|接下来|下面)" final/定稿.md
   ```
   命中 ≥3 次 → P2（学术过渡词过多）

8. **章节字数 vs 大纲预算差距**
   - 每节实际字数 vs 大纲预算偏差 >30% → P2（说明执行层失控）
   - 全文偏差 >30% → P1

## G9 时序合理性审计（v2.1.0 必查）

时序合理性 = "完成时间是否在合理区间"，**捕捉"卡死但假装完成"**。

### 9 项必查清单

1. **任务总耗时**
   - 写手轻量（4000-5000 字）：< 5 分钟正常 / 5-15 分钟警示 / >15 分钟 → P0
   - 写手中量（5000-8000 字）：< 8 分钟正常 / 8-20 分钟警示 / >20 分钟 → P0
   - 审计：< 5 分钟正常 / 5-10 分钟警示 / >10 分钟 → P0（>10 分钟意味着审计员本身卡了）
   - 任何角色卡死 > 30 分钟 → P0
   - **三方并行总耗时**（v2.1.8 必查，教训 #58）：T1+T2+T6 三检索员并行跑，从 spawn 到三方全 Done **墙钟应 < 15 分钟**（并行后总耗时 ≈ max(T1, T2, T6) runtime + DSH 调度延迟），若总墙钟 > 25 分钟 → P2（并行未达预期或某 T 卡死）
     - 运行时区分：**runtime** = 模型推理 + 工具调用纯耗时（每个 T 通常 1-3 分钟）；**墙钟** = runtime + DSH 调度 + 子会话启动 + 文件落盘（一般 8-15 分钟）。8 分钟硬卡**指的是墙钟**。

2. **分阶段 ack 完整性**
   - 5-15 分钟任务必须有 5 段 ack（启动+25%+50%+75%+完成）
   - 缺失 ack → P1（要么模型健康度预检坏了，要么被 kill 后假装完成）

3. **status.md 心跳记录**
   - 检查 `grep -E "心跳|ack" status.md`
   - 缺心跳 → P1（子代理没按协议走）

4. **模型降级日志**
   - 检查 `[降级 HH:MM] primary→fallbackN` 记录
   - 有降级但 final/产物与降级模型能力明显不匹配 → P2（如 deepseek-pro 降级到 flash 后字数暴减/语法崩坏）

5. **产出文件时间戳**
   - status.md Done 时间 vs 文件实际修改时间差 > 5 分钟 → P0（要么产出是上次的残留，要么 status 撒谎）

## G8+G9 失败处理

- **任一 P0** → T5 必须在审计报告写「建议主控拒收 + 触发 T4/T5 重试」
- **任一 P1** → T5 写「建议主控 1 轮修订」
- **仅 P2** → T5 写「建议主控直接放行 + 终检时修补」
- **P0 出现 ≥2 次** → T5 升级为「建议升级论衡 v2.1.x 补丁」
