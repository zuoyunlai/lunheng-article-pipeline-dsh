> 版本：v19.23.0（DSH bundle 插件）

# 负知识账本（已证伪项）——`audits/disproofs.jsonl`

> **性质**：机制文件（`references/_shared/` 下），默认禁写；改进动议只写 `audits/反哺报告-vN.md`。
> **触发**：Phase 3.6（T6 批判）与 Phase 4（T7 审计）**各自收到/得出「被证伪、被削弱、无法证实」的条目时**；以及 **Phase 4.6 G14 终闸**及其后（T5 修订 / T8 终检 / **Phase 4.7 T9 审稿**若启用）**消费**该账本时。
> **本文件是契约真源**（字段表 / 写者读者 / 边界 / 空状态）；**校验器** = `scripts/disproofs-check.mjs`（只读）。

---

## 一、为什么要有它（负知识流失）

论衡已有的机制都在**积累正向知识**：文献卡 `[Lxx]`、数据卡 `[Dxx]`、案例卡 `[Cxx]`、分析大纲、审稿意见；而**被证伪的东西**只散落在三处散文里——T6 批判报告的 C1–C7、T1 的 `[L99]` 对立证据索引行、T7 审计报告与 `final/局限性.md §四`。

后果有两个，实测都出现过：
- **只记通过的、不记被证伪的**：稿子改完，读者看到的是「修订后成立的主张」，看不到「哪些主张被证伪过、为什么」；
- **同一条证伪在下一轮被重新发现/重新争论**：没有可复用产物 → 每轮靠人回忆。

**判据一句话：一份研究交付物若只列出「我证明了什么」，而不列出「我证伪了什么」，它的可核验性是单边的。**

## 二、位置与写者 / 读者（**单一真源**）

| 项 | 值 |
|---|---|
| 路径 | `run/<项目>/audits/disproofs.jsonl`（**一行一条**，`UTF-8`，append-only） |
| **唯一写入者** | **T6（Phase 3.6）∥ T7（Phase 4）各追加自己那批**——两者是**串行阶段**，不并发（与 `sources/{T1,T2,T3}.jsonl` 分片、`status.md` 主控独占同属「写者归属」纪律；此处刻意**不分片**：账本要能被 T8/外审一次读完，而分片需要额外 merge 步骤） |
| **只读者（禁写）** | T5（修订轮消费）｜T8（终检摘录）｜T9（审稿视野）｜主控（校验、摘录） |
| 追加纪律 | **只追加、不改写既有行、不复用编号**（改判 → 追加一条新 id 并在 `note` 里写「取代 DP-00X」） |
| 与证据包 | **进证据包**（`build-evidence-bundle.mjs` 的 `RULES` 含一行 → 落在 `final/证据包/disproofs.jsonl`）：外审要看的正是「哪些被证伪」。⚠️ 本项目确实无已证伪项时该源缺席，bundle 会打印「跳过 1 个缺失源」——**这是正常的**，不是缺件 |

## 三、字段表（一行一个 JSON 对象）

```json
{"id":"DP-001","claim":"…","verdict":"disproven","basis":"…","evidence":["[L99] 反向研究 X（2023）结论相反"],"reproduce":"…","author":"T6","round":"v2"}
```

| 字段 | 必填 | 语义 | 判据 / 取值 |
|---|---|---|---|
| `id` | ✅ | 账本内唯一编号 | `DP-001` 起递增三位以上（`^DP-\d{3,}$`）；**不得复用** |
| `claim` | ✅ | **被证伪/削弱的那条主张**（逐字来自正文或大纲，便于回定位） | 不得写「某处论证不足」这类无主体描述 |
| `verdict` | ✅ | 判定 | `disproven`（已证伪）/ `weakened`（被削弱）/ `unverifiable`（无法证实） |
| `basis` | ✅ | **证伪依据**（一句话） | 反例 / 反向研究 / 数据不符 / 逻辑矛盾 |
| `evidence` | ✅ | 指向证据的**非空数组** | `[Lxx]` / `[Dxx]` / `[Cxx]` / `[L99]` / DOI / URL。**空证据不算记过**（校验器判非法） |
| `reproduce` | ✅ | **如何独立复现这条证伪**（竞品 `disproofs.jsonl` 的立意：强制复现） | 一句话可执行：查哪张卡 / 哪条数据 / 哪个 DOI 就能复核 |
| `author` | ✅ | 谁记的 | `T6` / `T7`（本账本只接这两族） |
| `round` | ⭕ | 发现在哪一轮 | 正文轮次 `v2` / 审计轮次 `T7-r1` |
| `note` | ⭕ | 备注（含「取代 DP-00X」） | —— |

## 四、写入时机（谁在什么时候记）

| 角色 | 何时记 | 记什么 |
|---|---|---|
| **T6**（Phase 3.6 批判） | C1–C7 反方攻击**成立**（即攻击命中、原主张站不住或被削弱）时 | 该主张 + 判定 + 依据 + 复现路径。**攻击未成立的不记**（那是「反方走过场」，记进批判报告即可） |
| **T7**（Phase 4 审计） | 核实出**证据级证伪**（某条数据/引文不支持其被引用的主张、某条正文论断与卡片矛盾、`[L99]` 反向结论成立）时 | 同上；`round` 写审计轮次 |

> **⚠️ 边界（极易混）：`disproofs.jsonl` 记的是「**知识**被证伪」，不是「**门**误判」。**
> 机检门误判（脚本判 P0/P1 但规范意图相反，已用证伪四件套驳回）→ 记 `final/局限性.md §四` 的「机检门误判」表，**不写本账本**。两者混写会让账本失去「研究结论」的语义。

## 五、消费（读者怎么用）

| 角色 | 动作 |
|---|---|
| **T5**（修订轮） | 在 `drafts/修订说明-vN.md` 里**逐条回应**：`DP-00X → 已改稿（改在哪一节）/ 保留并说明理由（为何该证伪不成立）`。**已证伪项不得静默消失**——这正是本账本要防的形态 |
| **T8**（终检） | 交付前跑 `node scripts/disproofs-check.mjs <项目>`；把结论（N 条 / 无账本 + 显式声明）写进 `final/交付说明.md` 的**既有字段**（§3 遗留风险 或 §4 人工核验项）——**不新增字段**（M-Exist-7 锁定 12 字段） |
| **T9**（审稿） | 作为「反方论证是否被认真处理」的一手材料（六维评分里的论证结构维度） |
| **主控**（Phase 0.5 查池） | 跑 `pool-query.mjs` 时**跨项目**只读提示相关条目（v19.6.10 · 动议 E 丙案；真源 = [`素材池.md`](素材池.md) §七 第 4 条）——让新选题在动笔前就看到「前人已证伪什么」。**只提示、不判同、不入池、不计数** |

## 六、校验器（只读；**刻意不挂闸门**）

```powershell
node scripts/disproofs-check.mjs run/<项目> [--json] [--file <账本路径>]
```

| 退出码 | 含义 |
|---|---|
| `0` | 账本存在且每行合法（逐条回显，供 T8 摘录） |
| `1` | 有非法行（JSON 解析失败 / 缺必填 / `verdict` 越界 / `evidence` 非数组或空 / `id` 重复或不合规）**或账本存在却 0 有效行**（空占位与「没记」同形，禁止） |
| `3` | **账本不存在**（适用却缺输入 → 须人工复核：「确实无已证伪项」还是「漏记」？——与 `g-audit-check` 的「`N/A` ≠ `SKIP`」同口径，**绝不把「没账本」读成通过**） |
| `10` / `70` | 参数或路径错 / 内部错误 |

**为什么刻意不挂 M 门、不判 P0/P1**：逻辑与 `quality-score.mjs` 同源——**挂成闸门会立刻产生「为过门补一条像样的证伪」的刷分压力**，而本账本的价值恰恰在于「**只记真的被证伪的**」。故它是一只**登记/校验型**工具：形状由机器核，**证伪得对不对仍归 T6/T7/T8 人工**。

## 九、未做 / 边界（如实）

1. **已实现（v19.6.10 丙案 → v19.7.2 丁案）**：账本的**跨项目提示层**已落地——`pool-query.mjs` 在 Phase 0.5 查池时**附加只读提示** `<工作区根>/run/*/audits/disproofs.jsonl` 的命中条目（带 `originProject` 回指）。**本条原先登记的「未做 = 判同 / 复用计数」两半已在 v19.7.2 以 §九.2 的口径落地**；**仍不做的是「去重 / 合并成一份检索库」**——账本保持**项目内 append-only**，跨项目只**提示 + 计数**，**不改写、不归并任何来源账本**。代价（如实）：同一主张在两项目各记一次时提示会重复出现；**该代价被接受**（不视为缺陷）。
2. **未做**：`verdict` 的自动推断（谁也没法从报告文字里可靠地判出「已证伪」）——故**写入是人的动作**，机器只核形状。
3. **不承诺**：账本的**完整性**。它依赖 T6/T7 如实记账；本账本的存在只保证「被记下的那些**不会静默消失**」（T5 逐条回应 + T8 摘录），这是它比现状强的那一半。

## 九.2、同名主张判同口径（v19.7.2 · 丁案，**强 / 弱两档**）

> **为什么单列**：丁案之前本条只写「未做：同名主张如何判同」——而**口径不定的计数不可信**，故先定口径、再上计数。
> **判据一句话**：**只有「同名」计入复用计数；「同域」只提示、永不计入。**

| 档 | 名称 | 判据 | 计入复用计数 |
|---|---|---|---|
| **1** | **同名**（**强**） | 两侧 `claim` 经**归一化**后**逐字相等** | ✅ **是**（唯一来源） |
| **2** | **同域**（**弱**） | **关键词子串**命中（`claim` / `basis` / `reproduce` / `note` / `evidence` 任一含该关键词） | ❌ **否**（只提示） |

**归一化规则（唯一实现 = `pool-query.mjs` 的 `normClaim()`）**：① `NFKC`（全角 → 半角，含全角标点）→ ② 去**全部空白** → ③ 去**标点与符号**（`\p{P}` / `\p{S}`）→ ④ `toLowerCase()`（只影响英文，中文不受影响）。⇒「人工智能的伦理原则已足以指导实践。」与「人工智能的伦理原则，已足以指导实践」**判同名**。

**为什么弱命中不计入（本口径的关键判据）**：同一关键词会命中**大量不同**主张 ⇒ 计数必然虚增，而**失真的统计量比没有统计量更坏**（同仓 `reuseCount` 非幂等 P1-1 的先例：**持久化的假数字不可自愈**）。

**复用怎么记（归属规则）**：判为同名时，向**查询方自己**的 `<工作区根>/run/<本项目>/audits/负知识复用.jsonl` **append** 一行——字段 `{at, queryingProject, originProject, originId, claimNorm}`。
- **只写自己的项目**：**绝不改写来源账本**（跨项目写是危险动作，同仓有专门教训）。
- **必须带 `--project <本项目名>` 才落痕**；不带则**只报不记**（并**如实打印**「未给 `--project` ⇒ 不落痕、不计入聚合」——不静默少做一步）。
- **计数口径 = 按项目去重**：报「已被 **N 个项目**复现」，同一项目重复查**不推高** N（**幂等已入回归网**）。账本本身是**查询事件流**（同项目重复查会多行）——**这是刻意的**：它是 append-only 留痕，不是去重集合。
- **聚合是只读的**：`pool-query` 现场扫 `<工作区根>/run/<各项目>/audits/负知识复用.jsonl` 现算，**无中心库、无跨项目写**。
- **与 `disproofs.jsonl` 的分工**：前者是**来源账本**（人写、T6/T7 记、append-only、**机器不改**）；后者是**消费留痕**（机器写、记录「谁复现过」）。**两文件不同源、不互相写。**
