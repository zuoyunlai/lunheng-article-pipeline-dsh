# 模型路由（角色 → 模型的能力匹配）— 单一真源

> 版本：v18.90.4（DSH bundle 插件）
> **历史叙事已外移**：正文只留现行规则；历史成因 / 逐版明细 / 教训编号见 CHANGELOG.md 对应版本段与 `memory/lessons.md`。
> 用途：定义「哪些角色需要什么能力」「怎么探测本机可用模型」「怎么把两者匹配起来」，以及**降级路径**。
> 实现：`scripts/model-routing.mjs`（只读脚本，按本机 `settings.yaml` 出建议）；机制约束在 `cordis.patch.yml` 的三档工具。

## 一、为什么需要它（三条已实测的硬约束）

1. **加载期读不到模型目录**：`cordis.patch.yml` 的 `!!js` 只能取 `process.env` 与 `baseUrl`（CI 红线：`consistency-check` 规则 ⑭ 禁 `fs.`/`node:`/`import`）→ 插件**无法在启动时知道本机有哪些 provider/模型**。
2. **宿主没有模型级回退**：`dsh-llm-retry` 只做**请求重试**（同模型），没有「模型不可用就换一个」的机制；`dsh-agent-loop` 里 `NO_ADAPTER` 虽被就地吞掉，但**模型名写错 = 该档工具实际不可用**。
3. **默认模型因环境而异**：本机实测 `agent-default-model` = `minimax-cn-openai / MiniMax-M3`（**不是 DeepSeek**）→ 任何「厂商默认值」（例如写死 `deepseek-v4-pro`）在多 provider 机器上都是错的。

**结论**：分层必须由**宿主侧配置**驱动，且默认值**宁可留空（继承）也不猜**。脚本负责把「本机实况 → 可复制的配置」变成一条命令。

### 能力维度与启发式判据（脚本实现，**明确标注为启发式**）

| 维度 | 判据 | 说明 |
|---|---|---|
| `fast`（便宜/低延迟） | 命名含 `flash|lite|mini|small|nano|turbo|oss|air`、`:Nb`/`-Nb` 参数规模 | **词边界匹配**——`MiniMax` 里含 "mini"/"max"，用子串会让同族模型同时判成便宜与强推理（首跑实测踩过） |
| `reasoning`（推理深度） | 命名含 `pro|max|plus|ultra|thinking|reasoner|opus|sonnet|large` 或 `M<数字>` 族版本号 | 族内**版本号**做档位内偏好：检索偏好低版本（便宜），强推理/审计偏好高版本（更强） |
| `context` | `settings.yaml` 的 `contextWindow` | ≥200k=3 / ≥100k=2 / ≥32k=1 |
| `local` | `baseURL` 含 `127.0.0.1|localhost|[::1]` | **不按命名加「快」分**（本机推理速度取决于算力）；仅 `--prefer-local` 时优先 |
| 同 provider 加分 | 与 `agent-default-model.provider` 相同 | 同 provider 只需给 `_MODEL`；跨 provider 必须同时给 `_PROVIDER` |

## 三、怎么用（三步）

```sh
# ① 探测本机实况 + 出建议（只读，不写任何文件）
node scripts/model-routing.mjs                 # provider×模型 + 四档路由 + 兜底链 + 可复制 env
node scripts/model-routing.mjs --json          # 机器可读（主控落路由表用）
node scripts/model-routing.mjs --no-probe      # 跳过本地探测（离线/无本地 provider 时）
node scripts/model-routing.mjs --prefer-remote # 显式选择「不用本地」：三档全走远端
```

**默认会自动探测本地 provider**：仅对 `baseURL` 为 `127.0.0.1|localhost|[::1]` 的 provider 发一次 `GET /models`（3 秒超时）——**零外发、不读密钥、不写文件**；远端 provider 一律不探测（脚本永不读取或发送任何 API Key）。
探测结果直接决定检索档：**本地可达 → 主选本地 + 远端兜底；本地不可达 → 主选远端便宜档**（并在报告里说明原因）。

② **主控把结果落到项目里**：`run/<项目>/model-routing.md`（含实况、选中档位、跨 provider 标记、未选原因），派发话术按该表选工具档位；交付说明的「成本指标」引用它。

③ **要真正启用分档**（可选，需重启 DSH）：把脚本给出的片段设成环境变量——**同 provider 只给 `_MODEL`**，跨 provider 才加 `_PROVIDER`：

```powershell
$env:LUNHENG_RETRIEVAL_MODEL = '<低版本/轻模型>'
$env:LUNHENG_STRONG_MODEL    = '<强推理模型>'
$env:LUNHENG_AUDIT_MODEL     = '<最强推理模型>'
```

**安全默认**：不设任何 `LUNHENG_*` → 三档 `agentOptions` 整块为 `undefined` → **全继承会话模型**（任何 provider 都能跑）。
**一键退路**：`LUNHENG_TIERING=off` → 即便其它变量已设也强制全部继承（用于「换了 provider 导致某档报错」的应急）。

## 四、降级路径（**兜底链**；宿主无模型级回退，故兜底由论衡在主控侧执行）

1. 三档 env 已配 → 按角色选 `subagent_retrieval/strong/audit`（推荐路径）；
2. **某档主选不可用/报错**（本地 provider 没起、模型名写错、provider 不可达）→ 主控按脚本给出的 **`fallback`** 改派：检索档主选本地时，兜底 = 该档次优的**远端**候选；
3. 兜底仍失败 → 设 `LUNHENG_TIERING=off`（三档工具仍在，但全继承会话模型）重派；
4. **跨平台回退（v18.79.0 新增第三跳；仅在 Phase 0 选了 ③ 跨平台分档时可用）**：同档改用**另一平台**的候选（跨平台候选必须同档 ≥2 且凭据已由 DSH 配好）；**仍失败才退到第 3 步的全继承**。⚠️ **换平台若同时降了能力档 = 降档，必须请示**（见 §八 硬约束 3）。
5. 三档工具未挂载 → 全部回退标准 `subagent`（继承会话模型）；
6. 每一级回退都要在**进展页 + 交接报告**如实记录（不得静默降级）。
   > **回退链全部用尽**（档内无候选 ＋ 跨档 ＋ 跨平台 ＋ 全继承都不可用）→ 走 **§九「额度墙的多米诺」**：暂停派发、原文上报、只做零模型成本的机械动作。**不要在同一面墙上反复重派。**

> **为什么「本地优先」必须配兜底**：本机实测 Ollama **未运行**（探测 `✗ 不可达`）——若把检索档写死本地，T1/T2/T3 会直接失败。默认策略因此是「本地可达才用本地，否则用远端便宜档」。

## 五、为什么**不**默认开启原生「按调用选模型」

宿主确实提供该能力（`dsh-tool-subagent` 的 `modelSelectionSettings: true` → 给工具加上 `provider`/`model`/`reasoning_effort` 三个按调用参数，并注册 **`list_subagent_models`** 让 agent 自己查可用路由），但**开启它有前置硬条件**（源码依据）：

- `apply()` 在 `modelSelectionSettings === true` 时会 `ctx.get("subagentModelSelection")`，**取不到直接抛错**：`requires @deepseek-ai/dsh-tool-subagent/model-selection-settings in the Host scope`；
- 还要求工具行位于 **Agent 或 preset scope**（`scopeOf(ctx)` 为空即抛错），而论衡的 patch 是**顶层 insert**；
- 宿主 standard 组合树的 `subagent` 行**默认没有开**它（本机实测：会话工具清单里没有 `list_subagent_models`）。

→ 论衡若默认开启，会在**不支持该服务的宿主上加载期直接失败**（比「不分层」坏得多）。故本包**不默认开启**；若将来 DSH 把它设为默认或宿主明确提供该服务，可另附可选 patch（需先验证目标宿主）。

> **主人已确认（2026-09-11）：维持「不默认开启」**——理由是「装了不坏」优先于「少一步手工」；等 DSH 把该能力设为默认、或宿主明确具备该服务时再评估启用。

### ⚠️ 三条口径与局限（**不要把本节读成受控 A/B**）

1. **它是观测性数据**：会话来自**不同项目 / 篇幅 / 轮次** → 混杂因素未控。**M/步 的差异主要反映「每步读进来多少」，不是「模型更聪明」**（强档往往被派到需要读更多材料的角色/阶段）。
2. **项目归属率低（实测 68/185 未识别）** → 目前**无法**做「项目级质量分 × 成本」的逐项配对（QLT-1 的分数是项目级的）。要打通这一层，得让派发文本稳定携带 `run/<项目名>` 或给投影缓存加项目字段。

### 受控 A/B 设计（**待主人授权真跑；本轮未做**）

- **做法**：取 golden 项目同题同卡，换档各跑一次（对照：全继承会话模型 vs 三档分档），比较 **QLT-1 合规分** 与 `--roles` 成本。
- **样本**：≥2 题 × 2 档 = **4 次完整流水线**（每次数小时 + 四个在环节点）→ **主人 2026-09-27 定案：修订完成后执行**（先把该方案的机制修订收尾做完，再排期跑这 4 次）。
- **判据**：**合规分差 vs 成本差**（**必须带样本数 + 日期 + 口径三要素**，MEA-2 同源要求）。
  > ⚠️ **不得越界**：QLT-1 的每个分量都是**门计数代理** → 本设计只能回答「**合规与成本**」的差异，
  > **回答不了「论证质量」的差异**。凡出现「分档臂写得更好/更差」这类说法，一律判为**超出量尺效度**。
  > ✅ **要答论证质量用 QLT-6**：`quality-score.mjs` 输出的**独立块** `qlt6`
  > （= 50% 审稿判断 + 50% 论证缺陷闭合率），与 QLT-1 **不得相加**。**跨臂比较前先看 ② 的 `closureBasis`**：
  > 无「绑定本版正文」的复核裁定时 ② 保守计 0（低估方向）→ 那种臂与有裁定的臂**不可横比**（标定见
  > `run/_AB-QLT5/QLT6-标定.md`）。
  > ⚠️ **`handoff` 分量不可跨边界横比**：它衡量**留痕形态**、不衡量论文质量；实验两臂同为 0 时
  > **臂间可比、跨金样本基线不可比**（金样本 0.5）。
- **为什么本轮没做**：需要数小时真实运行且含人在环四节点，**agent 无法自主完成**；本批交付的是**测量面**（`--by-model` 随包命令 + 本节的复算命令）与**设计**。

> **回滚**：本节的读数与设计可整体删除，不影响任何门（它是文档节）；`--by-model` 的回滚 = 摘除该旗标与两段聚合（脚本注释里写了回滚点）。

## 八、Phase 0「模型策略」：三选一（**默认 ①**；v18.79.0 反哺-v18.78.2 §七 T0-1 / T0-4）

> **为什么要有这一节**：旧口径下「模型怎么选」只由**环境变量是否已设**隐式决定——主人没有一处**显式选择**的落点，
> 于是要么零配置全继承（不知道还有没有别的档可用），要么配了分档却在**运行中额度耗尽**时无路可走（本项目实测：
> 三档预设 `minimax-cn`（M2.7/M3/M3）**指向同一家 provider** → `429 RATE_LIMIT` 之后**档内无候选可切**；
> 请示主人跨档降级后，回退通道 `deepseek-account` **随后也返回 `402 ACCOUNT_QUOTA`**）。
> **判据**：**选择只解决「用哪档」，解决不了「档没了怎么办」**——故本节 = 三选项 ＋ 三条硬约束（含回退链第三跳）。

**Phase 0 确认单选一个（写进 `阶段确认-Phase0.md` §6；默认 ①）**：

| 选项 | 含义 | 前置条件（不满足就不许选） |
|---|---|---|
| **① 继承会话模型**（**默认**） | 全角色零配置继承 DSH 当前对话模型（`LUNHENG_*` 全不设） | 无。**任何部署形态都能跑**——这也是「避免卡住」的**安全基线** |
| **② 同平台分档** | 按档位（检索 / 分析写作 / 批判审计）在**同一平台内**选不同模型 | `model-routing.mjs` 能探出**真实候选池**，且**每档 ≥2 个可用候选**（否则等于没有兜底） |
| **③ 跨平台分档** | 候选来自**多个已配置平台**，按档位分配（同档可有跨平台兜底） | ① 平台清单由 `model-routing.mjs` 实探得出（bundle 部署读 profile 的 `cordis.patch.yml`）；② 每平台凭据**已由 DSH 配好**（论衡不持有任何密钥）；③ **每档 ≥2 个候选且至少一跳跨平台** |

**三条硬约束（缺任一条，②③ 就是纸面选项）**：

1. **前置探测必须是真的**。`node scripts/model-routing.mjs` 的出口语义按**三种情形**分开（v18.79.0 落地）：
   `0` = 三档都有主选；`4` = **有档位无候选 / 本部署形态不受支持（需人工决定）**；`10` = 用法或**路径**错。
   ⚠️ **`4` 与 `10` 不得混读**：`4` = 「bundle 部署下模型清单不可探测」这类**形态**问题（处置 = 手工填本表或改走 ①），
   `10` = `--dsh-home` 指向的目录**根本不存在**。**读错这两个码，就会去查路径而放过真正的形态问题。**
2. **回退链至少两跳（现为三跳）**：档内切换 → 跨档降级（须请示） → **跨平台回退**（v18.79.0 新增第三跳，见 §九）。
   任一跳用尽仍失败 → **暂停派发、如实上报（错误码 + message 原文）、禁止静默降档**；并记入 `run/<项目>/model-routing.md` §四 回退记录。
3. **不得静默降档，也不得静默降平台**：**「平台」是「档」的组成部分**——把某档从顶级平台换到次级平台，等同于降档，
   必须请示主人。`LUNHENG_TIERING=off`（全继承）是**应急退路**，不是可以悄悄用的降档阀：用了要留痕。

**两条工程边界（如实）**：

- **跨平台会让成本口径失真**：`token-cost.mjs` 只读 `$DSH_HOME/sessions` 的**会话日志**——凡**绕过 DSH 通道**的直连调用
  **不在日志里**。选 ③ 时，交付说明 §6「token 成本（实测）」可能因缺这部分而偏小，须在 §8 声明口径边界。
- **错误形态随平台不同**：不同平台的错误码/文案/是否返回 closing message 都不同，`subagent` 失败时**往往零错误文本**。
  → 换平台前后一律先做 [`errors.md`](../errors.md) §七 的「**失败自诊断三步**」（定位会话日志 → 逐帧解压 → 取
  `finish.reason` 原文），**原文透传，不推断**。
- **默认 ① 时不必追问**：只有主人主动切到 ②/③、或探测显示「档内候选 <2」时才展开确认——省一次人在环交互。

> **单一真源的边界**：本节是**口径与选择规则**的真源；**档位↔角色的映射**真源在 §二 能力档表；**平台清单与可用性**真源
> 是 `model-routing.mjs` 的实探输出（**不得**用文档里的举例当清单）。

## 九、「额度墙的多米诺」——档内无候选 ＋ 回退通道亦耗尽（v18.79.0 反哺-v18.78.2 §七 T0-4）

**形态（本项目实测，2026-10-06）**：`minimax-cn` 三档同 provider → `429 RATE_LIMIT：已达到 Token Plan 用量上限 (2056)`
→ **档内无候选可切**；请示主人取得跨档授权 → 改会话模型 `deepseek-flash@deepseek-account` → **该通道返回 `402 ACCOUNT_QUOTA：Insufficient Balance`**。
**这是顺序多米诺**：`429` → 回退通道 `402`，而 §四 的降级链**隐含假设「候选池里还有下一档」**。

**判定（三条同时成立才叫多米诺）**：① 档内候选池为空或全部不可用（含「三档指向同一 provider」）；② 回退通道返回 `402/429`；③ 失败**不是**瞬时的。

**处置**：

1. **暂停派发**（不要在同一个墙上连撞：每次重派都在烧时间且**零信息**）；
2. **如实上报**：错误码 + message **原文**（经 §七 三步取得），**不得**用「大概是配额问题」顶替；
3. **禁止静默降档/降平台**——此时可选的只有：请示主人换通道、改用 ① 继承、或**只做不耗模型的机械动作**
   （跑门 / 核哈希 / 整理留痕，这些零模型成本，能把项目推进一段）；
4. **区分间歇性与持续性**：`402` **可能是间歇的**——本项目同一任务重派即成功。判据 = **确认性重试 1 次**；
   仍失败即按持续性处理（上报 + 暂停），**不得反复重试**；
5. **落盘**：写入 `run/<项目>/model-routing.md` §四 回退记录（本项目两条：`minimax-cn` 429 / `deepseek-account` 402），
   并在 `01-任务简报.md` §已知风险 与 `final/交付说明.md` §6＋§8 强制留痕。

## 十、各档「有效生成上限」实测表（v18.82.0 · LongWriter 借鉴批 LW-3；**维护期数据，非运行期探测**）

> **为什么**：`model-routing.mjs` 是只读复算面，**不知道各档模型真实单次输出上限**——标称 max_tokens ≠ 有效纯汉字上限（长输出会提前重复/塌缩）。该上限决定 **T5 单节字数预算的封顶**（超限的节在大纲期就该拆分）。
>
> **测法**：仓库级脚本（**不随包**）`node scripts/ruler-probe.mjs --plan --models <m1,m2>` 生成请求计划 → 主人在惯用客户端逐档生成并存 `<目录>/<模型>/<字数>.txt` → `--record <目录>` 输出本表行。**刻意不内置真实调用**（一次全档 ≈ 十几次长生成，防「随手重跑」烧钱；也不把 API key 依赖引进维护脚本）。
>
> **判据**：T5 单节预算 **≤ 写手档（`subagent_strong`）有效上限 × 80%**（留塌缩余量）；**无实测数据的模型按保守值 3000 纯汉字兜底**并在 Phase 0 status.md 注明「未实测」。

## 十一、provider 模型白名单的**覆盖语义** 与 启动期**版本登记**（v18.85.0 · 台海项目反哺 F-1 / F-4）

> **F-1 覆盖语义（实测事故）**：profile `cordis.patch.yml` 的 `<provider>.models:` 白名单是**替换**语义而非叠加——白名单存在时按白名单解析，**内置目录不再兜底**。实测：白名单只列一个不在内置目录的 id 时，三档工具对内置目录里的模型**全部报** `provider "…" has no configured model "…"`，**三次 spawn 零产出**。
>
> **三条判据**：① 白名单里必须列**该 provider 要用的全部候选**（不能只写"新加的那个"）；② 与内置目录**二选一为准**：写了白名单即以白名单为全集；③ 改完在 **Phase 0 对每一档做 1-token 极小 prompt 实探**——`model-routing.mjs` 是**只读复算面**，不会替你发预检请求。
>
> **F-4 启动期版本登记**：Phase 0 落 `run/<项目>/model-routing.md` 时，**头部记一行** `skill_version: vX.Y.Z`（值 = `SKILL.md` frontmatter `version`，读取即实测，**不得凭记忆写**）。**用途**：长项目跨会话 / 跨停机后校验「机制脚本有没有在项目进行中被换过」——实测一次停机 10h33m 期间插件由 v18.80.5 升至 v18.82.0，主控被迫事后补核。
