# 正文骨架（Genre Section Skeleton）

> **定位**：「每个文类的正文该有哪几节」的**唯一真源**——与 [`文类档案.md`](文类档案.md) 的 `code` 一一对应，一个文类一行。
> **它不是新门**：第 3 列「机检」如实写该节序列**有没有脚本断言**。写「不跑」的文类**不得读成已合规**（`N/A` ≠ 通过，口径同 [`glossary.md`](../glossary.md) §二）。
> **与 [`文类档案.md`](文类档案.md) 的分工**：文类档案 管**开关取值**（引用模式 / 引用格式 / 字数口径 / 结构门档位 / `--qlt` / T9 / 期刊匹配 / 文献下限）；本表只把它的「结构门」列**展开成节序列**——`kaiti` 行那个「开题九节」就是本表第一行。两表**不互相复述**：本表不写字数口径与 T9，文类档案不展开节名。
> **不在此表的三件事**：① 文末节顺序（真源 = `scripts/_lib/sections.mjs` 的 `ENDNOTE_ORDER`）；② 引言漏斗三要素与讨论四要素（真源 = `scripts/structure-check.mjs` 的三项检查）；③ 各节字数预算（真源 = 本项目的 `analysis/分析大纲.md`）。

> **`structure-check` 只有两个档位旗标**（`--humanities` = Alternate / `--kaiti` = 九节），**没有「不跑」旗标**——「不跑」永远是主控**不调用**该脚本（文类档案 F-04 的同一判据）。故本表「机检 = 无」的四类，其正文形状**只由当次大纲约束**，不构成任何结构性保证。

> **v19.22.0（人文结构门纠错批 · `audits/定位错配审计-2026-10-20` E1/E7，主人授权）**：
> ① 「结论」节接受**结语 / 余论**同义（中文人文长文常规体例 = 章节式论证 + 结语；实测 5 份真实人文稿 3 份因字面不认被判双缺）。
> ② **无「讨论」节 = P2 + T7 人工必核**（不再 P0）——Alternate 族的讨论常由结语/各章过渡承担，机器字面缺席 ≠ 结构缺失；「有讨论节而四要素全无」**仍 P0**。
> ⇒ 结语式人文稿的标准落点 = **exit 1**（S-IMRaD 仍记「讨论」缺 1 节 → P1，作为 T7 人工复核的可见标记），不再是 exit 2。

## 二、`book-review` 的二选一（判据在行动上，不在格子里）

- **调用** `structure-check.mjs --humanities` ⇒ 本表算「① 有」，节序列 = 引言 / 讨论 / 结论；
- **不调用** ⇒ 本表算「② 不跑」，**且**须在 `final/局限性.md` 写明目标刊/平台不要求学术结构的依据（不得只口头）；
- 两种处置都能被 `局限性.md` 复算；**记 `N/A` 不等于跳过**。

## 三、维护规则（改这张表 = 改机制）

1. **改节序列**：同一提交里改三处——本表 + `scripts/structure-check.mjs`（`kaiti` 的 `KAITI_SECTIONS` 或 IMRaD 两个数组）+ 展开件（仅 `kaiti` 有：`templates/开题报告-template.md` 的 `##` 标题）。`tests/batch30-正文骨架真源.test.mjs` 机械对账三方，**单改一处即红**。
2. **新增文类**：先在 [`文类档案.md`](文类档案.md) 登记 `code`，再在本表加一行。测试断言两表 `code` 集合**相等**——缺行、多行都红。
3. **本表不写判级阈值**（P0/P1 分界）**也不写门实现**：阈值真源在脚本的退出码语义里，抄一份到这里必然与本表各自漂移。读数去脚本。
4. **本表是索引，不是长文**：它随文类数线性增长，单行只放「节名 + 门的有无 + 指针」。需要解释「每节写什么」→ 写展开件（目前只有 `kaiti` 有），不要往格子里塞说明。

## 四、为什么只有 `kaiti` 有「展开件」

`kaiti` 是唯一 **T4 产出即终稿** 的文类：T5-T9/G14 全免（[`QUICKSTART.md`](../../QUICKSTART.md) §类型），流水线里没有「大纲 → 正文」这一环，故需要一份逐节填法说明的模板补位。其余文类的展开件**就是各自项目的大纲**——每个项目现生成、按项目定，不是按文类定的一份静态文件。
