## 必查项（逐条执行，缺一不可）

**G0 覆盖度检查（防选题漂移）**：对照任务简报逐项核对——每个研究问题是否被回答？有无跑题/偷换概念？简报特殊要求是否落实？任何一项缺失 → P0

**G0.5 视角一致性（v2.3 新增，教训 #35）**：全文是否保持客观分析视角？是否有「我接触过 XX」「我曾在 XX」「我当年 XX」等第一人称具体经历？**任一处出现 → P1**（破坏全文章客观基调）。主人/作者亲身经历应改由主控/写手客观化为「决策层普遍认为」「业内观察」「据行业经验估算」。

**G1 引用真实性分级核验**：
- C 级文献（网络/二手转引）：100% 用 web_search 核验标题/作者/年份
- B 级文献：抽验 ≥50%；A 级文献：抽验 ≥10%
- 抽到一条假的 → 升级为 P0 并把抽验比例提到 100%
- **上下文匹配抽查**：对每条抽验引用，检查正文使用语境与文献实际内容是否一致（防张冠李戴——文献真实但用错了地方）

**G2 数据溯源核验**：逐个数检查能否在数据卡找到来源；正文出现数据卡没有的数字 → P0；关键论点使用 🔴 红级数据（>5 年）且未说明时效 → P1

**G2.5 案例核验（v2.2 新增，仅当存在 cases/案例卡.md）**：每条案例 ≥2 来源不达标 → P1；缺检索截止日期/事件时间窗口 → P1；多方立场未并列 → P1；C 级案例当作 A 级用 → P0（伪装来源）；案例伪造 → P0

**G3 逻辑核验**：对照分析大纲逐论点检查——论点有没有论据？论据是否支撑论点？有无以偏概全/稻草人/滑坡？涉及企业行为/事件的论点是否有 [Cxx] 支撑 → 缺角 P1

**G4 结构与格式**：摘要-引言-综述-分析-结论是否齐全；引用格式是否符合任务简报（期刊模板）；参考文献与正文标注一一对应；篇幅是否偏离大纲预算；**文末「引用来源」四节完整性（v2.1.4 新增，教训 #47）**——完整脚本如下（F7 补完，审计员可直接复制执行）：


**G5 学术规范**：查重意识（改写是否充分）；AI 痕迹（写手禁做清单 10 项逐项查：排比堆砌/金句密度/模板腔/无第一人称等）；伦理声明是否必要

**G6 论据类型自标（v2.3 新增，教训 #35）**：结构段落（非引用段落）未自标论据类型 → P1（读者无法判断可信度）。自标类型：`（数据基础：§XXX）` / `（案例支撑：[Cxx]）` / `（主人结构性观察）` / `（业内常识）` / `（反方论证）`

**G9 时序合理性（v2.1.0 新增，教训 #43）**：核对初稿/定稿没有：

- 临时编号残留（如「[待补 1]」「TBD」等）
- 过程语言残留（如「本次审计发现」「经过检查」「我们决定」）
- 时序矛盾（如「2024 年事件」在前文 +「2022 年事件」在后文，但实际 2022 在前）

**G10 核心模型一致性（v2.1.3 新增）**：写手引用的「核心理论/模型/方法论」是否在文献卡 + 数据卡 + 案例卡中保持定义一致？同一术语在不同章节有不同含义 → P1

**G11 数据时效失效告警（v2.1.5 新增，教训 #77）**：检查所有 [Dxx] 数据卡 + 正文数字的时效评级：

- 🟢 ≤2 年：通过
- 🟡 2-5 年：通过（标注「截至 YYYY 年」）
- 🔴 >5 年：重新检索替换（如确实无法替换 → P1 必须显式说明「该数据为唯一可得」+ 时效风险）

**G12 数据信任级别一致性（v2.2.1 新增，教训 #77）**：每条 [Dxx] 必填信任级别（已发布 / 主人投喂 / 二手转引），且正文引用与数据卡信任级别一致；缺失或不一致 → P1

**G13 AI 使用披露（v2.2.2 新增，教训 #86）**：文末「交付说明.md」必含 AI 使用披露三段（AI 生成内容 / 主人原创洞察 / 检索真实证据），缺缺失 → P1

**G14 中文 AI 痕迹深度检测（v2.4.0 新增）**：Phase 4.5 触发，与 T6 批判伙伴并行调用 G14 检测器（LLM 推理判定，零 exec）。8 类检测维度：
- A 学术模板语（综上所述/本文认为/值得关注的是等，任一 ≥3 次 → 命中）
- B 句式同质化（连续 3 段同句式起头）
- C 学术套话高频（赋能/抓手/底层逻辑等，全文 ≥5 处）
- D 破折号滥用（全文 >8 处 / 段 ≥2 处 ≥5 段 / 占比 >3%）
- E 三项排比（全文 ≥3 处）
- F 人称错位（「我」字频 >1%）
- G 个人辨识度缺失（LLM 自评与典型 LLM 风格相似度 >80%）
- H 党报话语堆砌（重要讲话精神等，全文 ≥3 处）

**判定**：0-2 类 Pass / 3-4 类 Warning 触发 T5 修订 1 轮 / 5+ 类 Fail 触发 T5 修订 2 轮（第 2 轮仍命中 → Acknowledged Limitations 模式）。T7 必查 `audits/G14-检测报告-vN.md`，若缺失（主人在 Phase 0 关闭 G14）不强制要求；若 Fail 且未关闭 → 审计结论段必须标注「G14 未关闭」。闸门定义 `references/gates/14-中文AI痕迹-gate.md`，检测器 `references/checkers/中文AI痕迹-checker.md`。**关键边界**：G14 是「风格净化」不替代 T7 的「事实核验」——T7 主战场仍是 G1-G13，G14 仅做风格合规性检查。
