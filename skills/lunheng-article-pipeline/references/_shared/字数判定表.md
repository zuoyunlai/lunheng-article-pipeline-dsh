# 字数判定表（T7 审计 + T8 终检共用单一真源）

> **用途**：统一字数超限的判定标准，避免 T7 和 T8 口径不一致导致「T7 签 accept、T8 终检才发现超限」多一轮修订。
> **教训来源**：2026-08-24 实战——T7+T9 签 accept v2（5540 字，0.7% 超），T8 终检时 v2 修改后 5686（3.4% 超），触发 v3 多一轮修订（14m）。根因 = T7/T8 字数口径与分级判定不一致。

## 一、双口径（必须两个口径都报）

| 口径 | 定义 | 用途 |
|------|------|------|
| **口径 A（纯汉字）** | 纯中文字符数（Unicode 汉字，不含标点/英文术语/数字） | 学术论文核心篇幅判定 |
| **口径 B（含文末四节）** | 全文总字数（含参考文献/数据来源/案例来源/先行者文献/AI 使用声明四节） | 公众号/商业评论交付篇幅判定 |

> **核验方法参考**（可执行命令见下方「DSH 可执行核验命令」段；agent 侧跑白名单脚本 `scripts/count-chars.mjs`）：纯汉字**以正文区口径为准**（**`## 摘要` 之后 至 第一个文末节之前**，即含「关键词」段与「引言至结语」全部正文）；**禁止按字节区间切分统计**（UTF-8 下实测 20 倍失真）。

> **正文统计区间（v2.5.2-dsh 补丁统一，教训：善行实战三方口径打架 12,569 / 11,939 / 14,963；v18.0.5 以脚本实现为真源收敛）**：
> **正文区 = `## 摘要` 标题之后 → 第一个文末节（`## 参考文献` / `## 数据来源` / `## 案例来源` / `## 先行者文献` / `## AI 使用声明`）之前**；**含摘要正文与关键词段**，不含题名、不含文末五节、不含脚注。
> ⚠️ **v18.2.3 更正（本行旧文与实现相反）**：旧版写「**不含**摘要正文」，但 `count-chars.mjs` 的起点是 `text.indexOf('## 摘要') + '## 摘要'.length`，即标题之后**立刻**起算 —— **摘要正文被计入**（实测 2026-09-12 那篇论文的摘要为 243 汉字）。紧邻的「v18.0.5 更正」只收敛到「**关键词**」、漏了这一处，故错话延续至今。243 字之差在 §二 的 1% / 5% 阈值上**足以把判定翻档**。
> ⚠️ **同源告警（v18.2.3 修）**：`count-chars.mjs --summary` 的 `body.hanChars` 曾因用「**含关键词的列表**」求正文终点而只剩摘要正文（**5112 → 243，差 21 倍**，`bodyRatio` 4.1%），而脚本头注释恰恰让 T7/T8 用该模式判字数 → 会把长文判成「仅 4% 篇幅」。现两条路径**共用同一助手**、并由 `tests/scripts/count-chars.test.mjs` 的**跨路径对账断言**兜底；**若你看到 `--summary` 的 `body.hanChars` 与默认口径不等，即为回归**。
> **真源 = `scripts/count-chars.mjs` 的实现**（T5 自报 / T7 复核 / T8 终检**必须用它**，禁止各算各的）。⚠️ **v18.0.5 更正**：本节旧版把区间写成「引言起至结语（不含摘要/**关键词**）」，与脚本实现**不一致**——脚本从 `## 摘要` 之后起算，**包含关键词段**。差值是关键词那几十字，但在 1%/5% 阈值上足以把一个稿子从 P2 翻成 P1（决定是否触发 T5 修订轮），故按脚本收敛；若确实要「引言起」口径，须**先改脚本**再改本节（不得只改文档）。
> **DSH 可执行核验命令（pwsh，替代人工 grep；与脚本同区间）**：
> ⚠️ **v18.2.3 修：必须显式 `-Encoding utf8`**。本机 PowerShell **5.1**（实测 5.1.26100.9472）对**无 BOM 的 UTF-8** 文件用 `Get-Content -Raw` 会**按 ANSI 解码** → 中文全乱 → `'## 摘要'` 匹配不到 → 旧片段**静默返回 0**（实测 0 vs 真值 5112）。这正是本文件反复告诫的「静默退化」，故改用与脚本同构的 IndexOf 切片 + 编码显式声明：
> ```powershell
> $t = Get-Content -Raw -Encoding utf8 'drafts/初稿-vN.md'
> $from = $t.IndexOf('## 摘要') + '## 摘要'.Length
> $to = $t.Length
> foreach ($m in '## 参考文献','## 数据来源','## 案例来源','## 先行者文献','## AI 使用声明') {
>   $j = $t.IndexOf($m, $from); if ($j -ge 0 -and $j -lt $to) { $to = $j }
> }
> ([regex]::Matches($t.Substring($from, $to - $from), '[\u4e00-\u9fff]')).Count   # 口径A 纯汉字（摘要后至文末节前，与 count-chars.mjs 同构件同区间）
> ```
> **自检提示**：若结果为 `0`，**先怀疑编码/口径而非「文章没字」**——先确认 `$t.IndexOf('## 摘要') -ge 0`；仍为 0 且文件确实是 UTF-8，再检查是否存在 `## 摘要` 标题。（脚本侧不会踩此坑：`count-chars.mjs` 用 Node `readFileSync(utf8)`，并对 UTF-16 BOM 直接响亮失败。）

## 二、分级判定（**偏离方向与幅度** → 判定 → 处理）

> **本表是双向的**（2026-09-29 主人裁定补齐**不足**侧）——**超限**与**不足**是两个方向、各有档位，不得只按一侧理解。

| 方向与幅度（相对目标） | 判定 | 处理 |
|---|---|---|
| **超限 ≤5%**（含 ≤1% 与 1-5% 两段） | **P2**（轻微） | **标注即可 + T8 记录偏差**，**T5 不强制修订** |
| **超限 >5%** | **P1**（必须修订） | **触发 T5 v3 精简**（spawn 独立写手，主控不 edit） |
| **不足 >10%**（即低于下限 −10%；实测 < 目标 × 0.9） | **P0**（严重） | **须扩写**（`apply-revision-cycle.mjs` / `apply-compression-cycle.mjs` 的 `低于阻塞线` 判定） |
| **不足 ≤10%**（−10% ~ 0） | **本表不判级** | 由任务简报的「**字数判定层级**」（±0.5% / ±2%）决定 **T8 是否纠偏**（该档位的既有职责，见 `templates/任务简报-template.md`） |

> **⚠️ 两侧的档位不对称是刻意的，如实登记**：**超限侧**的 P0 档已被 2026-09-29 裁定废止（>5% 记 P1）；**不足侧**的 P0 档**被主人明示保留**——原话「**字数低于下限 −10% 直接输出「P0，须扩写」**」。故本表**不再自称「无 P0 档」**，正确说法是「**超限侧无 P0 档；不足侧 −10% 以下判 P0**」。
> **下限 = −10% 的唯一来源**：`scripts/apply-revision-cycle.mjs` 与 `apply-compression-cycle.mjs` 的 `floor = round(target × 0.9)`；**该 10% 阈值由脚本定义，本表按实现收录**（与「实现即真源」的既有判据一致）。

> **⚠️ 口径统一（2026-09-29 主人裁定，本表为实现真源）**：主人原话——「**字数超限 1–5% 的判级——判 P2、T5 不强制修；字数超限 5% 以上判 P1，触发 spawn T5 v3**」。
> **本裁定同时废止两处旧口径**：① 1-5% 原判 **P1 触发 v3** → 改为 **P2 不强制**；② >5% 原判 **P0（严重）** → 改为 **P1**（**修订仍触发**，但**档位由硬阻塞降为 P1**）。
> **⚠️ 一处须主人确认的连带影响**：`audit-checklist-quickref.md` 的 **v18.11.0（反哺 v2 F-3）「渐进式警告」** 曾把**字数硬阈**以上再切一刀（`11,550–12,000` = 「警告 +5% buffer 容忍，**需精简但不 P0、建议精简**」；`>12,000` = 「**P0 阻塞**」）。本裁定下 `>5%` 一律 **P1 触发 v3** → 该「容忍带」的**建议**语义与本裁定的**必须触发**不能并存，故已同批改为 **P1 触发 v3**；**主人其后另行定案**为「**保留一条默认关闭的例外通道**」（见下方 §二 例外通道）——那属 v18.10.0/v18.11.0 **+20% buffer 协调**的后续处置。
> **口径变更留痕（依本仓 `maintainers.md` §十一「计量口径变更固定动作」）**：
> - **fix 前 / fix 后（同一分级的档位与是否触发修订）**：`1-5%`：P1 + 触发 v3 → **P2 + 不强制**；`>5%`：P0 + 立即触发 → **P1 + 触发 v3**；**不足侧**：脚本输出 `P0，须扩写` → **本表收录该档为 P0（新登记）**（此前本表只写「超限幅度」、不足侧无档位）。
> - **受影响显示项**（**按概念穷举，非按已见措辞列举**）：① 本表 §二/§三/§四；② `00-主控-扩展职责.md` 字数红线条目；③ `07-审计-auditor.md` G8 核验行；④ `任务简报-template.md` 档位硬阈换算示例；⑤ `任务简报-template-lite.md` 档位注；⑥ `pipeline-readme.md` §硬上限段；⑦ `audit-checklist-quickref.md` 渐进式警告表 + G8 机检表行；⑧ `g-audit-check.mjs` G8 注释（判据档位描述 + 「只判候选」的档位表述）。
>   > **首轮普查漏了 ③④⑤⑦⑧ 中的后四项**——原因是 pattern 由**已见措辞**拼出（只扫「P0」「超限」字样），而漏掉处写的是「是否 P0 阻塞」「越限是否 P0」「1.05–1.09× 偏多」这类**同概念异措辞**。判据：**「全量普查」只有在 pattern 按概念穷举时才成立**（教训全文见 `audits/反哺报告-跨文档一致性对账-v1.md` §一）。
> - **不受影响项**：字数**计数口径**（纯汉字 `[\u4e00-\u9fff]`，与 `count-chars.mjs` 同源同区间）**不变**；「区间上下 0.5% 内不视为超标」**不变**；T8 亲修权限的「**≤字数 5%**」上限**不变**。

### 二·命名更正（2026-09-29，主人裁定）

**本判定的审计归属 = `G8`（成品度 + 字数偏差），机检项 = `G8-CharCount`**；**`G5` = 学术规范（查重 / AI 痕迹），与字数无关**（G 清单见 `glossary.md` §G）。
本仓曾把字数上下限叫「**G5 阻塞线 / G5 硬阈**」——那是**误称**，已全库更正为「**G8 字数硬阈**」（脚本侧的变量 / JSON 字段同步由 `g5` 改为 `charBand`、`g5Verdict` 改为 `charBandVerdict`）。**判据：读者按 `G5` 去查 G 清单会查到「查重 / AI 痕迹」，与字数无关——即按错编号理解判据。**

> **备注**：区间上下 0.5% 内不视为超标（v2.3.14 P1-3，反哺规则 5）——三方（T5 自报 / T6 攻击 / T7 核验）统一口径，不一致以 T8 为准。

> **例外通道（2026-09-29 主人定案 · 折中方案；默认关闭）** —— 本表是它的**判定真源**，机械识别见 `g-audit-check.mjs` 的 `evidence.bufferBand`。
> **通道形态**：任务简报的「字数判定层级」块新增机器标记 `BUF=on` / `BUF=off`（默认 `off`；见 `templates/任务简报-template.md`）。`BUF=on` 是容忍带的唯一依据，与 `QLT=on` 同形同源；不得按散文或勾选框推断。
>
> **显式豁免（本次审计修订）**：若主人明确批准本项目不按目标篇幅判级，在简报中写 `WAIVER=on`；否则写 `WAIVER=off`。只有这一独立机器标记能令 `G8-CharCount` 返回 SKIP。缺标记默认为不豁免；自由文本里的「字数不作硬规定」等语句（包括否定句、引用和历史记录）不改变机械检查状态，由 T7 阅读后按实际授权判级。`WAIVER` 只控制 G8 字数候选，不改变 M 门或其他门的判定。
> **生效条件（三条必须同时满足，缺一即回主判）**：
> 1. 简报**已标 `BUF=on`**；
> 2. 超限幅度落在 **+5% ~ +9%**（目标 11,000 时即 **11,550–12,000**，就是 v18.11.0 F-3 的**原容忍带**）；
> 3. **T5 交接报告已按其机检判别要求显式标注「本轮估算字数（含 +20% buffer）」**（该要求本就是 `05-写作-writer.md` §字数估算 的既有硬要求，见该节）。
> **满足时**：该档判 **P2（需精简但不触发 T5 v3）**，由 T8 记录偏差。**不满足任一条 / 超限 > +9%** → **一律按本表主判 P1 + 触发 T5 v3**。
> **为什么默认关闭**：该容忍带的存在理由只有「**写手估算偏差**」这一条工程原因（`05-写作-writer.md` §字数估算 +20% buffer 补丁，v18.8.x 实战反哺）。项目若**没有实际发生**这类偏差，容忍带就是**白白放宽了超长上限**——故它是**按项目逐次显式开启**的例外，不是默认档位。
> **为什么要有第 3 条**：它把「可归因于估算规则」变成**可核验的留痕**。否则任何人写一句「超长是因为 buffer」都能索要豁免，这条通道就会退化成事实上的默认档——**这正是本仓反复总结的形态：判据要落在留痕上，不落在许诺上**。

## 四、与 M-Gate 的关系

本表是 **G8 字数核验**（T7 审计 / T8 终检共用）的**统一判定真源**；M-Gate 算法文档里的字数判定以本表为准（双口径 + 分级）。

> ⚠️ **v18.2.6 审计修复（旧版本节写错）**：旧版此处自称「本表是 **M-Form-5 字数核验**（如有）+ G8 字数核验的统一判定真源」——**归属错误**，两条都错：
> ① **M 门 25 项里没有字数项**（机械 24 = M-Form 1-11 + M-Exist 1-11 + M-Integrity-1 + M-Fact-1；人工 1 = M-Integrity-2），故本表与 M 门无对应关系；
> ② **真正的 M-Form-5 = 过程语言残留**（`M-Gate-Algorithm.md` §M-Form-5；「过程语言 >10 处 = P0」，由 `scripts/m-gate-check.mjs` 的 `M-Form-5 过程语言残留` 与 T7 预检执行）——与字数无关，「字数核验」四字属**过程语言残留式的历史误标**。
> **正确定位**：字数归 **G8 成品度 + 字数偏差**（`glossary.md` §G 清单；**`G5` = 学术规范，与字数无关**）；**偏离方向与幅度 → P2/P1/P0** 的判定与处理见 §二（**超限侧无 P0 档；不足侧 >10% 判 P0**）；权威计数 = `scripts/count-chars.mjs`。
