# 字数判定表（T7 审计 + T8 终检共用单一真源）

> **用途**：统一字数超限的判定标准，避免 T7 和 T8 口径不一致导致「T7 签 accept、T8 终检才发现超限」多一轮修订。
> **教训来源**：2026-08-24 实战——T7+T9 签 accept v2（5540 字，0.7% 超），T8 终检时 v2 修改后 5686（3.4% 超），触发 v3 多一轮修订（14m）。根因 = T7/T8 字数口径与分级判定不一致。

## 一、双口径（必须两个口径都报）

| 口径 | 定义 | 用途 |
|------|------|------|
| **口径 A（纯汉字）** | 纯中文字符数（Unicode 汉字，不含标点/英文术语/数字） | 学术论文核心篇幅判定 |
| **口径 B（含文末四节）** | 全文总字数（含参考文献/数据来源/案例来源/先行者文献/AI 使用声明四节） | 公众号/商业评论交付篇幅判定 |

> **核验方法参考**（可执行命令见下方「DSH 可执行核验命令」段；agent 侧跑白名单脚本 `scripts/count-chars.mjs`）：纯汉字**以正文区口径为准**（**`## 摘要` 之后 至 第一个文末节之前**，即含「关键词」段与「引言至结语」全部正文）；**禁止按字节区间切分统计**（UTF-8 下实测 20 倍失真）。

> **正文统计区间（v2.5.2-dsh 补丁统一，教训：善行实战三方口径打架 12,569 / 11,939 / 14,963；v18.0.5 以脚本实现为真源收敛）**：
> **正文区 = `## 摘要` 标题之后 → 第一个文末节（`## 参考文献` / `## 数据来源` / `## 案例来源` / `## 先行者文献` / `## AI 使用声明`）之前**；不含摘要正文、不含文末五节、不含脚注。
> **真源 = `scripts/count-chars.mjs` 的实现**（T5 自报 / T7 复核 / T8 终检**必须用它**，禁止各算各的）。⚠️ **v18.0.5 更正**：本节旧版把区间写成「引言起至结语（不含摘要/**关键词**）」，与脚本实现**不一致**——脚本从 `## 摘要` 之后起算，**包含关键词段**。差值是关键词那几十字，但在 1%/5% 阈值上足以把一个稿子从 P2 翻成 P1（决定是否触发 T5 修订轮），故按脚本收敛；若确实要「引言起」口径，须**先改脚本**再改本节（不得只改文档）。
> **DSH 可执行核验命令（pwsh，替代人工 grep；与脚本同区间）**：
> ```powershell
> $t = Get-Content -Raw 'drafts/初稿-vN.md'
> $body = ($t -split '^## 摘要', 2)[1]
> $body = ($body -split '^## (参考文献|数据来源|案例来源|先行者文献|AI 使用声明)', 2)[0]
> ([regex]::Matches($body, '[\u4e00-\u9fff]')).Count   # 口径A 纯汉字（摘要后至文末节前，与 count-chars.mjs 同口径）
> ```

## 二、分级判定（超限幅度 → 判定 → 处理）

| 超限幅度 | 判定 | 处理 |
|---------|------|------|
| **≤1%** | P2（轻微） | 标注即可，**不触发修订** |
| **1-5%** | P1（超限） | T8 终检时**触发 T5 v3 精简**（spawn 独立写手，主控不 edit） |
| **>5%** | P0（严重） | **立即触发 T5 v3 精简**，优先处理 |

> **备注**：区间上下 0.5% 内不视为超标（v2.3.14 P1-3，反哺规则 5）——三方（T5 自报 / T6 攻击 / T7 核验）统一口径，不一致以 T8 为准。

## 三、核验点（谁在哪个环节核验）

| 环节 | 角色 | 核验内容 |
|------|------|---------|
| Phase 4 审计 | T7 | 跑双口径，报「纯汉字 XX 字（超限 X%）+ 含四节 XX 字（超限 X%）」+ 判定（P2/P1/P0） |
| Phase 5 终检 | T8 | 复用本表判定，**不一致以 T8 为准**；P1/P0 超限 → spawn T5 v3（主控只核验不 edit） |

## 四、与 M-Gate 的关系

本表是 M-Form-5 字数核验（如有）+ G8 字数核验的**统一判定真源**。M-Gate 算法文档里的字数判定以本表为准（双口径 + 分级）。
