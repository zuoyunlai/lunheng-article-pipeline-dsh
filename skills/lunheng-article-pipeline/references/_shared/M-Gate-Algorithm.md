### M-Form-1: 引用标注完整性（v2.2.0 原版 + v2.5.2-dsh.5 阈值提升）

```python
draft_text = read("final/定稿.md")

# 提取所有引用标注
import re
references = re.findall(r'\[(?:D|C|C-主|L|先)\d+\]', draft_text)
references_unique = sorted(set(references))

# === v2.5.2-dsh.5 修订：阈值提升（原 ≥1 即过 → 学术深度论文基线 L≥3）===

min_L = 3  # 学术深度论文基线（公众号/商业评论可降为 1，行业分析降为 2）
if len(references_unique) == 0:
    return {"通过": False, "失败原因": "正文无任何引用标注"}
elif L_count < min_L:
    return {"通过": False, "优先级": "P0",
            "失败原因": f"学术深度论文文献 [Lxx] < {min_L}（实测 L={L_count}），需补检索加固文献三角",
```

**v2.5.2-dsh.17 重写理由（自省审计）**：旧实现算的是「正文有、文末无」的编号（`orphan = 正文编号 − 文末编号`），而 **M-Exist-1 的 `leaked` 是同一个计算、同一套阈值档位** —— 两项恒同判，属**重复门**（同一缺陷报两次，覆盖率不增）。现「正文 ↔ 文末双向闭环」**只归 M-Exist-1**；本项回归名字本身，查定稿里残留的**占位符 / 临时标记**——这是此前的**真实空档**：`[待补]` 出现在定稿里，M-Form-4 的禁止清单不含它，等于**没人管**。

伪代码（v2.5.2-dsh.17）：

```python
draft_text = read("final/定稿.md")
TEMP_MARKERS = [
    r'\[(待补|待定|待查|待核|待回查|临时|占位|TBD|TODO|PLACEHOLDER)\]',  # 大小写不敏感
    r'【(待补|待定|待查|待核|临时)】',
    r'（(待补|待定|待查|待核|临时)）',
    r'_{3,}',        # 下划线占位
    r'[？?]{2,}',    # 连续问号占位
]
total = 各模式命中数之和
if total == 0: return {"通过": True}
else: return {"通过": False, "命中": total, "优先级": "P0" if total >= 3 else "P1"}
```

```python
forbidden_patterns = [
```

```python
whitelist = ["参考文献", "数据来源", "案例来源", "先行者文献", "AI 使用声明"]
```

```python
violations = []
for claim in claims:

    has_d = bool(re.search(r'\[(?:D-?基?-?\w*-?\d+)\]', section_for_claim))
    has_c = bool(re.search(r'\[C\d+\]', section_for_claim))

            "claim": claim,
            "section": section_for_claim[:50],

            "has_D": has_d,
```

### M-Form-9: 图件闭环（v2.5.2-dsh.16 新增，第三方 SVG 链路审计落地）

**检查对象**：`final/定稿.md` 的 `[图N：标题]` 图位 ↔ `final/图件/图N_标题.svg`（唯一口径）↔ 图上数字 vs 数据卡/正文。

**为什么必须有这一项**：T5 写作卡长期宣称「T7 跑 M-Gate 算法检查 `[图N]` 出现次数 ≥ 拍板图位数量 → P0 拦截」，但**当时**的 M 门里没有任何图项、T7 速查表 0 处提及「图」、证据包也不收图件——条文无落地路径（第三方 SVG 链路审计 findings #1）。本项即该条文的机械实现。

**判定伪代码**：

```
fig_dir = final/图件（缺省；--fig-dir 可覆盖）
P = 正文 [图N：标题] 的图号集合（独占一行与行内均识别）
F = fig_dir 下匹配 ^图N[_-]?.*\.svg 的图号集合

if P 为空 and F 为空:
    return N/A（未启用配图 → pass=true，detail 明说「本项不适用」；配图默认关闭，不得因此判失败）

问题（硬）= []
if P - F 非空:            问题 += 缺图（正文标了图位却没有图件文件）
if 简报「图位数量：N」可解析 and |P| < N:  问题 += 图位不足（T5 卡「≥ 拍板数量」不满足）

提示（软）= []
if F - P 非空:            提示 += 孤儿图件（图件未被正文引用）
for each f in F:
    结构不合格（未闭合/无 <svg> 根/无 viewBox 且无宽高/含 DTD·ENTITY）→ 问题 += 图N 结构不合格
    消毒告警（<script>/on*/foreignObject/javascript:/外部引用）→ 提示 += 图N 安全告警
    可见文字数字（<text>/<tspan>/<title>，跳过单字符刻度）不在 数据卡∪正文 中 → 提示 += 无出处数字

严重度: 图件全缺（|F|=0 且 P 非空）或 缺失数+图位不足 > 2 → P0；其余硬问题 → P1；仅软提示 → P2
```

**判定口径**：结构判定与消毒在 `scripts/_lib/svg.mjs`（单一真源，`md2html.mjs` 导出前用同一套）；数字对账是**启发式**（可能命中刻度/坐标），因此只给 P2 提示，需人工确认，不得当硬失败。

**触发时机**：T7 审计与 T8 终检各跑一次（`scripts/m-gate-check.mjs` 自动含此项）；图件在 Phase 4.5 生成，故 Phase 4 审计时若尚无 `final/图件/` 且正文有图位 → 判 P0 并给出「期望文件」提示，打回 Phase 4.5 补图。

**人类验证示例**（host shell，可选）：

```sh
ls -l final/图件/                     # 图件清单（应与正文 [图N] 一一对应）
node skills/lunheng-article-pipeline/scripts/m-gate-check.mjs final/定稿.md final/证据包 --summary
```

**实战背景**：本项落地时同步做了三件事——① `md2html.mjs` 支持 `--fig-dir` 按图号配图（旧版把同一份 SVG 嵌进每个 `[图N]`，多图文章导出 PDF 会得到 N 张相同的图，**静默错误**）；② 行内图位改为容错内联并告警；③ 坏 SVG 由「原样嵌入 exit 0」改为 **exit 2 拒绝导出**。三项均在 `CHANGELOG.md` 有端到端演练记录。

### M-Form-10: 索引段完整性（v2.5.2-dsh.17 新增）

**检查对象**：`文献卡.md` / `数据卡.md` / `案例卡.md` 的 **`## 📇 索引段`** ↔ 正文条目编号 ↔ 头部声明条数。

**为什么必须有这一项**：三张卡模板都写着「索引段编号必须与正文条目一一对应（**一致性自检可加**『索引编号 = 实际编号』校验）」——**这条校验一直没加**。而下游 T4/T5 的 token 优化恰恰依赖「**先读索引段、按编号定位**」：索引缺条 = **静默漏卡**，最后以「漏引 / 孤儿」（M-Form-3 / M-Exist-1）的形式在审计阶段才爆出来，属返工代价最高的一类。模板自己邀请了这条校验，本项即兑现它。

**判定伪代码**：

```
对每张卡（文献卡/数据卡/案例卡；文件缺失 → 仅记备注，不判失败）：
  index_ids = 「## 📇 索引段」标题起、到下一个 `## ` 标题止的区块内所有 [Lxx]/[Dxx]/[Cxx]
  body_ids  = 全文所有以编号开头的二~四级标题（^#{2,4}\s*\[(L|D|C)\d+\]）
  missing   = body_ids - index_ids     # 索引缺条 → 下游按索引定位会漏卡       → 硬（P1；合计 >2 条 → P0）
  extra     = index_ids - body_ids     # 索引悬空（正文无此条目）             → 软（P2）
  thin      = 索引行去掉编号后信息量 < 6 字（模板要求「编号+主题+支撑论点」） → 软（P2）
  head_n    = 头部声明条数（best-effort：/(?:总条数|合计)[^\d]{0,10}(\d+)\s*条/）
  若 head_n 存在且 ≠ |body_ids| → 硬（P1）
三张卡都找不到 → N/A（0 条场景或尚未进入检索阶段），pass=true
```

**严重度**：硬问题 → P1（合计 >2 条 → P0）；仅软问题 → P2；全绿 → 通过。
**触发时机**：随 `m-gate-check.mjs` 运行——**T2.5 闸门**（主控可先跑 `build-evidence-bundle --summary`；卡片不在证据包时脚本自动回退查 `<项目>/literature|data|cases`）＋ T7 审计 ＋ T8 终检。

**与读取纪律的关系**：`pipeline-readme` 的「共享读取纪律」要求 T4/T5「先读索引段、按编号定位、禁止整卡通读」；本项保证**索引段本身完整**——否则那条纪律会以「省 token」之名造成漏读。二者必须成对存在。

### M-Form-11: 素材按需加载闭环（v2.5.2-dsh.17 新增）

**检查对象**：`analysis/素材加载清单.md`（**## 已加载** 段）↔ `final/定稿.md` 正文引用的 `[Lxx]/[Dxx]/[Cxx]` ↔ 三张卡片的正文条目编号。

**为什么必须有这一项**：05 卡要求 T5「先读各卡索引段 → 按大纲映射表**只读相关条目，不读全文**」（**实测口径**：T5 占子代理 cacheRead 单项目峰值 76%（test-paper-02）、本机 34 会话聚合 63.6%；见 `本机实测：`node scripts/token-budget.mjs --roles``）。但「按需加载」与「整卡通读」在产物上**完全同形**——只看初稿无从区分，整条 token 优化的收益此前**全靠写手自述**。本项用一份 ≤30 行的留痕（`templates/素材加载清单-template.md`）把「到底加载了哪些编号」变成事实。

**判定伪代码**：

```
清单 = analysis/素材加载清单.md（找不到则回退 final/证据包/素材加载清单.md）
cited  = 定稿正文区出现的 [Lxx]/[Dxx]/[Cxx]（去版本后缀）
loaded = 清单「## 已加载」段内的编号（「已跳过」等其它段不计入 —— 允许写编号解释为何不读）
cards  = 三张卡以编号开头的二~四级标题集合（^#{2,4}\s*\[(LDC)\d+\]）
若无清单且 cited 为空 → N/A（尚未进入写作阶段），pass=true
若无清单但 cited 非空 → P1（正文引了素材却无加载留痕，无法区分「按需」与「整卡通读」）
notLoaded = cited - loaded          # 引了没读 = 引用不可信                → 硬（P1；合计 >3 → P0）
ghost     = loaded - cards          # 清单里卡片查不到的编号（清单编造）  → 硬（P1）
unused    = loaded - cited          # 读了不用 = 上下文浪费               → 软（P2）
若 |cards 索引段| ≥20 且 |loaded|/|索引| > 0.9 → 软（P2，选择性不足，疑似整卡通读）
若清单标注的「对应正文版本」落后于最新 drafts/初稿-vN.md → 软（P2，留痕未随修订轮刷新）
```

**严重度**：硬问题 → P1（合计 >3 条 → P0）；仅软问题 → P2；全绿 → 通过。
**边界（明确不查什么）**：本项**不能**证明写手没有整卡通读（读行为本身不留痕）——它守的是「**引用必须来自读过的条目**」与「清单必须与素材卡对得上」；「整卡通读」只能用「加载率 >90%」这一启发式软提示，不得当硬失败。
**触发时机**：T5 每轮写完后自跑、T7 审计、T8 终检（随 `m-gate-check.mjs`）。
