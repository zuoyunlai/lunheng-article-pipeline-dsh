# 论衡 M 门渐进式验证（v2.2.15 P2-2b 性能优化）

> **目标**：把 11 项 M 门检查从「T8 一次性全跑」改为「按阶段分批执行 + T8 兜底复跑」
> **预期效果**：错误提前暴露（不用等到 T7） + 单次执行检查项减少（节省 token）

---

## 一、问题背景

**当前模式（T8 一次性全跑 11 项）**：

```
T1 → T2 → T3 → T4 → T4 → T5 → T7（跑全部 11 项 M 门）
                                          ↓
                                    发现 P0（如缺信任级别）
                                          ↓
                                    退回 T2/T5 修订（浪费前序工作）
```

**问题**：
- ❌ P0 错误等到 T7 才暴露，前序工作（T4/T5/T7）全浪费
- ❌ 一次性跑 11 项，token 消耗大
- ❌ 子代理不知道「我这一步该跑哪几个 M 门」

---

## 二、渐进式验证设计（v2.2.15）

### 2.1 5 阶段分批执行

| 阶段 | 触发时机 | 执行的 M 门 | 检查什么 | 失败处理 |
|------|---------|-----------|---------|---------|
| **Phase 1.5** | T1/T2/T3 完成后 | M-Integrity-1 + M-Form-6 | 数据/案例卡完整性 + 信任级别 | 立即打回 T1/T2/T3 |
| **Phase 2.5** | T4 分析后 | M-Form-3 | 大纲中临时编号残留 | 立即打回 T3 |
| **Phase 3.5** | T4 写作后 | M-Form-1 + M-Form-2 + M-Form-4 + M-Form-5 | 初稿引用/文末四节/元数据泄露/过程语言 | 立即打回 T4 |
| **Phase 4.5** | T7 审计后 | M-Exist-1 + M-Exist-2 + M-Exist-3 + M-Integrity-2 | 引用存在性/sha256/信任一致性/阶段闸门 | 立即打回 T7 |
| **Phase 5（T7）** | 主控终检 | **全部 11 项快速复跑** | 兜底防漏 | 整文打回 |

### 2.2 触发时机调整

**原 T2.5 闸门**（v2.2.1）→ 现在是 **Phase 1.5**（T1/T2/T3 完成后）。
**原 T7.5 闸门**（v2.2.1）→ 现在是 **Phase 4.5**（T7 审计后）。

M-Integrity-1/M-Integrity-2 不是「在 T7 跑」而是「在 Phase 1.5 / 4.5 跑」，避免把闸门延迟到 T7。

### 2.3 M 门分组映射

```python
PHASE_1_5_GATES = ['M-Integrity-1', 'M-Form-6']
PHASE_2_5_GATES = ['M-Form-3']
PHASE_3_5_GATES = ['M-Form-1', 'M-Form-2', 'M-Form-4', 'M-Form-5']
PHASE_4_5_GATES = ['M-Exist-1', 'M-Exist-2', 'M-Exist-3', 'M-Integrity-2']
PHASE_5_GATES = ALL_11_GATES  # 兜底复跑
```

## 三、token 节省估算

### 3.1 优化前（T8 跑全部 11 项）

每次 T7 跑 11 项 ≈ ~2000 tokens（11 项伪代码 + 推理）

### 3.2 优化后（分批执行）

| 阶段 | 项数 | 单项 token | 合计 |
|------|------|-----------|------|
| Phase 1.5 | 2 | 150 | 300 |
| Phase 2.5 | 1 | 150 | 150 |
| Phase 3.5 | 4 | 150 | 600 |
| Phase 4.5 | 4 | 200 | 800 |
| Phase 5（兜底） | 11 | 150 | 1650 |
| **总计** | **22 项执行** | | **3500** |

**注意**：优化后总执行次数从 11 → 22，但每次执行**只跑当前阶段需要的项**，单次 token 显著降低。

**更重要的是**：
- 错误提前暴露（Phase 1.5 而不是 T7）→ **避免前序工作浪费** ≈ 节省 30-50%
- 单项 M 门 token 从 200 → 150（伪代码更精准）→ 节省 25%

**综合节省**：~40-60%（取决于错误类型）

### 4.4 Phase 4.5：M-Exist-1/2/3 + M-Integrity-2

grep -E "^\[L[0-9]+\]|^\[D[0-9]+\]|^\[C[0-9]+\]" drafts/初稿-v1.md | sort -u > /tmp/in_refs
