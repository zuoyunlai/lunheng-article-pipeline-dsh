# 机检硬格式（模板 ↔ `m-gate-check.mjs` 的排版契约）

> **本文件是唯一真源（v18.0.3 起）**：子代理照写的「确切字面」都在这里；四份 `*-template-lite.md` 与 `pipeline-readme.md` 的派发话术**只留指针**。
>
> **为什么单列**：模板此前是「人读的」、脚本是「机读的」，两者从未对照勾稽 → 子代理按各自的排版自由度产出，主控被迫逐条返工（实测单个项目 **5 类格式返工、约 40 次 edit**，且**全部不改变内容质量**）。
> **为什么收成一份**（v18.0.3）：同一契约曾以 **5 份副本**存在（4 份模板顶部 + 运行手册散文版），**已互有差异**且无一致性门禁——正是「模板人读、脚本机读」那类返工的复现路径。
>
> 引用方：`templates/{文献卡,数据卡,案例卡,任务简报}-template-lite.md`、`references/pipeline-readme.md`（派发话术 §格式硬约束）。

## 一、通用（三张素材卡：文献卡 / 数据卡 / 案例卡）

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 索引段标题 | `## 📇 索引段`（emoji 📇 + 一个空格，**逐字**）——**0 条空卡场景也必须有该标题**（表体写「（无）」） | M-Form-10 判「缺索引段」→ 下游按索引定位会漏卡 |
| 条目标题 | `### [L01] 主题` / `### [D01] 主题` / `### [C01] 事件名`（**方括号**包裹编号） | M-Form-11 判「编号在卡片中无对应条目」 |
| 索引段编号 | 索引表内亦须用 `[L01]`／`[D01]`／`[C01]`（**带方括号**） | M-Form-10 判「索引缺 N 条」 |
| 头部条数声明 | 「总条数」**只声明本类**正文条目数（如「总条数：18 条」）；基线 `[D-基-x-NN]`、先行者 `[先NN]` 等**另列**，勿并入同一「总条数」，**亦勿在别处写「（合计 N 条）」**（脚本 best-effort 会取错数） | M-Form-10 判「头部声明 ≠ 正文条目」 |
| 信任级别行（数据卡 / 案例卡） | `- **信任级别**：已发布（备注）`——冒号后**直接跟档位词**，档位词上**不得再加粗**（写 `**信任级别**：**已发布**` 即不匹配） | M-Form-6 判「独立段缺失」→ 连锁 M-Integrity-1 判 **P0** |
| **信任级别档位词**（v18.2.1 新增） | **只允许三个词**：`已发布` / `主人投喂` / `二手转引`（真源 = `scripts/_lib/trust.mjs` 的 `TRUST_TOKENS`）。**不得自造档位词**——「官方」「机构报告」「正式披露」「上市公司口径」「权威来源」等一律判失败，即使语义上更贴切 | M-Form-6 判「独立段缺失（描述字段仅提及）」→ P2，并连锁 M-Integrity-1 判 **P0**（T2.5 门过不去）。**实战（v18.2.0 短测试）**：T2 把人大平台页/微博财报/腾讯年报写成「官方」→ 8 条数据卡 3 条不合规 |

> **档位词的语义边界**（避免「官方」这类词自然冒出来）：**已发布** = 已正式公开发布（同行评审论文 / 上市公司财报 / 政府与高校机构公开发布的报告与页面）；**主人投喂** = 主人提供的一手数据（问卷/访谈/田野/实验）；**二手转引** = 转引他人（含媒体转引、机构报道转引、论文中转引）。**机构官网/财报属「已发布」而非「官方」**——「官方」不是论衡档位词。

## 二、文献卡 `[Lxx]` 专属

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 收录范围 | 文献卡**只收 `[Lxx]`**；先行者另立 `literature/先行者清单.md`（用 `[先NN]`） | M-Form-11 的 ghost 判定误报 |

## 三、数据卡 `[Dxx]` 专属

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 基线编号 | `[D-基-{R/T/C/E}-{NN}]`（glossary §三 正式格式，**必须保留**，勿简化为裸数字） | 写手传递会丢失可追溯性；勿因担心「临时编号」而改写（v18.0.0 已修 M-Form-3 误判） |

## 四、案例卡 `[Cxx]` 专属

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 0 条空卡标记 | `[C-空]`——**只用于卡内**；定稿正文的读者面写法见下一行 | 定稿若照抄内部说明会触发 **M-Form-4 文末二级扫描**（P0） |
| 0 条场景的定稿写法 | 定稿「案例来源」节**只写读者语境一句**，如：`本次任务无案例需求（哲学思辨类议题，不涉企业行为 / 司法 / 新闻事件；案例数量 0）。`——**不得**写「案例检索员 / 0 条空卡协议 / 任务简报第 N 行 / 主人 Phase 0 / spawn」等操作员语言 | 同上（P0） |

## 五、任务简报

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 研究问题编号 | **必须写成「子问题 A / 子问题 B / 子问题 C …」**（脚本正则 `子问题\s*([A-Z一二三四五六七八九十\d]+)`；亦兼容旧式 `S1/S2` 表行） | M-Integrity-1 判「任务简报未见子问题（研究问题段缺失）」 |
| 数据点需求 | **必须写成「需找数据点 ≥N」**（脚本正则 `需找数据点[^\d≥>]{0,4}[≥>]\s*(\d+)`；v18.2.1 起**容忍冒号/破折号**，如「需找数据点：≥ 3」亦可）。**计数口径（v18.2.2 修正）**：模板本身规定该短语写**两处**（研究问题段逐子问题各一条 + 数据需求段总量一条），脚本**不再一律求和**，而是按行归属分两组、**取两组之和的较大者**——`agg`（不在「子问题」行上之和，= 声明的总量）与 `scoped`（在「子问题」行上之和，= 分配量之和），需求 = `max(agg, scoped)` | **v18.2.2 前**：两处写法被**双重计数**（实测 3+6+8 子问题 + 25 总量 = 42，真值 25）→ 数据卡 32 条被判「32 < 42」→ **假 P0**，T2.5 门不可通过、M 门永不可 exit 0（只能写 Acknowledged Limitations）。**v18.2.1 前**：冒号/破折号写法失配 → 报「需求总数 0」假 P0 |
| 基线编号清单 | 用 `[D-基-{R/T/C/E}-{NN}]`（glossary §三 正式格式）逐条列出 | 写手传递时易丢失编号 → M-Form-6 / M-Exist-3 报缺失 |
| **参考文献条目标签形态**（v18.2.2 新增） | 文末**五节**的条目标签一律用**论衡编号**：`[L01]`（参考文献）/ `[Dxx]`（数据来源）/ `[Cxx]`（案例来源）/ `[先NN]`（先行者文献）。**GB/T 7714-2015 只约束「著录格式」**（`[M]/[J]/[R]/[EB/OL]` 标识 + 「作者. 题名[类型]. 出版地: 出版者, 年」著录顺序），**不约束标签形态**。正确：`[L01] Jonas H. …[M]. Chicago: …, 1984.`；错误：`[1] Jonas H. …[M]. …`（**顺序编码制的数字标签**）。**顺序不得重排** | `M-Exist-1` 的编号正则要求**字母前缀**（`\[(L|D|C-主|C|先)\d+\]`）→ `[1]` 一条都扫不到 → 文末字母编号集为空 → **正文全部 `[Lxx]` 被判「漏引」**（实战：v18.2.1「首版无 [Lxx] → 漏引 17」；**v18.2.2 再次踩到**）。v18.2.2 起该门在 detail **前置可操作提示**（但仍须写手按本行产出） |
| Phase 1.5 触发字段 | 必须显式写 `trigger: true/false` + 必补关键词（无则写「无」） | T4/T5/T6/T7/T9/T8 六处「触发条件读取」失去真源 |

## 六、审稿报告（T9）

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 六维名（**逐字，不得改写**） | `原创性` / `方法论` / `证据强度` / `论证结构` / `写作质量` / `引文规范`，每维须写出 `x/5` | M-Exist-6 逐维抓 `x/5`；名字一改（哪怕更贴切）→ 判「未找到该维评分」并连锁「总评分缺失」→ **P0** |
| 总评分 | 报告内须出现 **`总评分 XX/30`**，且 XX = 六维之和（脚本校验自洽） | M-Exist-6 判「缺总评分 XX/30」→ **P0**；与分项之和不符另判「评分表与总分自相矛盾」 |
| 建议词区间 | 总评分 ≥26 → `accept`；21–25 → `minor`；16–20 → `major`；<16 → `reject`（报告须含对应词） | 建议与区间不一致 → 软提示 |
| 期刊匹配表 | 表头须含 **`综合匹配度`**，且**每行**给出 `综合 / 主题 / 风格` 三个**百分比**；`综合 = 0.5×主题 + 0.3×风格 + 0.2×归一化总分`，`归一化总分 = clamp((总评分−16)/14, 0, 1)×100`（容差 ±1.5） | 缺百分比 → **P0**；算不出/超容差 → 判「匹配度不可复算」 |
| 具体修改建议 | 须有「给作者的具体修改建议」段（投稿适配用） | 软提示（T5/主控无据以做期刊适配修订） |

## 七、阶段闸门记录（T2.5 / T7.5）

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 检查项表 | 表头须含 **`检查项`** + **`实据`**（或「证据/依据」）+ **`结论`**（或「判定」）三列 | M-Exist-5 判「缺检查项表格」→ **P1** |
| 检查项齐备 | 逐项照抄 `references/templates/闸门记录-template.md` 的清单（T2.5 共 8 项 / T7.5 共 7 项），**缺项即判失败** | 判「检查项缺 X（模板为真源，逐项都要有行）」 |
| 实据列 = 机械证据 | 必须是**路径 / `exit N` / `node X.mjs` 命令 / sha256 / 数字+量词**（v18.2.1 起 `exit=2`、`exit: 2` 亦可识别）；**纯自述**（「已检查」「已核对」）判失败 | P1；实测踩点：写「exit=2」在 v18.2.0 及以前**不被识别** |
| 结论词 | 只允许 **`✓` / `✗` / `N/A`**（不得写「≥5 ✓」「部分通过」这类混合词） | 软提示（非固定词） |

## 八、素材加载清单（M-Form-11 输入）

| 机检项 | 必须的确切形态 | 违反后果 |
|---|---|---|
| 段标题 | `## 已加载`（逐字；「已跳过」等其它段的编号**不计入**加载集） | 判「加载清单缺 `## 已加载` 段标题」→ **P0**（无从定位加载集） |
| 编号写法 | **逐项列出** `[L01]`；v18.2.1 起也**容忍范围写法** `[D01]-[D08]`（同字母内展开，跨度 ≤30） | 范围写法在 v18.2.0 及以前只命中首尾 → 中间条目被判「引了没读」**假 P0** |
| 软提示阈值 | 「加载率 >90% 疑似整卡通读」仅在 **卡池 ≥30 条 且 正文 ≥3000 汉字** 时启用（v18.2.1 起） | 短文 + 小卡池场景此前必然误报（短测试 20 条卡、引用 18 条 = 90%） |
| 比率对账分子口径（v18.2.2 修正） | 分子 = **「已加载」∩「索引段」**；「已加载」中越出索引段的编号（先行者清单 / 基线编号等）**另记一条软提示**、不参与比率 | 实测出现过 `已加载 54 / 索引 52`（分子 > 分母）→ 比率 >100% 仍被判「>90% 整卡通读」，结论不可复算 |
| 「已跳过」段（v18.2.2 补充） | 允许另设 `## 已跳过` 段解释「读了索引段但为何不引用某条」；**这些编号不计入加载集，也不计入「白读」软提示** | 旧实现把「已加载但未引用」一律报「白读即为上下文浪费」——清单已明示跳过的条目也报，属噪声（实测 4 条命中里 [D12]/[D14] 即此类） |

## 九、维护规则

1. **改机检正则 ⇒ 必须同改本表**：本表是「脚本实际扫的字面」的人类可读镜像；`scripts/m-gate-check.mjs` 与 `references/_shared/M-Gate-Algorithm.md` 是另外两处真源（脚本＝实现、算法文档＝判定语义），三者不一致时以**脚本**为准并把另两处改齐。
2. **不得在别处复制本表**：模板 / 运行手册 / 角色卡只留指针（如「机检硬格式见 `_shared/机检硬格式.md` §X」）。历史教训见本文件开头。
3. **改本表后**：跑 `node scripts/consistency-check.mjs`（一致性）+ `node --test "tests/**/*.test.mjs"`（M 门回归），并用真项目跑一次 `m-gate-check.mjs` 复核。
