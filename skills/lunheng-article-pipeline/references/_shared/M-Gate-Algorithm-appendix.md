
## 一、M-Gate-Report 输出格式（JSON schema，v18.2.6 审计修复：按实现重建）

> **为什么重建**：本段旧版（v2.2.4 口径）只覆盖了部分 M-Form 子项与两三个 M-Exist 子项、退出码只写 `0 | 1`，**完全缺** `script_exit_raw` / `exit` / `_t8_llm_review` / `_t8_conclusion` 四个字段——而 `SKILL.md` §执行能力边界 与 `agents/08-终检-finalizer.md` 都**强制要求**它们，缺则「**视为伪造**」。**规范点了名、schema 里却没有 → 下游无从照做**，属「门覆盖不到自己声称覆盖的规范」那一类断链。
> **真源 = `scripts/m-gate-check.mjs`**（① 逐项结果 `results.push({ gate, pass, detail, severity })`；② `--report <path>` 落盘段）。与实现冲突时**以实现为准**。
> **两份形态**：**stdout**（脚本打印的 `report` 对象）与**落盘**（`final/M-Gate-Report.json` = stdout 对象 + `script_exit_raw` + 保留的 T8 裁定段）。T8 只需维护**落盘**那一份。

```jsonc
{
  // —— 脚本机械段（每次运行重写）——
  "draft": "<被审正文路径>",
  "date": "YYYY-MM-DD",
  "total": 22,                    // 恒 = 机械项数（M-Form 11 + M-Exist 10 + M-Integrity-1）
  "pass": 0, "p0": 0, "p1": 0, "p2": 0,
  "soft": 0,                      // severity === "LLM 兜底" 的失败项数（不计硬失败，但计入 anyFail）
  "skips": 0,                     // pass === "SKIP" 的项数
  "results": [
    { "gate": "M-Form-1 引用标注完整性", "pass": true, "detail": "<人读说明>", "severity": "通过" }
  ],
  "exit": 0,                      // 本次机械退出码；落盘时可能与 script_exit_raw 不同（见 §1.5）
  "verdict_scope": { "draft_sha256": "<sha256>", "draft_bytes": 0 },   // 被审正文指纹

  // —— 落盘态新增（只有 --report 写出的文件才有）——
  "script_exit_raw": 0,           // 脚本机械值，**T8 禁止修改**
  "_t8_llm_review": "<证伪证据四件套>",   // T8 手写；exit ≠ script_exit_raw 时必填
  "_t8_conclusion": "<裁定结论>",          // T8 手写；同上必填
  "verdict_stale": false,         // 正文变更致旧裁定作废时为 true（留痕）
  "verdict_stale_reason": "…",    // verdict_stale=true 时的原因（留痕）
  "script_exit_raw_prev": 0       // 上一次落盘的脚本原值（留痕，可比对回归）
}
```

### 1.1 逐字段语义

| 字段 | 取值 | 说明 |
|---|---|---|
| `results[].gate` | 固定标签 | **逐字**见 §1.2；标签是机械门的对外契约，文档/模板引用时必须与之一致 |
| `results[].pass` | `true` / `false` / `"SKIP"` | **三态**。`"SKIP"` 目前只有 M-Exist-1（文末缺失、M-Form-2 已失败时让位）；`SKIP` 计入 `skips` → 判 `exit 3`，**不得当通过** |
| `results[].severity` | `"P0"`/`"P1"`/`"P2"`/`"通过"`/`"LLM 兜底"`/`"SKIP"` | 硬失败 = severity ∈ {P0,P1,P2} 且 `pass:false`；`LLM 兜底` 单独进 `soft` 桶 |
| `results[].detail` | 文本 | 人读；**`[报告后激活]`** 前缀见 §1.4 |
| `total` | 整数 | 恒 22（机械项）。**M 门总项数 23 = 机械 22 + 人工 1（M-Integrity-2）** |
| `--summary` 下的 `results` | 子集 | 仅保留**硬失败项**（`pass !== true && severity !== "LLM 兜底"`）——**不是完整报告，不得直接当闸门口径**（取闸门结论须跑不带 `--summary` 的一次） |

### 1.2 机械 22 项 gate 标签（逐字；`m-gate-check.mjs` 的 `gate:` 值即真源）

| 组 | 项数 | gate 标签 |
|---|---|---|
| **M-Form** | 11 | `M-Form-1 引用标注完整性` / `M-Form-2 文末四节存在性` / `M-Form-3 临时编号残留` / `M-Form-4 元数据泄露` / `M-Form-5 过程语言残留` / `M-Form-6 信任级别` / `M-Form-7 文末白名单` / `M-Form-8 三角验证` / `M-Form-9 图件闭环` / `M-Form-10 索引段完整性` / `M-Form-11 素材按需加载闭环` |
| **M-Exist** | 10 | `M-Exist-1 引用双向对比` / `M-Exist-2 证据包完整性` / `M-Exist-3 引用闭环` / `M-Exist-4 审计条目闭环` / `M-Exist-5 阶段闸门记录表` / `M-Exist-6 审稿报告与期刊匹配` / `M-Exist-7 交付说明字段齐备` / `M-Exist-8 批判报告覆盖` / `M-Exist-9 审计报告 G 项覆盖` / `M-Exist-10 大纲 §11 精简段` |
| **M-Integrity** | 1（脚本内） | `M-Integrity-1 T2.5 完整性`（脚本佐证）；**M-Integrity-2 = 主控 T7.5 人工门，不在脚本内、不出现在 `results` 里** |

> ⚠️ **标签措辞的两条清仓判据**（v18.2.6 教训）：
> ① **M-Exist-3 是「引用闭环」而非「信任级别一致性」**——该门只对账正文 `[Dxx]` ↔ 数据卡条目；信任级别由 M-Form-6（独立信任级别段）+ G12（审计层）承担。曾有 15+ 处文档与 `templates/闸门记录-template.md` 的两行机检表沿用旧语义，形成「会被机检、但没有任何检查在跑」的**假绿**。
> ② **M-Form-5 = 过程语言残留**（>10 处 = P0），**不是字数核验**——M 门 23 项里没有字数项；字数归 G8（真源 `references/_shared/字数判定表.md`）。

### 1.3 退出码（与 `SKILL.md` §执行能力边界 逐字一致）

| 码 | 含义 |
|---|---|
| `0` | 通过——无失败项、无 SKIP |
| `1` | 存在 **P1** 失败 |
| `2` | 存在 **P0** 失败 |
| `3` | 仅 P2 / `LLM 兜底` / SKIP——**需 LLM 复核，不得当通过** |
| `10` | **参数或路径错误**（含异常路径：v18.0.5 起随包脚本装 `_lib/exit-guard.mjs`，fs 类异常统一映射为 10，不再让未捕获异常退化成 1）。路径错**不得与 P1 混用** |
| `70` | **内部错误（EX_SOFTWARE，脚本缺陷）**——与任何内容判定无关 |

判定式（脚本原样）：`exit = p0 > 0 ? 2 : (p1 > 0 ? 1 : (anyFail || skips > 0 ? 3 : 0))`
另：`model-routing.mjs` 用自有码 **`4`**＝需人工决定（旧版 `3` 与 M 门 `3` 撞码）；非闸门工具（`token-budget` / `md2html` / `pdfcheck` / `token-cost`）不共用本语义。

### 1.4 `[报告后激活]` 标记（四项）

`M-Exist-4` / `M-Exist-5` / `M-Exist-6` / `M-Exist-9` 的**前提是「相关报告已落盘」**：主控在 Phase 4 预跑时四项全 N/A，**报告一落盘，重跑同一命令立刻变化**（实战：T7 报告落盘后 M-Exist-9 转通过、M-Exist-4 进入实检、**M-Exist-5 由 N/A 直接转 P0**）。
故：非 N/A 时 `detail` 前置 `[报告后激活]`，用于区分「稿件缺陷」与「履历性新增」。**取闸门口径必须在相关报告落盘后重跑**；主控预跑的 JSON 不得直接当闸门输入。

### 1.5 四个 T8 字段与各自的必填条件

| 字段 | 写入者 | 必填条件（**否则视为伪造**） |
|---|---|---|
| `script_exit_raw` | **脚本** | **始终写入**（= 本次脚本机械 `exit`）。**T8 禁止修改**——它是「脚本说了什么」的唯一凭据 |
| `exit` | 脚本写机械值，T8 可改 | 落盘值 = T8 裁定值，**当且仅当**既有报告的 `verdict_scope.draft_sha256` 与本次正文指纹**一致**时才被保留；否则脚本落盘改用本次机械值并置 `verdict_stale: true` + `verdict_stale_reason`（旧裁定原文仍留在 `_t8_conclusion` 供追溯）——**正文改了就必须重新裁定** |
| `_t8_llm_review` | **T8 手写** | **`exit ≠ script_exit_raw` 时必填**：证伪证据四件套（逐条枚举 / 真阳性扫描 / 规范冲突说明 / 独立复核来源） |
| `_t8_conclusion` | **T8 手写** | 同上条件必填：裁定结论 |

> **为什么必须成对存在**：脚本是**筛子**、T7/T8 是**判别器**——实测约 45% 的 M 门项需人工修正，故 `script_exit_raw ≠ 0` **不等于**存在真缺陷。若允许「只改 `exit` 不留证据」，报告就从「可复核的裁定」退化成「无据的自述」。
> **示例（只示裁定四字段）**：`"script_exit_raw": 1` ｜ `"exit": 0` ｜ `"_t8_llm_review": "① 逐条枚举… ② 真阳性扫描… ③ 规范冲突说明… ④ 独立复核来源…"` ｜ `"_t8_conclusion": "机械 exit=1 的 P1 经证伪为文档层漂移，非稿件缺陷；本版正文裁定 exit=0。"`
