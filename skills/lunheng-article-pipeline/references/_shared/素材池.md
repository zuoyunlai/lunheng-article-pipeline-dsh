# 证据素材池（跨项目素材复用）

> **性质**：机制文件（`references/_shared/` 下），默认禁写；改进动议只写 `audits/反哺报告-vN.md`。
> **定位**：把各项目证据卡里**被采纳的条目**跨项目聚合成可检索、可去重、带「信任 + 时效 + 复用次数」护栏的共享池，新项目**先查池复用、不足再检索**，摊薄重复检索成本；主人预设的一手素材（专著 / 公共数据）同步入池，补齐论衡「不擅长主动采集」的硬缺口。
> **脚本**：`pool-query.mjs`（查池）/ `pool-extract.mjs`（回写）/ `pool-report.mjs`（统计）——三个都是随包脚本白名单成员。

---

## 一、能力/数据分离 + 惰性创建（先读）

| 层 | 随插件分发吗 | 何时生成 |
|---|---|---|
| **机制**（三个 `pool-*.mjs` + 本文档 + `SKILL.md` 协议行） | ✅ 随插件走，装新版就有 | 装插件即就位 |
| **数据**（`<工作区根>/evidence-pool/` + 池内容） | ❌ 不随插件走 | 主控**首次查池时惰性创建**空骨架 |

**惰性创建**：`pool-query.mjs` 发现池不存在 → 自动建空骨架 + 输出「✅ 已创建空素材池骨架（0 条）」→ 返回「空池无命中」。

**「不预设素材也生效」的滚雪球闭环**：

```
项目① Phase 5 回写 → 池 0 → N 条（渠道=项目沉淀）
项目② Phase 0.5 查池 → 命中项目① → 复用省检索
项目② Phase 5 回写 → 池 N → N+M 条
…… 池随项目数单调增长
```

主人**什么都不预设**（`raw/` 一直空着），这条链照跑——「项目沉淀」与「主人预设」是两个并列渠道，前者不依赖后者。

## 二、目录结构

```
<工作区根>/evidence-pool/          ← 惰性创建，与 run/ 平级
├── raw\{books,datasets,papers,misc}\   ← 主人预设原始文件（只读，永不回写）
├── transcripts\                        ← 二进制原件摄取产物（仅 docx/pdf 需要）
├── literature.json / data.json / cases.json / databases.json
├── index.md                            ← 人类可读视图（pool-report 生成）
└── manifest.json                       ← 池统计 / 创建时间 / 复用次数
```

**三条规则**：① 原件只读；② 条目回指原件（`sourcePath` + `sourceSha`）；③ 与项目内投喂两条路径——长期共享→`raw/`，一次性→`run/<项目>/materials/` + `主人投喂清单.md`。

## 三、数据模型

### 通用字段（文献/数据/案例）

| 字段 | 说明 |
|---|---|
| `poolId` | 全局唯一（`类型-hash(去重键)`，同条目稳定） |
| `type` | `L` / `D` / `C` |
| `title` / `source` / `year` / `url[]` / `doi[]` | 元数据 |
| `trustLevel` | `已发布 / 主人投喂 / 二手转引`（三档真源 `_lib/trust.mjs`） |
| `timeliness` | `🟢 / 🟡 / 🔴`（沿用数据卡口径） |
| `claim` | 关联论点摘要 |
| `abstract` | 条目摘要（复用时的引用素材） |
| `channel` | `主人预设 / 项目沉淀` |
| `originProject` / `firstRetrievedAt` | 首发项目 + 首次入池日期 |
| `reuseCount` / `reusedBy[]` | 复用次数 + 复用项目列表 |
| `sourcePath` / `sourceSha` | 回指原件（主人预设必填） |

### 数据库类专用字段（`databases.json`，CFPS/CGSS 等）

`dbName` / `wave` / `variable` / `access` / `citation` / `coverage` / `updateFreq` / `trustLevel`（固定「主人投喂」）。

## 四、去重键（单一真源）

| 类型 | 去重键（优先级） |
|---|---|
| 文献 | DOI → URL |
| 数据 | 「来源机构 + 年份 + 指标」→ URL（**URL 不优先**——同一 URL 可拆多个数据点；实测 D05/D06 同引 Pew 一页、D10/D17/D23 同引一篇新华网报道，URL 优先会误合并） |
| 案例 | 标题（事件名） |
| 数据库 | `dbName + wave + variable` |

去重命中 → 不新增，`reuseCount + 1`、追加 `reusedBy[]`。

---

## 五、信任级别归一化（已确认映射）

三档真源 = `已发布 / 主人投喂 / 二手转引`。旧格式「可信度 A/B/C」回填映射：**A/B → 已发布（含预印本）；C → 二手转引（含媒体转引）**。

## 六、复用护栏

1. **时效**：🟢 ≤2 年 / 🟡 2–5 年 / 🔴 >5 年；🟡/🔴 条目复用，派发话术须标「有时效风险，正文降级措辞/加时间锚点」。
2. **复用次数预警**：`reuseCount ≥ 3` 提示「已被 N 个项目引用，注意差异化表述，防 G7 撞车」。
3. **首发溯源**：回指 `originProject`。

---

## 七、流水线集成

### Phase 0.5 查池（Phase 0 定题 与 Phase 1 检索 之间）

1. 主控定题确定关键词 → `node scripts/pool-query.mjs <工作区根> <关键词...>`。
2. 命中 → 条目注入 T1/T2/T3 派发话术，标「已检索到的候选素材，核验 URL/时效/相关性，支撑则复用、不足才新检索」。
3. 复用**不绕过**三角验证 / G8 铁律 / G7 原创性审计。

### Phase 5 回写（终检交付时）

主控跑 `node scripts/pool-extract.mjs <项目目录> <工作区根>`——只抽取「被采纳、经审计」的证据卡条目（**证据层，非检索层**）。

## 九、与既有机制的关系

| 机制 | 关系 |
|---|---|
| `sources-index.mjs` | 素材池做**跨项目**复用；来源索引做**项目内**三线去重——互补，不替代 |
| `材料摄取.md` | 主人预设素材进池 = 摄取（二进制→文本）+ 转卡片（LLM 角色）两步复用现有机制 |
| 数据信任级别（3 档） | 池条目继承证据卡信任级别；主人预设一律「主人投喂」，不得升格 |

## 十、边界（如实）

1. **旧项目格式不统一**：早期文献卡「可信度 A/B/C」→ 回填时按 §五映射清洗。
2. **复用不降低审计门槛**：池条目仍过 G1/G2/G7/G8 全部门。
3. **素材池 ≠ 证据包**：池是候选素材库，进正文前仍逐条核验；池条目不自动获得「已审计」身份。
4. **dta 原始数据**：论衡不做统计，主人先算结果（结果表投喂、dta 原件留溯源）。
