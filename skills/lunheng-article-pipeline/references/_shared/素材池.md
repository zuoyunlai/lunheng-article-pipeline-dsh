# 证据素材池（跨项目素材复用）

> **性质**：机制文件（`references/_shared/` 下），默认禁写；改进动议只写 `audits/反哺报告-vN.md`。
> **定位**：把各项目证据卡里**被采纳的条目**跨项目聚合成可检索、可去重、带「信任 + 时效 + 复用次数」护栏的共享池，新项目**先查池复用、不足再检索**，摊薄重复检索成本；主人预设的一手素材（专著 / 公共数据）同步入池，补齐论衡「不擅长主动采集」的硬缺口。
> **脚本**：`pool-query.mjs`（查池）/ `pool-extract.mjs`（回写）/ `pool-report.mjs`（统计）——三个都是随包脚本白名单成员。

---

## 一、能力/数据分离 + 惰性创建（先读）

| 层 | 随插件分发吗 | 何时生成 |
|---|---|---|
| **机制**（三个 `pool-*.mjs` + 本文档 + `SKILL.md` 协议行） | ✅ 随插件走，装新版就有 | 装插件即就位 |
| **数据**（`<工作区根>/evidence-pool/` + 池内容） | ❌ 不随插件走 | 主控**首次查池时惰性创建**空骨架 |

**惰性创建**：`pool-query.mjs` 发现池不存在 → 自动建空骨架（已存在的池文件不覆盖）+ 输出「✅ 已创建素材池骨架: `<路径>`（池内 N 条）」→ 返回「空池无命中」。**池已存在但结构不完整**（如 `pool-extract` 只写了有卡的那几类）→ 补建缺失的空池文件与目录，输出「· 池结构此前不完整，已补齐…」——**不与「（现有 N 条）」并列声称「已创建骨架」**（V5b）。

**「不预设素材也生效」的滚雪球闭环**：

```
项目① Phase 5 回写 → 池 0 → N 条（渠道=项目沉淀）
项目② Phase 0.5 查池 → 命中项目① → 复用省检索
项目② Phase 5 回写 → 池 N → N+M 条
…… 池随项目数单调增长
```

主人**什么都不预设**（`raw/` 一直空着），这条链照跑——「项目沉淀」与「主人预设」是两个并列渠道，前者不依赖后者。

## 二、目录结构

```
<工作区根>/evidence-pool/          ← 惰性创建，与 run/ 平级
├── raw\{books,datasets,papers,misc}\   ← 主人预设原始文件（只读，永不回写）
├── transcripts\                        ← 二进制原件摄取产物（仅 docx/pdf 需要）
├── literature.json / data.json / cases.json / databases.json
├── index.md                            ← 人类可读视图（pool-report 生成）
└── manifest.json                       ← 池统计 / 创建时间 / 复用次数（**派生量：一律由池文件重算**，见 §三）
```

**三条规则**：① 原件只读；② 条目回指原件（`sourcePath` + `sourceSha`）；③ 与项目内投喂两条路径——长期共享→`raw/`，一次性→`run/<项目>/materials/` + `主人投喂清单.md`。

> **manifest 不是第二真源**：`totalEntries` / `byType` / `byChannel` / `reuseCountTotal` 四个字段**全部是派生量**，由四个池文件现算（单一实现 = `_lib/pool-store.mjs`）。三个 `pool-*` 脚本都走它：查池（`pool-query`）与回写（`pool-extract`）都会重算——manifest 缺失或失真时**当场自愈**并如实报出。判据：派生量被当成独立持久状态写，就必然与真源分叉。

## 四、去重键（单一真源）

| 类型 | 去重键（优先级） |
|---|---|
| 文献 | DOI → URL |
| 数据 | 「来源机构 + 年份 + 指标」→ URL（**URL 不优先**——同一 URL 可拆多个数据点；实测 D05/D06 同引 Pew 一页、D10/D17/D23 同引一篇新华网报道，URL 优先会误合并） |
| 案例 | 标题（事件名） |
| 数据库 | `dbName + wave + variable` |

去重命中 → 不新增；**首次由该项目复用时** `reuseCount + 1` 并追加 `reusedBy[]`（**幂等**：同一项目重复抽取——Phase 5 之后的修订轮 / 重跑交付都会再跑一次回写——不再重复计数；`reusedBy[]` 记的是**复用者**，首发项目在 `originProject`）。

## 六、复用护栏

1. **时效**：🟢 ≤2 年 / 🟡 2–5 年 / 🔴 >5 年；🟡/🔴 条目复用，派发话术须标「有时效风险，正文降级措辞/加时间锚点」。
2. **复用次数预警**：`reuseCount ≥ 3` 提示「已被 N 个项目引用，注意差异化表述，防 G7 撞车」。
3. **首发溯源**：回指 `originProject`。

## 七、流水线集成

### Phase 0.5 查池（Phase 0 定题 与 Phase 1 检索 之间）

> ⚠️ **Phase 0 须先定「检索范围」档（§十一）**：档 A（默认）下第 2 条的「不足才新检索」成立；**本地档（仅本地素材 / 仅项目素材 / 仅素材池）下该退路被主人主动关闭**——命中条目 + 投喂即 T1/T2/T3 的全部来源。

1. 主控定题确定关键词 → `node scripts/pool-query.mjs <工作区根> <关键词...>`。
2. 命中 → 条目注入 T1/T2/T3 派发话术，标「已检索到的候选素材，核验 URL/时效/相关性，支撑则复用、不足才新检索」（**本地档改为 §11.2 的逐字追加话术**）。
3. 复用**不绕过**三角验证 / G8 铁律 / G7 原创性审计。
4. **同一次调用还会打印「负知识提醒」**（**只读提示层**，v19.6.10 动议 E 丙案）——扫描 `<工作区根>/run/*/audits/disproofs.jsonl`（契约真源 = [`负知识账本.md`](负知识账本.md)）并按**同一组关键词**提示命中条目，附 `originProject` 回指。**它不参与「池命中 N/M」计数，也不受池内条数影响**——**池空 + 有历史证伪**恰是它价值最大的场景（没有正面素材可复用，但有前人踩过的坑）。

### Phase 5 回写（终检交付时）

主控跑 `node scripts/pool-extract.mjs <项目目录> <工作区根>`——只抽取「被采纳、经审计」的证据卡条目（**证据层，非检索层**）。

## 十、边界（如实）

1. **旧项目格式不统一**：早期文献卡「可信度 A/B/C」→ 回填时按 §五映射清洗。
2. **复用不降低审计门槛**：池条目仍过 G1/G2/G7/G8 全部门。
3. **素材池 ≠ 证据包**：池是候选素材库，进正文前仍逐条核验；池条目不自动获得「已审计」身份。
4. **dta 原始数据**：论衡不做统计，主人先算结果（结果表投喂、dta 原件留溯源）。

### 11.1 四档定义（Phase 0 由主人拍板，写入 `01-任务简报.md` 头部）

| 档 | 名称 | T1/T2/T3 的**合法来源** | 默认 |

### 11.2 本地档（B/C/D）的派发话术改写（主控在 T1/T2/T3 prompt 中**逐字追加**）

> 【本任务检索范围 = **仅本地素材 / 仅项目素材 / 仅素材池**】你**不得**调用任何网络检索工具（web_search / 网页抓取 / 在线数据库）。你的全部来源只有：① 证据素材池（Phase 0.5 查池命中条目已列在下方；**仅「仅本地素材 / 仅素材池」档含此项**）② 主人投喂材料（**仅「仅本地素材 / 仅项目素材」档含此项**）。逐条标注来源为「池」或「投喂」，并给出原件路径。**材料不足时照实报缺口，禁止为凑数改用网络检索。**

### 11.3 本地档 **不减少角色**（硬约束）

**T1/T2/T3 仍必须各自 spawn 独立子代理**（`glossary.md` §九「T1-T7 + T9 必须 spawn 独立子代理，不可由主控代做」）。档 B 只改**来源**，不改**角色与数量**。
唯一合法的减线仍是 Phase 0 显式 `cases=0`（`references/agents/03-案例检索-case-scout.md`）——**与档位无关，两档都适用**。

### 11.4 本地档的缺口申报口径（**复用既有机制，不新增门**）

材料不足**不算失败**，但必须走**既有**申报路径，**不得静默降级**：

| 情形 | 处置 | 真源 |
|---|---|---|
| 某论点三线覆盖不足（`cov < 2`） | 走 `ACCEPTED-GAPS:` 机读声明，写明缺的是哪条线及原因 | `scripts/_lib/mgate-gates/mform-gates.mjs` §M-Form-8 |
| 文献数 < 文类下限 `GENRE_MIN_L` | **如实报 P0**——不得因「主人只给本地」而改判或豁免 | 同文件 §M-Form-1 |
| T2 拿不到结果表 | 数据线报「N 条 + 原因」；**T2 仍需 spawn**，产出空/少数据卡并注明 | `dispatch-cards.md` T2 卡 |
| T3 独立来源不足 | 照实标「单源降级」（官方自源不计独立计数） | `dispatch-cards.md` T3 卡 |

### 11.5 本地档的三条诚实边界（**须在 Phase 0 向主人前置声明**）

1. **不外网 ≠ 零外发**：档 B 只关闭外部服务第 ① 项（Web 检索 provider）。**大模型推理全文始终外发**（`glossary.md` §九）——除非另走本地 Ollama。
2. **档 B 抬高硬门风险**：材料由主人供给决定，M-Form-1 / M-Form-8 撞 P0 的概率显著上升。**主控须在 Phase 0 就把这个代价说清**，不得等撞门再解释。
3. **档 B 关闭了自动补齐退路**：档 A 下主控可「池不足 → 新检索」；档 B 下这条退路**被主人主动关闭**，缺口只能回到主人（§11.4 照实报）。
4. **首用空源不是「本地档生效」而是「本地档不适用」（v19.6.6 新增；v19.9.x 扩四档）**：该档的合法来源为空时（`仅本地素材`/`仅素材池` → 池 0 条；`仅本地素材`/`仅项目素材` → 无投喂）→ T1/T2/T3 的全部合法来源为空，**不得直接开跑**。主控须回到 Phase 0 的 `POOL=` 行（§十二 / 简报 ④），向主人给出三选一：① 改档 A；② 先放长期共享原件进 `raw/` 或走 `主人投喂清单.md`；③ **显式接受**「本轮证据面受限，M-Form-1 / M-Form-8 撞 P0 风险自担」并据此如实报缺口。**三选一必须留痕**（写进简报同段），不得由主控代选。

## 十二、可见性与 `POOL=` 行（v19.6.6 新增）

> **为什么新增本节**：机制此前**在用户面几乎不可见**——入口文档 0 命中、面板无说明、简报只有一条定义链接、交付物不报增长。而池的**创建（Phase 0.5）晚于关于它的决策（Phase 0）**：用户是在不知道「本地素材」是什么、在哪、有没有存货的状态下被问检索档的。本节把「显形时点」固化为机制，使「用户不知道有这东西」不再成立。

**主控 Phase 0 必做**（与外部服务授权串**同一次**写清，落 `01-任务简报.md` 头部）：

1. **先跑只读查池**：`node scripts/pool-query.mjs <工作区根> <关键词...>`（池不存在时它本就会惰性建空骨架，见 §一）；
2. **抄它的事实**写机器可读行：`POOL=新建|已存在 / 路径=<工作区根>/evidence-pool / 现有条数=N(L=.. D=.. C=.. DB=..) / 命中=<M> / 检索范围=<全网检索|仅本地素材>`；
3. **档 B 前先看第 2 步**：池内 0 条 + 无投喂 ⇒ 走 §11.5 第 4 条的三选一，**不得直接开跑**。

**边界（如实）**：① 该行在 `run/**/01-任务简报.md` 内，**本仓 `run/` 为空**，故**未**为它加 `consistency-check` 规则（加规则在本仓恒真通过）；② 该行**不产生新的闸门**，只是把已在做的 Phase 0.5 查池**提前显形**；③ 查池是**只读入口**，非空池时 `writeManifest` 走 `onlyIfStale`（真源 = `_lib/pool-store.mjs`），故不越 Phase 0 写面。
