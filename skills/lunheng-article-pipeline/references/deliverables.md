## 交付边界（v2.2.0 新增，教训 #64，借鉴 vincentjiang06 paper-writer）

论衡的交付物分两类，二者**独立**：

1. **论文交付物**：`final/定稿.md` + `final/图件/`（可选）+ `final/证据包/`
2. **操作员报告**：`final/交付说明.md` + `audits/审计报告-vN.md` + `audits/反哺报告-vN.md`

**核心原则**：

- 论文交付物 = **给读者的**（学术发表 / 投稿 / 公众号草稿）
- 操作员报告 = **给主人的**（质量复核 / 局限性告知 / 建议人工核验项）
- 操作员报告**不进入**论文交付物
- 反哺报告**不自动 commit**到角色卡（v2.0.2 起）

**论衡哲学化**：「论文是给读者的，报告是给主人的。混淆两者 = 失去信任」—— 借鉴 vincentjiang06 「A course paper carrying a ## 合规报告 section is no longer a course paper」论衡化表述。

## F 失败模式防御段（v2.2.0 新增，教训 #64，借鉴 ARS M1-M7 + 补漏 4 个新模式）

论衡按「失败模式」组织防御能力（F1-F9），不替换内部 G 体系（G0-G13 是 14 项内部检查）—— F 体系是 G 体系的**对外叙述**，让主人理解论衡怎么防 AI 失败。借鉴 ARS Lu et al. *Nature* 2026 论文的 M1-M7 失败模式组织。

| F 模式 | 定义 | 论衡 G 项映射 | 状态 |
|------|------|-------------|------|
| **F1 幻觉引用** | 引用真实但用错语境 / 引用完全捏造 | G1 分级抽验 + G0.5 视角一致性 + M-Exist-1 双向 diff | 已有（强）|
| **F2 幻觉数据** | 数字真实但过期 / 数字完全捏造 | G2 数据溯源 + G11 时效告警 | 已有（强）|
| **F3 早期框架锁定**（**新增**）| 分析大纲先入为主，写手被锁死 | G0.5 + Phase 3.5 主人洞察补充窗口 + **新增「反方论证覆盖必查」**| 补强 |
| **F4 论证自洽陷阱**（**新增**）| 论据与论点逻辑脱节，读者无法验证 | G3 逻辑核验 + **新增「论点-论据一对一验证」**| 补强 |
| **F5 拼凑式章节断裂** | 章节间无过渡 / 章节顺序违反读者认知 | G4 结构 + G8 #7 段落结构过度对称 | 已有（强）|
| **F6 过度防御口吻** | 写手代入「过度保护」语气，破坏客观分析视角 | G0.5 + G6 论据类型自标 + 「据行业经验估算」限定 | 已有（强）|
| **F7 主人风格模仿失真**（**新增**）| 写手把主人洞察当「作者声音」，混入正文 | G0.5 + 主人深度洞察融合协议 | 补强 |
| **F8 数据信任失败**（**v2.2.1 新增**）| 已发布 vs 主人投喂 vs 二手转引 来源混入 + 公众号版不同步 + 转引未标注 + 信任级别遗漏 | M-Form-6 + M-Exist-3 + G12 + T2.5 + T5.5 | 补强 |
| **F9 论证强度不足**（**v2.2.2 新增**）| 论据单一 / 因果倒置 / 以偏概全 / 回避反方 / 反方走过场 | T8 批判伙伴 C1-C5（独立反方攻击） | 补强 |

**F8 数据信任失败 4 子项**（v2.2.1 新增）：

- **F8.1 来源混入**：已发布数据 vs 主人投喂数据没区分 → 数据卡必填「信任级别」段
- **F8.2 公众号版不同步**：run/ vs outputs/ 数据不一致 → M-Exist-3 强制 diff + T5.5 闸门
- **F8.3 转引未标注**：论文中转引未标 [二手] → 数据卡 [二手] 字段必填 + G12 信任级别一致性扫描
- **F8.4 信任级别遗漏**：数据卡无信任级别标注 → M-Form-6 必查 + T2.5 闸门

**F9 论证强度不足 5 种表现**（v2.2.2 新增）：

- ① 论据单一（单一来源支撑核心论点）② 因果倒置 ③ 以偏概全 ④ 回避反方 ⑤ 反方走过场
- **防御**：T8 批判伙伴（独立反方角色，不依赖写手/审计员自我认知）

**借鉴出处**：vincentjiang06 paper-writer Trust Boundary 论衡化。

**F 体系与 G 体系交叉引用**：详见 [`failure-modes.md`](_shared/failure-modes.md) 与 [`audit-checklist-quickref.md`](_shared/audit-checklist-quickref.md)。

## 阶段闸门 T2.5 + T5.5 硬约束（v2.2.1 新增，教训 #77）

- **T2.5（T2 数据检索 → T3 分析前，主控 checkpoint）**：数据条目数 ≥ 任务简报数据需求数 + 信任级别完整（M-Form-6 + M-Exist-3）+ 主人签字 Phase 1 → 通过才派 T3（不通过 → 触发 T2 重检索或主控补数据）
- **T5.5（T5 审计 → T7 终检前，主控 checkpoint）**：审计报告最新版 + P0/P1 清单 + M 门全 exit 0 + 论文交付物 vs 操作员报告隔离 + 主人签字 Phase 5 → 通过才派 T7（不通过 → 触发 T5 重审或主控补审）
- **不引入新 agent**，主控用 `todo_write` + `read` 工具实现
- **借鉴出处**：ARS Stage 2.5/4.5 论衡化为主控 checkpoint
- **实战反馈**：v2.2.0 实战 2（品牌一致性 14 条 [Lxx] 漏引）+ 实战 3（教师场域 outputs/ 45 条 [Dxx] 漏引）都是阶段交接未拦截导致 → T2.5 + T5.5 闸门可防
- **「不绕过交接直接派发」**—— 论衡主控纪律
