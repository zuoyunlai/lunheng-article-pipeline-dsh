## 交付边界（v2.2.0 新增，教训 #64，借鉴 vincentjiang06 paper-writer）

论衡的交付物分两类，二者**独立**：

1. **论文交付物**：`final/定稿.md` + `final/图件/`（可选）+ `final/证据包/`
2. **操作员报告**：`final/交付说明.md` + `audits/审计报告-vN.md` + `audits/反哺报告-vN.md`

**核心原则**：

- 论文交付物 = **给读者的**（学术发表 / 投稿 / 公众号草稿）
- 操作员报告 = **给主人的**（质量复核 / 局限性告知 / 建议人工核验项）
- 操作员报告**不进入**论文交付物
- 反哺报告**不自动 commit**到角色卡（v2.0.2 起）

**论衡哲学化**：「论文是给读者的，报告是给主人的。混淆两者 = 失去信任」—— 借鉴 vincentjiang06 「A course paper carrying a ## 合规报告 section is no longer a course paper」论衡化表述。

## 定稿文末纯净规范（v2.3.1 新增，教训 #120）

> **背景**：v2.3.0 首次实战（ai-pilled vs agi-pilled）定稿文末混入「图表清单」「引用规范（四节闭环）」「主控签字（T8 终检）」三段操作员报告内容，且缺「先行者文献」节——「论文交付物 vs 操作员报告」边界混淆的实战案例。

**定稿文末白名单**（`final/定稿.md` 文末只允许以下 5 节，顺序固定）：

| 顺序 | 节 | 内容 |
|------|-----|------|
| 1 | `## 参考文献` | [Lxx] 学术文献 + 权威报告 |
| 2 | `## 数据来源` | [Dxx] 数据 + 可信度标注 |
| 3 | `## 案例来源` | [Cxx] 案例 + [C-主xx] 主人洞察 |
| 4 | `## 先行者文献` | [先xx] 原创性差异点声明 |
| 5 | `## AI 使用声明` | 学术伦理披露（学术投稿必加） |

> **⚠️ 文末条目的 `[Lxx]`／`[Dxx]`／`[Cxx]` 必须沿用素材卡里的真编号**（v18.2.1 新增，本轮实战教训）：
> 文末每一条都要带上**与 `literature/文献卡.md`／`data/数据卡.md`／`case-studies/案例卡.md` 完全一致**的编号（可与 GB/T 7714 的 `[1] [2] [3]` 顺序号**并列双标**：`[1] [L01] LAZER D, ...`）。
> **禁止按文末出现顺序重编 `[L01] [L02] ...`**——文末通常**省略备查/未引用条目**（如卡里有 `[L06]` 但正文未引），
> 一旦顺序重编，后面的编号会**整体错位一位**（`[L07]` 实为卡里的 L08、`[D07]` 实为 D08），
> M-Exist-1 的双向对比按**编号集合**判定，随即报「漏引 N」。
> **判据**：文末编号集合 ⊇ 正文引用编号集合，且差集（仅文末有）= 0 或全部集中在「先行者/备查」节。
> **实战（v18.2.0 短测试）**：首版文末只写 `[1]-[7]` 无 `[Lxx]` → 判「漏引 17」；补双标后又因顺序重编 → 判「漏引 2」（[L08]/[D08]）。

**禁止出现在定稿文末**（属操作员报告，移入 `final/交付说明.md`）：
- ❌ `## 图表清单` → 交付说明「图件清单」节
- ❌ `## 主控签字（T8 终检）」 → 交付说明「终检结论」节
- ❌ `## 引用规范（四节闭环）」等元说明 → 删除（是说明规范本身，非给读者的内容）
- ❌ 内部流水线信息（教训编号 / 模型 fallback 记录 / spawn 细节 / 审计过程）→ 交付说明

**机械化硬门 M-Form-7（v2.3.5 新增，教训 #139）**：本白名单规范从「文档层声明」升级为「执行层硬门」——T8 签字前必跑 `_shared/M-Gate-Algorithm.md` 的 **M-Form-7**，提取文末所有 `^## ` 节标题，白名单外任何一节即 P0 fail。**禁止在 M-Form-7 exit 0 之前签「交付边界纯净」**（v2.3.1 实战教训 #139：T8 签字走形式，文档层规范到执行层断链）。

**AI 使用披露双通道（v2.3.1 澄清）**：
- `final/交付说明.md` → 「AI 使用披露」**完整版**（给主人：AI 生成段 + 主人洞察出处 + 检索证据 + 模型 fallback 记录 + 教训沉淀）
- `final/定稿.md` → 「AI 使用声明」**精简版**（给读者：诚实透明声明，**不含**模型 fallback 记录、教训编号等内部信息）

**先行者声明闭环（v2.3.1 补强）**：T1 **必产** `literature/先行者清单.md`（原创性保证机制，实战曾被跳过）；定稿文末**必含** `## 先行者文献` 节；正文 [先xx] ↔ 文末清单双向 对比。缺先行者 = 原创性保证失效（学术不端风险）。

## F 失败模式防御段（v2.2.0 新增，教训 #64，借鉴 ARS M1-M7 + 补漏 4 个新模式）

论衡按「失败模式」组织防御能力（F1-F9），不替换内部 G 体系（G0-G14 是 15 项内部检查，v2.4.0 加 G14）—— F 体系是 G 体系的**对外叙述**，让主人理解论衡怎么防 AI 失败。借鉴 ARS Lu et al. *Nature* 2026 论文的 M1-M7 失败模式组织。

| F 模式 | 定义 | 论衡 G 项映射 | 状态 |
|------|------|-------------|------|
| **F1 幻觉引用** | 引用真实但用错语境 / 引用完全捏造 | G1 分级抽验 + G0.5 视角一致性 + M-Exist-1 双向 对比 | 已有（强）|
| **F2 幻觉数据** | 数字真实但过期 / 数字完全捏造 | G2 数据溯源 + G11 时效告警 | 已有（强）|
| **F3 早期框架锁定**（**新增**）| 分析大纲先入为主，写手被锁死 | G0.5 + Phase 3.5 主人洞察补充窗口 + **新增「反方论证覆盖必查」**| 补强 |
| **F4 论证自洽陷阱**（**新增**）| 论据与论点逻辑脱节，读者无法验证 | G3 逻辑核验 + **新增「论点-论据一对一验证」**| 补强 |
| **F5 拼凑式章节断裂** | 章节间无过渡 / 章节顺序违反读者认知 | G4 结构 + G8 #7 段落结构过度对称 | 已有（强）|
| **F6 过度防御口吻** | 写手代入「过度保护」语气，破坏客观分析视角 | G0.5 + G6 论据类型自标 + 「据行业经验估算」限定 | 已有（强）|
| **F7 主人风格模仿失真**（**新增**）| 写手把主人洞察当「作者声音」，混入正文 | G0.5 + 主人深度洞察融合协议 | 补强 |
| **F8 数据信任失败**（**v2.2.1 新增**）| 已发布 vs 主人投喂 vs 二手转引 来源混入 + 公众号版不同步 + 转引未标注 + 信任级别遗漏 | M-Form-6 + M-Exist-3 + G12 + T2.5 + **T7.5**（v2.3.0 改 T5.5→T7.5） | 补强 |
| **F9 论证强度不足**（**v2.2.2 新增**）| 论据单一 / 因果倒置 / 以偏概全 / 回避反方 / 反方走过场 | **T6** 批判伙伴 C1-C7（独立反方攻击，v2.3.0 重命名原 T8→T6） | 补强 |

## 修订回环 ≤2 轮硬约束（v2.2.0 新增，v2.3.1 定义细化，教训 #64 + #120）

> **v2.3.1 定义细化（教训 #120）**：v2.2.0 立「≤2 轮」铁律时**没区分「什么算一轮」**——v2.3.0 首次实战中 T6 一轮=出 v2，T8 想再启 T5=第二轮，若 T7 的 P1 都需启 T5 就超 2 轮。v2.3.1 重新定义「轮」+ 引入「P1 分级」+ T8 小幅修补权限。

**「轮」的定义（v2.3.1 重定义）**：
- **0 轮** = 主控启动，T5 写手出 v1
- **1 轮** = T6 批判伙伴攻击 + T5 写手出 v2（融入主人洞察 + 批判反馈，Phase 3.5/3.6）
- **2 轮** = T8 主控亲修出 v3（**小幅修补**，见下方「T8 小幅修补权限」）
- **超 2 轮** = 结构性 P1（P1-A/B/C）+ P0 才启 T5 v3（独立写手）

**T8 小幅修补权限（v2.3.1 新增，教训 #120）**：T8 从「只做签字」升级为「可做小幅修补」——
- ✅ 可修：≤字数 5% 改动 / AI 披露修正 / 元叙事清理 / P1-D 事实错误（引用格式/元数据/漏引/拼写）
- ❌ 不可修：结构性改动（论证补强/结构缺失/反方缺失 = P1-A/B/C）+ P0 → 必须启 T5 独立写手

**P1 分级细分（v2.3.1 新增，教训 #120）**：
- **P1-A/B/C（结构性）**：论证补强 / 结构缺失 / 反方缺失 → **T5 重启**（独立写手，保留 v2.2.4 防自我说服哲学）
