# G14 中文 AI 痕迹深度检测闸

> **性质**：闸门（Gate），机械化 + LLM 推理双驱动
> **触发阶段**：**三层防御、仅一次 spawn**——
> ① **T5 v1 自检**（写作时由 T5 执行，**零 spawn**；8 类措辞层扫描，结论入 `drafts/修订说明-v1.md`）→ ② **修订轮收尾自查**（每轮 T5 修订落盘后由主控执行，**零 spawn**）→ ③ **终闸 = Phase 4.5 与 T9 同行评审并行**（**唯一一次 spawn**；`audits/G14-检测报告-v{N}.md` = **最终版本真源**）。
>
> **⚠️ 早闸（原「Phase 3.6 与 T6 同批并行 spawn」）已删除（v18.2.8，主人显式授权「G14 早闸去掉」）**。三条理由：**(a)** G14 是**二元闸**——Pass 即零输出，全部价值集中在「触发修订」这一下；实测该项目早闸判 **Pass（1/8 类）** → **该次 spawn 产出为零**。**(b)** 早闸判的版本到定稿时**已不存在**——实测 v1→v4 间共 50+ 处编辑，两闸结论不同（1/8 vs 0/8），早闸对 v1 的结论对 v4 无预测力。**(c)** 早修**无回归保护**——后续 v3/v4 由 T7 的 P0/P1 清单驱动，**该清单不含 G14 项**；实测早闸唯一建议（破折号降至 ≤80 处）**无人执行、指标反从 183 升到 200 处**。**原「终稿贴字数上限无法改写」的担心**（引入早闸的理由）改由两条既有规则化解：G14 属 **B 轨质量项**（判 Warning/Fail 时**可临时突破字数软档 ±2%**）+ 修订走**等量置换**。**完整论证与实测数据见仓库根 `CHANGELOG.md` §18.2.8（不建相对链接：CHANGELOG 不在技能目录内，技能目录按 bundle/镜像独立分发）。**
> **失败后果**：命中 ≥3 类触发 T5 回环（≤2 轮），第 2 轮仍命中 → 报告主人
> **⚠️ 检测范围**：**文末五节与「AI 使用声明」节不参与检测**——该节职责就是披露 AI 参与（`M-Gate-Algorithm.md` M-Form-4 v18.2.2 段定其**整体豁免**文末二级扫描）。故 §二 各类判据里的「**全文**」（C/E/F/H 类与 D 类分母）**一律指「排除文末五节与 AI 声明后的正文区」**；不排除会**系统性命中 A/C/H 类**，把 Pass 顶成 Warning/Fail、白吃一轮 B 轨修订。口径真源 = `templates/G14检测报告-template.md:138`「豁免：作者声明段」+ `dispatch-cards.md` G14 卡。

## 一、设计哲学

论衡的「G14 中文 AI 痕迹深度检测」——**不是检测器（GPTZero 类），是论衡自己的「中文学术话语风格指南」+ 检测算法**。

**核心承诺**：
- **风格净化，非隐瞒**：G14 的目标是「去 AI 腔 + 提升中文学术话语可读性 + 贴近主人个人风格」，**不是「让 AI 痕迹不被检测到」**——G13 AI 使用披露照常在交付说明声明「本文由 AI 辅助生成」，**不隐瞒 AI 身份**
- **诚实透明**：G13 AI 使用披露照常在交付说明声明（不试图隐瞒 AI 痕迹）；G14 与 G13 互补不重叠（前者声明 + 后者净化）
- **中文特化**：所有检测维度针对**中文学术话语**，不是英文模式直接套用
- **可关闭**：主人可在 Phase 0 选择「关闭 G14」（不强制）

## 二、检测维度（8 类）

| 类别 | 检测点 | 阈值 | 借鉴来源 |
|------|-------|-----|---------|
| **G14-A 学术模板语** | 「综上所述/笔者认为/本文认为/值得关注的是/不容忽视/在新时代背景下/具有重要的理论与现实意义」 | 任一模板出现 ≥3 次 | chinese-writing 7.4 |
| **G14-B 句式同质化** | 连续 3 段同句式起头（如「首先...其次...最后...」「不仅...而且...」） | 同模板 ≥2 次连续段 | 论衡自有 |
| **G14-C 学术套话高频** | 「赋能/抓手/底层逻辑/范式/迭代/路径」每段 ≥1 次 | 全文 ≥5 处 | humanizer-zh |
| **G14-D 破折号滥用** | **占比 > 3%**（单一判据，口径见 §三「D 类判定口径」） | 占比 > 3% | humanizer-zh |
| **G14-E 三项排比** | 全文 ≥3 处「A/B/C」式排比 | 全文 ≥3 处 | humanizer-zh |
| **G14-F 人称错位** | 学术论文滥用第一人称「我」超过全文1% | 「我」字频 > 1% | 论衡自有（中文规范）|
| **G14-G 个人辨识度缺失** | LLM 判定：本文与10 篇同主题论文风格相似度 >80% | LLM 自评判定 | 论衡自有 |
| **G14-H 党报话语堆砌** | 政治学科特化：「重要讲话精神/重要指示/根本遵循」过多 | 全文 ≥3 处 | 论衡自有 |

## 三、判定规则

**单条命中**：每类单独计算，每类内部阈值独立判定。

**整体判定**：
- 命中 0-2 类 → ✅ Pass（轻微 AI 味，可接受）
- 命中 3-4 类 → ⚠️ Warning（触发 T5 回环，1 轮修订）
- 命中 5+ 类 → ❌ Fail（触发 T5 回环，2 轮强制修订；第 2 轮仍不通过 → 报告主人手工润色）

**例外豁免**（主人可在 Phase 0 关闭）：
- 「本文认为」/「笔者认为」等学术模板语在**引言/结论**段可豁免（学术规范要求）
- 破折号在**正文叙述**段豁免（仅检查论点段）

### D 类判定口径（全库唯一口径）

**唯一口径（单一判据，无歧义）**：

```
破折号      = 连续两个 U+2014（即「——」）；单个 U+2014 不计
占比分母    = 全文汉字数（口径 = scripts/_lib/han.mjs 的 countHan，U+4E00–9FFF，与 count-chars 同源）
占比分子    = 破折号个数 × 2（每个破折号占 2 个字符位）
命中 ⟺ 分子 / 分母 > 3%
```

### ⚠️ 配额耗尽时的降级路径（v18.51.0 反哺 **F-AT**；QLT-5 实测命中率 **2/4 项目**）

**问题（机制时序缺口，非执行偏差）**：本闸的触发轮**属 B 轨**（「B 轨主控触发轮」）；而 B 轨的真源是 [`../glossary.md`](../glossary.md) 的「**至多 +1 深化轮**（全周期累计）」，`pipeline-readme.md` 更明写「**B 轨累计已达 1 → 不再开**」，且 **B 轨开与不开由主控在 Phase 4.5 之前判定**。而本闸的 Warning **产生于 Phase 4.5** → **额度在先、告警在后**：若 B 轨配额已在 4.5 前用掉（T6 批判 / T9 审稿 / 主人洞察任一触发过深化轮），**本闸的 Warning 便无轮可开**。

**降级路径（在「触发 T5 修订」不可执行时，按序执行，不得静默跳过）**：

1. **如实判定「中不中」**：逐类列出命中项（**含行号**），并**逐项回答「这一处能不能在不损伤术语精度/论证结构的前提下改掉」**；
2. **能改但无轮可开** → **不得为过门而改**。判据：**术语精度 / 论证结构 > 门口径达标**（QLT-5 实测：为降 C 类计数而替换核心机制术语属于**损害**，写手应**如实报告「未达成降门目标」**）；
3. **在 `final/局限性.md` 单列一条 Acknowledged Limitation**（标题含「G14 Warning 未修订 + 配额依据」），**并在 `final/交付说明.md` §3「遗留风险」写一条摘要**（指向该局限性条目，并写明「本闸 Warning 未修订」的事实与配额依据）；
4. **结论表不得引用本闸档位作为交付质量证据**——须写明「本闸档位在跨臂/跨项目间**不可比**」（豁免口径分歧见反哺 F-AS），**QLT-1 等分数亦不得用来支撑"论证质量"结论**（见反哺 **F-BC**）；
5. **主人可显式放开额度** → 此时按 `AGENTS.md` §机制文件写保护 的**主人授权例外**条款执行，并遵守 **F-AX 三步协议**（见 [`../maintainers.md`](../maintainers.md)）：**辨名 → 记例外（不改规则数值）→ 读数冻结 + 投递读数并列**。

> **判据**：**门的义务是"把话说清楚"，不是"必须把档位刷绿"。** 无轮可开时，正确产出是**一条可核查的已披露风险**，而不是一个被改写掉的词。

## 五、报告输出

G14 检测报告路径：（检查 audits/G14-检测报告-vN.md）

报告模板见 [`../templates/G14检测报告-template.md`](../templates/G14检测报告-template.md)

**报告必含字段**：
- 8 类检测项逐项判定（命中数 + 阈值 + 原文示例）
- 整体判定（Pass / Warning / Fail）
- 详细命中位置（章节 + 段落 + 行号）
- 修订建议（按类别给出改写示例）
  > **⚠️ 供选建议的自检义务**：每条建议写入报告前，先问一句 **「照我说的改，会不会改变本报告任一维度的命中计数？」**——若会改变，则**要么撤回、要么显式标注冲突**，不得直接输出。
  > **判据（可迁移）**：**报告的建议与报告的判据互斥时，以判据为准；建议须先通过其自身判据的自检。**
- T5 写手处理状态（已修订 / 未修订 / 修订后仍命中）
- **按章命中定位表**（章名 / 该章汉字数 / 命中类别 / 命中条目与行号——**只报可核查事实，不出「AI 痕迹密度」类分数**）
