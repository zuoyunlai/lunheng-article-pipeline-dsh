## 二、三层防御体系

- **性质**：机械化、零人工判断、可自动化
- **算法**：Python 伪代码 + Bash 验证命令
- **执行模型**（v2.2.12 澄清，v2.5.2-dsh.4 审计修订）：
  - ✅ **主控 LLM 推理判定**：主控用 `read` 读取算法文档，按伪代码**推理**判定

## 三、数据信任级别（v2.2.1 核心机制）

### 🟢 Level 1：已发布公开数据（最高信任）
- **定义**：通过正规渠道发布的官方/学术数据
- **示例**：
  - 官方统计年鉴（国家统计局）
  - 学术论文中的研究数据（已发表）
  - 行业协会公开报告（中国汽车工业协会）
- **验证要求**：来源 URL 可核验（已发布数据，G1/G2 核验）
- **引用形式**：内联引用 `(来源，年份)` 或编号引用 `[Dxx]`

### 🟡 Level 2：主人投喂数据（中信任）
- **定义**：主人提供的一手数据、内部资料、专家访谈记录
- **示例**：
  - 主人提供的企业内部销售数据
  - 主人进行的问卷调查结果
  - 主人的实地考察笔记
- **验证要求**：主人确认记录（主人投喂数据）
- **引用形式**：标注 `[主人提供]` 或 `[内部数据]`

### 🔴 Level 3：二手转引（低信任，严格限制）
- **定义**：从新闻报道、自媒体、二手资料转引的数据
- **限制条件**（v2.2.1 铁律）：
  1. 必须回溯到一次文献（新闻/报告必须引出原始来源）
  2. 顶部标注 `[二手转引]` 警告
  3. **T7** 审计 G12 专项检查（v2.3.0 改 T5→T7）
- **禁止场景**：核心论据、统计数据、精确数字

### 基线引用 [D-基-xx-xx] 格式（v2.3.7 论文三实战升级，P1-2）

- **背景**：论衡 v2.3.7 论文三实战中 T2 数据检索员产出 6 条基线数据（资金/阈值/案例/其他），命名为 `[D-基-R-01]` `[D-基-T-01]` `[D-基-C-01]` `[D-基-E-01]` 等。但 T5 写手传递时可能简化成"基线一致"或具体数字，导致基线编号格式丢失，影响证据可追溯性。v2.3.7 升级后**基线数据编号格式正式规范化**。
- **格式定义**：`[D-基-{类别}-{序号}]`
  - `D-基`：基线数据前缀（区别于普通数据卡 `[Dxx]`）
  - `{类别}`：单字符类别码
    - `R` = Resource（资源/资金/成本）
    - `T` = Threshold（阈值/拐点/临界值）
    - `C` = Case（案例事件）
    - `E` = Evidence（其他证据）
  - `{序号}`：两位数序号（01-99），项目内唯一
- **示例**：
  - `[D-基-R-01]` = 资金基线第 1 条（如"开模打样成本"）
  - `[D-基-T-01]` = 阈值基线第 1 条（如"60% 一致性阈值"）
  - `[D-基-C-01]` = 案例基线第 1 条（如"某家居品牌原创失败事件"）
  - `[D-基-E-01]` = 其他证据基线第 1 条（如"10.6% 市场增速"）
- **数据卡模板要求**：T2 数据检索员产出基线时，必须按上述格式在数据卡 entry 顶部标 `**基线编号**：[D-基-R-01]` 字段。
- **写手传递要求**：写手 v1/v2/v3/v4/v5 引用基线数据时，**必须保留完整 `[D-基-xx-xx]` 格式**，不允许简化成"基线一致"或裸数字。M-Form-6（信任级别独立段）+ M-Exist-3（引用闭环）双格式检查会拦截丢失基线编号的引用。
- **任务简报要求**：§四 数据基线段必填基线编号清单（如"资金基线：[D-基-R-01]；阈值基线：[D-基-T-01]"），写手 v1 看清单引用。
- **T7 审计检查**：G12 数据信任一致性 + 基线编号双格式检查——丢失编号 = P1 必补。

## 四、关键协议

## 十一、关键术语

### 主控 vs 子代理
- **主控**：T0，流程编排者，不替代子代理执行具体工作（除 T8 终检——主控 = T0 调度 + T8 终检执行双重身份）
- **子代理**：**T1-T9**，专项任务执行者（v2.5.2-dsh.8 语义定案：9 个独立角色各有独立子代理身份，**唯一例外 T8 终检由主控亲执行不 spawn**——T1-T7 + T9 必须 spawn 独立子代理，不可由主控代做）

### spawn vs yield
- **spawn**：主控通过 `subagent` 创建子代理
- **yield**：主控通过 `等完成通知` 挂起等待子代理完成

### 引用匹配度（v18.8.0 借鉴）
引用数量与质量是否达到主人设定的目标（目标引用数 / 优先同刊比例 / 影响因子门槛 / 卷期页码完整率 / auto_cite 替换率）。审计项 = G15；机检联动 = **M-Exist-6**（任务简报 vs T9 一致性）+ **`g-audit-check.mjs` 的 `G15-VolIssue`**（v18.41.0 实装：逐条列出缺字段的 [Lxx]，**候选 P2、不设阈值**；**模式相关**——简报标 `QLT=on` 时 T7 须传 `--qlt`，未传则该判 `N/A` 不是「已核通过」）。⚠️ 旧文写的 `M-Form-2 v2` 分支**不存在**（作废号案卷见 `规范-机械门对照表.md` §二 末行）；「无门」那句在 v18.41.0 已过期，v18.43.0 更正。详见 `audits/反哺报告-v3-引用数量与期刊指定.md`。

### 真源 vs 副本
- **真源**：论衡 skill 目录 `references/`（本 skill 的流水线真源）
- **副本**：发布渠道 ZIP / GitHub 仓库

### 蒸馏 vs 压缩
- **蒸馏**（Distillation）：从日记忆提炼长期记忆（有损压缩）
- **压缩**（Compact）：减少重复内容（无损压缩）

## 十二、本技能自用术语与文档约定（v18.0.0 新增）

> **为什么单列这一节**：DSH 官方对仓库文档的要求是「用直接、具体的术语，**不用隐喻**；**不保留审查历史**；一事实一处」（见官方 `AGENTS.md` §Type safety and documentation）。本技能**刻意偏离**了后两条，此节把偏离**显式声明**，以免后续维护者（或官方规范审阅）误以为是疏漏。

### 12.1 自用术语（**非通用术语**，仅在论衡语境内有定义）

| 术语 | 在本技能中的确切含义 | 不是 |
|---|---|---|
| **承重墙 / 承重证据** | 支撑力最强的**单条**证据（每论点标一条 `承重证据 top1`）；同一证据被 ≥3 个论点标为承重即**超载** | 不是建筑隐喻，也不是「重点段落」的泛称 |
| **三角验证** = **三角证据底座** | 论点必须能映射到 **`[Lxx]`（文献）+ `[Dxx]`（数据）+ `[Cxx]`（案例）** 三类证据（涉事件者必须有案例） | 不是「多方求证」的泛称，是**三类证据编号的硬约束**；两个叫法**同义**（英文 README 作 "Triangular evidence base"），以本行为准 |
| **M 门** | `M-Form 11 + M-Exist 11 + M-Integrity-1 + M-Fact-1 = 机检 24 项`（另 M-Integrity-2 人工门 1 项 → 总 25 项），由 `scripts/m-gate-check.mjs` 机械判定 + T8 LLM 复核 | 不是「质量评分」 |
| **G 清单 / G0-G14 + G15** | 审计员逐项执行的 **15 主项（G0-G14 硬门）+ G15 模式相关项**检查（覆盖度 / 引用核验 / 溯源 / 逻辑 / 格式 / 原创性 / 时效 / 信任级别 / AI 披露 / 中文 AI 痕迹 / 引用数量与质量） | 不是「评分维度」 |
| **F 模式 / F1-F9** | **失败模式**清单（幻觉引用 / 幻觉数据 / 早期框架锁定 / 论证自洽陷阱 / 拼凑式断裂 / 过度防御 / 风格失真 / 数据信任失败 / 论证强度不足） | 不是「功能编号」 |
| **闸门（T2.5 / T7.5）** | 主控在两个阶段边界执行的**完整性检查点**（不绕过即不派下一阶段） | 不是 DSH 的 approval 机制 |
| **回环 / 修订轮次** | **三环**：审计打回 → 写手修订 → 复核，**A 轨 ≤2 轮**硬约束；主控触发轮（T6/T9/主人洞察）为 **B 轨**，**至多 +1 深化轮**；**G14 终闸 Warning/Fail 为 G 环**（v18.75.0 新立，独立额度、**不占 B 轨**，重跑 G14 至 Pass） | 不是「迭代次数」 |
| **卡级 / 修卡** | 素材卡（文献/数据/案例）层面的字段缺失与修补（属 T7 建议，非正文缺陷） | —— |
| **筛选器 vs 判别器** | 脚本 = **筛子**（可能误报/漏报），T7/T8 = **判别器**（逐项复核裁定）；实测约 45% 的 M 门项需人工修正 | 不是「自动化程度」之分 |
| **正文字数** | `scripts/count-chars.mjs` 的 **body 区纯汉字数**（`[\u4e00-\u9fff]`，摘要后~文末节前；标点 / ASCII / 编号 / 破折号一律不计）——**唯一字数验收口径**（v18.5.1 显式化）。`build-evidence-bundle.mjs` 视图里的「正文纯汉字」是**全文口径**（含文末节），仅作参考，**不得用于验收** | 不是「含标点总字符数」，也不是全文汉字数——实战同稿两口径 8,356 vs 9,509 曾被混用（2026-09-22 反哺报告-v1） |

### 12.2 文档约定（与官方规范的刻意偏离）

| 项 | 官方规范 | 本技能做法 | 理由与代价 |
|---|---|---|---|
| **隐喻** | 「Do not use metaphors」 | 使用上表自用术语（在 12.1 统一定义） | **理由**：中文写作场景下这些术语已成为团队内稳定黑话，且与英文术语（gate / audit / failure mode）无一对一直译；**代价**：新人需先读本节 |
| **审查历史** | 「Do not preserve review history」 | 正文保留 `教训 #N`（累计 #1–#144）与 `v2.5.2-dsh.N` 版本注解 | **理由**：这些编号是**跨项目可复用的实证资产**（每条对应一次真实事故），删除即失去可追溯性；官方规范面向**有 git log 的代码仓库**，而 skill 是**模型读物**（无 git log 语境）；**代价**：文档 token 成本上升，论衡已用「注解聚合」缓解（同主题合并为单行） |
| **一事实一处** | 「one home per fact」 | 承认存在多宿主（`SKILL.md` / `AGENTS.md` / `glossary.md` / `pipeline-readme.md` / 角色卡） | **理由**：不同读者（主控 / 子代理 / 主人）加载不同文件，收敛到一处会导致「读 A 文件的人看不到该事实」；**代价**：必须靠 `scripts/consistency-check.mjs` 机械校验漂移（**规则清单与条数真源 = `scripts/_lib/cc-rules/rule-registry.mjs`**；v18.78.2 起此处**不再写数字**——本行手写的「N 类主规则」在 v18.2.6 / v18.18.0 / v18.22.1 / v18.78.0 四次被审计抓到与脚本头注释不一致，故 A2 把清单上提为代码登记表并由规则 ㉟ 机械对账）。**⚠️ 已知边界（v18.12.0 审计）**：该门只能抓「集合 / 计数 / 版本点位 / 字符串」四类漂移，**抓不到语义级事实**——「文末五节 vs 九节」「B 轨不限额 vs 至多 +1」在字符串层面互不冲突，故真正的一事实一处仍靠本节与人的 review |
| **词预算** | 有 word budgets | 单文件可达 20-70 KB | **理由**：流水线复杂度使然（9 角色 + M 门 25 项 + 15 审项）；**代价**：主控需「分层按需读取」（见 SKILL.md 启动清单） |
| **修订回环命名** | 官方未规定 | **三环制 A 轨 / B 轨 / G 环** | **理由（v18.77.0 P-4）**：避免「A/B/C 三类」「0/1/2/超 2 轮」等多套命名在同一文档并存导致读者无法对齐；**代价**：其他文档用替代命名时须做引号→三环制名映射（本节已写） |
| **v18.x 文档归档标记**（v18.78.0 §7.5 立项，**刻意不建 archive 目录**） | 「Do not preserve review history」 | 主线保留「当年版 + 现行口径」段位；过期段位以版本注聚合到卡头一行，不另建 `docs/archive/` | **理由**：与本表「审查历史」行同族——版本注解是可复用实证资产；`changelog/archive/` 已是既有归档真源，再建 `docs/archive/` 会形成两套机制。**代价**：膨胀由 `repo-hygiene-check` 规则⑨（棘轮）+「注解聚合」兜底，与「多宿主」的张力由主控 review 化解 |

### 12.3 规范冲突仲裁：文末五节 vs 国标不重复著录（v18.5.1 新增，主人授权修订）

> **冲突**：M-Form-7 要求文末**五节齐全且顺序固定**（参考文献 → 数据来源 → 案例来源 → 先行者文献 → AI 使用声明）；而 GB/T 7714-2015 不允许同一文献著录两次。当 `[先xx]` 与 `[Lxx]` 指向同一文献时（常见：先行者就是核心文献，如 [先01]≡[L05]），两规范相撞。
>
> **仲裁**：**论衡五节结构优先**。理由：① 它是机检硬门（M-Form-7），服务流水线内部的原创性追溯，不随期刊格式变化；② 国标约束的是**面向印刷的著录行为**，投稿时由作者按目标期刊要求合并即可，与流水线内部结构无涉。
>
> **落地写法**：「先行者文献」节保留节名与位置，但**不重复著录**——每条只写 `[先NN] + 短标识 + 与本文差异点 + 「完整著录详见参考文献 [Lxx]」`。
> **实战教训**（2026-09-22 ai-content-farm-retractions）：T6 只援引国标报「重复著录 P1」、未核对 M-Form-7，主控照做把该节改成纯差异说明——若删节名将直接破坏五节结构（P1）。
> **一般化规则**：T6/T7/T9 引用的任何外部规范（国标 / 期刊指南 / 出版伦理守则）与本项目机检契约冲突时，**机检契约优先**，除非主人显式裁定相反。引用外部规范前须核对契约（见 pipeline-readme「派发前 preflight 反注」与 T6/T9 派发话术第 9 条铁律）。

> **给维护者的规则**：若日后要把本技能纳入官方风格审查，**先读本节**——12.1 的术语可在保留语义的前提下改写为无隐喻表述（工作量集中在 glossary + 9 张角色卡）；12.2 的「审查史」与「多宿主」是**刻意设计**，改动前须评估教训可追溯性的损失。
