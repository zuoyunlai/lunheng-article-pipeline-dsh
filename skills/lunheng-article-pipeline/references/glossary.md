## 三、数据信任级别（v2.2.1 核心机制）

### 🟢 Level 1：已发布公开数据（最高信任）
- **定义**：通过正规渠道发布的官方/学术数据
- **示例**：
  - 官方统计年鉴（国家统计局）
  - 学术论文中的研究数据（已发表）
  - 行业协会公开报告（中国汽车工业协会）
- **验证要求**：M-Exist-1 检查来源 URL
- **引用形式**：内联引用 `(来源，年份)` 或编号引用 `[Dxx]`

### 🟡 Level 2：主人投喂数据（中信任）
- **定义**：主人提供的一手数据、内部资料、专家访谈记录
- **示例**：
  - 主人提供的企业内部销售数据
  - 主人进行的问卷调查结果
  - 主人的实地考察笔记
- **验证要求**：M-Exist-3 检查主人确认记录
- **引用形式**：标注 `[主人提供]` 或 `[内部数据]`

### 🔴 Level 3：二手转引（低信任，严格限制）
- **定义**：从新闻报道、自媒体、二手资料转引的数据
- **限制条件**（v2.2.1 铁律）：
  1. 必须回溯到一次文献（新闻/报告必须引出原始来源）
  2. 顶部标注 `[二手转引]` 警告
  3. **T7** 审计 G12 专项检查（v2.3.0 改 T5→T7）
- **禁止场景**：核心论据、统计数据、精确数字

### 基线引用 [D-基-xx-xx] 格式（v2.3.7 论文三实战升级，P1-2）

- **背景**：论衡 v2.3.7 论文三实战中 T2 数据检索员产出 6 条基线数据（资金/阈值/案例/其他），命名为 `[D-基-R-01]` `[D-基-T-01]` `[D-基-C-01]` `[D-基-E-01]` 等。但 T5 写手传递时可能简化成"基线一致"或具体数字，导致基线编号格式丢失，影响证据可追溯性。v2.3.7 升级后**基线数据编号格式正式规范化**。
- **格式定义**：`[D-基-<类别>-<序号>]`
  - `D-基`：基线数据前缀（区别于普通数据卡 `[Dxx]`）
  - `<类别>`：单字符类别码
    - `R` = Resource（资源/资金/成本）
    - `T` = Threshold（阈值/拐点/临界值）
    - `C` = Case（案例事件）
    - `E` = Evidence（其他证据）
  - `<序号>`：两位数序号（01-99），项目内唯一
- **示例**：
  - `[D-基-R-01]` = 资金基线第 1 条（如"开模打样成本"）
  - `[D-基-T-01]` = 阈值基线第 1 条（如"60% 一致性阈值"）
  - `[D-基-C-01]` = 案例基线第 1 条（如"某家居品牌原创失败事件"）
  - `[D-基-E-01]` = 其他证据基线第 1 条（如"10.6% 市场增速"）
- **数据卡模板要求**：T2 数据检索员产出基线时，必须按上述格式在数据卡 entry 顶部标 `**基线编号**：[D-基-R-01]` 字段。
- **写手传递要求**：写手 v1/v2/v3/v4/v5 引用基线数据时，**必须保留完整 `[D-基-xx-xx]` 格式**，不允许简化成"基线一致"或裸数字。M-Form-6 + M-Exist-3 双格式检查会拦截丢失基线编号的引用。
- **任务简报要求**：§四 数据基线段必填基线编号清单（如"资金基线：[D-基-R-01]；阈值基线：[D-基-T-01]"），写手 v1 看清单引用。
- **T7 审计检查**：G12 数据信任一致性 + 基线编号双格式检查——丢失编号 = P1 必补。

## 五、工具能力边界（DSH 版，替代 OpenClaw 白名单）

**DSH 无技能级工具白名单/denied**——工具集由 Agent 预设（组合文件）决定，以当前会话预设为准（standard 预设含 read/write/edit/web_search/read_page/todo_write/subagent/list_agents/pwsh/bash 等）。论衡流水线用到的核心工具：

- **文件操作**：read / write / edit
- **Web 检索**：web_search / read_page
- **子代理编排**：subagent / list_agents
- **计划跟踪**：todo_write
- **Shell（可选）**：pwsh / bash（standard 预设含，经主人同意可执行）

> OpenClaw 版 15 项可用 / 7 项禁用白名单在 DSH 下无效（原 `image_generate`/`exec` deny 等条目由预设与授权约束替代）。

### ℹ️ 关键澄清
- **M 门算法**：主控 LLM 通过 `read` 读取算法文档，按伪代码**推理判定**
- **不执行 shell**：算法文档中的 `sha256sum`/`grep`/`awk`/`comm` 命令仅供人类主人手动验证
- **纯推理流水线**：论衡是 LLM 推理 + 文件读写 + Web 检索，没有任何 shell 执行能力

### ❌ 不适用场景（5 类，v2.1.7）
1. **理工科论文**（需数学推导/代码实现/实验设计）
2. **文学创作**（小说/诗歌/剧本）
3. **新闻快讯**（时效性要求 <24 小时）
4. **营销软文**（非客观分析）
5. **需要主人一手数据但主人未提供**（田野调查/问卷/实验数据）

## 九、外部服务声明（v2.1.2，DSH 版）

### 🌐 涉及的外部服务（DSH）
1. **Web 检索**：`web_search` / `read_page` → DSH 配置的 web provider（无独立 Tavily 工具）
2. **封面/配图**：默认本地 SVG（程序化，不外发）；如需文生图另配图像生成 MCP（如 MiniMax image-01，外发）
3. **模型推理**：文章全文发到当前模型 provider（deepseek/MiniMax/Anthropic 等）用于推理/写作/审计

### 🔒 数据流方向
- **向外发送**：检索关键词 / （可选）图像生成 prompt
- **不发送**：原始文献内容 / 主人投喂数据 / 中间产物

### 🛡️ 主人拒绝外部服务时的备选方案
1. **Web 检索**：主人手动提供文献/数据 PDF（投喂）
2. **封面生成**：
   - 方案 A：主人提供封面图片（投喂）
   - 方案 B：使用 SVG 手绘（本地生成，默认）
   - 方案 C：使用本地模型（如 Ollama 等本地 provider，零外发推理）

根据研究[L1]，中国城市化率从 2010 年的 49.95% 提升到 2020 年的 63.89%[D3]。

## 十一、关键术语

### 主控 vs 子代理
- **主控**：T0，流程编排者，不替代子代理执行具体工作（除 T8 终检）
- **子代理**：**T1-T7**，专项任务执行者（v2.3.0 改 T1-T6 → T1-T7，T8 终检 = 主控亲完成无独立子代理）

### spawn vs yield
- **spawn**：主控通过 `subagent` 创建子代理
- **yield**：主控通过 `等子代理完成通知` 挂起等待子代理完成

### 真源 vs 副本
- **真源**：论衡工作区 `工作区/pipeline/`
- **副本**：ClawHub skill ZIP / GitHub 仓库

### 蒸馏 vs 压缩
- **蒸馏**（Distillation）：从日记忆提炼长期记忆（有损压缩）
- **压缩**（Compact）：减少重复内容（无损压缩）
