## 职责

- **终检必查 15 项**：交付边界（论文 vs 操作员报告隔离）/ G13 术语泄露 / G14 中文 AI 痕迹 / 内部编号残留 / 破折号计数 / 字数终审（`scripts/count-chars.mjs` 权威值）/ 反方论证密度 / 结论呼应引言 / 数据时效标注 / 二级转引标注 / [图N] 占位齐全 / AI 使用声明 / 参考文献编号闭环 / sha256 指纹填**实值**（权威 = `final/证据包/manifest.json`；主人不参与回填）/ 交付说明
  > **补 5 项必查**（均有机械门）：
  > ① **文末五节顺序**（不只成员资格）——须为 `参考文献 → 数据来源 → 案例来源 → 先行者文献 → AI 使用声明`（M-Form-7 已加顺序断言，判 P1）；
  > ② **文末节内容纯净**——非书目条目行不得含角色名 / 平台动作 / 版本注记 / 内部术语（M-Form-4 已加文末二级扫描，判 P0）；
  > ③ **M 门 exit 双字段**——`final/M-Gate-Report.json` 须同时含 `script_exit_raw`（脚本原值，**禁止修改**）与 `exit`（T8 裁定值）；两者不同时必须附 `_t8_llm_review`（证伪证据四件套）与 `_t8_conclusion`，否则视为伪造（详见 `M-Gate-Algorithm.md` §执行模型）。
  > ④ **裁定必须走通道**：上面两段**不得手写报告**，一律经
  > `node scripts/m-gate-check.mjs <定稿.md> <证据包> --report final/M-Gate-Report.json --adjudicate <裁定.json>` 写入。
  > 脚本会自行校验：缺 `true_p0`/`true_p1`、命中**硬 P0 红线**、或裁定值 ≠ 机械值而四件套不足三项 → **拒绝并 exit 30**（报告保持机械值）；
  > 通过后写 `exit`=裁定值 + 保留 `script_exit_raw` + `verdict_stale:false` + `_t8_adjudicated_at/_by`，且**进程退出码 = 裁定值**。
  > **判据**：`exit 30` 是「裁定无效」而非「稿件不合格」——**不得**读成内容失败去触发 T5 修订轮。
  > ⑤ **裁定书齐备**（v18.79.0 · 反哺-v18.78.2 §七 T0-8）：`audits/t8-conclusion.json` **必须在盘**——它是裁定的**书面依据**，含 `true_p0 / true_p1 / verdict / note / llm_review` 五要素（`note` 载正文 sha256；`llm_review` 须含**证伪四件套**）。**坑位 = T8（主控亲执行）**，其余角色只读；普通 `--report` 复跑会**保留**既有裁定段（不清除），要改只有 `--adjudicate` 一条路。
  > ⑥ **别用「报告文件哈希」做下游互锁**（v18.79.0 · 反哺-v18.78.2 §七 T0-9①）：`final/M-Gate-Report.json` 每次**非裁定复跑**都会变（顶层 `generatedAt` 每跑必更新），**判定本身不变**。凡需要「这份报告是不是那一份」的互锁，请用**内容级指纹** `verdict_scope.draft_sha256`（＋ `exit` ＋ `_t8_concluded_at`），**不要**用文件 sha256。

- **AI 使用声明填实**：按 `templates/AI-使用声明-template.md` 三版本（学术/出版/公众）取对应版本填实
- 产出 `final/定稿.md` + `final/图件/图N_标题.svg`（数据卡数字逐一核对）+ `final/交付说明.md`

- 判定：**exit 0 + 15 项全过 → 交付主人终审**；任一失败 → 记录并告知主人

## 铁律
1. **只做终检不改论点**：T8 不新增/删除论点、不改引用，只做格式/字数/交付层修复——论点问题打回 T5 修订（≤2 轮）
2. **⚠️ 亲修必须回写「正文真源」**：T8 若对正文做了亲修（编号形态 / 文末节齐备性等），**必须同时把同样的改动施加到 `drafts/初稿-vN.md`**，使 `final/定稿.md` 与 `drafts/` **在亲修后重新同源**。
   > **判据**：**「亲修」不是只改交付件——它改变了正文，就必须同时改变正文的唯一真源。** 落盘后**当场问一句**：**「正文的真源在哪？我改的是不是它？」**
   > **替代方案**：若因故不回写 `drafts/`，则**后续所有以正文为基的轮次（B 轨 / 再修订）派发对象一律改用 `final/定稿.md`**，并在 `修订说明` 中显式写明基稿来源。
   > **⚠️ 不在中间态收数**：换稿重裁时**两份都要先更新完再跑 M 门**（`audits/闸门记录-T7.5.md` 的指纹互锁值 **+** `final/M-Gate-Report.json`）——只更新其一会让那一次运行落在**中间态**，M-Exist-5 的「闸门 ↔ 报告」互锁短暂判 P0，而**该瞬时值会被"如实"写进交付报告**。**判据**：**交付件的机械面必须是稳定态**。报告里 `transient: true` 即表示该次机械值**不构成权威**（`write_run` 记第几次写入）→ **再跑一次**取稳定态，再把值写进 `交付说明.md` / `闸门记录`。**两次读数并存时，交付件只引用稳定态那一次。**
3. **交付边界**：`final/定稿.md` 只含论文内容（摘要/正文/图表占位/参考文献/AI 声明）；所有操作员报告（审计/修订说明/证据包清单）进 `final/交付说明.md` 或 `final/证据包/`
4. **审计视图优先**：`audits/审计视图-v0.md` 是 T4/T5/T6/T7/T9/T8 共用的轻量摘要（**先读这个**，按需跳转全文/素材卡，不强制重读 86K 全文）。**视图头必须按源判断可信度**（生成时自动写入）：
   - 源 = **定稿**（Phase 5）→ 终态视图，其字数/引用闭环可直接引用；
   - 源 = **草稿**（Phase 3-4.5）→ **草稿快照**，字数/闭环只代表该轮次，定稿后必须重新生成；
   - **无正文源**（Phase 1-2）→ 仅素材与报告状态视图（供 T4 分析/Phase 2.5 前闸门用）。
   生成方式：`node scripts/build-evidence-bundle.mjs <项目> --summary`——源按 `--source <路径>` ＞ `final/定稿.md` ＞ `drafts/` 最高版本正文 三级解析，**任何阶段都能生成**。节省机制是**按需跳转而非全文通读**，不给未实测的百分比。
5. **证据包自动生成**：不手工复制文件——`scripts/build-evidence-bundle.mjs` 一次性完成，避免漏拷
6. **一键终检脚本 final-check.mjs**：Phase 5 终检时**直接跑 `node scripts/final-check.mjs <run/项目名>`**，自动串联（**顺序不可交换**）：
   - ① `count-chars.mjs <定稿.md> --full`（字数权威值）
   - ② `build-evidence-bundle.mjs <项目> --summary`（**先刷新证据包** + 审计视图）
   - ③ `m-gate-check.mjs <定稿.md> <证据包>`（**M 门机械 24 项**——M-Form 1-11 + M-Exist 1-11 + M-Integrity-1 + M-Fact-1，含 M-Form-9 图件闭环 + M-Form-10/11 与 M-Exist-5/6/7；**M 门总 25 项 = 机械 24 + 人工 1（M-Integrity-2 主控门）**）
   > ⚠️ **证据包刷新必须排在 M 门之前**：现行真源 = `scripts/final-check.mjs:7-15` 的「顺序不可交换」注释。

   一次跑出终检所需 3 项输出，省主控 T8 三次手动调用 + 三次上下文切换。**m-gate-check 失败（非零退出）即中止终检**，标「M 门未过」打回 T5/T7；`--no-summary` 选项跳过第 ② 步（已生成过审计视图时复用，避免重复）。
7. **M 门 exit 0 是硬门**：任何一项不过都不得标记「终检完成」，必须修复或如实报告主人
8. **不编造**：终检发现缺数据/缺引用 → 标 `[待补]` 打回 T5/T7，不自行补
9. **裁定 JSON = 主控 LLM 亲写（v18.77.0 P-2）**：跑 `m-gate-check --adjudicate` 前的 `<裁定.json>`（即 `--adjudicate <裁定.json>` 的输入）**由主控 LLM 在执行时手工准备**，凭证伪四件套（`_t8_llm_review` + `_t8_conclusion` + `true_p0`/`true_p1`）由主控在裁定过程中推理产出；该 JSON **不是任何子代理产物**，不是 T7 复核产物，不是 G14 检测器产物。判据：本卡第 8 行已写「T8 不 spawn 子代理」——子代理 spawn 出来的"裁定 JSON"在本卡禁止出现。
10. **触发条件（v18.77.0 P-8）**：T8 启动时**正文已是 Phase 4.6 G14 终闸冻结的版本**（N = 与 T9 评审同号）；若 T9 启用（T9 评审通过版本），正文应是 T9 评审通过版本，与 G14 冻结版本一致。**版本不一致 → 报告主人，不要擅自合并**。`final/` 落盘在 T8 内，但**正文真源**自 Phase 4.6 冻结那一刻起就归 `final/定稿.md` 持有（与 `drafts/初稿-vN.md` 在亲修后重新同源——见铁律 #2）。

- **📉 交付前跑负知识账本校验（v18.64.0，非闸门）**：`node scripts/disproofs-check.mjs <项目>` —— `0` 合法（把**条数与逐条结论摘录进 `final/交付说明.md` 的既有字段**：§3 遗留风险 或 §4 人工核验项，**不新增字段**——M-Exist-7 锁定 12 项）；`3` 账本不存在 → 须在交付说明 / 交接报告**显式声明**「本项目无已证伪项」（**不得沉默跳过**）；`1` 形状不合 → 退回 T6/T7 补记。契约 = [`../_shared/负知识账本.md`](../_shared/负知识账本.md)。

### 终检顺序契约——**步骤不可交换**（v18.62.7 反哺 §A8/A11 起含 ②′ / ⑤a / ⑤b / ⑦′）

> **判据**：**正文冻结必须早于指纹与裁定**；顺序颠倒 = 重做。
>
> | 步 | 动作 | 不可交换的理由 |
> |----|------|--------------|
> | ① | 复制 `drafts/` 最高版 → `final/定稿.md` | 定稿是后续一切指纹的基准 |
> | ② | **完成全部正文层修改**（AI 声明填实 / 占位符清理 / 术语清理 / 亲修项） | 任何后续正文改动 → ③ 的指纹失效、④⑤⑥ 全部重做 |
> | **②′** | **跑 `node scripts/fix-gates.mjs <项目>`（零写盘）**，按它的输出把机械缺陷一次修完 | 它是**修法生成器**（M-Form-10 索引锚点 / M-Form-11 `## 已加载` / M-Form-4 文末禁词 / **M-Exist-7 字段含 `<…>`**），**必须在冻结之前跑**——冻结后再修就又回到 ②。**它不判通过**，闸门结论仍以 M 门为准 |
> | ③ | **冻结定稿 → 记录 sha256**（`Get-FileHash -Algorithm SHA256`） | 该值将被 ④⑤⑥⑦ 引用 |
> | ④ | 刷新证据包（`build-evidence-bundle.mjs <项目>`） | manifest 的 `auditTargetSha256` 绑定 ③ 的正文 |
> | **⑤a** | 刷新**正文指纹**：`node scripts/refresh-gates.mjs <项目>` → 一次刷 `audits/闸门记录-T2.5.md` / `-T7.5.md` / `final/交付说明.md`（§1 / §9）**三个交付件** | M-Exist-5 的「闸门 ↔ 报告」指纹互锁要求它们与 ③ 同源。**手写易漏**（实测主控手工同步 4 处/轮）——**有脚本就别手写**；`--dry-run` 可先看差分。⚠️ 它报 `warn`（检测到标签但解析不出指纹）= 实据列写法与模式不兼容，**不是「已同步」**，须人工核 |
> | ⑤b | 写 `audits/闸门记录-T7.5.md`（**在 ⑥⑦ 之后写**，见下方「T7.5 的落盘时点」） | 它的「M 门全部 exit 0」行要引报告的裁定值，而报告由 ⑦ 产生 → **写早了必然引不到** |
> | ⑥ | 跑 M 门（`m-gate-check.mjs`）取**机械值** | 机械值须在指纹就位后取，否则是中间态 |
> | ⑦ | 写 T8 裁定 → `--adjudicate` **一次性**写入 | 裁定值 ≠ 机械值时需证伪四件套 ≥3 项；写入后 `verdict_stale` 方为 false |
> | **⑦′** | 落 `final-check-v0.json` 至稳定态（进程退出码与 `exit` 字段都已取稳定态） | 见下方「两个 exit 数」 |
> | ⑧ | 同步 `final-check-v0.json` 至稳定态 | 交付件机械面须只引用**稳定态**那一次读数 |
> | ⑨ | **不再触碰正文**——任何后续正文修改 = 回到 ② | 否则 ⑦ 的裁定作废（`verdict_stale` 单调保留） |
>
> **伴随判据**：报告里 `transient: true` 表示该次机械值**不构成权威** → **再跑一次**取稳定态，再把值写进 `交付说明.md` / `闸门记录`。**两次读数并存时，交付件只引用稳定态那一次。**
> **若已 stale**：`--adjudicate` 会提示「须重新裁定」——此时**先确认正文已冻结**（否则将再次 stale），再按 ⑥⑦ 重走。

#### ⚠️ T7.5 的落盘时点与「两个 exit 数」（v18.62.7 反哺-主控实测 §A11）

**循环依赖（如实描述）**：`M-Exist-5` 对 T7.5 记录的「M 门全部 exit 0」行做**行级绑定**——该 ✓ 行的实据既要给出 exit 数，又要与 `final/M-Gate-Report.json` 的 `script_exit_raw` **或** `effectiveExit` 相符，**且**要求该报告**存在**。而报告的裁定段是 ⑦ 的产物，`闸门记录-T7.5.md` 按上表 ⑤ 的位置本该写在它**之前** → **先写记录就引不到裁定值，先写报告又缺记录**。

**唯一走通的顺序（照抄即可，实测已走通）**：

1. ⑤a 刷指纹（`refresh-gates.mjs`）→ ⑥ 跑 M 门取机械值；
2. **⑦ 先落带裁定的报告**：`node scripts/m-gate-check.mjs final/定稿.md final/证据包 --report final/M-Gate-Report.json --adjudicate audits/t8-conclusion.json`
   —— 此刻报告里仍会包含「T7.5 记录缺失」那一项（**无妨**，它不是硬 P0 红线）；
3. **⑦′ 再写 `audits/闸门记录-T7.5.md`**，其「M 门全部 exit 0」行的**实据同时给两个数**：
   `M 门 exit 1（script_exit_raw）／ exit 0（T8 有效裁定）`；
4. ⑧ 复核 `final-check.mjs` 的读数（`exit` = 稳定态，`script_exit_raw` = 机械值）。
