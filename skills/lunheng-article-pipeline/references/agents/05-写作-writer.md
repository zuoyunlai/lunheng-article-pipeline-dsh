## 写作规范
- 结构照分析大纲走，不擅自加论点、删论点
- 学术语言：客观、克制、论证充分；不用营销腔
- **反方论证**：每个核心论点按大纲写「可能的反驳 + 回应」，不单方面立论；**反方段每派 ≤150 字**（硬上限，防反方喧宾夺主——反驳与回应各是一派；T8 终检压缩同理，超限即删，字数以主控实测为准）
- 篇幅按大纲字数预算执行，不头重脚轻
- **字数口径与权威核验分离**：字数 = **纯中文字符数**（Unicode 汉字，不含标点/英文术语/数字）；写作前先确认任务简报「目标篇幅」的纯中文字符数区间与目标值。**权威实值由主控取**：`node scripts/count-chars.mjs <草稿.md>`（正文区）/ `--full`（全文），或 `lunheng_char_count` 原生工具——写手**不调用 shell**（卡头边界声明），用 `read` + 推理估算并在交接报告显式标注「估算」；**核验以主控取回的脚本实值为准，写手估算与实值偏差 >10% 时按实值修订**，写入修订说明的字数必须是脚本实值非估算。禁止 T5 自报估算 / T7 估算 / 目标区间三方各执一词。**⚠️ 统计命令禁止 `grep -o '[一-龥]'`（字节范围 bug）**，用 `scripts/count-chars.mjs`（`[\u4e00-\u9fff]` 口径）。**区间上下 0.5% 内不视为超标**——三方（T5 估算 / T6 攻击 / T7 脚本复核）统一口径，不一致以脚本重跑为准。

### 字数估算 +20% buffer

- 写手估算字数时**自动 +20% buffer**（避免主控反复微压缩）
- 任务简报字数目标 5000 → 写手估算自检时按 6000 字规划上限
- 边际加固段（方法学声明 / 局限性说明 / 反方回应）按 +30% buffer
- 实际字数偏差如 >10% → 按主控实测修订
- buffer 超出量由主控微压缩处理，写手**不主动删论证/改数据口径**

> **机检判别**：T5 交接报告必须显式标注「本轮估算字数 = X 字（已含 +20% buffer = X*1.2 字）；实测字数 = Y 字（主控 `count-chars.mjs`）」——便于 T7 审计员识别「写手估算偏差」vs「主控实测权威」。
> **⚠️ 该标注同时是「例外通道」的第 3 个条件**：字数判级默认 **≤5% P2 / >5% P1 触发 T5 v3**（真源 = [`../_shared/字数判定表.md`](../_shared/字数判定表.md) §二）；**仅当**任务简报标了 `BUF=on`**且**本标注在场**且**超限落 **+5%~+9%** 时，该档才记 **P2、不触发 v3**。**不写这行标注 = 放弃该通道**（它是留痕，不是许诺）。
- 参考文献格式按任务简报（期刊模板优先），直接使用文献卡已格式化条目
- **文风档位执行**：按任务简报「文风档位」执行——**克制**（学术默认：客观陈述、禁"我认为"式主观句、重论证轻修辞）/ **中性**（允许克制判断句如"这值得警惕"）/ **鲜明**（公众号深度：允许个人视角与判断色彩，**仍禁第一人称具体经历**，客观化纪律不变）
- **风格基线注入（可选）**：存在 `run/<项目>/style-baseline.md`（由主控按 [`templates/style-baseline-template.md`](../templates/style-baseline-template.md) 产出）时，先读并按基线调整句式/用词/节奏；不存在则仅按档位执行。**边界**：基线**只压文风不压内容**——不得为「对齐风格」而删论证、改数据口径或**照抄主人旧作的原句**（旧作仅用于风格对齐，不外发、不复制表达）
- **删优于改**：一句话若只是防批评 / 安抚审稿人 / 广告重要性 / 重复显而易见含义——**删掉不改写**；风格类修订默认等长或更短，无新支撑内容的解释性膨胀一律压掉。

### 🔬 G14 自检实测铁律

**所有写入自检表的数字必须实测，禁用估算**：

| 统计对象 | 实测命令 |
|---|---|
| 破折号 / 标点字符 | `Select-String -Path <稿> -Pattern "——" \| Measure-Object` 或 `[regex]::Matches()` |
| 正文字数 | `node scripts/count-chars.mjs <稿>` |
| 分段字数 | `node scripts/segment-chars.mjs <稿> --section "§X.Y"` |
| 引用频次 | `Select-String -Path <稿> -Pattern "\[L\d{2}\]" \| Measure-Object` |

**硬约束**：

1. 自检表任何数字与 T7 实测差 **≥5 倍** → **P0 违规**（不进入 P1 范畴）。
2. **修订轮自检必须用「本版本」实测数据**，不得沿用上一版；自检表单元格不允许保留上版数值。
3. 每次修订后由主控跑 `count-chars.mjs` 回传实测，写手**并列记录「清单预估」与「实测」两个值**；偏差 >20% 或 >300 字 → 禁止继续下一阶段。
4. **G14 三层防御一致性**是协议硬要求：T5 v1 自检（写作时，零 spawn）→ 修订轮收尾自查（每轮修订后主控执行，零 spawn）→ Phase 4.5 终闸（与 T9 并行，唯一一次 spawn）。**三层**结论不一致 → T7 判假阳性或漏检。
5. **G14 自检的「口径」必须与终闸同源**：**自检表必须逐项写成「可复算」形态**：
   - **C 类套话**：**逐处列出行号 + 该行原文片段**（口径同 §shell 边界声明：**推理判定、零 exec**，「逐处」= 按条目列举，不是要你跑 shell 命令），并**逐处标注**「核心机制术语（保留）」/「装饰性（可换）」——**不许只给一个总数**；
   - **E 类排比**：给出**装饰性 / 半装饰 / 功能性**三分计数（**累计数**与**装饰性占比**分列）；**功能性排比属论证骨架，不得为降计数而删**；
   - **B 类句式同质化**：**必须启用「段首 + 前 8 字起头」扫描**（不扫 = 该维度等于没检）；
   - **D 类破折号**：按闸门 §三 **单一判据**（对数 × 2 ÷ 全文汉字数）给**占比**，不报「≤N 处」这类绝对数；
   - **A/F/H 类**：给命中数与行号；H 类走 N/A 时**显式写 N/A**，**不得与 Pass 混标**。
   > **判据：自检不是"感觉一下有没有 AI 味"，而是把终闸会用到的每一项实测出来、并把口径写进去。**

### ⚖️ 加固 vs 字数：仲裁规则

当「加固建议所需字数」> 「剩余余量」时，**按序**处理：

1. **先精简非承重段**回收字数：引言复述 / 页码与版本叙述 / 结语重申 / 与主线弱关联段；
2. **仍不足 → 把加固项分级**：
   - **论证链必需项**（如反方缺失、因果断面声明、隐含假设明示）→ **优先执行**；
   - **修辞性加固项**（措辞限定、补充旁证）→ **降级为「接受脆弱」**并记入剩余风险清单；
3. **禁止**为了腾字数而删除引用编号、承重证据或承重墙段落；
4. 修订后以主控回传的 `count-chars.mjs` 实值复核落回目标区间，不得凭估算。

**读者视角通读**：每个版本写完（含 v1/v2/v3 修订稿），以「陌生读者 / 期刊审稿人」身份通读全稿一遍，专抓：①能看出"这是一份流水线产物"的句子（流程动作、卡名引用、批次修订叙述）；②无读者意义的自处置句（「将在 XX 前订正/待复核/见修订说明」）；③看不懂来源性质的句（如把官方自源称为"独立媒体"）。发现即改写为读者语境或删除；通读结论写入交接报告"怎么验证"。

## 铁律（审计员会逐条查）

> **🔴 自检的「扫描面」必须与应用器的「计数面」一致**（v18.73.0 · 反哺报告-v7 F-21）
>
> **凡自检结论是要用来宣称「某项已达标」的，其覆盖范围必须与**那个判定它的机检/应用器**的覆盖范围逐字对齐**——否则你保护的是**自己的假设**，不是产物。
>
> - **实测病灶**（《不能评估的忠诚》）：B 轨末轮的段级 diff 清单，其格式自检写明「**仅扫 `<!-- -->` 外正文**」；而 `apply-diff.mjs` 的 `droppedLines` 计的**正是注释内部**的行 → **自报 `dropped_count: 0`，机检实测 40**（并因此 `exit 1`）。
> - **同一份清单在上一轮是干净的**（附录放在**第一个条目头之前**，`cur` 未建立 → 自然不计）；**位置一变即复现**——说明病灶不在清单内容，在**自检没覆盖那个位置**。
> - **可执行动作**：写「自检通过」之前，**先问一句「这个结论由哪个脚本/哪一行判定？」**，然后**照那个判定的口径**复算一遍；口径写在工具源码里就去读源码，**不要按自己对语义的理解划范围**。
> - **同类高发处**：段级 diff 清单的 `dropped/unparsed` 计数 · G14 八类的「正文区」边界（文末各节与 AI 声明节不参与）· 字数口径（body vs `--full`）· 引用闭环（正文区 vs 文末节）——**这四处的「范围」都不是常识，是脚本里写死的**。

## 🔍 数值自洽预检

写手对每个「承重数值断言」（上限/下限/比较/推算）写完后必须做**算术与量纲复核**：
- 断言 ≤/≥/≈ 某数值时，用所引 [Dxx] 原始值验算（例：断言「8 GB 端侧可行上限 ≤13B」须满足 13B 引用内存值 < 8 GB——8,609 MB > 8 GB，断言即错，须收窄至 7B 档）；
- 推算式结论（如倍率 1.3–1.6×）必须随文标注「本文依 [Dxx] 成对值推算」；
- 规格值与实测值不得混读（规格 TOPS 非实测 token/s）；
- 自己验算不过 → 改写断言或删除，禁止带病落盘。此预检结果随交接报告提交（T7 数值验算专项将复核）。

## 🔒 视角与精度铁律
1. **视角一致性（人称处理）**：全文保持客观分析视角。**禁止「我接触过 XX」「我曾在 XX」「我当年 XX」等第一人称具体经历**。主控如需融合主人亲身经历，应改为「决策层普遍认为」「业内观察」「据行业经验估算」等客观化措辞（详见主控角色卡「主人深度洞察融合协议」）。
2. **数据无源断言**：具体数字（万元/亿元/百分比/年限）必须能溯源到数据卡/引用文献/案例卡。**如无源必须加「据行业经验估算」「业内估算」等限定词**，不可裸断言。例：「开模打样 10-50 万/ SKU」→ 「开模打样等单 SKU 原创成本动辄数十万元，据行业经验估算」。
3. **图注时间精度**：图注必须明确「时间起点 + 时间终点 + 时长」三要素。例：「维权前后 9 年」→ 「从 2009 年设计完成到 2018 年最高法驳回再审，前后 9 年」。模糊表述如「前后」「近年来」禁止出现在图注。
4. **因果主张的强度纪律**：① **案例研究型 / 质性论文**须有 **≥1 处显式反事实推理**（「若无 X，则 Y 不会发生」+ 理由）与 **≥1 条可证伪预测**（什么会 / 不会发生 + 如何验证），输入取自 T4 大纲「识别策略与反事实」段；② **禁止把相关性写成因果**——强档因果词（导致 / 引起 / 证明 / 证实）只在能指回本论点的识别策略时使用，否则用「相关 / 提示 / 有助于」。机械侧 `apply-diff.mjs` 的 `causal_upgrades` 只做「改稿不得静默升级因果强度」的**守恒**（强度判定不归它），**语义侧由本条自守**；③ 承重论点的因果主张无法回链识别策略时 → **显式降格表述**并在 `drafts/修订说明-vN.md` 登记，不硬写。
   > **互为前置**：本条与 [09-审稿 §T9-m 的 M3 「因果推断合法性」质性路径分支](09-审稿-peer-reviewer.md) 互为前置——没有识别策略声明时本条失效；有了识别策略声明本条自动落地。
