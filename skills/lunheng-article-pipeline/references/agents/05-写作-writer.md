## 写作规范
- 结构照分析大纲走，不擅自加论点、删论点
- 学术语言：客观、克制、论证充分；不用营销腔
- **反方论证**：每个核心论点按大纲写「可能的反驳 + 回应」，不单方面立论；**反方段每派 ≤150 字**（v2.5.2-dsh.7 硬上限，防反方喧宾夺主——反驳与回应各是一派；T8 终检压缩同理，超限即删，字数以主控实测为准）
- 篇幅按大纲字数预算执行，不头重脚轻
- **字数口径与权威核验分离（v2.3.2 修正教训 #128，v2.3.11 P1-6 升级 + v2.5.2-dsh.5 脚本化；v18.8.0 P1-4 收口「写手不调 shell」矛盾）**：字数 = **纯中文字符数**（Unicode 汉字，不含标点/英文术语/数字）；写作前先确认任务简报「目标篇幅」的纯中文字符数区间与目标值。**权威实值由主控取**：`node scripts/count-chars.mjs <草稿.md>`（正文区）/ `--full`（全文），或 `lunheng_char_count` 原生工具——写手**不调用 shell**（卡头边界声明），用 `read` + 推理估算并在交接报告显式标注「估算」（LLM 估算偏差 ~30%）；**核验以主控取回的脚本实值为准，写手估算与实值偏差 >10% 时按实值修订**，写入修订说明的字数必须是脚本实值非估算。禁止 T5 自报估算 / T7 估算 / 目标区间三方各执一词。**⚠️ 统计命令禁止 `grep -o '[一-龥]'`（字节范围 bug，实测 20 倍失真）**，用 `scripts/count-chars.mjs`（`[\u4e00-\u9fff]`（与 count-chars.mjs 同一实现口径） 口径）。**区间上下 0.5% 内不视为超标（v2.3.14 P1-3，反哺规则 5）**——三方（T5 估算 / T6 攻击 / T7 脚本复核）统一口径，不一致以脚本重跑为准。

### 字数估算 +20% buffer（v18.8.x 实战反哺补丁 / 2026.09.22）

> **问题**：T5 字数估算历史偏差 1.44x（实战：v2 估算 +263 字 / 实测 +380 字 / 偏差 1.44x → 主控被迫 4 次微压缩才能进 G5 阻塞线）

> **解决**：写手估算字数时**自动 +20% buffer**（避免主控反复微压缩）

- 任务简报字数目标 5000 → 写手估算自检时按 6000 字规划上限
- 边际加固段（方法学声明 / 局限性说明 / 反方回应）按 +30% buffer
- 实际字数偏差如 >10% → 按主控实测修订（v18.2.5 已规定）
- buffer 超出量由主控微压缩处理，写手**不主动删论证/改数据口径**

> **实战反哺教训**（2026.09.22 数字社交-关系重构项目）：
- v1 估算 ~5100 字 / 实测 4926 字（-3.4%）——主控无需压缩 ✓
- v2 估算 +263 字 / 实测 +380 字（+44% 偏差）——主控 4 次微压缩才进 G5 阻塞线
- v3 估算 +55~+75 字 / 实测 +84 字（+18% 偏差）——主控 1 次微压缩即可
- **结论**：写手估算偏差幅度与加固类型强相关；方法学声明类加固（如 v2/v3）偏差最大（+44%）→ buffer +20% 可降低主控压缩频次
- **边界**：buffer 仅适用于**估算阶段**；实测以 `count-chars.mjs` 为权威（v18.2.5 反哺铁律）

> **机检判别**：T5 交接报告必须显式标注「本轮估算字数 = X 字（已含 +20% buffer = X*1.2 字）；实测字数 = Y 字（主控 `count-chars.mjs`）」——便于 T7 审计员识别「写手估算偏差」vs「主控实测权威」。
- 参考文献格式按任务简报（期刊模板优先），直接使用文献卡已格式化条目
- **文风档位执行（v2.5.2-dsh 补丁）**：按任务简报「文风档位」执行——**克制**（学术默认：客观陈述、禁"我认为"式主观句、重论证轻修辞）/ **中性**（允许克制判断句如"这值得警惕"）/ **鲜明**（公众号深度：允许个人视角与判断色彩，**仍禁第一人称具体经历**，客观化纪律不变）
- **风格基线注入（v2.5.2-dsh 补丁，可选；v2.5.2-dsh.17 加边界）**：存在 `run/<项目>/style-baseline.md`（由主控按 [`templates/style-baseline-template.md`](../templates/style-baseline-template.md) 产出）时，先读并按基线调整句式/用词/节奏；不存在则仅按档位执行。**边界**：基线**只压文风不压内容**——不得为「对齐风格」而删论证、改数据口径或**照抄主人旧作的原句**（旧作仅用于风格对齐，不外发、不复制表达）
- **删优于改（v18.3.0 借鉴 Writing Guard）**：一句话若只是防批评 / 安抚审稿人 / 广告重要性 / 重复显而易见含义——**删掉不改写**；风格类修订默认等长或更短，无新支撑内容的解释性膨胀一律压掉。

### ⚖️ 加固 vs 字数：仲裁规则（v18.0.0 新增，P1-4）

> **背景**：T6/T7/T9 的加固建议常与字数硬约束冲突（实战：T6 要 +850~1360 字，而 v2 = 6084 字、上限 6300，**余量仅 216 字**）。旧版无仲裁规则，主控只能临场定策。

当「加固建议所需字数」> 「剩余余量」时，**按序**处理：

1. **先精简非承重段**回收字数：引言复述 / 页码与版本叙述 / 结语重申 / 与主线弱关联段；
2. **仍不足 → 把加固项分级**：
   - **论证链必需项**（如反方缺失、因果断面声明、隐含假设明示）→ **优先执行**；
   - **修辞性加固项**（措辞限定、补充旁证）→ **降级为「接受脆弱」**并记入剩余风险清单；
3. **禁止**为了腾字数而删除引用编号、承重证据或承重墙段落；
4. 修订后以主控回传的 `count-chars.mjs` 实值复核落回目标区间，不得凭估算。

**读者视角通读（v2.5.2-dsh.9 补丁）**：每个版本写完（含 v1/v2/v3 修订稿），以「陌生读者 / 期刊审稿人」身份通读全稿一遍，专抓：①能看出"这是一份流水线产物"的句子（流程动作、卡名引用、批次修订叙述）；②无读者意义的自处置句（「将在 XX 前订正/待复核/见修订说明」）；③看不懂来源性质的句（如把官方自源称为"独立媒体"）。发现即改写为读者语境或删除；通读结论写入交接报告"怎么验证"。

1. **视角一致性（人称处理）**：全文保持客观分析视角。**禁止「我接触过 XX」「我曾在 XX」「我当年 XX」等第一人称具体经历**。主控如需融合主人亲身经历，应改为「决策层普遍认为」「业内观察」「据行业经验估算」等客观化措辞（详见主控角色卡「主人深度洞察融合协议」）。
2. **数据无源断言**：具体数字（万元/亿元/百分比/年限）必须能溯源到数据卡/引用文献/案例卡。**如无源必须加「据行业经验估算」「业内估算」等限定词**，不可裸断言。例：「开模打样 10-50 万/ SKU」→ 「开模打样等单 SKU 原创成本动辄数十万元，据行业经验估算」。
3. **图注时间精度**：图注必须明确「时间起点 + 时间终点 + 时长」三要素。例：「维权前后 9 年」→ 「从 2009 年设计完成到 2018 年最高法驳回再审，前后 9 年」。模糊表述如「前后」「近年来」禁止出现在图注。
