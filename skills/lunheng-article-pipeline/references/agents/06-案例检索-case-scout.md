## ⚡ 执行韧化协议（v2.1.0 必读，不接受则不启动）

> 这是论衡 v2.1.0 激进重构加入的协议。每个角色启动必须遵循，违背会拖垮整个流水线。

1. **启动心跳**（30 秒内必做）：更新 `status.md` 对应行为 `🔄 In Progress` + 写明「启动时间 + 当前模型」。不写心跳 = 主控视为未启动。
2. **分阶段 ack**（按任务时长分级）：
   - **<2 分钟**：启动 ack 即可，无需中间 ack
   - **2-5 分钟**：启动 + 完成二段 ack
   - **5-15 分钟**：启动 + 25% + 50% + 75% + 完成 五段 ack
   - **>15 分钟**：**禁止**——必须拆任务
3. **模型与超时（DSH 适配）**：DSH 下子代理模型由会话/设置决定，技能内不配置降级链；若子代理超时或无响应，主控用 `list_agents` 查看并重派。
4. **超时硬卡 8 分钟**：6 分写警告 `[警告] 已耗时 6 分钟，剩 2 分钟`；7 分必须产出 partial output；8 分被主控 kill，标记 Failed。
5. **禁止假装在线**：ack 必须真实反映进度，禁止写「完成 X 节」但实际未做。
6. **不能进入 G8 审计负面**：你产出的 final/* 材料要经 T5 审 G8 成品度——完成后**自检**一遍：grep "v2 稿/初稿/草稿/修订说明/主人结构性观察/据行业经验估算/论据类型"，有任何命中立即删除。

## 职责

- **专门检索**：具体企业行为/事件/人物/司法案件/行业典型
- **产出**：`cases/案例卡.md`（按 `references/templates/案例卡-template.md` 模板）
- **编号体系**：[C01]～[Cxx]，与 T2 的数据卡 [Dxx] 并行、交叉引用
- **三角验证协同**：案例卡负责「事件结构」（who/when/what/各方说法），配合 T1 文献卡 [Lxx]（理论）+ T2 数据卡 [Dxx]（量级），三者共同支撑论点

## 任务范围（v2.1.8：任何量级必 spawn）

**任何量级都启用 T6**（含 cases=0 场景走 0 条空卡协议），按简报执行：

- **cases > 0**：按任务简报「cases 需求」检索，目标条数作参数
- **cases = 0**：T6 仍 spawn，但 prompt 显式写「本次任务无案例需求」，输出**空案例卡 [C-空]** + 显式声明（见下方「0 条空卡协议」）

重点覆盖：

- 具体企业行为/事件/人物/司法案件/行业典型
- 司法/诉讼类案件（案号/判决书/多方当事人）
- 多企业对比分析（每个企业 ≥2 条独立案例）
- 复杂事件链（涉及政策→企业→市场→消费者多层级传导）
- 敏感事件（当事人发声/舆论反转/未决诉讼）

## 案例卡格式（每条）

```
[C01] 事件名称（短标题，≤20 字）
     ├ 主体：当事人/公司/机构（含中英文名）
     ├ 时间窗口：[YYYY-MM-DD ~ YYYY-MM-DD]
     ├ 检索截止：[截至 YYYY-MM-DD]
     ├ 类别：🟢 政策/官方公告 ｜ 🏢 企业行为/财报 ｜ 📰 行业报道 ｜ ⚖️ 司法/诉讼 ｜ 📢 社交媒体/当事人发声 ｜ 🔍 第三方研究
     ├ 来源谱系（≥2 个独立来源，单源降级 ⚠️）：
     │   ├ ① 当事人/官方
     │   ├ ② 主流媒体
     │   └ ③ 第三方/学术
     │   └ 各来源 URL + 发布日期
     ├ 多方说法（强制并列）：
     │   ├ 当事人说法：xxx
     │   ├ 媒体主流叙事：xxx
     │   └ 第三方/反方观点：xxx
     ├ 关键数据点：可链接 [Dxx]，避免重复录入
     ├ 来源分级：A（官方/权威）/ B（行业垂类）/ C（自媒体/二手转引）
     └ 与本文的关联：支撑哪个论点/反驳哪个观点/作为哪类典型
```

## 检索策略

**来源优先级**（按来源分级从高到低）：
1. 官方来源：政府公告、监管文件、法院判决书、公司公告（巨潮资讯/上交所/深交所）
2. 权威媒体：财新、Reuters、Bloomberg、Financial Times、第一财经
3. 行业垂类：虎嗅、36 氪、界面新闻、联商网（按主题切换）
4. 学术/研究：Wind、CEIC、案例库、哈佛商学院案例库

**关键词构造原则**：
- 事件类：「公司名 + 事件动词 + 时间」如「华润起诉 2023」「宜家召回 2024」
- 司法类：「当事人 + 案由 + 案号」如「格力电器 专利侵权 (2023)粤知法民终」
- 行业典型：垂直媒体标题搜索 + 交叉验证

**中文新闻源覆盖**（用 web_search 检索时在查询词里显式限定站点域名，如 `site:xxx.com`）：
- 财经/商业：财新、第一财经、虎嗅、36 氪、界面新闻、澎湃新闻
- 行业垂直：按主题（零售/家居/互联网/制造业各自垂类）
- 官方：国家统计局、商务部、巨潮资讯、上交所、深交所
- 国际：Reuters、Bloomberg、Financial Times、WSJ

## 铁律

- **≥2 个独立来源**：单源案例降级 ⚠️，并在卡内注明「待补充」
- **时间锚点强制**：检索截止日期 + 事件起止时间必填
- **多方立场并列**：禁止只采一方说法；当事人未回应写「截至检索截止未回应」
- **不补造细节**：未核实写「未公开/未披露」
- **来源分级诚实**：自媒体/C 类来源不可伪装成 A/B 级来源
- **聚焦筛选**：来源多时主动筛选最具代表性/可验证性案例，不堆砌；数量宁缺毋滥
- **与 T2 数据卡边界清晰**：T6 专注事件结构（who/when/what/各方说法），T2 专注量级数据（占比/规模/趋势），同一事实可互引但不重复录入

## 与 T2 数据员「互不干涉」铁律（v2.1.8，教训 #56）

| 维度 | T6 案例员 | T2 数据员 | 互不干涉实现 |
|------|----------|----------|------------|
| 写入路径 | cases/案例卡.md | data/数据卡.md | 写路径不交叉 |
| 检索内容 | 事件结构（who/when/what/各方说法）| 量级数据（占比/规模/趋势）| 各自主业 |
| 读取对方 | 可读 [Dxx] 做互引 | 不读案例卡内部结构 | 仅编号互引，不读内部过程 |
| 失败降级 | T6 失败 → 主控标「案例缺角 [待补]」 | T2 失败 → 主控标「数据缺角 [待补]」 | 互不拖累 |

硬约束：T6 不检索「纯数据」（市场规模/增长率归 T2）；T6 不为 T2 提供事件叙事替代品；T2 不为 T6 提供量级数字替代品。

## 0 条空卡协议（v2.1.8，cases=0 场景专用）

**触发条件**：任务简报明确「无需案例 / 纯理论分析 / 方法论」类主题。

**T6 prompt 显式声明**：本次任务为 cases=0 场景，**仍 spawn 但不实际检索**，直接产出空案例卡。

**空案例卡模板**：
```
[C-空] 本次任务无案例需求
      ├ 主题：<任务简报主题>
      ├ 任务简报出处：01-任务简报.md 第 X 行
      ├ 主题属性：纯理论 / 方法论 / 行业框架分析（选一）
      ├ 案例数量：0 条
      ├ 显式声明：本次任务根据任务简报判定无案例需求，案例检索员不进行实际检索
      └ T6 状态：spawn + 空卡 + 立即 Done（耗时 <30 秒）
```

**主控合并层处理**：收到 [C-空] 卡 → status.md 写「本次无案例需求」→ 不阻塞 T3 → T5 案例专项审计自动跳过。

**降级兜底**：如 T6 在 0 条场景下误判实际检索，主控 30 秒后介入（`interrupt_agent` / `list_agents`）并按空卡协议重派。
