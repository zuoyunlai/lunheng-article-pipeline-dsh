  > **⚠️ 口径更正（v18.80.1+v · 独立审计批 5）**：本行原写「N = **被审初稿轮次**，与审计报告同号」，与本卡上方的「`-vN` 的 N = **审计轮次**」**自相矛盾**，也与脚本不符——`handoff-check.mjs` 的 `VERSION_INDEPENDENT = {反哺报告, 审计报告, 复核报告}` 明写这三族**豁免**「报告 vN == 最新正文 vN」（机检 **A4**），即它们的 N **与正文轮次无关**。**判据**：被审初稿轮次 = 「当时读的是哪一版」，审计轮次 = 「第几次审计」——**打回 ≥1 次后两者必然分叉**（实测 `run/test-v18-78-2-县中塌陷`：审计/复核报告均 `-v1`，而 `初稿` 已到 `-v5`）。写错会让复核报告号与审计报告号错开 → **A4b 判 hard 且无合法出口**（改名则多次复核重名，不改名则硬失败）。
  > **⚠️ 复核 = 只读 diff**：复核轮**只读**三样——① `drafts/修订说明-vN.md` ② 段级 diff 清单（或 `apply-diff.mjs` 的应用记录）③ 被审正文里**被改的段落**（按修订说明给出的定位）。**不重读全稿**（除非该轮改动跨节、或主控在派发话术里显式豁免——豁免须写进报告）。
  > 报告**首节必须写「已读范围」**：逐项列出本轮实际读过的载体（含被审正文的**节号**）。**没读的不算已核**——「P0-n 已关闭」必须能指回你读过的载体；指不回的一律写「✗未关闭（未复核）」，**不得**写「✓」。
  > **报告按模板产出**：`references/templates/复核报告-template.md`——**照模板填即天然满足 A8**；模板把「已读范围」放在**首节**，并带「逐条判定 / 未读 / 结论」骨架。**不要改名**（机检只认 `audits/复核报告-vN.md`；`复核记录-` / `审计复核-` 两种历史命名对本门不可见）。
  > **机检**：`handoff-check --role T7 --level strict` 的 **A8**——「**有节但空**」（只写标签）判**硬**（exit 21）；「**完全缺节**」**同样判硬**。**闭合极轻**——补一节「已读范围」即可。
- **G1 引用核验两档标注**：G1 引用核验不再一刀切，区分「**存在性核验**（标题/作者/年份 是否真实存在）」与「**数字级核验**（具体数值是否准确）」两档——存在性核验通过 ≠ 数字级核验通过。PDF/反爬源（付费墙等）无法全文核验时，用 Crossref/DOI 兜底核验存在性，并标「待人工复核」。

## M 门算法 + 必查项 + F 失败模式（v2.2.8 按需加载）

### 📐 学术结构合规段

> **本段义务**：T7 审计**必跑** `node scripts/structure-check.mjs <final/定稿.md> [--humanities] [--report <报告路径>]`，把结果纳入审计报告：
> - **S-IMRaD 缺失节**：1-2 节 → P1；≥3 节 → **P0**
> - **S-Intro-Funnel 缺要素**：1 项 → P1；2 项以上 → **P0**
> - **S-Discussion-4 缺要素**：1 项 → P2；2-3 项 → P1；4 项全缺 → **P0**

> **人文学科豁免**：使用 `--humanities` flag 改检 IMRaD-Alternate（Introduction / Discussion / Conclusion 三节），其他两个检查不变。

> **M 门契约**：本脚本的「方法节参数完整性 / 统计-数据匹配 / 结果-方法闭环」三检属于 **methodology-check.mjs 自有命名空间**（前缀 `MC-` 防撞号），**不是 M 门体系编号**——M 门体系总 25 项 = 机械 24（M-Form 1-11 + M-Exist 1-11 + M-Integrity-1 + M-Fact-1）+ 人工 1（M-Integrity-2），无 M-Form-12。S-IMRaD 缺失节检查走本脚本，**格式级**走 m-gate-check.mjs。

### 🔬 方法论可复现性段

> **本段义务**：T7 审计**必跑** `node scripts/methodology-check.mjs <final/定稿.md> [--report <报告路径>]`，把结果纳入审计报告：
> - **MC-Form-12 方法节参数完整性**：方法节至少含「样本量 / 抽样方式 / 变量定义 / 统计模型 / 超参数 / 随机种子 / 软硬件环境」中 4 项，< 2 项 → **P0**；2-3 项 → **P1**
> - **MC-Exist-11 统计-数据匹配**：方法节同时含「检验类型声明 + 效应量 + 置信区间或 p 值」三项，缺任一项 → **P1**
> - **MC-Exist-12 结果-方法闭环**：结果节是否引用方法节中的关键方法名（OLS / PSM / DID / 中介效应等），不可回链 → **P1**

> **命名空间契约**：本脚本三检对应 `methodology-check.mjs` 的**自有前缀** `MC-`（`MC-Form-12` / `MC-Exist-11` / `MC-Exist-12`），**不属于 M 门体系编号**（M 门 = M-Form 1-11 + M-Exist 1-11 + M-Integrity-1/2）；本批次以独立脚本形式落地，与 `_lib/mgate-gates/*` 的框架层注册无关。

> **⚠️ 字数预算列的估算规格（v18.73.0 · 反哺报告-v7 F-15；本列的缺失是本批最严重流程缺陷的根因）**
>
> **实测（《不能评估的忠诚》）**：任务书给 16 条 P1 的**合计**声明为 **+460 字**（≈29 字/条），而每条动议都是「补 1 段 / 补 1–2 句」，**真实写出 +622 字**（apply 实测）。当时篇幅档仅余 **15 字** → **整轮修订无法落地** → **主人在 Phase 4.5 被迫把目标从 11,000 上抬到 12,000**。**一次真实的方向调整，起因是这张表少了一列且没有估法规格。**
>
> **估法规格（三条，缺一不可）**：
> 1. **按句量估，不按「条」估**：`每条的净增 ≈ 该条要补的句数 × 20–60 字`。**禁止**给出「每条 +12 字」这类无法写出完整句子的额度——那不是预算，是占位。
> 2. **补写与压缩分列两侧**：本列写 `+N / −M（等量对冲）` 形式；**只写净增而不写明对冲来源的，视为未给预算**。
> 3. **表尾必须给合计行并做对账**：
>    ```
>    | 合计 | — | — | — | — | — | Σ增 +X ／ Σ压 −Y ／ 净增 = Z | — |
>    ```
>    且须与**主控核算的 `净增预算 = 上限 − 当前值`** 并列写出。**`Z > 预算` 时必须显式写「本轮预算不足，缺口 = Z − 预算」并给出降级建议**（哪些条走「接受脆弱」、哪些条砍掉）——**不得靠把每条额度写小来「使合计看起来可行」**。
>
> **判据**：**预算是可算的，不该让写手猜**（与 `00-主控-扩展职责.md` §B1 同源）。§B1 要求主控把**总量**写进派发话术；本列要求审计员把**逐条**写进任务书——**两者是同一账的两端，任一端缺失都会让缺口在写手那一轮才暴露**。
>
> **诚实边界**：本列的数值是**估算**，实测偏差 >20% 属正常（`pipeline-readme.md` §修订轮默认段级 diff 已规定偏差 >20% 或 >300 字时的处置）。**本规格要防的不是估算不准，而是「合计看似可行、实际不可行」**——那正是本项目踩的坑。

**编号与真源规则**：① 编号沿用 `P0-n` / `P1-n` **连续编号、同报告内唯一**；② **「关闭状态」的真源是复核报告**——任务书该列在初轮一律写「**待复核**」，**未复核不得填「已关闭」**；③ 「验收标准」必须是**可机械检查**的指标（脚本命令/计数/存在性），不写「表述更严谨」这类无法判定的描述。④ **rule/action 分离**：「违反规范」列引用**真源条目名**（`deliverables.md` / `glossary.md` / `_shared/audit-checklist-quickref.md` 的具体条目；无对应规范写「无既定规范」）；「怎么改」列的**处置动作**必须以 **补 / 删 / 改 / 降级** 动词开头、再给具体动作——**只给方向与约束，不代写句子**（不提供可粘贴的改写段落，从格式上杜绝建议被主控顺手塞进正文）。以上由 M 门 **M-Exist-4 审计条目闭环**机检（结构 + 编号唯一 + 审计↔复核编号闭环）。

**「关闭/未关闭」显式字段**：修订回环中「T5 修订说明声称『已处理』 vs T7 实测判『未关闭』」的歧义，靠本字段固化——每项 P0/P1 必须显式标「已关闭 / 未关闭」，**非 T7 自由发挥**，而是修订任务书固定模板字段。T5 声称「已处理」≠ 自动「已关闭」，T7 必须逐条对照验收标准机械判定后填写；未关闭 → 升级 P0 或进入 Acknowledged Limitations 模式。

**要求**：
1. 每个「打回」结论必须附修订任务书（表格形式），验收标准必须是可检查 / 可 sha256 验证的机械指标，而非模糊描述。

  1. **规则原文位置**（`文件:行号`，逐字引用该处文本），**不得凭印象**；
