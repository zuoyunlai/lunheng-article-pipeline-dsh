
## 主人深度洞察素材（2026-08-13 起，v2.1.4 明示化，v2.1.5 加类型分类）

主人在 Phase 3.5 提供的亲身经历/观察，可作为案例素材以 `[C-主xx]` 编号进入正文。每个洞察独占一行，注明出处 + **类型**（v2.1.5 新增，必须二选一）：

- **[C-主01 v1]**：（主人原话/观察描述） ｜ **类型**：[观点来源 / 理论贡献]（v2.5.2-dsh 补丁：洞察编号带版本号，Phase 3.5 更新 → [C-主01-v2]，改论据 → T5 融入，改框架/总命题 → T4 大纲复核）
  - **录入回执（v2.5.2-dsh.17）**：主控录入后**当场回执**「✅ 已录入 [C-主NN v<k>]（类型 X）→ 将用于 §Y」；**原话逐字落盘**（不改写、不概括）
  - **当场退回**（不留到 T5 猜）：① 无法定位到论点/论据的要求（如「写深一点」）→ 回问「具体改哪段/哪条证据」；② 涉第三方隐私或涉密 → 先问清可引用边界；③ 其实是一手数据 → 改走 [`主人投喂清单-template.md`](主人投喂清单-template.md)，不占洞察编号
- **[C-主02 v1]**：（主人原话/观察描述） ｜ **类型**：[观点来源 / 理论贡献]
- ...

**两种类型的区别**（论衡 v2.1.5 明示化）：

| 类型 | 定义 | 写手引用策略 | 示例 |
|------|------|-------------|------|
| **观点来源** | 主人亲身观察 / 业内判断 / 从业经验 | 作为「业内观察」引用，写明「据主人从业观察/业内经验」，不当作实证数据用 | 「主人『我接触过的教师很市例精明』」 |
| **理论贡献** | 主人的原创框架 / 结构性判断 / 新提法 | 作为「本文提出的框架」引用，**不是论据是论点**，写手需发展论据支撑 | 主人「五方合谋」框架 → 写手需展开五方各自实证支撑 |

**注意**：① [C-主xx] 不进入 cases/案例卡.md（独立编号空间）；② 终稿文末「案例来源」节需为每个 [C-主xx] 留 1 条「主人深度洞察」说明（含任务简报第 X 行出处 + 类型）；③ 主控融合时需按写手卡「主体声音 ≠ 第一人称经历」铁律客观化处理（详见写手卡视角与精度铁律）；④ **类型必须在 Phase 3.5 由主人明确标注**——主控不可默认推断，因为「理论贡献」+「观点来源」的边界很微妙，主人最清楚。

**洞察-数据一致性预检（v2.3.2 新增，教训 #132）**：主人洞察里若引用了具体数据（如「中国 61% 监管信任」），主控在 Phase 1 检索后必须**回查该数据是否可被检索到**——若不可检索/不可验证 → 标 🔴，T4 分析员准备替换为可检索数据（或让主人补充数据出处）。**防止主人洞察里的「引文锚」是不可验证数据 → 写手误当硬数据引用 → T6 攻击「数据无源」**。

## 执行约定（DSH 精简版，v2.5.2-dsh.13 起为唯一口径）

> **已废止**：v2.1.0 的「30 秒心跳 / 5 段 ack / session-kill」协议在 DSH 下**不再适用**（`SKILL.md` 执行能力边界、`AGENTS.md` 关键规则、`glossary.md` 三处已定案「无心跳、无 ack」）。历史见 git log。

**现行四要素**：
1. **状态机**：`status.md` 由主控独占写；子代理只读，不直接 write/edit（进度经交接报告回报）。
2. **交接报告六要素**：做了什么 / 产物在哪 / 怎么验证 / 已知问题 / 下一步 / 状态更新——缺一不可。
3. **G8 自检**：交付前对照 `references/_shared/audit-checklist-quickref.md` 自查。
4. **进度播报三播报**：派发即播报 / 完成即转播 / 卡住即告警（防主人干等）。

**卡住时的介入动作（现行）**：先用 `list_agents` 查看子代理**注册表状态**（`running` / `idle` / `ready`——注意它**不返回**「最近输出」）；产物缺失 → 按三段式处理（落盘校验 → `send_message` 续接原代理 → 才重派新子代理）；连续失败先查 DSH 环境；同场景重试 ≤2 次仍卡 → 升级主人决定。
