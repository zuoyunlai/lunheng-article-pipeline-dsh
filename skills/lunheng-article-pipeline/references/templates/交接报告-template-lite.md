# 交接报告

> **位置**: 追加写入项目根的 `run/<项目名>/agents-log.md` 的 `### Tn 执行记录` 段（**五要素** ≤5 行：**输入文件清单 / 已读编号·已落盘条数 / 已完成步骤 / 产物路径 / 下一步**——⚠️ 这**五项**与下面「回报本身」的**六要素**是**两套字段**，见下条）
> **与「回报」的关系（v2.5.2-dsh.17 定清双轨）**: 本模板的**六要素 = 交接回报本身**（回给主控的消息里给，≤10 行，**不单独落文件**）；`agents-log.md` 是**落盘的中断续接快照**。两轨各司其职，不再有「第三个交接文件」这类不确定口径。
> ⚠️ **「五要素」与「六要素」是两份不同的契约，不得并成一份（v19.5.0 · 主控核实结论）**: ① **交接报告（回报本身）= 六要素**：`做了什么 / 产物在哪 / 怎么验证 / 已知问题 / 下一步 / 状态机更新`——`handoff-check` 的 **B1** 逐段核验，**缺「状态机更新」即硬 21**（实测 T3 首次回报写「状态更新」当场被判 hard）；② **`agents-log.md` 的「### Tn 执行记录」= 五要素**：`输入文件清单 / 已读编号·已落盘条数 / 已完成步骤 / 产物路径 / 下一步`（≤5 行，真源 = `pipeline-readme.md` §两轨各司其职 与 `00-主控-扩展职责.md` §子系统巡检；本门对它**只判「该不该有这一节」（A6），不核其内部字段**）。**反哺清单 §三.11 曾主张把 ② 并成「六要素」——经主控核实为假**（那会造出「既非回报六段名、也非执行记录五项」的**第三种清单**），故此处只留判据、**不追加 `状态机更新`**。

> 每条产物**必须同时给** ① **相对路径** ② **字节数或行数** ③ **结构自检命令与实测结果**。
> ⚠️ 实战教训：某轮 T7 派发产出了 M 门报告却**缺审计报告 + 反哺报告**即结束（写盘前失败），

- `path/to/file1`（N 字节 / M 行；自检：`grep -c "^## " path/to/file1` = X）
- `path/to/file2`（N 字节 / M 行；自检：`node scripts/count-chars.mjs path/to/file2` = X）
