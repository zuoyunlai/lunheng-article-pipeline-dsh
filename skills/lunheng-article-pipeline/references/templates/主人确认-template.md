# 主人确认单（人在环门）

> 版本：v18.1.0（DSH bundle 插件）
> 用途：**四个**人在环确认节点通用——**Phase 0（定题）** / Phase 2.5（分析大纲）/ Phase 3.5（初稿结构 + 洞察落地）/ Phase 5（终稿交付）。
> 流程：主控把确认单写到 `<项目>/阶段确认-<阶段>.md` → **用 `ask_user_question` 向主人提问（§7）** → 主人确认或驳回 → 主控按回复继续或修订 **并把主人回复原文回填到 §6**。**未获确认不得跳过下一闸门；未回填 §6 不算闸门完成。**

### 本阶段定什么 / 不定什么（避免主人以为要一次定死）

| 阶段 | 本阶段要定的 | 留给下一阶段 |
|------|------------|-------------|
| **Phase 0** | 主题 / 类型 / 篇幅 / 引用格式 / 语言 / 文风档位 / 外发 4 选 1 / 配图**意向** / T9·G14 开关 / 是否需要投喂 | **具体图位数量与图表类型**（Phase 2.5 拍板）；**具体期刊**（T9 后出 Top 3）；**各段论点**（Phase 2 分析） |
| **Phase 2.5** | 大纲主线 / 论点层次 / 三角验证缺角处置 / **图位数量与类型** | 正文措辞与段落（Phase 3）；审计与审稿意见（Phase 4/4.5） |
| **Phase 3.5** | 主人洞察是否已被 v2 正确融合 / 是否需补充洞察 | 批判与审计结论（Phase 3.6/4） |
| **Phase 5** | 接受交付 / 补改（给出类型）/ 重走某阶段 | —— |

### 7. 提问方式：用 `ask_user_question`（v18.1.0 新增，主控照做）

**动作**：主控把本确认单写到 `<项目>/阶段确认-<阶段>.md` 之后，**用 `ask_user_question` 工具**向主人提问（而不是只在回复里贴一段文字）：

- **一问即可**（闸门是单决策点，不必拆成多问）；`header` 用阶段名，`question` 写「<阶段名>：产出 <路径>，主控建议 <通过/驳回>——是否按建议推进？」
- **选项 ≤5 个**，**第一个必须是主控建议**并在标签末尾加「（推荐）」（官方约定：推荐就是「放最先 + 标注」，**没有独立的推荐字段**）；其余选项 = §5 的四类驳回 + 「其他（我会补充说明）」。
- **`multi_select` 留默认 false**（本门是单选）。
- 主人选「其他」或改选项后补充文字，以**主人实际回复**为准（§6 逐字记录），**主控不得替主人勾选**。

**为什么用工具而不是纯文字**（如实）：官方 `docs/tool-catalog.md` 记录该工具写入 `tool/call` + `tool/result` 两个事件——问题原文在 `tool/call`（log-only），答复在 `tool/result`（surface），**两者都在 append-only 会话日志里、可重放**。**诚实边界**：官方**没有** `user-questions/*` 专用日志事件（「审计事件对」的说法只存在于 `approval/asked` + `approval/decided`），所以 §6 的人工回填**仍是权威留痕**，工具只让「问过什么、什么时候问的」自动进日志。

**三条边界（踩到会出真问题）**：

1. **只有主控问得了**：官方 `docs/subsystems/user-questions.md` 明确「owned child has no human answerer」——被父代理拥有的子代理调用该工具会被拒（`DELEGATED_CALLER`）。**T1-T9 子代理不得自行向主人提问**；它们只能把「需要主人决定」写进交接报告，由主控统一提问。**故闸门必须留在主控**（现状正确，勿外移）。
2. **工具失败 ≠ 主人同意**：无 UI 提供方 / 无人应答渠道 / 会话被中止时，该调用**失败**（`NO_PROVIDER` / `ASK_ABORTED`），**不得当作通过**。此时退回**书面路径**（把确认单交给主人，按回复回填 §6），并在 §6「提问方式」栏如实写失败码。
3. **不设超时、不刷屏**：官方未定义超时；主人在读文件时不要反复重问同一门（同一闸门只问一次，未答复就等；等待期间可在 `进展-主人版.md` 记一行「已请确认，待回复」）。
