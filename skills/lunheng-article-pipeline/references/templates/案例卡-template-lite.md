> **精简版**：只保留骨架 + 必填字段，详细说明见 [`案例卡-template.md`](案例卡-template.md)

## ⚠️ 机检硬格式（v18.0.0 新增）

| 机检项 | 必须的确切形态 | 违反后果 |
|--------|--------------|---------|
| 索引段标题 | `## 📇 索引段`（emoji 📇 + 空格，**逐字**）——**0 条空卡场景也必须有该标题**（表体写「（无）」） | M-Form-10 判「缺索引段」 |
| 条目标题 | `### [C01] 事件名`（**方括号**包裹编号） | M-Form-11 判「编号无对应条目」 |
| **0 条空卡标记** | `[C-空]` —— **只用于卡内**；定稿正文的读者面写法见下 | 定稿若照抄内部说明会触发 **M-Form-4 文末二级扫描**（P0） |
| 0 条场景的定稿写法 | 定稿「案例来源」节**只写读者语境一句**，如：`[C-空] 本次任务无案例需求（哲学思辨类议题，不涉企业行为 / 司法 / 新闻事件；案例数量 0）。` —— **不得**写「案例检索员 / 0 条空卡协议 / 任务简报第 N 行 / 主人 Phase 0 / spawn」等流程信息（这些移入 `final/交付说明.md`） | M-Form-4 判 P0（实战：本项目 3 处泄露中 2 处源于此） |
| 信任级别行 | `- **信任级别**：已发布（备注）` —— 冒号后直接跟档位词，档位词上不得加粗 | M-Form-6 判「独立段缺失」 |

````markdown
# 案例卡（Cxx 系列）

> **位置**: （检查 cases/案例卡.md）
> **检索员**: **T3** 案例检索员（启动时间 + 模型，v2.3.0 重命名原 T6→T3）
> **截止**: YYYY-MM-DD

## 基本信息

- **总条数**: N
- **0 条空卡**: 如果 N=0，输出 `[C-空]` 标记（v2.1.8 协议）

## 案例卡格式（每条）

```markdown
### [C01] 事件名称（短标题，≤20 字）
- **主体**: 当事人/公司/机构
- **时间窗口**: YYYY-MM-DD ~ YYYY-MM-DD
- **事件状态**: 🟢 已结 / 🟡 发展中 / 🔴 反转风险（v2.5.2-dsh 补丁；🟡🔴 → T8 终检强制复核）
- **信任级别**: 🟢 已发布 / 🟡 主人投喂
- **类别**: 🏢 企业行为 / ⚖️ 司法 / 📢 社交媒体 / 🔍 第三方研究
- **来源谱系**: ≥2 个独立来源（单源降级 ⚠️）
  - ① 当事人/官方
  - ② 主流媒体
  - ③ 第三方/学术
- **多方说法**:
  - 当事人: xxx
  - 媒体主流: xxx
  - 反方观点: xxx
- **关键数据**: [Dxx] 链接（避免重复录入）
- **支撑论点**: 论点 X（详见分析大纲.md）
```

## 三角验证逻辑

- **T1 文献卡**: 理论 / 学术依据
- **T2 数据卡**: 量级 / 趋势
- **T3 案例卡**（v2.3.0 重命名原 T6→T3）: 事件结构（who/when/what/各方说法）

三者共同支撑论点。
````
