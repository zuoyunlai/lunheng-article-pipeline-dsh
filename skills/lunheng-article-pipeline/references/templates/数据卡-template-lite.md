## ⚠️ 机检硬格式（v18.0.0 新增 —— 这几条不照做，下游 M 门必失败）

| 机检项 | 必须的确切形态 | 违反后果 |
|--------|--------------|---------|
| 索引段标题 | `## 📇 索引段`（emoji 📇 + 空格，**逐字**） | M-Form-10 判「缺索引段」 |
| 条目标题 | `### [D01] 主题`（**方括号**包裹编号） | M-Form-11 判「编号无对应条目」 |
| **信任级别行** | `- **信任级别**：已发布（备注）` —— 冒号后**直接跟档位词**（档位词上**不得再加粗**） | M-Form-6 判「独立段缺失」→ 连锁 M-Integrity-1 判 P0（实战踩坑：写成 `**信任级别**：**已发布**` 即不匹配） |
| 头部条数声明 | 「总条数」只声明 `[Dxx]` 条目数（如「总条数：12 条」）；基线 3 条 `[D-基-x-NN]` **另列**，勿并入同一「总条数」；**亦勿在别处写「（合计 N 条）」**（脚本 best-effort 会取错数） | M-Form-10 判「头部声明 ≠ 正文条目」 |
| 基线编号 | `[D-基-{R/T/C/E}-{NN}]`（glossary §三 正式格式，**必须保留**，勿简化为裸数字） | 写手传递会丢失可追溯性；勿因担心「临时编号」而改写（v18.0.0 已修 M-Form-3 误判） |

```markdown
# 数据卡（Dxx 系列）

> **位置**: （检查 data/数据卡.md）
> **检索员**: T2 数据检索员（启动时间 + 模型）
> **截止**: YYYY-MM-DD

## 基本信息

- **总条数**: N
- **信任级别声明**: 已发布 N1 / 主人投喂 N2 / 二手转引 N3（N1+N2+N3 = N）

## 数据卡列表（按主题分组）

### [D01] 数据标题
- **主题**: xxx
- **数值**: xxx
- **来源**: 机构名 + 年份 + URL
- **信任级别**: 🟢 已发布 / 🟡 主人投喂 / 🔴 二手转引
- **时间窗口**: YYYY-MM-DD ~ YYYY-MM-DD
- **支撑论点**: 论点 X（详见分析大纲.md）

### [D02] ...

## 交付前自检（v2.2.10 新增）

<!-- 人类验证命令（agent 零 exec，由主控 LLM 推理完成） -->
- 统计实际条目数：`^### [D` 开头行数
- 统计声明总条数：基本信息段声明的 N
- 两数必须一致 → T2.5 闸门不拦截
```

**关键约束（v2.2.1 起强制）**：

| 字段 | 说明 |
|------|------|
| **信任级别必填** | 每条 [Dxx] 必须标 🟢/🟡/🔴（M-Form-6 + M-Exist-3 校验） |
| **URL 必填** | M-Exist-1 双向 对比 校验 |
| **时间窗口** | G11 时效告警 |
| **支撑论点** | F1 论证依据匹配 |

**字段命名约定**：
- 主题：一句说人话
- 数值：精确数字 + 单位
- 来源：机构 + 年份 + URL
- 支撑论点：链向分析大纲
