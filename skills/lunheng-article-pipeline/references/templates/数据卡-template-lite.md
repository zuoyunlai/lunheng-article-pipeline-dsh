**卡头汇总行纪律（v19.5.0，反哺 §5「视图派生失真」/ 总表「卡片头部手写汇总」）**：

- **由逐条独立行自动统计生成，禁手写**：`总条数：N` = 本类正文条目数；`信任级别声明：已发布 N1 / 主人投喂 N2 / 二手转引 N3` = **逐条独立行**的分类计数（三档之和 + **双标**数 = N，未声明另计）。
- **双标单列**：一条数据兼有两种来源成分（如「原始文本属已发布 + 其中数量出自媒体转述」）→ **同一行并列写两档**（`已发布（…）+ 二手转引（…）`），它在审计视图里记为「**双标**」、**不并入**任一单类。只写其中一档会让分类计数与逐条真源对不上（实测病灶：卡头手写 `已发布 39 / 二手转引 17`，逐条实为 **42 / 13 / 双标 1** —— 手写汇总与逐条不一致会让 G1/G12 的**分母漂移**）。
- **缺口条目单列**：检索不到的项以 `[Gnn]` 走 `## 缺口清单（🔴 单列，不计条）`，**不计入「总条数」**（契约见 [`../_shared/机检硬格式.md`](../_shared/机检硬格式.md) §一 与 §十一）。

**关键约束（v2.2.1 起强制）**：

| 字段 | 说明 |

| **信任级别必填** | 每条 [Dxx] 必须有「**信任级别**：」独立行，档位词 = 已发布 / 主人投喂 / 二手转引（**禁 🟢/🟡/🔴 emoji**——那是事件状态/时效评级用的，不是信任档；M-Form-6 + M-Exist-3 校验） |
| **URL 必填** | M-Exist-1 双向 对比 校验 |
| **时间窗口** | G11 时效告警 |
| **支撑论点** | F1 论证依据匹配 |

- 来源：机构 + 年份 + URL
- 支撑论点：链向分析大纲
