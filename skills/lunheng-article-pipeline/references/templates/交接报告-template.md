# 交接报告模板

> 每个角色完成任务时交付。六要素缺一不可。写不下就写「无」。

## 1. 做了什么
（完成内容摘要，2-3 句）

## 2. 产物在哪
（精确文件路径，如 `run/数字鸿沟/literature/文献卡.md`）

## 3. 怎么验证
（验收标准/自查项：如"每条引用都带 URL，可随机抽 3 条搜索验证"）

## 4. 已知问题
（缺口、风险、没找到的东西——**必须如实写，不许藏**）

## 5. 下一步
（给下游角色的明确指令，如"分析员请优先处理第 2 组缺口"）

## 6. 状态机更新
（status.md 对应行已置为 Review/Done；如有失败写明原因）

## 7. AI 使用披露（v2.2.2 新增，教训 #86，T4 写手 + T7 主控必填）
```
### AI 使用披露
- ① AI 生成内容：本角色产物哪些部分由论衡 AI 生成（如「初稿正文由 T4 写手生成」）
- ② 主人原创洞察：[C-主xx] 主人洞察（如有），出处（任务简报第 X 行）
- ③ 检索真实证据：[Lxx]/[Dxx]/[Cxx] 编号全部来自真实检索（非 AI 编造）
```

# 修订说明模板（写手被审计打回时附在修订稿头部）

```
# 修订说明 vN（F9 补完：含 v2.1.4 文末四节差异项）
| 问题编号 | 严重级 | 修改内容 |
|---------|--------|---------|
| P0-1    | P0     | 删除了编造的第X段引用，替换为文献卡 L05 并标注 |
| P1-3    | P1     | 全文引用格式统一为 GB/T 7714 |
| G4-2-1  | P1     | 补完「## 数据来源」节：v2.1.4 要求所有 [Dxx] 需在文末有对应数据来源条目 |
| G4-2-2  | P1     | 补完「## 案例来源」节：[Cxx] + [C-主xx] 主人在文末各有 1 条说明（含任务简报出处行号） |
| G4-2-3  | P1     | 删除孤儿条目：文末「## 参考文献」有但正文未引用的 L 条目 |
| G4-2-4  | P1     | 测算值/综合判断条目加「测算值/综合判断（基于 Dxx/Dxx）」标注 |
...（逐条回应审计报告全部 P0/P1，P2 可选回应）

## v2.1.4 文末四节完整性自检（修订交付必走）
1. grep -oE "[D[0-9]+]|[C[0-9]+]|[C-主[0-9]+]|[L[0-9]+]|[先[0-9]+]" final/定稿.md | sort -u 拿到正文全部编号
2. 与文末「## 数据来源」「## 案例来源」「## 参考文献」「## 先行者文献」四节双向 diff
3. 漏引 → 补列 / 孤儿 → 删除 / [C-主xx] 补说明 → 调整
4. 未通过 → 在本修订说明单上明确「G4-2 未修复」状态，不得标「完成」
```
