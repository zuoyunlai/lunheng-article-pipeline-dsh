# 来源索引 — 三线共享（v18.29.0 EFF-5 新增）

> **谁读这份模板**：T1 文献检索 / T2 数据检索 / T3 案例检索（**登记**）、主控（**合并**）、T7 审计（**查实据**）。
> **为什么有它**：实测三线合计 ≈58.1M cacheRead（T1 28.19M / T2 19.63M / T3 10.32M），而**三条线各自抓取**——
> 同题三线的来源重叠通常 **10–30%**，同源命中本该**只付一次抓取与一次阅读**。

## 一、目录与文件（**每线一个分片，独占写**）

```
run/<项目>/
├── sources/
│   ├── T1.jsonl    # T1 独家写（文献线）
│   ├── T2.jsonl    # T2 独家写（数据线）
│   ├── T3.jsonl    # T3 独家写（案例线）
│   └── T1-补.jsonl # 可选：同一条线的**补检索段**（Phase 1.5；文件名 `T<n>-<后缀>.jsonl`）
└── sources.json    # 主控在 Phase 2.5 跑 --merge 生成（三线不写）
```

> **⚠️ 补检索段（v18.78.0 反哺 F2）**：Phase 1.5 的那一轮补检索若单独落盘，文件名必须是 **`T<n>-<后缀>.jsonl`**
> （如 `T1-补.jsonl` / `T2-补.jsonl`）——`sources-index.mjs` 会把它**归并入基础线 T<n>**（line 标记仍是 T1/T2/T3），
> 不必也不得改写主分片（分片 append-only、每线独占）。
> **不按此命名的 `*.jsonl` 会被响亮报错**（`--check` → exit 1：`分片文件名未识别`）而不是被静默忽略——
> 旧实现只读 `T1/T2/T3.jsonl` 三份**固定名**分片，补检索产物因此**一行都进不了 `sources.json` 而退出码仍 0**。反过来也别把补检索段直接追加进主分片以外的名字（如 `T4.jsonl`、`sources2.jsonl`）：基础线只认 T1/T2/T3。

> **⚠️ 为什么不是「三线共写一个 sources.json」**：三个子代理并发写同一文件必然互相覆盖——这正是本仓
> `status.md`（主控独占）/ `agents-log.md`（子代理各自追加）分离的**同一条判据**。分片**append-only**，只追加不改写。

## 二、行 schema（JSONL：一行一个对象，**必须是合法 JSON**）

```json
{"url":"https://example.org/a","title":"来源标题","fetchedAt":"2026-09-27","summary":"一行摘要：这条来源支撑什么、口径是什么","tool":"advanced_search","engine":"exa","query":"AIGC 意向性 美学"}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `url` | ✅ | 须形如 `http(s)://…`（`--check` 会校验形态） |
| `title` | ✅ | 来源标题（原文标题，不要改写） |
| `fetchedAt` | ✅ | 抓取日期 `YYYY-MM-DD`（或完整 ISO 8601 如 `2026-10-08T21:13:00+08:00`）；**同一项目内保持一种格式**（2026-10-09 检索审计反哺 R7：实测同项目混用两种格式，下游按字符串排序/比对时会错位） |
| `summary` | ✅ | **一行摘要**（这条来源支撑哪个子问题 / 什么口径）——下游据此判断要不要重抓 |
| `line` | — | 缺省取分片名（T1/T2/T3）；**跨线转引**时才显式写来源线 |
| `tool` | ⚠️ 新行必填 | **实际调用的检索工具名**（`advanced_search` / `multi_search` / `platform_search` / `web_fetch` / `search_papers` …）——**v18.62.7 §A22 新增** |
| `engine` | ⚠️ 新行必填 | 该次调用的**引擎**（`advanced_search` 的 `engine` 参数值；`multi_search` 写聚合名 + `seenIn` 数） |
| `query` | ⚠️ 新行必填 | 该条来源对应的**检索式** |

> **溯源三字段的口径（v18.62.7 反哺 §A20/§A22）**：**要么三个都不写**（= 旧格式行，`--check` 只报软提示点名，**不判红**），**要么三个写齐**（写了一个就要求全有，缺则 `--check` 判不合法 → exit 1）。
> **分片级一致性（v18.86.0-prep · 台海反哺 F-14 · 兼容期→强制的渐进升级）**：**同一分片要么全带齐、要么全不带**——**混用**（部分行带齐溯源、部分行全缺）**判不合法 → exit 1**。判据：同一分片是**同一轮检索的产物**，不可能一半有溯源一半没有；行级规则挡不住「写一半就停」，而写一半已足以让换档/换工具**不可逐条标注**。**升级路径**：新项目（或新一轮分片）应**全片带齐**；纯旧分片仍在兼容期内（仅软提示，存量项目不被打红）。
> **重建 sources.json 的唯一正名命令 = `node scripts/sources-index.mjs <项目> --merge`**（2026-10-09 检索审计反哺 R7）——**禁止在项目目录自造 normalize/rebuild 类脚本**（实测某项目自造重建脚本重造轮子，且绕过 `--check` 同判据语义）。
> **为什么必需**：没有它们，「**某条数据是不是用规定的检索源取的**」在交付物里查不到——实测要回答「检索用了哪些插件」，只能回翻 DSH 会话缓存数工具调用；而那正是「角色卡点名了本机未安装的工具」这类错位（§A19）**能被藏住**的原因。加上它们之后，**换档/换工具可被机检发现**。
> **同项目不同轮次换过工具**时：**逐条**标注归属（这就是这三字段的用途）；**同一轮内**建议只用一个档（§A20：两轮走不同引擎 → 召回率与偏差结构不可比，而稿件把两轮当同一证据底座）。

## 二·五、落盘纪律（**写分片之前先读这一节**，v18.78.0 反哺 F1/F5/F6/F7）

实测（本项目 Phase 1/1.5）四条**各自独立**的翻车，都不是「内容写错」，而是「写分片的工艺选错」：

| 纪律 | 必须怎么做 | 踩过的坑（实测） |
|---|---|---|
| **① 行 = 本 schema，不是卡片 schema** | 一行一个**本文件 §二** 的对象；`id` / `type` / `credibility` / `vendor` / `input_price` / `event_status` **都不是**本 schema 的必填键 | 三线各写了一版自造 schema（文献卡式 / pricing 式 / index 式）→ `--check` 全行判非法；`--check` 现在会**直接点名 schema 出处** |
| **② 序列化交给程序，不要手拼字符串** | 用 `JSON.stringify(obj)`（Node）或等价序列化生成整行 | 主控用 PowerShell 文本管线拼 JSONL → 5.1 的 `ConvertFrom-Json` 遇**中文内嵌双引号**（如「"价格屠夫"」）直接报 `Invalid object passed in` |
| **③ JSONL 一律 UTF-8 无 BOM** | 写盘不带 BOM（契约见 `.gitattributes`）；脚本 v18.78.0 起**剥首行 BOM 后照常解析并点名** | `Set-Content -Encoding UTF8`（Windows PowerShell 5.1）**会写 BOM** → `JSON.parse('\uFEFF{…}')` 抛 `Unexpected token`；旧报文把它报成「不是合法 JSON」，主控去查 JSON 写坏了（真因是编码头） |
| **④ 从 Markdown 链接提 URL 要清洗尾部** | `[name](url)` 用正则取 URL 后**循环剥尾部** `)` `]` `"` `」` `。`，再校验 `^https?://` | `https?:\/\/[^\s]+` 会把 Markdown 的收尾 `)` 一起吃进去 → 分片里存了带尾括号的 URL，后续抓取/去重全部错位 |

> **判据**：这四条**都不是「内容」问题而是「工艺」问题**——它们不会被 T7 的语义审计看出来（行里该有的信息都在），
> 只会以「脚本莫名判非法 / 数据静默丢失」的形式在**下一阶段**爆出来。
> **为什么写在这里**：本表是分片形态的真源；**改工艺纪律只改本表**，三线开工话术只留指针（v18.78.0 前此处无任何落盘纪律可指）。

## 三、三线各做什么（**查 → 抓 → 登记**）

1. **抓之前先查**：`node scripts/sources-index.mjs run/<项目> --query <关键词>`——命中同 URL 就**直接用索引里的标题与摘要**，不必重抓（需要更细内容时再抓，并在自己的分片里补一行说明）。
2. **抓到就登记**：把该条追加到**自己线**的分片（`sources/T{n}.jsonl`），一行一条；**不要**动别人的分片。
3. **主控在 Phase 2.5 合并**：`node scripts/sources-index.mjs run/<项目> --merge` → 生成 `sources.json`（按 url 去重 + 计数 + 跨线重复清单）。

## 四、两条边界（如实声明）

- **它不是门**：`--check` 只校验**行是否合法**、并**统计跨线重复**（重复是**收益来源**，只报不判错）；「该不该抓某个源」由各线自行判断。
- **缺分片/空分片不算问题**：那是「**该线尚未登记**」。`--check` 对缺分片**不判错**——与 M-Exist-10/11 对「缺输入记 N/A 且未检」同一口径。

## 五、交接报告里怎么写（T1/T2/T3）

- 在「做了什么」里写：**登记 N 条来源**（其中**复用已有索引** M 条）；
- 在「怎么验证」里写：`node scripts/sources-index.mjs run/<项目> --check` 的 exit code + 输出行数（**机械证据**，与 T2.5/T7.5 闸门口径一致）。
