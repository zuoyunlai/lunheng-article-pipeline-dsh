> 版本：v18.58.0（DSH bundle 插件）
> 用法：**抄两份**，各自只保留对应闸门那一段 → `audits/闸门记录-T2.5.md`、`audits/闸门记录-T7.5.md`

> 用途：把「主控 LLM 兜底执行」的两道闸门变成**可核对的结构化记录**——机检 **M-Exist-5** 逐项核验：检查项齐备 / 实据是机械证据 / 结论词固定 / 判 ✗ 的行写了原因。

> **为什么需要这张表**：T2.5 与 T7.5 此前只有伪代码，**没有任何落盘表单**——闸门过没过、依据是什么只留在会话里，换会话或事后审计就不可追溯；M-Integrity-2 的判定也没有可核对的输入。本表把闸门从「主控说过了」变成「有据可查地过了」。

## 结论图例

| 结论词 | 含义 |
|--------|------|
| ✓ | 该项通过 |
| ✗ | 该项未通过（**必须在「失败原因」列写明**，并按严重度决定是否放行） |
| N/A | 本项目不适用（如未启用配图 / 无修订轮；需在失败原因列写一句理由） |

> **「实据」列的硬要求**：必须是**机械证据**——文件路径、脚本 exit code、执行的命令、sha256 值。
> ⚠️ **「实据」列禁止出现未转义的竖线 `|`**（v18.8.0 反哺）：markdown 表格以 `|` 分列，单元格内的 `|`（如命令 `Select-String -Pattern "a|b"`）会**撕开表格列**，使机检把后半段文本误读为「结论词」→ M-Exist-5 报非固定词软提示。**改法**：命令里的 `|` 写成 `\|`，或改用不含竖线的等价命令（如 `Measure-Object` 计数器单独成行）。
> **实战**：本项目 T7.5 闸门记录写 `-Pattern "\[D\d{2}\]\|D-空"`，机检把结论词读成 `D-空" 命中 1 处」`。
> 写「已检查」「已核对」「确认无误」这类自述 = 机检判失败（闸门留机械证据，见 `AGENTS.md`）。
> **v18.12.0（全量审计 L-03/L-22）——实据**要与产物绑定，不再只看「像不像证据」**：M-Exist-5 现对**每个结论为 ✓ 的行**逐行核对：
> ① 行内提到 **M 门**时，实据里的 `exit N` 必须**等于** `final/M-Gate-Report.json` 的 `script_exit_raw`（不等 → **P0** 实据与产物不符）；
> ② 且 M 门的**有效裁定值必须为 0**（T8 裁定段干净才认 0；命中硬 P0 红线时裁定一律不采信 → **P0**）；
> ③ 实据引用的项目内路径（`audits/` `drafts/` `analysis/` `literature/` `data/` `cases/` `final/证据包|图件/`）**必须真实存在**（不存在 → 软提示）；
> ④ 涉及 `handoff` 的行必须给出 `exit ∈ {0,20,21,22}`（缺 → P1）。
> ⚠️ **别写「M 门 exit 0」而报告不是 0** —— 这是现在最容易被抓的一行。机械值非 0 但 T8 已就本版正文裁定为 0 时，实据如实写 `exit 3（T8 裁定 0）`。
> **v18.6.0 起**：T2.5/T7.5 闸门记录须把**交接门 `handoff-check.mjs` 的 exit code（20/21/22）连同被验收角色**写入「实据」列（如 `handoff-check --role T7 → exit 0`）——**不写 = 闸门记录缺实据**（回报侧 B 模式强制落地的可核对抓手；执行指令真源 = [`../agents/00-主控-扩展职责.md`](../agents/00-主控-扩展职责.md) §子系统巡检）。
> **落地现状（v18.46.0 起：**已全部判硬**）**：**下面两张表的末尾都已有这一行**，照填即可——
> ① 行在、但实据**没给 exit**（0/20/21/22 之一）→ **硬判**；② 记录里**根本没有这一行** → **硬判**（由「模板为真源，逐项都要有行」接管）。
> ⚠️ **不要删这一行**：它是唯一承重件，删了这条要求会**静默退回**无判定状态（`tests/mexist5-binding.test.mjs` 的 v18.46.0 钉子守着它）。
