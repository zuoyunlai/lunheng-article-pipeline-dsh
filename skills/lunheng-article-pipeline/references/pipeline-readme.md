# 人文社科论文多 Agent 流水线 — 运行手册

> **DSH 适配（v2.1.8-dsh.1）**：工具映射（`sessions_spawn`→`subagent`、`sessions_yield`→等完成通知、`tavily_search/extract`→`web_search`（无 include_domains，可在查询里用 `site:` 限定）、`update_plan`→`todo_write`、`image_generate`→无内置（降级 SVG/投喂）、`memory_*`→文件记忆、`exec`→`pwsh`/`bash`）见 `SKILL.md`「🔧 DSH 适配说明」。

> 使用方式：主控 Agent（论衡）按本文档派发任务。角色定义见 `agents/`，模板见 `templates/`。

> **⚠️ Phase 0 强同意关卡**：本流水线下面任何一个阶段调用以下工具，**会**发数据到**外部服务商**——主控必须告诉主人明示同意，否则不可调用：
>
> | 工具 | 外发服务商 | 发送内容 |
> |------|---------|---------|
> | `web_search` | DSH 的 web_search 提供方（按 DSH 配置） | 查询关键词 |
> | 主控推理调用 | 当前模型 provider（按 DSH settings.yaml） | 文献/数据/案例/草稿/大纲/全文 |
>
> **项目名/主题/论文纲要可能含未公开信息**——主控 Phase 0 必须问主人：
> 1. 同意全部外发？（默认）
> 2. 脱敏措辞 + 封面 SVG（本地）？
> 3. 只同意一部分（如文献检索同意）？
>
> 主人选定后写入 `01-任务简报.md` 作为「外发同意项」记录。**未同意前不可跳到 Phase 1**。

## 快速开始

```
1. 主控确认主题（Phase 0）→ 写 01-任务简报.md + 初始化 status.md
2. 主控记录 cases 需求（含 0 条场景显式声明），写入 status.md（v2.1.8 取消三档决策，教训 #56）
3. 并行 spawn 文献检索员 + 数据检索员 + 案例检索员（用下面的派发话术，DSH subagent 后台并行）
4. 等三者完成通知
5. spawn 分析员 → 分析大纲产出 → Phase 2.5 送主人确认 → 通过后 spawn 写手
6. spawn 审计员 → 审计不过 → 写手交修订说明 + 修订稿（≤2 轮）→ 终检交付（含证据包）
```

## 🚫 不适用场景（边界明示）

论衡是「论文/深度文章」**写作流水线**，**擅长主动检索已发布证据 + 整合主人投喂的证据**。

**论衡能主动采集**（T1 文献检索 / T2 数据检索 / T6 案例检索 sub-agent）：
- ✅ 已发布的学术文献（PubMed / CNKI / Web of Science 等数据库）
- ✅ 已发布的统计数据（教育部 / 统计局 / 行业协会等公开数据）
- ✅ 已发布的案例与报道（媒体 / 法院判决 / 行业报告等公开案例）
- ✅ 政府发布的统计 / 报告 / 调查 / 政策文件

**论衡不能主动采集**（需要主人提前准备素材投喂）：
- ❌ **一手原始数据采集**：实验设计 / 调查问卷投放 / 用户访谈 / 田野调查 → 需要主人亲自调研，原始数据投喂为「数据源」
- ❌ **统计分析**（SPSS/R/Python 跑模型）：论衡可以引用统计结果，但**不执行统计计算**。如需跑回归/聚类/因子分析，请主人用专门工具，结论以「数据 + 方法描述 + 结果」形式投喂
- ❌ **图表原始数据采集**：论衡生成的是**数据可视化**（matplotlib/SVG），数据本身需主人提供。如需爬虫/OCR/语音转文字，请主人用专门工具，原始数据投喂后论衡制作图表
- ❌ **原创图片 / 视频生成**：DSH 无内置图像生成工具 → 封面/插图用 SVG 矢量风（程序化，本地）或主人投喂；**不能拍摄实物照片 / 录制视频**。如需实物素材，请主人拍摄后投喂文件路径
- ❌ **代码执行**：本技能不主动跑代码；DSH 下如需跑代码验证论据，可经主人同意后用 `pwsh`/`bash` 执行，结果投喂为证据

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」——是，论衡主动采集；不是（是一手原始数据 / 自己拍的素材 / 自己跑的计算），主人投喂后再用。

## 执行韧化与介入（DSH 版）

- 每个角色启动 30 秒内更新 `status.md` 心跳 + 按任务时长分阶段 ack；
- **超时硬卡 8 分钟**：任一子代理 8 分钟内未出产物 → 判定超时，主控介入（用 `list_agents` 查看，必要时重派）；
- **主控兜底产物明确标注**：任何 T 阶段主控亲自产出 → 文件头标注「主控兜底」+ 失败原因；
- DSH 下子代理模型由会话/settings 决定，技能内不配置模型降级链。

## 流水线全景

```
Phase 0 定题       主人确认主题/期刊模板/篇幅/cases 需求（含 0 条显式声明） → 01-任务简报.md + status.md
Phase 1 并行检索   T1 文献检索员(文献卡A/B/C分级) ∥ T2 数据检索员(数据卡🟢🟡🔴+冲突并列) ∥ T6 案例检索员(cases/案例卡.md,**任何量级必 spawn**，含 0 条空卡协议)
Phase 2 分析       T3 分析员 → 分析大纲.md（论点-论据映射 + 反方论证 + 三角验证标注）
Phase 2.5 大纲确认 主人过目大纲 → 确认/修改（人在环，改方向成本最低）；主控把关三角验证（[L]+[D]+[C]）
Phase 3 写作       T4 写手 → 初稿-v1.md（禁做清单 + 反方论证 + 字数预算；引用标[Lxx]/数字标[Dxx]/案例标[Cxx]；修订 v2/v3 显式覆盖同路径）
Phase 4 审计       T5 审计员 → 审计报告（G0-G11 全项检查）
Phase 4.2 修订     写手交 修订说明 + 修订稿 → 审计员复核 → 最多 2 轮 → 仍不过升级主控
Phase 4.5 配图     仅当简报「配图需求」非无：写手已在正文标 [图N] 图位 → 主控程序化生成数据图表（数字与数据卡/[Cxx] 一致）
Phase 5 终检      主控终检 → final/定稿.md + 图件/（如有）+ 证据包/(文献+数据+案例+审计) + 交付说明.md → 高频问题反哺报告（不自动 commit 角色卡）
```

## status.md 状态机（主控维护，角色交接时更新）

- 模板：`templates/status-template.md`
- 每个角色交接时必须更新 `status.md` 对应行
- 失败要留原因；任一行停留 >8 分钟无进展 → 主控介入

## 派发话术（主控复制即用）

### 文献检索员（并行①）

```
你是「文献检索员」。任务编号 T1。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search 检索主题相关文献（中英文；知网/万方/Google Scholar/期刊官网/SSRN 等）
2. 产出 literature/文献卡.md：8-12 条核心文献，按子问题分组
3. 每条必须真实存在：作者、年份、标题、期刊/来源、DOI 或 URL、与本文的关联
4. 每条标可信度等级：A（核心期刊/权威机构）/ B（一般期刊/预印本）/ C（网络/二手转引）——C 级必须诚实标注
5. 参考文献条目按任务简报指定格式输出（默认 GB/T 7714），写手可直接粘贴
6. 严禁编造引用；检索不到就写「未检索到」，不许凑数
7. 交接报告六要素（含 status.md 更新）
8. **先行者检索（原创性保证）**：主动搜「该主题是否已有公开深度文/论文写过类似核心论点」，产出 `literature/先行者清单.md`（每条含：文章标题/作者/来源/年份/URL + 核心论点 + 与本文的差异点）
```

### 数据检索员（并行②）

```
你是「数据检索员」。任务编号 T2。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search 检索主题相关统计数据与实证材料（国家统计局/世界银行/CEIC/皮书/权威数据库）
2. 产出 data/数据卡.md：每个数据点含「数值 + 来源机构 + 年份 + URL」；按子问题分组
3. 每条标时效评级：🟢 ≤2年 / 🟡 2-5年 / 🔴 >5年（红级显著标注）
4. 同指标多来源矛盾 → 强制并列呈现 + 口径差异说明，不擅自二选一
5. 严禁编造数据；找不到精确数据就标注「缺口：建议人工查 XX 数据库」
6. 交接报告六要素（含 status.md 更新）
```

### 案例检索员 T6（v2.1.8 强化：任何量级必 spawn，与 T1∥T2 三方并行互不干涉，含 0 条空卡协议）

```
你是「案例检索员」。任务编号 T6。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search 检索主题相关具体事件（条数按任务简报「cases 需求」；cases=0 时**不实际检索**，走 0 条空卡协议输出 [C-空] 卡）
2. 产出 cases/案例卡.md，按 templates/案例卡-template.md 格式：[C01]... 每条含事件/主体/时间窗口/多方说法/≥2 来源
3. 中文新闻源覆盖（在查询词里显式限定站点域名，如 site:xxx.com）：财经（财新/第一财经/虎嗅/36 氪/澎湃）、官方（国家统计局/商务部/上市公司公告）、国际（Reuters/Bloomberg/FT/WSJ/HBR）
4. 每条必填：检索截止日期 + 事件时间窗口 + 来源谱系（≥2 独立来源）+ 多方说法（当事人/媒体/第三方）
5. 来源分级：A（官方公告/权威媒体）/ B（行业垂类/专业媒体）/ C（自媒体/二手转引）——C 级必须诚实标注
6. 严禁编造案例细节；找不到的写「未公开/未披露」；当事人未回应写「截至检索截止未回应」
7. 案例卡编号 [Cxx] 与文献卡 [Lxx]/数据卡 [Dxx] 互引（不重复录入）
8. 交接报告六要素（含 status.md 更新）
```

### 分析员

```
你是「分析员」。任务编号 T3。
项目目录：run/<项目名>/
先读：01-任务简报.md、literature/文献卡.md、data/数据卡.md、cases/案例卡.md；更新 status.md
任务：产出 analysis/分析大纲.md，包含：
1. 研究问题界定与文献缺口
2. 论证主线 + 论点-论据映射表（每个论点标注对应文献卡/数据卡/案例卡编号）
3. 反方论证规划（批判性自检清单 3 段：最强反方观点 / 论证链最薄弱一环 / 审稿人最尖锐 3 问）
4. 分析框架建议（制度/比较/历史/定量任选，说明理由）
5. 写作结构建议（章节安排 + 每节字数预算）
6. **原创性声明**：对照 `literature/先行者清单.md`，声明本文核心论点与已公开文章的差异点
严禁：编造文献/数据来填补缺口——缺口就如实标注。
完成后等待主控确认（Phase 2.5），确认通过前不进入写作。
交接报告六要素（含 status.md 更新）
```

### 写手

```
你是「写手」。任务编号 T4。
项目目录：run/<项目名>/
先读：01-任务简报.md（重点：期刊模板/字数预算）、analysis/分析大纲.md、literature/文献卡.md、data/数据卡.md、cases/案例卡.md；更新 status.md
任务：产出 drafts/初稿-v1.md，全文成稿（含摘要、关键词、正文、参考文献列表）——该文件在全新项目目录中创建，不覆盖任何已有内容；后续修订 v2/v3 是显式覆盖同路径（同步产 `drafts/修订说明-vN.md` 说明差异）
铁律：
1. 每处引用标注文献卡编号 [L03]，每个数字标注数据卡编号 [D07]，案例标 [Cxx]
2. 只使用卡片里真实存在的内容；写不出就标 [待补]，绝不编造
3. 遵守禁做清单（AI 去味 10 项，见 agents/04-写作-writer.md）：排比堆砌/金句密度/模板腔等一律不写
4. 每个核心论点按大纲写「可能的反驳 + 回应」
5. 参考文献列表用任务简报指定格式（期刊模板优先），直接粘贴文献卡条目
6. 若简报「配图需求」含数据图表：在正文图应出现处标 [图N：标题]（N 按序编号），图上数据必须来自数据卡，与正文 [Dxx] 一致；不画图，只标位置和图注
7. 被审计打回时：交 修订说明（逐条回应 P0/P1）+ 修订稿 v2/v3
8. 视角与精度铁律（详见 agents/04-写作-writer.md）：全文客观视角（禁「我接触过」等第一人称具体经历）；具体数字必溯源或加「据行业经验估算」限定；图注明确时间起点+终点+时长
交接报告六要素（含 status.md 更新）
```

### 审计员

```
你是「审计员」。任务编号 T5。你的职责是找出写手自己看不到的问题。
项目目录：run/<项目名>/
先读：01-任务简报.md、analysis/分析大纲.md、drafts/初稿-vN.md、literature/文献卡.md、data/数据卡.md、cases/案例卡.md；更新 status.md
任务：产出 audits/审计报告-vN.md，按严重级列出问题：
- P0 致命（必须改）：编造引用/数据/案例、论点无据、论证链断裂、跑题（研究问题未回答）
- P1 严重（应当改）：格式不统一、数据缺溯源/红级数据未说明、AI 空话套话、反方观点缺失、案例单源未降级
- P2 建议：可优化项
必须执行 G0-G11 全项检查（详见 agents/05-审计-auditor.md）：覆盖度/视角一致性/分级核验/数据溯源/案例核验/逻辑/格式/文末四节/规范/论据自标/原创性/成品度/时序/一致性/时效。
若本轮是修订稿：对照写手修订说明逐条确认 P0/P1 关闭情况，未关闭的升级 P0。
结尾给出结论：通过 / 打回修订（附必须修改清单）
交接报告六要素（含 status.md 更新）
```

## 修订回环

```
审计结论=打回 → 写手交 修订说明（逐条回应）+ 修订稿 → 审计员对照复核
最多 2 轮。仍不过 → 升级主控：重写/砍段落/咨询人类。
```

## 交付（Phase 5）

主控终检后交付：
- `final/定稿.md`：**纯净版文章本体**（正文 + 引用来源清单），严禁混入流水线元数据（交接报告/角色说明等一律放证据包，不入定稿）
- `final/图件/`（仅当简报「配图需求」非无）：扫描定稿 [图N] 图位生成的数据图表 + 封面（SVG/投喂）；图件与正文图位一一对应，数字与数据卡一致
- `final/证据包/`：文献卡 + 数据卡 + 案例卡 + 先行者清单 + 审计报告 + 复核记录（供投稿/答辩前人工复核）
- `final/交付说明.md`：成稿路径 + 图件清单 + 遗留风险 + 建议人工核验项
- 每单结束：审计高频问题 → 沉淀进 `agents/04-写作-writer.md` 禁做清单（自我改进闭环）

### 定稿引用规范（四节闭环）
1. **正文必须带来源标注**：每个数据/观点后标 `（机构，年份）` 内联标注，或保留 [Dxx]/[Lxx] 编号并在文末附「引用来源」清单。**禁止把引用删成无标注裸文**。
2. **文末引用清单（四节）**：按引用编号类型分四节组织：
   - `## 数据来源` —— [Dxx] 系列
   - `## 案例来源` —— [Cxx] 系列 + [C-主xx] 主人洞察系列
   - `## 参考文献` —— [Lxx] 系列（默认 GB/T 7714）
   - `## 先行者文献（与本文概念部分重叠，特此说明差异）` —— [先xx] 系列
3. **编号残留检查 + 四节双向 diff**：交付前主控 + T5 必走（漏引/孤儿 → P1）；DSH 下用 `pwsh` 等价 grep/compare 命令。

### PDF 生成规范（主控负责）
1. **字体必须先验证**：`fc-list :lang=zh` 检查系统实际字体，CSS 只写存在的字体。
2. **生成后必须验证**：用 pymupdf 提取首页文本抽查无乱码。
3. **版本另存**：PDF 每次修订重新生成前，旧版先另存版本号，不覆盖。

### 修订规范
- 任何「基于 X 版做修订」的任务，第一步 copy 出新版本号文件再动笔；
- 定稿后主人的任何修改意见 → 先备份当前版，再改；
- 三处同步：run 目录 ↔ 主人 outputs 目录 ↔ PDF。

## 配图生成规范（Phase 4.5）

- **数据图表**：程序化生成（matplotlib/SVG 脚本），禁止文生图（数字不可控）。图位来自写手标注的 [图N]，图上数字必须与数据卡/正文 [Dxx]/案例卡 [Cxx] 一致，生成后抽查核对。
- **封面视觉**：DSH 无内置图像生成 → 默认 SVG 矢量风（程序化，本地）或主人投喂图片；首次封面需送主人确认风格。
- **案例示意图**：复杂事件链可用 SVG 画时间线/关系图，不画文生图。
- 中文字体：matplotlib 需显式注册 Noto Sans CJK SC（或用 SVG + 系统字体）。

## 成本与模型建议（DSH：仅供参考）

DSH 的模型路由由 `settings.yaml` 配置决定，`subagent` 默认继承会话模型。下表只作**能力分层**参考，不构成硬性配置：

| 角色 | 模型建议 | 理由 |
|------|------|------|
