# 论衡（lunheng-article-pipeline）— 通用深度长文多 Agent 流水线 运行手册（v2.2.14）

> **定位（v2.2.4）**：论衡是**通用深度长文引擎**，不只用于公众号，而是可产出**学术论文、商业评论、行业分析、公众号深度长文**等各类深度长文。学术论文用 `[Lxx]/[Dxx]` 编号引用；公众号/商业评论用内联（机构，年份）引用（M 门 v2.2.4 新增内联引用分支）。

> 使用方式：主控 Agent（论衡）按本文档派发任务。角色定义见 `agents/`，模板见 `templates/`。

## 🚫 不适用场景（边界明示 — v2.1.5 新增，v2.1.5.1 修正表述）

论衡是「论文/深度文章」**写作流水线**，**擅长主动检索已发布证据 + 整合主人投喂的证据**。

**论衡能主动采集**（T1 文献检索 / T2 数据检索 / T3 案例检索 sub-agent，v2.3.0 改 T6→T3）：
- ✅ 已发布的学术文献（PubMed / CNKI / Web of Science 等数据库）
- ✅ 已发布的统计数据（教育部 / 统计局 / 行业协会等公开数据）
- ✅ 已发布的案例与报道（媒体 / 法院判决 / 行业报告等公开案例）
- ✅ 政府发布的统计 / 报告 / 调查 / 政策文件

**论衡不能主动采集**（需要主人提前准备素材投喂）：
- ❌ **一手原始数据采集**：实验设计 / 调查问卷投放 / 用户访谈 / 田野调查 → 需要主人亲自调研，原始数据投喂为「数据源」
- ❌ **统计分析**（SPSS/R/Python 跑模型）：论衡可以引用统计结果，但**不执行统计计算**。如需跑回归/聚类/因子分析，请主人用专门工具，结论以「数据 + 方法描述 + 结果」形式投喂
- ❌ **图表原始数据采集**：论衡生成的是**数据可视化**（SVG 矢量图，参考 `图表-SVG-template.md`），数据本身需主人提供。如需爬虫/OCR/语音转文字，请主人用专门工具，原始数据投喂后论衡制作图表
- ❌ **原创图片 / 视频生成**：DSH 无内置文生图——封面/插图降级为 SVG 矢量风（本地 write 生成，零外发）或主人投喂/图像 MCP，但**不能拍摄实物照片 / 录制视频**。如需实物素材，请主人拍摄后投喂文件路径，论衡可在文末引用
- ❌ **代码执行**：`exec` 类任意命令不在随包脚本白名单内；主流程默认零任意 exec。如需跑代码验证论据，请主人用专门环境执行，结果投喂为证据

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」——是，论衡主动采集；不是（是一手原始数据 / 自己拍的素材 / 自己跑的计算），主人投喂后再用。

```
5. 等完成通知 等两者完成
6. spawn 分析员 → 分析大纲产出 → Phase 2.5 送主人确认 → 通过后 spawn 写手
7. spawn 审计员 → 审计不过 → 写手交修订说明 + 修订稿（≤2 轮）→ 终检交付（含证据包）
```

## 调度模型健康度预检（v2.3 新增，教训 #35）

> 实战中 T3 连续 3 个模型（deepseek-v4-pro / minimax-m3 / claude-opus-5）全部超时，论衡主控亲自产出大纲。本机制旨在预判 + 降级 + 硬卡超时。

**主控 T 派发前必须执行 3 步**：

1. **健康度预检**（避免一上来派发到已知慢模型）：
   - deepseek-v4-flash：轻量检索默认，置信度高
   - deepseek-v4-pro：推理/分析默认，但有过超时历史（教训 #35）
   - minimax-m3：推理/分析 fallback，但近期 T3 三连超时主要责任方
   - claude-opus-5：审计顶配（T7 审计员主模型），但成本高 + **有 kkaiapi 接口静默无响应前科（教训 #119）**
   - **T7 审计员派发前必查**（v2.3.1 新增，教训 #119）：T7 属「批判审计=顶配」能力档，候选池见 [`_shared/模型路由.md`](_shared/模型路由.md) §二（**唯一真源**）；派发前 1-token ping 预检，若顶配模型静默无响应 → 走候选池下一档，并在产物头标注兑底事实。
  - **角色级 fallback 分级（v2.3.12 P0-2 能力抽象，已取代 v2.3.7 硬编码链）**：v2.3.7 的硬编码 fallback 链（T7 审计 fallback 链 / T5 写手链 / T4 分析链 / T1-T3 检索链）已废弃，统一为「能力档 + 候选池」（候选池唯一真源见 [`_shared/模型路由.md`](_shared/模型路由.md)），角色卡不再硬编码单一模型，候选池按本机可用模型自动适配。
   - **主控派发前查 status.md 顶部「论衡本轮可用模型」表**（论衡会话启动时自动填）

2. **超时介入（DSH 精简版，无 8 分钟硬卡）**（实战中旧阈值过宽，介入太晚）：
   - T 派发后长时间无产出 → 主控用 `list_agents` 查看并介入（无 8 分钟硬卡；旧协议仅参考（历史见 git log））
   - 不允许「静默干等」

3. **主控兜底产物明确标注**（v2.0 机制没标 → 写手不知道这是主控产物不是 T 产物）：
   - 任何 T 阶段主控亲自产出 → 必须在文件头标注「主控兜底 v1.0」+ 注明失败原因
   - 写手收到时能识别这是非 T 产物，调整引用对齐策略

## 模型配置与更换指南（v2.3.10 补全）

> **背景**（主人 2026-08-22 指出）：operations.md 引用「模型配置与更换指南」段，但 v2.3.0 重构时 TOC 加入了三个子标题（`三层模型配置`/`更换的自由、途径、权限`/`能力分层原则`），**正文未补**——造成文档漂移（教训 #60 双形式同步漂移反模式）。本节为 v2.3.10 补全。

### 三层模型配置（从外到内，v2.3.13 能力抽象后）

v2.3.13 起模型不再硬编码，模型解析分**三层**（从唯一真源到兑底兜底）：

1. **[`_shared/模型路由.md`](_shared/模型路由.md) 四档能力表**（能力档 + 角色 + 候选池 + 实战选型建议，**唯一真源**）
   - 检索=便宜快 / 分析写作=强推理 / 批判审计=顶配 / 主控=稳定路由（终检 T8 不参与分档）
   - 每个能力档的候选池按优先级排列，换系统/换模型改这一处即可（**本手册与角色卡不再重复该表**）

2. **Phase 0 模型自检**（运行时映射）
   - 主控启动扫本机可用模型（按 DSH `settings.yaml` 配置），每个能力档从候选池选第一个可用模型
   - 顶配档候选池全不可用 → 显式告知主人，禁止静默降级

3. **外部网关模型**（仅兑底兜底，非硬配置）
   - `agents.list[].model.primary + fallbacks` 仅作 Phase 0 自检失败时的最后兜底
   - 不再需要为论衡单独建 agent 或手动配模型（v2.3.13 skill 化）

### 更换的自由、途径、权限

| 层面 | 谁能改 | 怎么改 | 生效时机 |
|---|---|---|---|
| agent 配置 | 主人（DSH settings.yaml / 会话预设） | 需 backup 后改，gateway 重启生效 | 重启后 |
| 角色卡推荐模型 | 主人 / 主控（经主人同意） | edit 角色卡顶部，版本维护脚本 同步 | 下一轮会话 |
| 本轮可用模型 | 主控在 status.md 顶部填 | write status.md 头部「本轮可用模型」表 | 即时生效 |

**主人的自由度**：
- ✅ 任意层都可改，无需经过论衡批准
- ✅ 任何可用模型都可接入（含 Ollama 本地）
- ✅ fallback 顺序可自由调整
- ⚠️ 改完需**重跑论衡首单测试**，验证模型组合不超时/不崩

### 模型能力抽象 + 自检 + 预算闸门（v2.3.12 新增，P0-1/P0-2/P0-3）

> **背景**：v2.3.12 前模型名硬编码在角色卡/SKILL.md，换系统即失效；且主控无「余额不足」预检，claude-opus-5 余额不足时顶配审计**静默降级**（本机测试 T6/T7 全兑底 minimax-m3，A 级抽验仅 17%）。

- **能力抽象（P0-2）**：模型名 → **能力需求 + 候选池**（检索=便宜快 / 分析写作=强推理 / 批判审计=顶配 / 主控=稳定路由），候选池见 [`_shared/模型路由.md`](_shared/模型路由.md)。
