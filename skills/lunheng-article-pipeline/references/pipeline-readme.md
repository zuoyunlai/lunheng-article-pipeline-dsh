# 论衡（lunheng-article-pipeline）— 通用深度长文多 Agent 流水线 运行手册

> **定位（v2.2.4）**：论衡是**通用深度长文引擎**，不只用于公众号，而是可产出**学术论文、商业评论、行业分析、公众号深度长文**等各类深度长文。学术论文用 `[Lxx]/[Dxx]` 编号引用；公众号/商业评论用内联（机构，年份）引用（M 门 v2.2.4 新增内联引用分支）。

> 使用方式：主控 Agent（论衡）按本文档派发任务。角色定义见 `agents/`，模板见 `templates/`。

> **⚠️ v2.1.7 Phase 0 强同意关卡**：本流水线下面任何一个阶段调用以下工具，**会**发数据到**外部服务商**——主控必须告诉主人明示同意，否则不可调用：
>
> | 工具 | 外发服务商 | 发送内容 |
> |------|---------|---------|
> | `web_search` | DSH 配置的 web provider | 查询关键词 |
> | `read_page`（可选） | DSH 配置的网页读取引擎 | 目标 URL |
> | 封面/插图 | —（DSH 无内置文生图） | 降级 SVG 矢量风（本地）或主人投喂，不外发 |
> | 主控推理调用 | 当前模型 provider（deepseek/MiniMax/Anthropic） | 文献/数据/案例/草稿/大纲/全文 |
>
> **项目名/主题/论文纲要可能含未公开信息**——主控 Phase 0 必须问主人：
> 1. 同意全部外发？（默认）
> 2. 脱敏措辞 + SVG 封面 + 本地 Ollama（gemma4:31b）推理？
> 3. 只同意一部分（如文献检索同意、封面生成拒绝——DSH 无文生图，封面降级 SVG/投喂、不外发）？
>
> 主人选定后写入 `01-任务简报.md` 作为「外发同意项」记录。**未同意前不可跳到 Phase 1**。

## 🚫 不适用场景（边界明示 — v2.1.5 新增，v2.1.5.1 修正表述）

论衡是「论文/深度文章」**写作流水线**，**擅长主动检索已发布证据 + 整合主人投喂的证据**。

**论衡能主动采集**（T1 文献检索 / T2 数据检索 / T6 案例检索 sub-agent）：
- ✅ 已发布的学术文献（PubMed / CNKI / Web of Science 等数据库）
- ✅ 已发布的统计数据（教育部 / 统计局 / 行业协会等公开数据）
- ✅ 已发布的案例与报道（媒体 / 法院判决 / 行业报告等公开案例）
- ✅ 政府发布的统计 / 报告 / 调查 / 政策文件

**论衡不能主动采集**（需要主人提前准备素材投喂）：
- ❌ **一手原始数据采集**：实验设计 / 调查问卷投放 / 用户访谈 / 田野调查 → 需要主人亲自调研，原始数据投喂为「数据源」
- ❌ **统计分析**（SPSS/R/Python 跑模型）：论衡可以引用统计结果，但**不执行统计计算**。如需跑回归/聚类/因子分析，请主人用专门工具，结论以「数据 + 方法描述 + 结果」形式投喂
- ❌ **图表原始数据采集**：论衡生成的是**数据可视化**（matplotlib/SVG），数据本身需主人提供。如需爬虫/OCR/语音转文字，请主人用专门工具，原始数据投喂后论衡制作图表
- ❌ **原创图片 / 视频生成**：DSH 无内置文生图（原 OpenClaw `image_generate` 不可用）——封面/插图降级为 SVG 矢量风（程序化，本地）或主人投喂图片；**不能拍摄实物照片 / 录制视频**。如需实物素材，请主人拍摄后投喂文件路径，论衡可在文末引用
- ❌ **代码执行**：原 OpenClaw 环境 `exec` 被 deny；DSH standard 预设含 `pwsh`/`bash`，如需跑代码验证论据，经主人同意后主控/子代理可执行，结果投喂为证据

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」——是，论衡主动采集；不是（是一手原始数据 / 自己拍的素材 / 自己跑的计算），主人投喂后再用。

> 实战中 T3 连续 3 个模型（deepseek-v4-pro / minimax-m3 / claude-opus-5）全部超时，论衡主控亲自产出大纲。DSH 下模型路由由 `settings.yaml` 决定、无脚本级 fallback 链，本机制精简为「能力分层参考 + 超时介入 + 兜底标注」。

**主控 T 派发前**：

1. **能力分层参考**（避免一上来派发到已知慢模型）：
   - deepseek-v4-flash：轻量检索默认，置信度高
   - deepseek-v4-pro：推理/分析默认，但有过超时历史（教训 #35）
   - minimax-m3：推理/分析 fallback，但近期 T3 三连超时主要责任方
   - claude-opus-5：审计顶配，但成本高
   - 装「分档预设」后按角色分档自动路由（`LUNHENG_*_MODEL`）；否则主控在派发话术里说明用哪个档（未挂载则继承会话模型）

2. **超时介入（无 8 分钟硬卡）**：
   - T 派发后长时间无产出 → 主控用 `list_agents` 查看子代理状态（真卡 vs 模型思考中）
   - 判定超时 → 介入（拍醒/换模型重派/接受 partial/写介入日志/重试上限 2 次）

3. **主控兜底产物明确标注**（v2.0 机制没标 → 写手不知道这是主控产物不是 T 产物）：
   - 任何 T 阶段主控亲自产出 → 必须在文件头标注「主控兜底 v1.0」+ 注明失败原因
   - 写手收到时能识别这是非 T 产物，调整引用对齐策略

```
若本轮是修订稿：对照写手修订说明逐条确认 P0/P1 关闭情况，未关闭的升级 P0。
结尾给出结论：通过 / 打回修订（附必须修改清单）
交接报告六要素（含 status.md 更新）
```

## 修订回环

```
审计结论=打回 → 写手交 修订说明（逐条回应）+ 修订稿 → 审计员对照复核
最多 2 轮。仍不过 → 升级主控：重写/砍段落/咨询人类。
```

### v2.2.0 修订回环 ≤2 轮硬约束（教训 #64 子教训 3）

```
第 1 轮：T5 打回 P0/P1 → T4 修订 → T5 复核
第 2 轮：若仍有 P0/P1 未关闭 → T4 再修订 → T5 再复核
第 3 轮触发 → Acknowledged Limitations 模式：
  - T5 在「结论」段显式列「未关闭 P0/P1」清单
  - 主控 T7 把清单搬入 final/局限性.md
  - T7 终检通过，但「通过」≠「完美」
  - 主人决定：接受 / 加主人深度洞察 / 重走流水线
```

**为什么 ≤2 轮**：「不要无限循环。无限循环是 LLM 的舒适区陷阱」—— 论衡主人口吻。

## M 机械化硬门（v2.2.0 新增，教训 #64 + #65；v2.2.8 合并完整版）

> **核心**：T7 终检前**必读** `references/_shared/M-Gate-Algorithm.md`（合并完整版），按伪代码执行 M-Form 6 项 + M-Exist 3 项 + M-Integrity 2 项。

### M 门算法规约（v2.2.8 合并完整版）

**不引入 Python 脚本**——M 门由 LLM 兜底执行：
1. 主控用 `read` 工具读 `references/_shared/M-Gate-Algorithm.md` 全文
2. 主控用 `read` 工具读 `final/定稿.md` + `final/证据包/` 所有文件
3. 主控按伪代码推理执行 M-Form 6 项 + M-Exist 3 项 + M-Integrity 2 项
4. 主控用 `write` 工具产出 `final/M-Gate-Report-v2.2.4.json`
5. **exit 0 才能返回**——M-Form 失败 = 触发 T4 修订；M-Exist 失败 = 触发主控补检索或砍论点

**M-Form 6 项**：
- M-Form-1：引用标注完整性（正文所有 `[Dxx][Cxx][Lxx][先xx][C-主xx]` 编号 > 0）
- M-Form-2：文末四节存在性（数据来源/案例来源/参考文献/先行者文献 4 节齐全）
- M-Form-3：临时编号残留（v2.2.1.2 双向 diff 算法，正文有而文末无才算残留）
- M-Form-4：角色元数据泄露（无 T1-T8/交接报告/六要素/论衡主控/子代理/反哺报告/角色卡）
- M-Form-5：过程语言残留（无 v[0-9] 稿/初稿/草稿/修订说明/据行业经验估算未标记）
- M-Form-6：信任级别标注完整性（数据卡每条必填 已发布/主人投喂/二手转引，双格式兼容）

**M-Exist 3 项**：
- M-Exist-1：文末四节双向 diff（漏引 / 孤儿清单为空；内联引用模式走可回溯性检查）
- M-Exist-2：证据包文件完整性 sha256（写入 final/交付说明.md「证据包指纹」段）
- M-Exist-3：数据信任级别一致性 diff（正文引用 vs 数据卡条目，信任级别全填）

**M-Integrity 2 项**（阶段闸门）：M-Integrity-1 T2.5（T2→T3 前）、M-Integrity-2 T5.5（T5→终检前），详见 M-Gate-Algorithm.md。

**借鉴出处**：vincentjiang06 paper-writer objective/verify gate 硬约束理念 + ARS M1-M7 失败模式组织。
**论衡哲学化**：「**形式合规 ≠ 存在性合规 ≠ 信任一致**」+ 「**M 门由 LLM 兜底执行，零 shell 依赖**」（DSH 下可用 `pwsh`/`bash`，但 M 门判定不依赖执行脚本）。

### 定稿引用规范（主人 2026-08-12 确立，水与麦单修正 + v2.1.4 四节闭环，教训 #47）
1. **正文必须带来源标注**：每个数据/观点后标 `（机构，年份）` 内联标注（公众号风格），或保留 [Dxx]/[Lxx] 编号并在文末附「引用来源」清单（编号→机构→年份→标题→URL）。**禁止把引用删成无标注裸文**——删掉引用即删掉可信度。
2. **文末引用清单（四节，v2.1.4 起强制）**：按引用编号类型分四节组织：
   - `## 数据来源` —— [Dxx] 系列，每条含编号+机构+年份+标题+URL
   - `## 案例来源` —— [Cxx] 系列 + [C-主xx] 主人洞察系列；主人洞察照写 1 条「主人深度洞察」说明并注明出处（任务简报第 X 行）
   - `## 参考文献` —— [Lxx] 系列，每条按任务简报指定格式（默认 GB/T 7714）
   - `## 先行者文献（与本文概念部分重叠，特此说明差异）` —— [先xx] 系列，每条含机构+年份+标题+URL + 与本文差异点简述
   
   **测算值/综合判断条目（如 [D03 测算值] [D105 综合判断]）**如实标注"测算值/综合判断（基于 Dxx/Dxx）"，**不伪称有第三方来源**。
3. **编号残留检查 + 四节双向 diff（v2.1.4 机械化校验，教训 #47）**：交付前主控 + T5 审计必走。以下为校验逻辑（shell 示意；DSH 下用 pwsh 或 DSH 内置 grep/Select-String/Compare-Object 等价实现，或由主控按此逻辑推理执行）：
   ```bash
   # 拿正文所有编号
   grep -oE "\[D[0-9]+\]|\[C[0-9]+\]|\[C-主[0-9]+\]|\[L[0-9]+\]|\[先[0-9]+\]" final/定稿.md | sort -u > /tmp/intext.txt
   # 拿文末四节条目编号（以 数据来源/案例来源/参考文献/先行者文献 四节为界）
   awk '/^## 数据来源/,/^## 案例来源/' final/定稿.md | grep -oE "\[D[0-9]+\]" | sort -u > /tmp/data.txt
   awk '/^## 案例来源/,/^## 参考文献/' final/定稿.md | grep -oE "\[C[0-9]+\]|\[C-主[0-9]+\]" | sort -u > /tmp/case.txt
   awk '/^## 参考文献/,/^## 先行者/' final/定稿.md | grep -oE "\[L[0-9]+\]" | sort -u > /tmp/ref.txt
   awk '/^## 先行者/{flag=1;next} /^## /{flag=0} flag' final/定稿.md | grep -oE "\[先[0-9]+\]" | sort -u > /tmp/xian.txt
   # diff
   comm -23 /tmp/intext.txt <(cat /tmp/data.txt /tmp/case.txt /tmp/ref.txt /tmp/xian.txt) # 漏引（正文有但文末无）→ P1
   comm -13 /tmp/intext.txt <(cat /tmp/data.txt /tmp/case.txt /tmp/ref.txt /tmp/xian.txt) # 孤儿（文末有但正文无）→ P1
   ```
   不通过 → 写手必须补/删，主控必须 grep 复核，**不通过不交付**。详细规范见写手卡铁律 #9 + 主控卡终检必查项 ⑨ + 审计卡 G4。

### PDF 生成规范（主控负责，水与麦单修正）
1. **字体必须先验证**：Linux 用 `fc-list :lang=zh`，Windows 用 PowerShell 查已装字体（`Get-ChildItem $env:WINDIR\Fonts` 或 .NET InstalledFontCollection）；CSS 只写实际存在的字体（本机为 Noto Serif SC/微软雅黑/宋体），写不存在的字体名（如未安装的 Noto Serif CJK SC）会导致乱码。
2. **生成后必须验证**：用 pymupdf 提取首页文本抽查无乱码，检查页数与末页内容。
3. **版本另存**：PDF 每次修订重新生成前，旧版先另存版本号（如 `-v1.pdf`），不覆盖。
