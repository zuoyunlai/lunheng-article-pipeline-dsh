### 2.1 【R1 · P1】`sessionLog` / `sessionRoot` 被读面围栏拦死

**现状（逐字，`lib/tools.js`）**：

- `:546`：`argv = ['--project', resolveReadablePath(exec, args.project, 'project'), …]`
- `:554`：`argv.push('--session-log', looksLikePath ? resolveReadablePath(exec, v, 'sessionLog') : v)`
- `:557`：`argv.push('--session-root', resolveReadablePath(exec, String(args.sessionRoot).trim(), 'sessionRoot'))`
- 而 `resolveReadablePath`（`:107-119`）只放行**会话工作区 ∪ `os.tmpdir()`**。

**真源判定**：

| 侧 | 事实 |
|---|---|
| 文档侧 | `SKILL.md:86`：`handoff-check --role T8 --require-gates --session-log <本会话 id> [--session-root $DSH_HOME/sessions]`（方括号 = 读作可选）；`lib/tools.js:492-494` 称「`requireGates + sessionLog` 是 Phase 5 的标准调用形态」 |
| 脚本侧 | `handoff-check.mjs:209-211`：`--session-log` 传 id 且**未给** `--session-root` → `exit 10`；脚本刻意不做 `DSH_HOME` 兜底（防跨宿主假红，见 `:202-204`） |
| 围栏侧 | `$DSH_HOME/sessions`（或 `~/.dsh/sessions`）必然在工作区与 tmpdir 之外 → **必被拒** |

⇒ 工具面同时容忍两种入参形态（会话 id / 路径），但**路径形态必被围栏拒**、**id 形态必因缺 `--session-root` 而 exit 10**——两形态均不可达。**这是「接线 ≠ 可用」的复发**：v19.19.0 只测了「参数存在」，没测「参数组合能跑到脚本」。

**修订方案**：

1. `lib/tools.js` 新增导出 `sessionLogRoots()`：由 `DSH_HOME`（缺省 `~/.dsh`）派生 `sessions` 只读根；
2. `resolveReadablePath(exec, p, label, opts)` 增加**可选** `extraRoots`（仅对**显式登记**的调用点生效，默认不放宽）；
3. handoff 的 `sessionLog` / `sessionRoot` 传 `{ extraRoots: sessionLogRoots() }`；
4. `sessionRoot` 描述去掉「默认 `$DSH_HOME/sessions`」的错误承诺，改为「传 id 时**必须给**」；
5. `SKILL.md:86` 去掉 `[--session-root …]` 的方括号（它现在是必填形态）。

**验收判据**：

1. 新增 `tests/session-log-fence.test.mjs`：`~/.dsh/sessions/...` 在**未登记 extraRoots** 时抛 `INVALID_ARGS`、登记后放行；`sessionLogRoots()` 随 `DSH_HOME` 派生；
2. 源码钉：handoff `execute` 段内 `resolveReadablePath(exec, …, 'sessionLog'|'sessionRoot', { extraRoots` 逐字存在；
3. `node --test tests/session-log-fence.test.mjs` 全绿；`tests/batch21` 旗标对账仍绿。

### 2.3 【R3 · P2】`placeOnly` 判据把「候选数」当「替换数」

**现状（逐字，`lib/index.js:672`）**：

```js
const placeOnly = aggReplacements > 0 && Object.entries(aggCounts).every(([k, v]) => v === 0 || k === "place")
```

**真源判定**：

- `aggCounts` 含 `personLow`（`ethics-sanitize.js:223` 起九个键）；`personLow` = **候选数**（姓氏命中但无角色词，默认不改写），近乎恒 > 0；
- 因此「除 place 外全 0」在真实文本上几乎不可能成立 → v19.14.0 的 place-only 豁免**实际失效**；
- B14-③ 只修了「低置信候选**单独**触发注入」，没修「低置信候选**破坏** place 豁免」。

**活体证据（本会话，逐字）**：

> 〔论衡 H2 伦理脱敏〕basic 模式：命中替换 **1** 处（place=1）；另有**低置信候选 95 个未改写**……待复核类别：person-low-confidence。

即：1 个地名 + 95 个候选 → 豁免失效 → 注入约 190 字。本批审计期间**同形标记共出现 4 次**。

**修订方案**：

- 判据只看**真实替换**：`person`（= high + low 的合计）与 `personLow`（候选）**不参与** place-only 判定；`personHigh`（真替换）参与。
- 补一条「候选数不消失」的边界：`personLow` 仍在 `ethicsSanitized.counts` 与工具面。

**验收判据**：

1. 新增行为测（`tests/h2-h5-listeners.test.mjs`）：构造 `place ≥ 1 且 personLow ≥ 1 且 replacements === 1` 的文本 → `additionalContexts` **为空**，且 `ethicsSanitized.counts.personLow ≥ 1`（非空转 fixture）；
2. 既有 `H2 ③`（纯候选不触发）与 `H2 ①`（byType 不印 `person`）仍绿。
