## 六、已知边界与如实声明

1. **本批自查出一个由本批引入的真缺陷并已修（SELF-1）**：`maintainers.md` 的三处外部引用（context-mode 的 ADR-0001/0004 与 Tier-2 冒烟工作流）**只写了路径、未带行号**，而 `link-check` 的提取规则是「含 `/` + 扩展名白名单的 code span」——**带 `:行号` 的引用因扩展名正则不命中而免检**，不带行号的被判为**本仓相对路径** → **3 条未归类断链**（测试实测红）。
   **修法**：按该门设计的正解**标明属主**（改为「context-mode 的 **ADR-0004（…）**」并加一行**属主标注**），**未新开 `CROSS_SKILL_*` 豁免**——判据：`link-check` 的白名单是「属主登记表」，为一次性外部引用开三条常驻豁免，会让门失去「未归类」这一信号。

### 9.1 EXEC-4 实核 —— **孤证被证伪，但政策是对的**（本轮最重要的区分）

**实核方法**：spawn 一个**只读探针子代理**，要求它 ① 逐个列出**真实注册**的工具 ② 报告是否含 `pwsh` ③ **实际执行**一条只读命令贴真实输出 ④ 报告其提示中是否有禁止执行脚本的规则。

**实测结果**：

| 问题 | 结论 |
|---|---|
| 子代理是否有 `pwsh` | **有**（真实注册名 `pwsh`；无独立 `bash`） |
| 能否实际执行 | **能**：`echo exec-probe-ok` → `exec-probe-ok`；`node --version` → `v24.20.0` |
| 是否有禁止执行脚本的规则 | **没有**（全库 grep 亦零命中） |

→ **`segment-chars.mjs:19` 原文「T5 子代理无脚本执行能力（论衡主流程零 exec）」两处均不准**：
① 「写手不调 shell」是**任务约定**、不是能力缺失（`05-写作-writer.md:11`「写手**本任务约定不调用 shell**」，v2.3.18 / v2.5.2-dsh.4 审计修订）；② 论衡**不是**「零 exec」（`glossary.md:316` 明写「论衡**不是零 exec**」）。

**⚠️ 但政策必须保留 —— 这是本轮最容易改错的地方**：`05-写作-writer.md:31` 已由 **v18.8.0 P1-4 专门收口**过「写手不调 shell 矛盾」，其设计意图是**「字数口径与权威核验分离」**（T5 估算 → 主控取脚本实值 → T7 用实值核，三方不各执一词）。**若因「子代理其实能跑脚本」就去放开 T5 自测，等于推翻一个已有定案**，正撞 `glossary.md` §十二「本包与官方的刻意偏离」所要防的「把刻意设计当疏漏改掉」。
→ **处置：政策一字不动；只改注释表述**，把「能力不能」改为「任务约定不」并补实测事实与「政策不变」一句，防后人据此**放宽约定**或**误判环境受限**。

### 9.2 A2b 试点（**回顾性**，不新建项目）

计划的 A2b 判据是「三卡**卡片条数 ≥ 交接报告自报的取回条数**」。本轮用**现成 `run/*` 产物**做试点（成本 ≈ 0），两项发现：

1. **「## 已跳过」段的实际使用分布**（19 个 `素材加载清单.md`）：命中 0 处的项目有 4 个（`AB-ai-content-farm-B` / `海外驻军-主权分离` / `筛选竞赛的均衡` / `论衡M门自省`），其余 1–11 处。→ **佐证「可选 = 等于不写」**，即 §一的「已跳过改必填」是对的。
2. **判据没有数据源**：`T1/T2/T3` 三卡**均未要求报「取回条数」**（grep 零命中），`agents-log.md` 亦无该字段；三卡只报**落卡条数**。→ **A2b 原设计的判据在当前产物面无法计算**。

### 9.3 ⚠️ SELF-3 —— 本批**自造的第三个缺陷**，且形态最隐蔽

**缺陷**：§一 A2 的卡层规则初版写「**卡片条数 = 实际取回条数**」。核查后发现它**同时踩两个坑**：

1. **撞既有条数上限**：01 卡「文献卡 **8-15 条**」/ 02 卡「**15-25 条**」/ 03 卡「**3-5 条**」——要求「条数 = 取回数」与上限**直接冲突**。
2. **重建它本想防的失败模式**：`02-数据检索-data-scout.md:75` 有 **反凑数纪律**（v2.5.2-dsh.9 教训：数据卡 30 条中 **20+ 为「缺口」占位**，**数量上限诱发填充**）。把「不得静默丢弃」写成「**数量必须相等**」，等于把**留痕要求改造成了配额要求** → 必然诱发填充。

**修法（已落地）**：`检索注入防御.md` §落盘不得预筛 第 1 条由「条数相等」改为「**核验通过却未落卡的条目必须留痕**」（卡内「本轮未落卡」子节或交接报告一行：`已核验未落卡 N 条 + 理由`；无则显式写「无」），并加**两条边界**（不改既有条数上限 / 不得为凑数而填充）。
> **教训（可复用）**：**「不得静默丢弃」的正确机械形态是「留痕」，不是「数量相等」。** 凡把「禁止某事」写成数量约束的规则，都要先问一句：**这个数量能不能通过「多写几条」来满足？** 能，就是伪装的配额要求。
