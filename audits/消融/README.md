# 消融读数（`audits/消融/`）

> 性质：**仓库级维护目录（不随包）**——运行期角色（T0-T9）不读它；它服务「机制该不该留」这个维护期问题。
> 缘起：[`反哺报告-AgentWrite借鉴评估-v1.md`](../反哺报告-AgentWrite借鉴评估-v1.md) §三 A1（**减配版**：只做存量回放）。
> 夹具：`node scripts/ablation-report.mjs [--run-dir <dir>] [--limit N] [--json] [--out <file>]`

---

## 一、它治什么

本仓机制**只增不减**——31 个随包脚本、25 项 M 门、9 角色、G14 三层防御、B 轨深化轮、期刊匹配、auto_cite……每一项都消耗 token 与步数（交付说明「成本指标」正在记实测成本），但**没有任何一处回答「关掉它，质量掉多少」**（实测：技能目录内 `消融|ablation` **0 命中**）。后果双向：

1. **已失效的机制长期空转**（先例：G14 早闸因实测「产出为零」被删，`references/gates/14-中文AI痕迹-gate.md:10`）；
2. **承重机制被精简时无法预判损失**。

本目录把「该删哪个」从轶事变成**可复算的读数**。

## 二、硬纪律（四条，缺一条读数就不可用）

1. **只做存量回放，禁止为做实验重跑完整项目**——一次完整项目数小时（`SKILL.md` 实测 17 个有效项目里 8 个跨度 ≥8 h）。开/关 A/B 需配对实验，**本期刻意不内置**。
2. **先定口径，再读数**——两个必查项：① 该脚本的 `exit 3` 是「仅 P2 软提示」还是缺陷？（混算会把「有提示」读成「有缺陷」）；② 该机制对本稿**体例是否适用**？（非 IMRaD 且未传体裁旗标 → **N/A**，口径照抄 `quality-score.mjs:223-229`，**不进分母**）
3. **未测 ≠ 通过**——LLM 判定类机制（G14 / G1 / G3 / G5 / G6 / G7 / G10 与 T6/T7/T9）本夹具**不产出任何数字**；缺即标「未测」，不得读成「已核」。
4. **样本量写进结论**——`n < 5` 只报读数、**不下机制判定**。

## 三、报告格式（照此写，便于逐轮对照）

```markdown
# 消融读数 — <机制名>（<轮次>）
## §0 性质与授权          ← 谁下令、哪一批、**是否预注册**（见下「诚实条款」）
## §1 方法与覆盖边界        ← 夹具 / 样本 / 适用性判据 / 已做的口径修正
## §2 读数                 ← 夹具原样输出（机器生成，禁止手工转录）
## §3 判定                 ← **能说什么 / 不能说什么**（分开写，等长）
## §4 后续                 ← 再议触发条件 + 下一轮改进项
```

### 诚实条款（本目录特有）

- **预注册纪律**：QLT-6 的判据必须**执行前冻结**。本目录首轮读数（`QLT-7-*`）**是先跑后补判据**，故其文件内**如实标注「非预注册」**——不得借用 QLT-6 的方法论信用。
- **循环风险**：任何阈值在**同一批稿**上标定过的机制，其「0 命中」是**构造成立**的，**不得**作为该机制有效/无效的证据（可读性剖面四指标即是此例）。
