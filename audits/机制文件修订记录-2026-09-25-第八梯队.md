## 二、逐条改动与验证

### L-67 退出码撞码收口（三处最后残留）

**缺陷**：这三个脚本**都不做内容判定**，却把「未知参数 / 参数值非法 / 未给模式 / 会话缓存不存在 / settings.yaml 读不到」一律记 `exit 1`。而 `1` 在 M 门语义里是「**P1 内容失败**」——主控统一按 0/1/2/3/10/70 读码时，会把「`--top` 写错」读成「正文有 P1 残留」并**误触发 T5 修订轮**（多跑一轮 = 一次完整写手 spawn）。这正是 v18.0.5 引入 `exit-guard` 要消灭的那类撞码，当年这三个文件漏改。

**修法**：一律改 **exit 10**（参数或路径错）。判据一句话写进 `AGENTS.md`：**只要脚本不做内容判定，它的 `1` 就一定是撞码**。

- `token-budget.mjs`：7 处（用法错 2 + 路径错 1 + 其余经 guard）
- `token-cost.mjs`：7 处（未知参数 / 数值非法 / 缓存缺失 / `--project` 无日志 / 未提取到会话 ID / Node 版本不足 / 未给模式）
- `model-routing.mjs`：3 处（用法错 / settings.yaml 读不到 / 未解析到 provider）

**连带更新**（同一事实不得两处不一致）：脚本头注释退出码表 ×3、`docs/troubleshooting.md` §8、`AGENTS.md` 闸门行、`M-Gate-Algorithm-appendix.md` §1.3、`EXIT_CONTRACT` 三行。

**验证**：`tests/batch8-scan-surface.test.mjs` 逐条钉死（4+4 组参数各断言 exit 10）+ 源码级断言「两个 token 脚本不再出现 `process.exit(1)`」；`tests/scripts.test.mjs` 三处编码旧契约的断言同步改为 10。

### L-68 退出码契约覆盖面（13/23 → 23/23，并把判据机械化）

**缺陷**：`EXIT_CONTRACT` 是人工维护的表——新增脚本「装了 guard 却忘了登记」，等于给自己开了一个「表外退出码随便用」的后门，而**没有任何门会看这张表完不完整**。

**修法**（两步，缺一不可）：
1. 补齐 10 处缺失登记（`apply-compression-cycle` / `apply-revision-cycle` / `cite-coverage-check` / `fix-gates` / `journal-fit` / `lunheng-stats` / `meta-synthesize` / `methodology-check` / `segment-chars` / `structure-check`），全部按脚本内字面量 + guard 的 10/70 实测解析；
2. 新增 `EXIT_GUARDED_EXEMPT`（**当前为空**）与覆盖面断言：**凡真 import `_lib/exit-guard.mjs` 的随包脚本必须登记**，豁免须写明理由、不得静默跳过。

**验证**：新用例独立复算一遍该判据（不复用门的实现，防门自己退化）；门的 note 现在输出「覆盖面：凡 import exit-guard 的脚本 100% 已登记（豁免 0 个）」。

### L-69 零改动不得写出「下一版」

**缺陷**：`apply-diff` 只要清单**解析出条目**（哪怕全部因「定位不到」被跳过、正文逐字节未变）就写盘 + 报 `written: true` → 产出与输入**逐字节相同**的 `初稿-vN+1.md`。主控在修订说明里照抄 `han.delta = 0` 时看似正常，但下游会把这份「未修订的正文」当修订版继续流。与 v18.2.6 修掉的「清单 0 条仍写盘」是同一类假成功，只是触发条件不同（那次 0 条目，这次 0 改动）。

**修法**：写盘前比对 `text === readFileSync(targetPath)`；相同则 `noop = true`、**不写盘、不留 `.bak`**，并打印可操作提示（「若这不是预期：检查清单『现况』行是否与正文逐字一致」）。`--in-place` 亦然——写回同一份内容只会平白多出一个回滚点。

**验证**：2 条对照用例（零改动 → 不写盘 + `noop:true` + 源正文逐字节不变；**确有改动 → 照常写盘**，防修 noop 把正常路径一起改坏）。

### L-70 `md2html` 围栏感知（两处静默失真）

**缺陷**：`md2html` 逐行跑行首正则，**完全不认 ` ``` ` 围栏**：
- 围栏内的 `# 标题` 被升格 `<h1>`/`<h2>` → 示例代码变成文档结构，导出件层级错乱；
- 围栏内的 `[图N：…]` 被当真图位去配图（示例代码被替换成一张图），而 `figurePlaceholders` 也把围栏内图号计入「正文引用」→ **与 M-Form-9 的孤儿图件判定口径不一致**。

**修法**：
1. `md2html.mjs` 增围栏配对扫描（口径与 `_lib/sections.mjs` 的 `maskFences` **一致**：行首 ≤3 空格 + ≥3 个 `` ` `` 或 `~`；未闭合到文末），围栏整体渲染为 `<pre class="md-fence" data-info="…"><code>…</code></pre>`，块内**不解析**标题/列表/图位；内容转义（示例里的 `<script>` 不得被浏览器当标签）；补 `.md-fence` 样式。
2. `_lib/svg.mjs` 的 `figurePlaceholders` 改走 `maskFences`（**逐字节等长遮罩**，偏移不变，正则行为与原实现一致，只是围栏内的方括号不再匹配）。

**验证**：端到端用例断言「真 H1/H2 在、围栏内假标题不在、`<li>` 不在、正文图位 0 个、无缺图占位元素、围栏内容原样保留」。

### L-72 SVG `<style>` 处置 + `--report` 目录口径

**缺陷 ①**：`DANGEROUS` 有 `<script>` / `<foreignObject>` / `on*` / `javascript:`，**没有 `<style>`** → `<style>@import url(https://evil.example/x.css)</style>` 通过 sanitize 且**零告警**；导出 HTML 一打开即按 `@import` 外发——而本包对「外部资源引用」的既有口径是**必须告警**。

**修法**：`<style>` 块与标签一并**剥离 + 告警**（本包图件由主控手写，样式走元素属性，`<style>` 不是支持形态；剥离比放行安全）。同步 `references/operations.md` 与 `audit-checklist-quickref.md` 的「禁止」清单（**一事实一处**）。

**缺陷 ②**：`--report` 目标目录不存在时口径不一——`m-gate-check` / `final-check` 在调用前自己 `mkdirSync`，其余 6 个（apply-diff / cite-coverage / structure-check / methodology-check / journal-fit / meta-synthesize / consistency-check）**没有**：temp 落盘那步 ENOENT → exit 10（码对，但报错只说「路径错」，主控多半反复试写法）。

**修法**：建目录统一到 `writeReport()`（`recursive: true` 幂等），且**排在同文件守卫之后**——拒绝路径上不落一个字节、也不新增一个目录；建失败给「检查路径拼写与写权限」的可操作提示。

**验证**：2 条用例（嵌套三层新目录 → 报告落盘 + 建目录留痕；`--report` 指向被审正文 → exit 10 且正文逐字节不变）。

### L-72b `mform-gates.mjs` H2 切分改走真源

**缺陷**：该门用 `body.split(/^##\s+/m)` 切段，这是 H2 口径的**第三份实现**，与 `sections.mjs` 的 `H2_LINE_RE` 有三处可观测分歧，最要紧的是**完全无视围栏**——代码块里的 `## 示例` 被当真段切开，进而被判「段缺 [Lxx]」。

**修法**：改用 `h2Headings(body)` 的 index 切片（该函数已围栏感知）。改后本门与 `count-chars` / `segment-chars` 的段边界**逐字节一致**。

**验证**：全量 M 门既有用例（含 `gate-hardening` / `mexist5-binding` / `endnote-nine`）全绿。
