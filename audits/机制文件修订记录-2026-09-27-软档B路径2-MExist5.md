## 一、为什么先量再动手（以及我上一轮的一个错判）

上一轮我把选项 B 描述为「模板加行 + 触发条件写进软提示，**零代价**」。动手前按本仓规矩先读机制实现，发现这个描述**不成立**：`mexist-gates.mjs` 的检查项清单是**从模板表派生的**——

```js
for (const need of tplItems[gateId]) { … if (!hit) findings5.push(`${gateId} 检查项缺「${need}」（模板为真源，逐项都要有行）`); }
```

**故「给模板加这一行」本身就是一次收紧**，实测（22 个项目真跑）：

| 变体 | 新增「检查项缺行」硬问题的项目 | 跨档 |
|---|---|---|
| 两张表都加 handoff 行 | **9/10** | **1 个**（`海外驻军-主权分离`，findings 3→4 → P0） |
| **只** T7.5 表加行 | **7/10** | **1 个**（同上） |

→ **结构性结论（本批的主要产出）**：**在这张表上，「让条件可达」与「不新增红线」不可兼得**——模板行同时是可达化手段与收紧手段。既有的 `筛选竞赛的均衡` 就是这条规则的实证（今天已被判 3 处「缺行」）。
→ 故本批改走**散文层可达化**，并在动手前把这个错判如实报告给主人。
