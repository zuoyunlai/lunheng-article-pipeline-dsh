## 一、真缺陷：机制实现与文档/契约不一致（**导致静默失败或整条路径空转**）

### F-1 🔴 `apply-diff.mjs` 的 parser 标签与协议文档不一致 → 机械应用路径**整体空转**
- **现象**：A 轨第 1 轮 dry-run `parsed: 0 ／ dropped_lines: 233`，一条都没解析出来。
- **根因**：`references/pipeline-readme.md` 行 306 的协议原文要求清单给「`定位 / 旧串 / 新串 / 现况汉字 / 修改后汉字`」；而 `scripts/apply-diff.mjs` 行 194–197 **只识别 `定位` / `**现况**：` / `**修改｜增补｜改为**：`**。「旧串/新串」不在识别集内，全部落进 `droppedLines`。
- **影响**：**照文档写清单 = 必然失败**。主控为此写了转换器（`mk-machine-readable.mjs`）才走通。
- **另**：parser 每条**只吃一对** `cur/new`，而协议与主控话术都要求「同段多处改动合并为一条」→ 语义上又冲突。
- **建议**：① 同步两处措辞；② 或在 parser 里把「旧串/新串」也纳入别名。

### F-2 🔴 `apply-diff.mjs` 不支持「空新串 = 删除」
- **现象**：A 轨撤条目 3 条（`[P1-15c/d/e]`）全部落 `unparsed` —— 因 `const parsed = items.filter(it => it.cur && it.new)`，空串为假。
- **影响**：撤条目类改动**必然转嫁主控手工**。本轮主控为此写了两个收口脚本。
- **建议**：支持 `new=""` 删除语义（或文档明确「用边界写法」并给示例）。

### F-3 🟡 `apply-diff.mjs` 的 HTML 注释只跳「行首 `<!--`」→ 成对包裹无效
- **现象**：B 轨末轮 `dropped_count: 40 / exit 1`，而清单作者自报 `0`。
- **根因**：跳过判据是 `!/^<!--/.test(t)`（行 200）——**只跳过自身以 `<!--` 开头的行**；`<!-- … -->` **块内的行不被视为注释**，全被计入上一条目的 `droppedLines`。
- **旁证**：同一清单作者在 v3 那轮把附录放在**文件顶部**（第一个条目头之前）→ `cur` 未建立 → `if (!cur) continue` → `dropped_count: 0`。**位置一变即复现**。
- **建议**：加 `INSIDE_HTML_FRAGMENT` 状态机；或在文档写死「附录须置于第一个条目头之前」。

### F-4 🟡 `handoff-check` 的 A4b「审计轮次」二义性 → 多次复核**必然撞车**
- **现象**：B 轨复核写 `复核报告-v2.md`（第二次独立复核）→ A4b 报 hard，要求 v1。
- **判据原文**：「审计族（审计报告 / 复核报告 / 反哺报告）的 N = **审计轮次**；复核必须与它复核的那轮审计同号」——**该契约假定「一个审计轮次只做一次复核」**。本项目对**同一个 `审计报告-v1`** 做了**三次**独立复核（A 轨、B 轨第 1 轮、B 轨末轮）。
- **影响**：无解的两难——改名则三份复核重名，不改名则 A4b 恒 hard。本项目选择「保持语义正确的文件名 + 如实登记冲突」（T7 与主控各留痕一次）。
- **建议**：明确「审计轮次」定义，并令 A4b 对 `复核报告-vN.md` 接受 **N ≥ 1**。

### F-5 🟡 `M-Exist-5`「报告后激活」与 T7.5「裁定后落盘」构成**时序死结**
- **现象**：审计报告一落盘，`M-Exist-5` 即开始要求 `闸门记录-T7.5.md` 存在；而 T7.5 的模板规定**在 T8 的 `--adjudicate` 之后**才落盘（因为其「M 门全部 exit 0」行要引裁定值）。
- **本项目处置**：提前落盘 + 第 3 行如实记 **N/A**（附理由），T8 阶段再回填两个 exit 数。**这条绕法未被文档承认**。
- **建议**：把该绕法写进模板（「T7.5 允许两阶段落盘：先落骨架并记 N/A，T8 回填」）。

### F-6 🟡 `count-chars.mjs` 无 `--report` 旗标，而角色会**自报不存在的产物路径**
- **现象**：T7 B 轨复核交接报告声称落盘 `t7-review/count-chars-v2.json`；**该文件实际不存在**（目录内只有 4 份报告）。
- **影响**：低（不影响其读数，其实测与主控同口径），但属**假产物声明**。
- **建议**：补 `--report`；或在下游明确「本工具无报告输出」。

## 二、判据误报：**假阳性，逼作者改内容或做无谓裁定**

### F-7 `wallTextAnchor` 正则不容忍章节号前缀 → M-Form-8 误报
- 标题写成 `### §11.6 承重墙清单（…）` 时，`^#{2,4}\s*(承重墙|…)` **不匹配** → 脚本退选到下一个匹配项，报「承重墙清单无结构性条目」。改名后即报「22 条标注、无超载」。
- **v1 已记**（M-Form-11 幽灵编号同源），本条补充**锚点正则**这一具体位置。

### F-8 `idsByToken` 与模板形态耦合 → 幽灵编号 P0
- 清单条目写成表格行 `| [先01] | …` 时，正则 `^#{0,4}\s*\[先\d+\]`（锚定**行首裸编号**）不命中 → 报「幽灵编号 `[先01]`–`[先05]`」P0。改为行首后 P0→P2。**v1 已记**。

### F-9 🔴 `structure-check` 引言漏斗词表滞后 → 假阳性 P1，**且只能靠改内容迎合**
- **现象**：`S-Intro-Funnel` 报 P1「缺领域重要性 / 知识缺口」。正文实际**都有**：行 11「**已经构成**一组嵌套的制度装置」、行 13「**尚无**研究从…」。
- **根因**：脚本词表**收「已成为」不收「已经构成」**、**收「尚未」不收「尚无」**。
- **影响（最要紧的一条）**：这项**不能靠正当手段通过**——只能把正文用词改成词表收录形态（**为过门而改内容**）。T7 在 v1/v2/v3 **三轮独立复核**均判「词面错位假阳性」；主人 Phase 5 裁决「**按已知偏差记载，不改稿迎合词表**」。
- **建议**：词表纳入等价词面（「已形成/已经构成」≈「已成为」；「尚无/未有」≈「尚未」），或改成「语义判定 + 词面为提示」。

### F-10 `methodology-check` 对 `academic-hum` 报 P0（**文类档案未标 N/A**）
- 现象：`M-Form-12`（样本量/抽样/变量/模型）报 **P0**，而本项目文类 `academic-hum` + IMRaD-Alternate **根本没有方法节**。
- 影响：每个理论类项目都要人工 N/A 裁定一次；若无人裁定，会以 P0 阻塞。
- **v1 已记**（T7 列为 P2 候选 + 规则 B「工具侧例外」）。本条补充：**T9-m 独立复核也判 N/A**，两次独立定性一致。

### F-11 🔴 `M-Exist-7` 把**说明文字里的尖括号**当未填占位符
- **现象**：交付说明被判 P0「字段『反哺清单』仍含模板占位符 `<…>` 未填」。
- **根因**：该字段里我写的是 **`apply-diff.mjs` 的 `<!-- -->` 注释处理**——描述 HTML 注释语法用到的 `<!--` 与 `-->` 被 `<[^>]{1,25}>` 命中。同类第二处：成本指标里写 `--sessions <主会话>`。
- **影响**：**惩罚了正常的技术表述**。作者要么绕开（我最终改成「HTML 注释标记」），要么被迫写不准确的描述。
- **建议**：占位符检测排除**反引号包裹的代码片段**与**已配对的 HTML 注释**。

### F-12 `M-Exist-6` 的「修改建议段」形态识别与自然写法不匹配
- 我把 `## 给作者的具体修改建议（按优先级）` 重写为 `## 修改建议（按优先级逐条列）`，每条带 `[P0]/[P1]/[P2]/[事实]` 标记并附图例——**仍被报「无有效条目（须按优先级逐条列）」**。
- 影响：作者无法从报错反推期望形态（判据在共享模块里，`m-gate-check.mjs` 本体查不到）。
- **建议**：报错时给出**期望的条目标记形态示例**。

### F-13 `G8-CharCount` 从简报解析候选区间误读
- 简报「篇幅: ≥5000（全量流水线档）…目标正文 11000」被解析成候选区间 `[5000, 10000]`，得出「11205 = 1.121× 超上界」的 P2。按简报**实际档位**（11000 ±2%）该值在档内。
- **v1 已记**（P1 候选）。T7 复核独立判「**假阳性**」。

### F-14 `G15-VolIssue` 对 `[M]` 专著要 ISBN/DOI 过严
- 15 条候选中，T7 逐条定性为「**可补不可得**」：`academic-hum` 文类下 GB/T 7714-2015 对文献页只约束五要素，DOI 属数字优先权而非著录必需。**v1 已记**。

## 三、预算与度量失灵

### F-15 🔴 **T7 任务书的字数预算低估约 2 倍**（本轮最严重的流程性缺陷）
- **现象**：T7 给 16 条 P1 的**合计**预算 **+460 字**（≈29 字/条），而每条动议都是「补 1 段 / 补 1–2 句」；真实写出 **+622**（apply 实测），T5 清单估 **+511**，B 轨第 1 轮又 **+391**。
- **连锁后果**：本项目 Phase 0 定的 11000 档只剩 **15 字**余量 → 修订**根本无法落地** → **主人被迫在 Phase 4.5 把目标上抬到 12000**（一次真实的方向调整，起因是预算表算错）。
- **建议**：任务书的字数额度按「**补 N 句 × 20–60 字**」估算，而不是按「每条 +12~+24 字」；并**在任务书里显式给「本轮总净增预算」并做合计校验**。

### F-16 字数判定表「偏差 >20% 禁止继续」未考虑**授权上限在 apply 之前已被变更**
- **现象**：A 轨实测偏差 **+21.7%（>20%）但仅 +111 字（<300 字）**。条款触发；而该轮的目标档在 apply 前已被主人上抬，实测 11,827 落在新档内，**条款要防的情形并未发生**。
- **建议**：偏差判定的**分母取「本轮授权的净增预算」，而非「清单自报的净增」**；或在条款里加「若授权上限已变更，以变更后档位重新判定」。

## 四、覆盖盲区：**机检根本不查的**

### F-17 🔴 **`M-Form-9` 只核「图位数 = 图件数」，不校验 SVG 内部几何**
- **现象**：图3 对位矩阵**通过了全部机检**（M 门 24 项 / T7 三轮复核 / T9 / G14），但实测其 **35 个标记中有 6 个不落在列中心**、2 个 ○ 漂在 C01/C02 边界上、**反身性行多出一个不该有的 ○**（该格按推导规则应为 `－`）。
- **发现途径**：**主控借 PNG 目视**发现——不是任何一项机检。
- **建议**：新增 SVG 几何自检：**标记坐标 ⊆ 行/列中心集合**、**标记数 = 行数 × 列数**、**图内引用的编号 ⊆ 素材卡编号**。

### F-18 PNG 导出需求真实存在，但**论衡无 SVG→PNG 通道**
- 实测三条路：`cairosvg` **已安装但缺 cairo 原生 DLL，不可用**（Windows 经典问题）；论衡 `scripts/` 内**只有 `md2html.mjs`**，无任何 svg→png；**Edge/Chrome 无头截图可用且零安装**（本项目即用它，3× = 2100×1500）。
- **建议**：把「浏览器无头截图」写进 `references/operations.md` 作为**推荐路线**并给可复制命令；同时说明 `cairosvg` 在 Windows 常不可用，避免后来者踩坑。

### F-19 图件字体栈在本机**从未生效**（配置与实况脱节）
- 三张图的 `font-family` 是 `-apple-system, 'PingFang SC', 'Noto Serif CJK SC', 'Source Han Serif SC', serif`；**这三个命名字体在本机 632 个字体中一个都没有** → 实际一路落到通用 `serif`（宋体）。
- 影响：模板的「品牌调性 = 衬线字体」在 Windows 上**靠兜底碰巧满足**；一旦兜底是 sans（如某些 Linux），视觉规范会静默失效。
- **建议**：模板的字体栈**补入跨平台实际可得字体**（`'Microsoft YaHei'` / `'SimSun'` / `'Noto Serif CJK SC'`）并在 `operations.md` 注明「命名字体不保证存在，**通用族兜底才是实际生效项**」。

## 五、角色行为层

### F-20 🔴 **子代理会把机制文档的「能力说明」当成本项目已发生的事实**
- **现象**：T7 首审报告写「`audits/G14-检测报告-v1.md` **已落盘**」（**同一句的括注里又写「项目目录下无该文件」**，自相矛盾），并在任务书附注写「本轮 G14 检测报告由主控在 **Phase 0 关闭**」。
- **真源**：`01-任务简报.md` 行 84「**☑ 启用** G14 中文 AI 痕迹（三层防御：… / **Phase 4.5 终闸**）」——**G14 从未被关闭**，只是终闸未到。
- **根因**：T7 读了 `gates/14-中文AI痕迹-gate.md` 里「**可关闭**：主人可在 Phase 0 选择『关闭 G14』（不强制）」这条**能力说明**，把它当成了本项目的裁定。
- **判据（建议写进角色卡）**：**机制文档写「允许 X」≠「本项目做了 X」**；任何关于「本项目已执行 / 已落盘」的断言，**必须能指回本项目产物**（`Test-Path` / `Get-FileHash`）。本项目据此要求 T7 逐个 `Test-Path` 其报告里引用的 39 条路径（结果 38 真 / 1 缺，唯一缺失正是那份不存在的 G14 报告）。

### F-21 🔴 **子代理自检的「扫描面」与应用器的「计数面」不一致 → 自检通过而机检失败**
- **现象**：B 轨末轮清单作者自报 `dropped_count: 0`；**实测 40**（且因此 exit 1）。
- **根因**：作者的格式自检写明「**仅扫 `<!-- -->` 外正文**」——而应用器算的正是**注释内部**的行。**扫描面与应用器计数面不同**。
- **判据（建议写进角色卡）**：**自检的覆盖范围必须与应用器的计数范围一致**；自检只覆盖「自己认为相关」的区域时，它保护的是作者的假设，不是产物。

### F-22 段级 diff 模式下，「主控手工收口」是**串行瓶颈**
- A 轨 5 条手工收口（1 条因「现况」写成说明文字、1 条因旧串仅 2 字不可唯一、3 条因空新串不支持删除）；B 轨两轮因格式一次通过而 **0 条**。
- 对照：主控是**串行资源**，子代理可并行。机制自己也写了「把重写全文的负担从 T5 转嫁给主控并不划算，应转给脚本」——**本轮再次验证**。
- **建议**：清单**格式校验前置**（T5 交清单后、主控 apply 前，先跑一次 `--dry-run` 并把 `parsed/skipped/unparsed/dropped` 四项回传 T5 自纠），把收口成本推回可并行的角色。

## 六、易错但**设计正确**之处（建议明确化，非缺陷）

### F-23 编号契约是**双轨**的，且文档分散
- 「审稿报告 / G14 检测报告」的 **N = 正文轮次**；「审计报告 / 复核报告 / 反哺报告」的 **N = 审计轮次**。本项目正文走到 v4、审计只有 v1 → 两类报告的 N **不同步**。主控首派 T9 时**也一度写错**（写成 N=1，实为 N=2）。
- **建议**：在派发话术模板里**内联**该契约（照抄即可的判断句），而非让主控去查文档。

### F-24 本项目**未发生**但值得记的机制优点（避免将来改坏）
- **指纹互锁**（`refresh-gates.mjs` + `M-Exist-5`）：本项目实测有效——它抓出了「T7.5 第 3/4 行仍指向 v2」的失配，逼出一次刷新。
- **`fix-gates.mjs`「修法生成器」**：本项目返回「零修复项」，证明**正文层在冻结前已干净**（先跑它再冻结的顺序是对的）。
- **`final-check.mjs` 的「两个 exit 数」**：机械值 3 与裁定值 0 **同写并存**，使「机械值非 0 但已裁定放行」可被独立核对——本轮 M 门正是这一情形。
- **G14 自证档位不依赖争议项**：终闸自己算了两遍（采纳豁免 vs 最严口径），证明「Pass 不依赖主控对 C 类『路径』的定性」。**这是好的设计，建议推广**。
