## 一、背景与问题（出现位置）

**问题**：`kaiti` 文类（v19.8.0 反哺 v9 D7）是**终止型**——`开题报告-template.md` 写死「Phase 2 后分岔终止」，T4 产出开题报告即停，T5-T9/G14 全免。但「开题获批 → 正式写论文」是高频真实场景，插件目前**没有一等公民衔接机制**，只能靠三个通用机制手工拼：

| 可继承产出 | 现状承载 | 是否一等公民 |
|---|---|---|
| 证据卡片（[Lxx]/[Dxx]/[Cxx]） | 素材池 `pool-extract`/`pool-query` | ✅ 已有 |
| 理论框架 + 可证伪命题（创新点/F1-F3） | 无（须主人手动搬） | ❌ 缺 |
| 已知缺口（[G01]-[G03] → 必补检索） | 无（须主人手动搬） | ❌ 缺 |

**根因**：素材池是**卡片级**复用（去重键 = DOI/URL/事件名，条目带 `claim` 论点摘要），但装不下**论点级**的「框架」和**负知识级**的「缺口」——把框架塞进池会污染池的去重/复用计数。缺的这两层需要一个轻量载体，而非扩池。

---

## 二、设计方案：续写种子（Continuation Seed）

**核心判断**：不引入「同项目切文类」（kaiti 与 academic 的篇幅/结构门/文末节/机检/角色全不同，切文类破坏 `文类档案.md` 的 Phase 0 锁定）；改为 **kaiti Phase 5 产出种子 + 新项目 Phase 0 继承**。

### 2.1 kaiti Phase 5 新增产物 `final/续写种子.json`

由 `pool-extract.mjs` 新增 `--seed` 输出（复用 `_lib/pool-store.mjs` 读卡片 + `_lib/sections.mjs` 读开题报告节），机械提取框架/命题/缺口：

```json
{
  "schema": "lunheng-continuation-seed/1",
  "originProject": "腐败资产外逃",
  "originGenre": "kaiti",
  "title": "统计真空与传言生产——腐败资产外逃规模为何没有权威数字",
  "recommendedGenre": "academic-cn",
  "targetJournal": "社会学研究",
  "framework": {
    "theses": ["创新点①统计真空结构化阐释", "创新点②传言生产四节点", "创新点③可证伪命题"],
    "propositions": ["F1 净误差遗漏<1000亿则传言频度下降", "F2 口径标注提高复引率", "F3 查处案数与净误差同向"],
    "causalStrategy": "congruence testing + process tracing"
  },
  "gaps": ["G01 世行/IMF/央行对比表", "G02 腐败vs合法投资区分", "G03 大数转引路径"],
  "poolQueryHints": ["腐败资产外逃", "资本外逃", "资本外流"]
}
```

**关键点**：种子**不复制卡片**，只记录 `poolQueryHints` 关键词 + 框架 + 缺口；卡片仍走池（`reuseCount`/`reusedBy[]` 幂等累计、`originProject` 溯源，不破坏现有护栏）。

### 2.2 新项目 Phase 0 新增继承入口 `SEED=` 字段

沿用插件既有的「机器可读行」模式（与 `外部服务授权` / `POOL=` / `ETHICS=` 同族），任务简报加一行：

```
SEED=run/腐败资产外逃/final/续写种子.json
```

主人 Phase 0 一句「续写 腐败资产外逃」→ 主控读种子 → 预填任务简报：
- 文类 = `recommendedGenre`（主人可当场改）
- 研究问题 = `framework.propositions`（F1-F3 转子问题）
- 必补检索关键词 = `gaps`（G01-G03 → Phase 1.5 触发词）
- 复用卡片 = Phase 0.5 `pool-query` 按 `poolQueryHints` 命中注入派发话术

## 四、可消融性声明（AW-1）

- **关掉怎么测**：不产 `续写种子.json` / 不设 `SEED=`，走回现行手工流程（pool-extract → 起新项目 → 手动搬框架/缺口 → 重新拆子问题），功能退化但**不破坏**任何现有门/脚本。
- **预期影响哪项成品指标**：新项目 T1/T2/T3 首轮检索步数下降（池命中复用）、Phase 0 定题往返从「手动 4 步」压到「一句续写」；**不改变**任何 M 门/G 审计/原创性护栏的判定。
- **读数边界**：本机制是「Phase 0 预填器 + 素材池检索提示」，**不是新机检对象**——其效果只能按「新项目首轮检索步数 + 复用卡片数」实测，不进入任何 exit 语义。

---

## 五、边界与未做项

- **刻意不做**：① 不新增门/档位/文类（受控取值纪律 P5）；② 不把框架/缺口塞进素材池（防污染去重/计数）；③ 不做「同项目切文类」（破坏文类锁定）。
- **复用护栏不降低**：种子命中的卡片仍过池的三道护栏（时效 🟡🔴 标风险 / 复用次数 ≥3 防撞车 / `originProject` 溯源），框架/命题仍过新项目的三角验证 + G7 原创性审计。
- **未做项**：未实装（本报告仅为设计动议）；未跑回归测试；未验证 `--seed` 提取的机械可复算性。
