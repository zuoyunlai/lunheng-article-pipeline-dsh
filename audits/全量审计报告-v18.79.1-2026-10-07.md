## 五、进一步优化的空间（每条给机制，不给形容词）

1. **给每条规则与每个门登记「扫描面」与「真源缺失时的行为」，并让二者可被机械核验。**
   现状：扫描面写在头注释里（`link-check.mjs:42`「只扫技能目录」），真源缺失行为散在各规则里（A6 修好后是 P0，但其余是否都走了 `requireTruthSource` 我只逐条验了少数）。机制：把「规则 id → 扫描面 glob → 缺失时行为」做成登记表（与 `rule-registry.mjs` 同构），并加一条元规则：**任何 glob 在本次运行中命中 0 个文件即报 note**。这条最便宜，能一次性消灭「扫描面悄悄失效」这一整类——本轮 P1-1 就是它的实例。
2. **把「计数 / 集合 / 阈值」三类事实的派生收口做成可复用模式。**
   A2/A4 修得非常好（登记表 + 共用派生 + 双向覆盖 + 重号检测），但它是**手工为一族建的**。机制：抽一个 `_lib/truth-source.mjs`，提供 `register(name, deriveFn)` + `requireTruthSource(path, ruleId)` + 「文档只许写 `→ ref(name)` 指针」三条，然后逐族迁移（脚本数 / 命令数 / G 项数 / 终检项数 / 退出码族 / 角色数 / 阶段序列）。现状里 `docs/quick-facts.md` 的其余硬数字我还没证是否受门，这正是下一族的候选。
3. **区分「在册事实」与「历史叙述」，并给后者一个不进门的居所。**
   本轮多处膨胀都来自同一模式：把「为什么这么改」写进**门文件本身**（`DOC_BUDGET` 的 36 条长理由 / 各脚本头注释的病灶复述）。机制：门的注释只留「判据 + 指针」，理由正文入 `changelog/`；再由一条规则核验「抬升理由能在 CHANGELOG 找到对应版本段」。这同时解掉 P2-2 与 P2-3。
4. **把「常驻上下文预算」从逐文件改成集合级。**
   现状两个文件各自合规、合计 96.6 KB 无门。机制：`SKILL.md + AGENTS.md + QUICKSTART.md + dispatch-cards.md` 的**合计**设一个预算，超合计即红——因为真正消耗主人 token 的是合计，而不是单文件。
5. **给 H2 这类「无条件改写上游内容」的钩子补一条通用纪律。**
   现状：钩子对 `read|web_|subagent*` 的所有 text 块无条件跑 `basic` 模式并改写（`lib/index.js:415`）。机制：凡**改写**上游内容形态的监听器，必须满足两条——① 有显式开关；② 报告里区分「改写了 N 处」与「发现 N 处候选，未改写」。P1-2 的 ③ 与 ④ 正是这条纪律的具体化。
6. **给「被声明为 LLM 判定」的项补一层可机检的代理。**
   `M-Form-8`（承重墙质量）与 `M-Integrity-2`（跨文件判断）刻意不做机械门，这在本仓是**如实的**设计，不是缺陷。但它们也是整套流水线里唯一完全无网的部分。机制：不追求自动判定，而是要求 T8 的裁定**落成结构化字段**（判了哪一项 / 依据指向哪一行 / 若不通过则缺什么），再由 `m-gate-check` 核验「裁定字段非空且指向的锚点存在」——把「判断的质量」留给 LLM，把「有没有做、有没有留证」变成机械门。这与本仓既有的「闸门留机械证据」纪律同源。
