## 一、A 类：机制与脚本缺陷（逐条给证据）

### A1｜`refresh-gates.mjs` 静默漏判（**实测复现，本次最高价值的工具缺陷**）

- **现象**：T8 终检期生成 `final/定稿.md` 后，`audits/闸门记录-T7.5.md` 第 4 行的「本阶段正文 sha256」仍指向 `drafts/初稿-v3.md` 的旧指纹；`M-Exist-5` 立刻报 **P1**（detail：「实据里的 sha256=… 与 M-Gate-Report.json 的…不匹配」）。主控**手工**修正后才发现：**仓内本来就有一个专门为此写的脚本**。
- **关键实验（受控对照，同一份文件、只改格式）**：

  | T7.5 实据单元格写法 | `node scripts/refresh-gates.mjs <项目> --dry-run` |
  |---|---|
  | `` `final/定稿.md` sha256 `<旧值>` ``（**本次实际写法**） | `audits/闸门记录-T7.5.md: ok（无可刷新项（未找到已知形态指纹））` — **静默漏判** |
  | `` 正文 sha256 `<旧值>` ``（去掉中间的反引号路径） | `audits/闸门记录-T7.5.md: would-replace ×2` — **正常触发** |

- **根因（代码定位）**：`scripts/refresh-gates.mjs:100-101`
  ```js
  { rel: 'audits/闸门记录-T7.5.md', patterns: [/正文 sha256[^`\n]*`([0-9a-f]{64})`/g, /draft_sha256=`([0-9a-f]{64})`/g] }
  ```
  模式的 `[^`\n]*` **不允许跨越反引号**。而闸门记录模板的「实据」列**恰恰鼓励写带反引号的路径**（本次实据 = `` `final/定稿.md` sha256 `81f9…` ``）→ 第一个反引号就截断，模式永远匹配不到 → 报「无可刷新项」。
- **加重情节（这是本条判 P1 的理由）**：脚本**把「无可刷新」与「解析失败」报成同一个 `ok`**（其边界②明文写「抓不到旧指纹 → 如实报『无可刷新项』并不写盘（**这不是错误**）」）。于是**失败是静默的**：主控看到 `ok` 会认为「已同步」，而 `M-Exist-5` 会在下一步判 P1 → 变成「两个工具各说各话，人得自己查」。
- **修法（两条，建议同做）**：
  1. **放宽模式**：把 `[^`\n]*` 改为 `[^\n]{0,200}?`（允许跨反引号），**同时保留**其既有的 `CONTEXT_RE = /正文|定稿|被审|draft_sha256/` 行内语境守卫——该守卫正是它当初为防「误伤 manifest 条目 sha256」而加的（见同文件 85–97 行注释），放宽后守卫仍在，风险不升。
  2. **区分「无旧值」与「标签在但抓不到」**：若目标文件里**存在**「正文 sha256 / 本阶段正文 sha256」等标签，却**一个指纹都没抓到** → 不应报 `ok`，应报**告警 + exit 10（或专门的软码）**，detail 打印「检测到标签但指纹解析失败，请检查实据列格式」。
- **验收**：① 用本次的原始格式（带反引号路径）跑 `--dry-run`，须报 `would-replace`；② 构造「有标签、无指纹」的文件，须报告警而**非** `ok`。
- **另注（留给机制侧判断，本报告不擅断）**：实验还出现 `would-replace ×2`——同一次替换声称 2 处。若其中一个匹配起点落在**表格的「检查项」单元格**（其标签本身含「本阶段正文 sha256」），则放宽模式后有**改写标签文本**的风险。建议修完 ① 后补一条「替换后标签文本不变」的回归用例。

### A2｜`M-Form-8` 证据类别字母表不含 `[先xx]`

- **现象**：`## 六 讨论` 一节以 `[先01]`–`[先19]`（先行者清单）承载与既有研究的差异对账，被判「覆盖 ＜2 类证据」→ **P1**。
- **根因**：证据类别表只枚举 `[Lxx]` / `[Dxx]` / `[Cxx]`，未纳入 `[先NN]`；而 `[先NN]` 是**《机检硬格式》确认的合法编号族**（先行者清单，且 `M-Exist-1` 等门认可其存在）。
- **后果**：以「与先行者对话」为主要论证方式的**任何**稿件都会拿到这个 P1，且**改稿无法消除**（除非把先行者编号换成普通文献编号——那是内容降级）。
- **修法**：把 `[先NN]` 纳入 cov 类别字母表（真源 `scripts/_lib/mgate-gates/mform-gates.mjs:442-444`）；或在「清单锚点表」的类别映射里按**编号族通配**而非硬编码三族。
- **验收**：构造一个仅以 `[先xx]` + 散文承载的讨论节 → `M-Form-8` 应判通过。

### A3｜`M-Form-8` 无法识别「已声明并被主人接受的缺口」

- **现象**：`## 二` 的缺角是 `analysis/分析大纲.md` **§十一 缺口表显式声明**、且**主人在 Phase 2.5 门明确接受**的 Permanent Gap（论点1/2/8），仍被判 P1。
- **根因**：机检不解析大纲的缺口表；「已接受缺口」这一**合法状态在机械层不存在**。
- **修法（择一）**：
  - ① 引入**机读声明**：在 `01-任务简报.md` 或大纲首部加一行 `ACCEPTED-GAPS: 论点1,论点2,论点8`，`M-Form-8` 读它并把对应论点从「弱段」判定中排除；
  - ② 在 `final/M-Gate-Report.json` 增加 `accepted_gaps` 字段，由 T8 裁定通道写入（与 `_t8_conclusion` 同寿）。
- **验收**：声明后 `M-Form-8` 不再对这三个论点报 P1；未声明时行为不变（防滥用）。
- **备注**：本条与 A2 是本次**同一项 P1 的两个独立成因**——T7 的审计报告已分别给出成因定位（这也是 T7 推翻我「单一成因」归因的那处）。

### A4｜`M-Form-10` 与《机检硬格式》§二 结构性冲突（**脚本注释自承**）

- **现象**：文献卡索引段的 `[L00]` / `[L99]`（及 `[L-cross]`）在正文无 `###` 条目 → 报「索引悬空」软提示。
- **证据**：`scripts/_lib/mgate-gates/mform-gates.mjs:918-919` 的注释**逐字自承**「**合规稿必然拿不到 exit 0**」。
- **根因**：《机检硬格式》§二要求这三个特殊编号写成**索引段独有行**且**不计入总条数**；`M-Form-10` 却按「索引 ↔ 正文条目一一对应」判。
- **后果**：门禁的设计目标（合规稿应通过）与实现（合规稿必然带非通过项）**不一致**；主控只能诉诸证的伪裁定，增加虚假的「假阳性」噪声。
- **修法**：`M-Form-10` 对 `[L00]` / `[L99]` / `[L-cross]` **显式豁免**（不计入「缺失」集合），或在 `idxIds` 侧就排除它们。
- **验收**：一份只含合规特殊编号的稿件，`M-Form-10` 应能判 **pass**（而非永远 soft）。

### A5｜`final-check.mjs` 退出码与裁定语义不一致

- **现象（本次实测）**：`final/M-Gate-Report.json` 的 `exit` = **0**（T8 经 `--adjudicate` 写入，`script_exit_raw` = 1 另存），但 `node scripts/final-check.mjs <项目>` 的**进程退出码 = 1**，`recommendation` = 「⚠️ 终检存在 P1 残留，主控**可**触发 T5 修订一轮」。
- **真源**：`scripts/final-check.mjs:234-243` 用 `exitCode`（**机械值**）生成 recommendation；同文件 199–229 已同时输出 `hardExit` / `adjudicatedExit` / **`stableExit`**，并注明「交付件只引用稳定态」。
- **后果**：交付终结点上**同一件事有两个读数**，且退出码偏向悲观。T8 若照 `recommendation` 走，会对一个**已被证伪四件套裁定为干净的稿子**再开一轮修订（而本次 B 轨额度已用尽，等于无路可走）；若照 T8 角色卡走，则要**忽略**脚本文案。两种做法都不该由人来选。
- **修法**：① recommendation 与退出码改用 `stableExit`（有裁定取裁定）；② 至少把文案改成「退出码 = 机械读数；**交付判据 = stableExit = N**」，让两个数**在文案里同时可见**。
- **验收**：构造「机械 1 / 裁定 0」的项目，`final-check` 的退出码应为 **0**，或文案明确以 stableExit 为交付判据。

### A6｜`M-Exist-4` 与 `handoff-check` A1 口径相反

- **现象**：T7 首审时 `M-Exist-4` **硬要求** `audits/复核报告-v1.md`（真源 `mexist-gates.mjs:277-278`，detail：「已有修订说明（N 份）但缺同号复核报告」），而 `handoff-check` 的 **A1** 判该报告「首轮可缺」。
- **本次后果（可复现的无效动作链）**：T7 被迫补交一份**内容全为「✗未关闭（未复核）」**的形式产物 → 修订轮结束又要用**同号**覆盖它 → 主控再把它**归档**为 `_backup-复核-首轮形式稿-20261002.md`。**一次无意义的写入 + 一次归档**，且全程无人需要那份初版内容。
- **修法**：统一口径——① 若坚持「必须落盘」，则 A1 也应判硬；② 若认可「首轮可缺」，则 `M-Exist-4` 在「已有修订说明、尚无复核」时应降为**提示**而非硬问题。
- **验收**：在一份「有修订说明、无复核报告」的项目上跑两门，结论须**一致**（同为失败或同为放行）。

### A7｜报告编号的两套体系（命名契约不在派发话术里）

- **现象**：`handoff-check.mjs:62-71` 把 `反哺报告` / `审计报告` / `复核报告` 列为 `VERSION_INDEPENDENT`，其中**审计报告的 N = T7 审计轮次、复核报告 N = 同一轮**（注释记主人 2026-09-25 定案）；而 **A4b**（:220-231）要求「审计报告 vN ↔ 复核报告 vM 必须 N === M」。**但 `审稿报告` 与 `G14-检测报告` 不在白名单** → 它们的 N 必须等于**正文轮次**（由 **A4** 判）。
- **本次后果**：① 我把复核报告写成 `复核报告-v2`（跟着正文轮次），被 **A4b** 判 exit 21；读源码后才改名为 `v1` 并删 v2 残留；② 而**同一时刻** `审稿报告-v3.md` / `G14-检测报告-v3.md` **必须**跟正文轮次。**同一项目里两种规则并存**，且只在源码注释里。
- **修法（择一，建议 ①+③）**：
  - ① 把命名契约**写进 T7/T9/G14 的派发话术**（一句话：「审计族跟审计轮次，审稿/G14 跟正文轮次」）；
  - ② 或在 `handoff-check --help` / 失败 detail 里**打印正确做法**（本次 A4b 的 detail 只说「不同轮」，没说该写几）；
  - ③ 统一为正文轮次（若机制层愿意承担 `复核报告` 反复覆盖同号的代价）。
- **验收**：A4b 报错时的 detail 应包含「正确文件名应为 `复核报告-v1.md`」这类**可执行指引**。

### A8｜两个「正好对治本次自伤」的助手脚本，只存在于 `SKILL.md` 的长清单里

- **事实（逐文件检索证实）**：`refresh-gates` 在 `SKILL.md:47` 有整段说明；但 **`references/agents/08-终检-finalizer.md` 未提及**，**`references/_shared/M-Gate-Algorithm.md` 未提及**，**`references/templates/交付说明-template.md` 未提及**，**`references/templates/闸门记录-template.md` 未提及**。`fix-gates.mjs` 同样如此。
