> **审计问题**（主人 2026-10-18）：「快写、写一篇、学术投稿，以及文类的所有机制是不是都是完善的、畅通的？」

> **纪律**：本报告只提动议；修法由主人逐条批准后 apply（本批主人已授权「依次开始修」）

## 一、结论（先给答案，再给证据）

**「跑得通」成立；「完善」要打折扣。** 它是**分层机制**，不是全自动闭环：

| 层 | 内容 | 状态 |
|---|---|---|
| **有机械门** | 引用模式（M-Exist-1）/ 引用格式（`cite-format`）/ 结构门（`structure-check` 三档）/ `QLT`（`g-audit-check`）/ 字数口径（`count-chars` + 判定表）/ 文献下限（`GENRE_MIN_L`，与档案逐值一致） | **6 列通** |
| **仅登记、人工责任点** | 补扫 / 文风档 / T9 视角 / 期刊匹配 / GB/T 7713.2 三项（题名≤25、摘要分型、关键词） | **档案已明写「无门、登记 ≠ 已合规」**，非疏漏 |
| **脚本有、工具面缺** | `--lite-profile`（**未登记**）/ `--genre` / `--fig-dir` / `--adjudicate` | **F-01 / F-02** |

**实跑证据**：
- 快写（`--lite-profile`）：本项目 `run/中国古典学的学科划界` → **exit 0 / 5 通过 / P0=P1=P2=0**
- 学术投稿（全量 25 门，`run/生成式AI`，academic-cn）→ **exit 3**（P0=0 / P1=0 / P2=4），25 项全跑、无假红；4 条 P2 是该旧项目的内容软提示（审稿报告缺「具体修改建议」段、批判报告节体过短、审计报告 G4 邻域无结论词、交付说明决策记录无决策词），**非机制不通**

## 二、发现清单

### F-01（P1 · **未登记**）工具面缺 `--lite-profile`，快写入口用工具跑必然假红

- **现象**：`lunheng_m_gate` 的 `parameters` 只有 `draft` / `evidence` / `summary` / `report` 四个（`lib/tools.js`）；而脚本 `m-gate-check.mjs` 支持 `--lite-profile`（只评估 M-Form-1/3/5/7 + M-Exist-2 五道）。
- **根因**：`TOOL_FACE_FLAG_GAPS` 只登记了 `figDir` / `adjudicate` / `genre`（`lib/tools.js`），**`lite-profile` 从未进表**，工具 description 也只声明「未暴露 `--fig-dir` / `--adjudicate` / `--genre`」——即**声明面与实现面同时漏了它**。
- **影响**：快写项目若用工具跑 M 门 → 跑**全量 25 门** → 快轨没有批判报告/审计报告/审稿报告/G14 报告 → M-Exist-6/8/9 一类必然报缺 → **假红**，且使用者会以为「快轨稿不合格」而不是「跑错档」。本次实战只能靠 `pwsh` 直调绕过，而**文档没写必须直调**。
- **建议**：工具入参加 `liteProfile: { type: 'boolean' }` + 映射 `--lite-profile`；从 `TOOL_FACE_FLAG_GAPS` 无需移除（本就不在表内），但**须在 description 里声明已支持**。

### F-02（P2 · 已登记，但后果要写明）工具面缺 `--genre` 与 `--fig-dir`

- **`--genre`**：`GENRE_MIN_L` 的实现与档案逐值一致（academic 3 / book-review 2 / policy 2 / industry 2 / report-3rd 1 / biz-review 1 / wechat 1 / kaiti 10，缺省 **3**）。工具面传不进去 ⇒ 用工具跑**非学术文类**（biz-review / report-3rd / wechat 下限 1，book-review / policy / industry 下限 2）时**一律按 3 判 → 多判**。
- **`--fig-dir`**：缺它 ⇒ **M-Form-9 图件闭环在工具面判不了**（缺图 P1 / 全缺 P0 都出不来）。
- **建议**：与 F-01 同批接线（`genre` / `figDir`），`TOOL_FACE_FLAG_GAPS` 只保留 `adjudicate`（其保留理由——「T8 不 spawn、裁定 JSON 由主控亲写」——**仍然成立**，不应顺手放开）。

### F-03（P2 · 已登记为 R-11b）`count-chars --genre` 只有它自己接了

- **现象**：`bodyStartForGenre` 目前只被 `count-chars.mjs` 使用；`m-gate` / `g-audit` / `quality-score` / `apply-*-cycle` / `cite-coverage` 仍走「必须 `## 摘要`」的旧口径。
- **影响**：学术类无影响（都有摘要）；**评论文类无摘要时**，这些门的字数判定仍按「起点退化为文件开头（含题名）」→ 虚高。
- **建议**：**不本批修**（改口径影响历史可比性，须单独立项并决定要不要留旧口径开关）。已登记于 `字数判定表.md` §一 与 `反哺报告-v1.md` §6.7。

### F-04（P3 · 表述模糊）`book-review` 的「结构门」写「Alternate / 不跑」

- **现象**：`structure-check.mjs` 只有 `--humanities`（Alternate）与 `--kaiti`（九节）两个档位旗标，**没有「不跑」的表达**；「不跑」全靠主控自己决定不调用。
- **影响**：同一文类两种处置都「合规」，无人能判选错了。
- **建议**：档案把该格改为**二选一 + 判据**（如「默认 `--humanities`；仅当目标刊不要求结构时记 `N/A` 并在 `局限性.md` 声明」）。

### F-05（P3 · 无机械校验）入口 → 机检档的推导没有守卫

- **现象**：跑 5 门还是 25 门，全凭主控照 `文类档案.md` §三 手工决定；**选错无人发现**（快写跑 25 门 = 假红；学术只跑 5 门 = 漏检）。
- **建议**：`m-gate-check` 可加一条**软提示**：读 `01-任务简报.md` 的「入口 / 文类」，与本次调用的 `--lite-profile` / `--genre` 是否匹配做对账（不匹配 → soft，不改判级）。**不本批做**，先登记。

## 四、实施记录（2026-10-18 21:1x–21:3x，v19.16.0 批）

**F-01 + F-02（`lib/tools.js`，+1,313 B）**
- `lunheng_m_gate` 的 `parameters` 新增 `liteProfile` / `genre` / `figDir`；`execute` 里分别映射 `--lite-profile` / `--genre <code>` / `--fig-dir <dir>`（`genre` 加 `^[a-z0-9-]{2,32}$` 校验，非法抛 `INVALID_ARGS`）。
- `TOOL_FACE_FLAG_GAPS` 由 `['figDir','adjudicate','genre']` 收敛为 **`['adjudicate']`**——`adjudicate` 保留的理由不变（裁定 JSON 须主控亲写、T8 不 spawn）。
- description 同步改写：由「未暴露 --fig-dir / --adjudicate / --genre」改为「仅剩 --adjudicate 未暴露；liteProfile / genre / figDir 已接线」。
- 路径围栏复核：`figDir` 走 `resolveReadablePath`，该 helper **只做三层围栏判定、不做 `isFile` 检查**，故传目录合法。

**F-04（`references/_shared/文类档案.md`，仅加判据）**
- **过程反转（如实）**：第一版我直接把该格从 `Alternate / 不跑` 改成 `Alternate（默认）`，结果**两个测试立刻变红**——`P1-2 与文类档案对账` 与「开工台内置文类表必须与档案逐列一致」同时失败：档案的表格值**有副本同步检查**（开工台内置表逐列对账）。
- 结论：**F-04 缺的是判据，不是取值**。改回原值，改为在同一节插入一段判据——「保留两种取值，但必须按下述判据二选一：默认 `--humanities`；只有目标刊明确不要求时才『不跑』，此时记 `N/A` 并在 `final/局限性.md` 写明依据；**判据不在格子里，在行动上**」。
- 收益：模糊消除，且**零副本同步成本**、不动任何测试断言。

### 6.9 F-03 实施记录（2026-10-18 22:2x，v19.17.0 批 · 主人定案「不留开关」）

**决策**：主人选「**不留旧口径开关**」= 口径统一。这反而给出了比原方案更干净的实现——**不给 5 个消费者各加参数，而是改 `bodyStartAfterAbstract` 自身**。

**改法（6 文件联动）**
- `_lib/sections.mjs`：`bodyStartAfterAbstract` 在**无摘要时回落到「首个正文二级标题行末」**（新增 `source: 'abstract' | 'first-h2' | 'none'`）；`bodyStartForGenre` 同步；`bodyBounds` 新增 `bodyStartFound` / `bodyStartSource`——**「有没有摘要」与「有没有可用正文起点」从此是两件事**。
- 4 个直接用 `.index` 的消费者（`apply-revision-cycle` / `apply-compression-cycle` / `run-report`）**自动受益**；3 个用 `found` 判断的（`g-audit-check` / `quality-score` / `cite-coverage-check`）改为认 `index` / `source`。
- `count-chars.mjs`：`degraded` 改判为「连正文二级标题都没有」。
- `字数判定表.md` §一 同步登记「口径已统一」。

**验证（5 组 + 回归）**
| 场景 | 结果 |
|---|---|
| 无摘要 + 有正文 H2 | **27**（原 35）、**不 degraded** ✓ |
| 无摘要 + `--genre biz-review` | 27 ✓ |
| 有摘要 | **25**（一字不变）✓ |
| 只有文末节 H2（测试夹具） | degraded ✓（起点退化，符合「无正文起点」语义） |
| 本项目定稿（3,059 字） | **3,059 不变** ✓ |
| 回归 | **1306/1305/0** |

**本轮自造两个缺陷（均已被测试抓到，如实登记）**
1. **回落没跳过文末节**：第一版用 `hs[0]`（首个二级标题）作回落起点，而测试夹具的唯一 H2 正是 `## 参考文献` → 起点落到正文之后、算出 0 字级结果。修法：回落时过滤 `ENDNOTE_SECTIONS`，取「首个**正文**二级标题」。**这个缺陷只有那个 fixture 能抓**（真实稿件的首个 H2 通常是正文节），说明该测试的夹具选得好。
2. **改文案把「摘要」二字改没了**：把 degraded 原因改成「无正文二级标题」后，测试断言 `/摘要/` 立刻失败。修法：文案同时含「摘要」与「正文二级标题」——**语义也更准确**（此时确实两样都没有）。

> **对历史项目的影响（已在文档写明）**：有摘要的稿件字数**一字不变**；无摘要稿件的历史字数记录会**变小**（原含虚高的题名/前言）。这是「不留开关」的既定代价，主人已知悉。
### 6.10 F-05 实施记录（2026-10-18 22:4x，v19.17.0 批）

**改法（`scripts/m-gate-check.mjs`，+1,830 B）**：从被审正文上溯 ≤3 层找 `01-任务简报.md`，解析「入口」「文类」，与本次 `--lite-profile` / `--genre` 对账，结果写进**独立的 `advisories` 数组**并打到 stderr。

**关键设计决定（为什么不走 soft bucket）**：本仓的 soft bucket 是 `severity: 'LLM 兜底'`，而 `softOnlyCount > 0` 会把 **exit 推到 3**——那等于「用一个提示把合规项目判成需复核」，正是本仓反复反对的「提示当判据」。故 `advisories` **不进任何统计桶、不改退出码**，只做「让机器侧看得见」。

**三条对账规则**
1. 简报入口=快写 但**未加** `--lite-profile` → 提示「会按全量 25 门审快轨稿，典型结果是缺批判/审计/审稿报告 → 假红」；
2. 入口≠快写 但**加了** `--lite-profile` → 提示「只跑 5 门，审计链可能漏检」；
3. `--genre` 与简报文类不一致 → 提示；另：文类有档案下限且 ≠3 而未传 `--genre` → 提示「M-Form-1 按缺省 3 判」。

**验证（三场景，均为实跑）**
| 场景 | exit | advisories |
|---|---|---|
| 快写项目 + `--lite-profile` + 正确 `--genre` | 0 | **0 条**（字段不出现）✓ |
| 快写项目但**不传** `--lite-profile` | 2 | **2 条**：入口不符 + 文类下限未生效 ✓ |
| 传 `--lite-profile` 但 `--genre=academic-cn`（简报是 biz-review） | 0 | **1 条**：genre 与简报文类不一致 ✓ |

> **一处观察（PowerShell 陷阱，与本仓无关但值得记）**：`@($null).Count` 在 PowerShell 里返回 **1**，故「字段不存在」在快速检查里会伪装成「1 条」。判定须用 `$o.PSObject.Properties.Name -contains 'advisories'` 或看原始 JSON。
