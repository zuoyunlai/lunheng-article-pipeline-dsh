## 二、阻断项（必须处置）

### F-1 🔴【阻断 · 权限与安全】机制文件写保护可被工具调用绕过

**位置**：`lib/guard.js:47-52`（`WRITE_TOOLS` 不含任何 `lunheng_*` 工具）+ `:310-311`（`if (!WRITE_TOOLS.has(name)) return undefined`）；`lib/tools.js:196`（schema 暴露 `report`）+ `:247-248`（`argv.push('--report', resolveSessionPath(exec, args.report))`，`resolveSessionPath` 只做基准解析、**不做包含判定**）。

**触发**：任何角色（含子代理）发一次 `lunheng_m_gate({ draft, evidence, report: '<任意路径>' })`。**不需要 `pwsh`**——而 `pwsh` 是本包唯一已声明的绕过口。

**已验证事实**（主理人逐行复核代码 + 安全线端到端实测）：

1. guard 对 `write` / `edit` 拒绝，对 `lunheng_m_gate` **放行**（工具名不在集合内即短路返回 `undefined`）；
2. `report` 指向会话工作区之外 → 目标文件被写出；
3. `report` 指向受保护根内 → **文件被真实创建**（探针已即时删除，仓库 `git status` 已复核为空）；
4. `m-gate-check.mjs --report <任意路径>` 会自动 `mkdir -p` 后落盘。

**影响**：可覆盖 `skills/**`、`lib/**`、`scripts/**`、`cordis.patch.yml` 或任意用户文件；本包自定政策「agent 自主改机制文件 = P0 违规，本次交付作废」**在机制层已失去强制力**。好消息是 `writeReport` 会留时间戳 `.bak`，属**策略失效**而非不可逆毁坏。

**同版本内 5 处文档自相矛盾**：`SECURITY.md:22`、`SECURITY.md:32`、`skills/lunheng-article-pipeline/SKILL.md:55`、`SKILL.md:121`、`lib/tools.js:185` 仍称这些工具「只读 / 不暴露 `--report` / 无写面冲突」。其中 `SECURITY.md:32` 的「`--report` 允许写到项目外」这一既定设计，其前提正是「该面不经工具调用可达」——v19.6.0 的接线已使该前提失效。

**最小修复（建议两道 + 文档同批）**：

- (a) guard 侧：判据从「工具名」扩为「路径型写参数登记表」（如 `WRITE_PARAMS = { lunheng_m_gate: ['report'] }`），命中受保护根即返回理由——与 `WRITE_TOOLS` 同样只收紧；
- (b) 工具侧：`report` 加围栏（允许会话工作区内 + `os.tmpdir()`，否则 `INVALID_ARGS`），复用 `lib/run-path-fence.mjs` 的三层判定，不另写一套；
- (c) 同批修正 5 处文档并加机械门，否则下批必再漂。

**回归用例（当前完全缺失）**：`tests/guard-config.test.mjs` 增「该工具 + 受保护根 report → 必须返回理由」；`tests/entry.test.mjs:214-242`（现只验「给了 report 必须落盘」）增「工作区外 / 受保护根 → 拒绝且目标不存在」。

### F-2 🟠【阻断 · 正确性 + 测试】素材池是唯一「零测试 + 绕过写盘安全网 + 标准流程动作」三重叠加的子系统

**位置**：`skills/lunheng-article-pipeline/scripts/pool-extract.mjs:163-165`（幂等）、`:182`/`:213`（裸写）；`pool-query.mjs:41-59`（骨架写恒 0）；`_lib/round-ledger.mjs:187,190`；`build-evidence-bundle.mjs:811,881`。

**三条独立复核一致的事实**：

1. **幂等缺陷（已复现）**：`reuseCount` 在每次命中去重键时无条件 `+1`，而 `reusedBy` 用 `includes()` 去重 → 同一项目连跑 3 次得 `reuseCount: 2` 但 `reusedBy` 只有 1 项；`manifest.reuseCountTotal` 同步虚增。**判据不一致**是根因。
2. **manifest 与池自相矛盾（已复现）**：`ensureSkeleton()` 判据只看 `manifest.json` 在不在，写入的计数**恒为 0** → 删掉 manifest 后查池，同一进程内先打印「已创建空素材池骨架（0 条）」再打印「命中 1/1 条」；且在下次跑 `pool-extract` 前**不自愈**，而主人侧读面正是 `pool-query` / `pool-report`。
3. **零覆盖**：36 个随包脚本中**只有 pool-extract / pool-query / pool-report 三个在 `tests/**` 里零提及**；这直接解释了 1、2 长期潜伏。

**次要事实（结构缺陷，未见已发生）**：上述写入 + 修订账本共 8 处是**裸 `writeFileSync`**，绕过 `_lib/destructive-write.mjs` 的「同文件守卫 + 时间戳 `.bak` + temp→rename 原子写」三条保证。并发丢失更新经 3 组实验（含 16 MB / 30000 条大池、同 tick 双进程）**均未复现**——**只主张「原子性与回滚点缺失」，不主张「已丢数据」**。

**最小修复**：`reuseCount` 递增绑定到「新项目入 `reusedBy`」这一唯一事实（4 行）；`ensureSkeleton()` 改为复用 `updateManifest()` 的重算逻辑（抽到 `_lib/` 两处共用）；8 处裸写改 `writeWithSafety(..., { inPlace: true })`（≈8 行，零行为变更）。

**回归用例**：`tests/scripts/pool-{query,extract,report}.test.mjs` 四条最小集——① 空池惰性建骨架；② 同项目连跑 2 次 `reuseCount` 不变；③ 删 manifest 后查池不自相矛盾；④ BOM 输入可解析。**建议先补用例再修缺陷**，修复才有回归网。

### F-6 🟠【放行条件 · 权限与安全】运行面板 `/file` 可被项目内目录 junction / 软链接逃逸

**位置**：`lib/panel.mjs:790-791`（`join` 后仅 `abs.startsWith(t.dir)`——**字符串前缀，无 realpath**）；`/snapshot` 走 `:106-119` / `:486-518`（递归遍历跟随链接）。对照同仓真源 `lib/run-path-fence.mjs:88-102` 明确「三层缺一不可」，而其头注释①点名的正是这一类缺陷；`lib/commands.js:99-107` 连叶文件都做了物理层围栏——**面板是唯一没接这套真源的读面**。

**已实测**：项目内建 junction 指向工作区外 → `/file` 返回 **200 + 外部文件内容**，`/snapshot` 响应体含外部文件名；同时 `rel=../outside/…` 正确 403（说明词法层有效，缺口纯在物理层）。

**影响**：可只读下载工作区外任意 ≤8 MB 文件；面板自 v18.93.0 起**默认开启**。**前提**：可访问面板地址（默认回环）＋项目目录内已存在链接（agent 有工作区写权限，可自行植入）。

**最小修复**：`/file` 改用 `isPathInsideRunDir(t.dir, abs)` 替代 `startsWith`；递归遍历对目录改 `lstatSync` + realpath 判定，越界跳过。

**回归用例**：`tests/panel.test.mjs:830-854`（现只覆盖词法越界四类）增 junction/软链用例，沿用 `tests/fs-semantics-matrix.test.mjs` 的「能力探测 + 带理由 skip」形态。

### 4.3 收敛后的贯穿性判断

四份独立结论指向**同一个结构性病因**——**「声明」跑在「实现」前面**，本轮阻断项全部是它的实例：
