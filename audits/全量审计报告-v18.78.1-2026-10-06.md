## 五、可优化方向（每条给机制，不给形容词）

1. **把「计数类事实」从手写数字改成派生**。现状：规则数、M 门项数、终检项数、G 项数、测试用例数各有一批手写副本，且**数字类事实是本仓最活跃的漂移源**（本次审计中 P1/P2 里一半是计数）。机制：让每个「有唯一枚举真源」的数字由其枚举自动导出（规则数 ← `cc-rules` 登记表；M 门 ← gate 标签；G 项 ← `G_MAIN.length`；用例数 ← `node --test` 输出），文档只允许写「真源指针」或从该导出注入。
2. **给每道门加一行「0 命中可见性」**。⑥b 有两条子探针在全库 0 命中却静默；差集门被我证明近乎恒空。机制：所有 `check(regex, expected, …)` 型子探针累计命中数，收尾对「0 命中」输出 `note`（不计失败但必须可见）。这条最便宜，能一次性消灭「扫描面悄悄失效」这一整类。
3. **棘轮双向化 + 总余量入报告**。现状 94.7 KB 总余量无监测、26/38 超自述长期目标。机制：报告里直接打印「合计上限 / 实测 / 余量」与「超长期目标 N 个」，并规定「文件缩小 >1.5 KB 时同批下调上限」。
4. **把常驻面从 70 KB 压向自述的 51 KB**。`SKILL.md` 50.9 KB + `AGENTS.md` 20.9 KB = 97.4% 上限；`SKILL.md` 的「DSH 能力接缝」「执行能力边界白名单」等段是**按需**信息（已有 `ref-get.mjs` 按锚点读的机制），是唯一能同时降每会话固定开销与撞上限频率的动作。
5. **门自身的体积治理**：`repo-hygiene-check.mjs` 81% 是预算表。机制：预算表的「理由」字段改存 `版本指针 + CHANGELOG 锚点`，理由正文留在仓库向文档里（它们本就不进上下文）。
6. **给「模板产出的链接」上真值通道**。两个任务简报模板的断链会被复制进每份任务简报——模板是全流水线唯一被**逐字复制**的产物源。机制：对 `templates/**` 单独跑一遍 Markdown 语义解析（A3 的真值通道已覆盖），并在模板里禁止用「指向 `_shared/` 的裸相对路径」。
