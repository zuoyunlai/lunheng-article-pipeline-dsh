## §一、结论（先给答案）

**总体判断**：论衡的机制严谨度在同类的「中文长文流水线」里是顶级的——三层门（F/G/M）、exit 语义族、教训台账、文档↔实现双向对账测试、落地前五门。它甚至已经把「文档与实现会漂」写成了自己的维护判据（`consistency-check`、机检契约字符串、`tests/batch21`）。

**但 UX 层的瓶颈不是能力不足，而是「承诺面 ≠ 可达面，且失配时不报警」**：

1. 文档承诺「工具优先用」，而 Phase 5 唯一防伪造层（`--session-log`）**在工具面上不存在**，缺口登记表却写着「已清零」；
2. 文档承诺「11 个 `/lunheng` 斜杠命令」，宿主实际只注册 **2 个**，其余 9 个是「模型路由口令」；
3. 工具的 `output.schema` 用 `additionalProperties: false`，把脚本刚加的两条 `advisories`（唯一能解释「为什么 P0=3」的提示）**静默丢弃**；
4. 运行面板把 workdir 解析成无关目录 → 项目列表恒空，而真实工作区直接 403，**空与读不到同形**。

这四条同源：**「可达面」没有被当作一等契约来维护**——机械门维护的是「文档里写了什么」，没人维护「用户点得到什么」。v19.18.1 自己总结的教训「没警告与没读到在 UI 上完全同形」，在面板、工具 schema、命令注册三个面上**同时复发**。

## §三、动议清单（含来源 / 痛点 / 改动 / 影响 / 验证）

> 编号与 §二 对齐。每条给「定位（真源）」与「验收判据（可跑）」；不做无法机械验证的承诺。

### 批 A · 工具面契约（先修「机械面无牙」，再做接线）

#### U-01 工具面接 `--session-log` / `--session-root`，并把「刻意不接」写进描述

- **来源**：§2.1 U-01。
- **痛点**：`SKILL.md:86` 是 Phase 5 必跑，且「清单里有就优先用工具」——两条规则叠加=调用方**必然**少做唯一独立核对层；而缺口表说零缺口，等于宣告「按文档走就够」。
- **定位**：`lib/tools.js:445-453`（参数）、`:480-500`（`execute` push argv）、`:52`（缺口表）、`:436-444`（描述）、`tests/batch21-seam-gates-v18-80-1.test.mjs:42-46`（`REQUIRED` 表）。
- **改动**：
  1. 参数加 `sessionLog` / `sessionRoot`（`sessionLog` 可能是**会话 id**而非路径，须单独分支校验，不能直接套 `resolveReadablePath`）；
  2. `execute` 里 `if (args.sessionLog) argv.push('--session-log', …)`，`sessionRoot` 同理；
  3. 缺口表与描述同步；`REQUIRED` 表加 `{ tool: 'lunheng_handoff_check', flag: 'sessionLog' }`；
  4. 若主人裁定**不接**（读宿主会话日志的隐私/授权顾虑），则必须在描述里点名「Phase 5 须 `pwsh` 直调」——**不能靠空白表达刻意**。
- **验收判据**：负向注入——把 `args.sessionLog` 从实现里删掉 → `node --test tests/batch21-seam-gates-v18-80-1.test.mjs` **必须红**；接回后正向跑 T8 一次，`--session-log` 打开时账本缺 `callId` 应判 21（`tests/gate-receipts.test.mjs` S4 已钉住）。

#### U-02 无对象时不「静默放行」：22 补语义 + T8 空壳显式告警

- **来源**：§2.1 U-02。
- **痛点**：`total=0`（一项没核）与 `total=3 全软`（核了但无确定答案）都渲染成同一个 `exit=22`，而 `SKILL.md:106` 把 22 读作「放行」→ **空转被写成已验收**。
- **定位**：`lib/tools.js:471-477`（render）、`SKILL.md:106`（语义）、`skills/lunheng-article-pipeline/scripts/handoff-check.mjs`（22 的产生处）。
- **改动（二选一，建议 ①）**：
  1. **渲染侧**：`v.exit === 22` 时补一行「⚠ 仅软提示，≠ 已验收」；且当 `v.role === 'T8' && !args.requireGates` 时首行加「⚠ 空壳检查：未核四门、未核五件交付物——**这不是验收**」；
  2. **语义侧**：新增 `inconclusive` 码（或 `total===0 → 21`），让「没有可核项」严格强于「有项全过」。
- **验收判据**：`render` 单测（或 `tests/lib-static-check.test.mjs` 加断言）——`exit=22` 的渲染文本必须含「≠ 已验收」；`SKILL.md:106` 的「22 放行」改为「22 = 仅软提示，不等于已验收」。

#### U-06 `lunheng_m_gate` schema 补三字段，`render` 首行插 `advisories`

- **来源**：§2.2 U-06 / U-07。
- **痛点**：`advisories` 是 v19.18.0 专门为「选错机检档能被看见」加的，且设计决定是「不进任何统计桶、不改退出码」（`反哺报告-2026-10-18-三入口…` §128-144）——**唯一不污染判级的提示通道，却在工具面被 schema 丢掉**，而工具面正是被推荐路径。
- **定位**：`lib/tools.js:280-314`（schema）、`:315-323`（render）。
- **改动**：`properties` 加 `advisories: string[]`、`unchecked: string[]`、`hardRedLineHits: string[]`；`render` 首行（统计行之前）插 advisories，每条一行。
- **验收判据**：对 U-07 同一稿跑工具（全量档）→ 返回必须含两条 advisories 文案；负向：删掉 schema 字段 → 同一调用返回的 `v.advisories` 为 `undefined` 且渲染无提示（即复现旧缺陷）。

#### U-10 `lunheng_char_count` 补 `genre` + 描述对齐 + `scope` 携带来源

- **来源**：§2.2 U-10。
- **痛点**：字数直接喂 G8 阈值与交付说明的字数声明；文类分派拿不到 → 非学术文类按旧口径判；`degraded` 说明过期 → 用户要么白紧张要么忽略真降级；`scope` 标签对无摘要稿说谎 → 数字对了但解释错了（v19.17.0 想根除的那类）。
- **定位**：`lib/tools.js:372-381`（描述/参数）、`count-chars.mjs:256-261`（`scope` 硬编码）、`:58-67`（`--genre` 已支持）。
- **改动**：
  1. 参数加 `genre`（复用 `m-gate` 的 `^[a-z0-9-]{2,32}$` 校验）；
  2. 描述改为 v19.17.0 口径（无摘要但有正文二级标题**不再**置 `degraded`）；
  3. **未知旗标统一 exit 10**（复核更正：`count-chars` 与 `m-gate-check` **实测本已**如此；本批把三脚本的 `--help` 语义补齐——`--help` 一律 exit 0）；
  4. `scope` 标签改为携带 `bodyStartSource`（`abstract` / `first-h2` / `none`），并让标签按来源派生（「摘要后」/「首个正文二级标题后」/「文件开头」）。
- **验收判据**：无摘要稿的 `body.scope` 不得再含「摘要后」；工具面非法 `genre` 抛 `INVALID_ARGS`，脚本面多余 token exit 10。
