## 一、结论与分级

**总判：0.2.2-rc.3 不破坏论衡的加载面与硬接口。** 插件正常加载、四个工具可调、面板路由 200、peer 区间覆盖。官方迁移面（upgrade-guide）在 rc.1 之后没有新增条目。

**但存在一类真问题：文档里有 4–5 处指令，教主控使用宿主已不再提供的能力。** 它们不会报错、不会让门变红，只会让主控按一个不存在的字段做判断——属于「静默失真」，比崩溃更难查。

| 级别 | 项 | 一句话 |
|---|---|---|
| P1 | 主控巡检口径失效 | `list_agents` 只剩 name/status/description，文档 4 处仍在教「看最近输出 / 查循环 / 认 runId」 |
| P2 | 宿主新能力未登记 | `subagent` 可选 `name`、按步骤准入的 `ctx.tools.register(def,{when})` 均可用，论衡现用 bundle 级 disabled，粒度更粗 |
| P2 | `workflow` 可用性判据缺失 | 文档把它写成「DSH 原生工具」一行，实际本机 39 个 bundle 里没有它，配方在未挂载时不可用 |
| P3 | peer 区间语义 | 区间未覆盖 rc 类 prerelease 的严格语义，宿主按 includePrerelease 放行；0.3.0 会真的挡住 |

## 五、残余边界

- 本轮核到**加载层 + 工具层 + 宿主 HTTP 路由层**三面；**编排行为层未端到端实测**（一篇完整流水线 = 数小时 + 四道人在环），F4/F5 的「不受影响」是按宿主 guide 与论衡源码静态推的，不是跑出来的
- `list_agents` 的 status 语义（running/inactive 与「完成/失败」的关系）宿主文档未定义终态；文档改后措辞刻意不承诺「inactive = 完成」
- 桌面壳与内核版本号不同源：崩溃日志 `app: @deepseek-ai/dsh-desktop 0.2.2-rc.1`，内核是 0.2.2-rc.3。**判内核版本只能看 CLI `--version`**，别读日志那行
- 本报告不触发版本号变更；如后续要发版，CHANGELOG 另记
- **`.dsh/skills` 镜像目录在本工作区不存在**（`ls` 报 No such file），技能由 bundle 提供 → `consistency-check` 规则⑨ 的镜像对账对象缺位，本轮「0 漂移」**不等于镜像已验证**；若别处仍走镜像部署，需单独同步
- **机制文件写保护未观察到拦截**：`plugin-info` 报 `allowMechanismEdit: false`，而本轮用 `edit` 成功改了 `SKILL.md`/`references/**`。按 `AGENTS.md` 该路径本应被 `ctx.tools.guard()` 在分发前拒。**待查**（疑似 guard 只作用于子代理、或路径匹配未覆盖）；本轮改动有主人明确授权，合法性不受影响，但「写保护是否真生效」需要一个反向用例来验
- 两处已贴顶：`SKILL.md` 45,031 B（上限 45,056，余 **25 B**）、`DSH-集成方案.md` 36,854 B（上限 36,864，余 **10 B**）——下次任何增写先撞词预算门，须先瘦身或按登记表流程抬上限
