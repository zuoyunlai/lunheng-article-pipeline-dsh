### 八、v18.90.2：真根因（上一节的服务时序是**次因**）

主人装 18.90.1 后路由**仍 404**，且**诊断状态文件连 `enter` 都没写** ⇒ `registerPanel` 在宿主里**从未被执行**（它第一句就写状态文件）。补充证据：全盘搜索只有我 11:32 测试写的那份；条目 `enabled + active`；同 host 的 `/modsearch/config` 仍 200；宿主进程 12:04:35 启动晚于 11:55:38 的安装。

**真根因**：`apply` 的异步链上每个安装块后都有 `if (!alive) { …; return }`，`alive` 由 effect 的 disposer 置位；宿主**启动期多次 reconcile**（bundle 层 → profile patch 层 → …）**反复处置并重建 fiber** ⇒ 最后一次处置若落在异步链尚未走到尾段注册时，就 `return`，此后**无更新** ⇒ **面板永久不注册**。

**修法**：注册**上移到 `apply` 的同步段**（独立 `ctx.effect`，在任何 `await` 之前），服务时序仍由 `ctx.inject(['webServer'], …)` 负责；异步链里那处删除并留注释。**新增入口结构钉**：`registerPanel(ctx, cfg, say)` 恰好一处且必须在第一个 `await import(` 之前（机器判据，不再靠人记）。测试 16→17；全量套 1001 / 1000 pass / 0 fail / 1 skip。

**本轮教训（值得进长期记忆）**：**插件里「可选能力」的注册不要放在 await 链的尾段**——Cordis 的 fiber 会在启动期被 reconcile 反复重建，链上的 `alive` 早退闸会把尾段工作静默吞掉；凡「必须在宿主里生效」的注册，一律放同步段，服务时序交给 `ctx.inject`。

**修法**：改为 `ctx.inject(['webServer'], cb)` 等服务就绪再注册（服务迟到也接得住；fiber 被处置时回调不执行）；仍不把 `webServer` 写成硬依赖。**新增证据通道**：系统临时目录下的 lunheng-panel-status.json（开关来源 / 服务就绪 / 注册结果 / 错误原文 / 版本 / pid），已在 `SECURITY.md` §运行面板 披露；它在修好前就已用上——我用它读到测试期分支（`stage: registered` / `source: env`）。
