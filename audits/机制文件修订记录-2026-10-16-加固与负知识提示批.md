## 三、逐条落点

### 加固 1｜收窄触发语义：**引述 ≠ 使用**

- **病灶（批次一遗留）**：`[L00]` 方法论扫描的触发条件是「**分析大纲含「方法名」**」——只要出现「复杂网络」「内容分析法」这类词就**必跑**，而这两个词**正列在该节自己的方法名示例里**。后果：一篇 `industry` / `biz-review` 只要**提一句**某方法就触发，进而按字面要求「指向 `[Lxx]` 条目 + 补方法学四字段」。
- **改法（两处真源同改）**：`01-文献检索` §方法论扫描 与 `机检硬格式.md` §二 都改为「**本文把某方法用作分析工具**」，并在 01 卡写明判据：「**引述他人用过某方法**（如『已有研究用 PSM 检验过 X』）**不触发**」。
- **为什么必须两处同改**：这两份是「运行期角色卡」与「机检契约唯一真源」——只改一处即成该仓反复踩过的「同一事实两处互漂」缺陷类别。

### 加固 2｜补显式 `N/A` 口径：**非学术类有正当的不适用声明**

- **病灶（批次一遗留）**：非学术 7 类**最缺「说明哪些不适用」的机制面**（结构门不跑、T9 默认不选、`--qlt` off），于是「方法学字段块」会**无声地落在非学术稿上**，没有任何落点说它不适用。
- **改法**：三处（01 卡 / 机检硬格式 §二 / 对照表 §三）并列写明 **记 `N/A`（≠ 通过，不得读成已核）** 的三种形态：
  1. **引述他人用过某方法**；
  2. **单视角 T9 模式**——`course` / `book-review` / `policy` / `report-3rd` / `biz-review` / `industry` / `wechat` 七类，真源 = [`文类档案.md`](../skills/lunheng-article-pipeline/references/_shared/文类档案.md) §T9 决策树（**不 spawn T9-m ⇒ 方法学字段块无消费者**）；
  3. **`--qlt` 关闭**。
- **援引的既有判据**：该仓 `规范-机械门对照表.md` 的 G15 行已立「**模式相关项的开关只能由调用方显式声明，刻意不从简报字面推断**」，且 `g-audit-check` 有「`N/A`（不适用）≠ `SKIP`（适用但缺输入）」的成文口径——本加固与之同口径，**不新造判定语义**。
- **实际影响面（如实）**：非学术类的 T9 **默认不选**（`文类档案.md:57`），即便主人显式开也走**单视角**，而单视角的维度 2「方法论」数据源是「T4 分析大纲 + **数据卡**」（`pipeline-readme.md:532`）——**不含 M3、不含方法学字段块**。故对非学术类，本批是**把"本就为零的影响面"显式写成零**，防的是**将来** T9 对非学术类启用或 `[L00]` 被误读时的无声误用。

### 动议 E｜负知识进池（**丙案**）

- **病灶**（反哺报告 F6）：`素材池` 的 type 只有 `L/D/C/DB`，`pool-extract` 只抽「被采纳的证据卡条目」；而 `run/<项目>/audits/disproofs.jsonl` 是**项目内** append-only 账本、**不进池** ⇒ A 项目核实出的「某条数据并不支持它被引用的主张」在 B 项目查池时**不可见**，B 会照样引进来。**正面素材复用只省检索时间，证伪结论复用能直接避免一次踩坑。**
- **改法（丙案 = 只读提示层，零新脚本、零新文件、不动数据模型）**：`pool-query.mjs` 新增 `readDisproofs()`，只读扫描 `<工作区根>/run/*/audits/disproofs.jsonl`，按**同一组关键词**匹配 `claim / basis / reproduce / note / evidence`，命中则以「负知识提醒」段落原文照印（含 `originProject` / `id` / `round` 回指 / `reproduce` 复现路径）。
- **三条设计判据（逐条对应本仓既有顾虑）**：
  1. **放在「空池早退」之前**——池空 + 有历史证伪，正是本提示**价值最大**的场景（没有正面素材可复用，但有前人踩过的坑）；实测夹具 A 已复现该序。
  2. **正面回答 `负知识账本.md` §九.1 自己登记的「未做」理由**（原话：「聚合会引入新的口径问题（**同名主张如何判同？**）」）——**本层不做判同**：只提示原文、由主控读原文判适用。故该顾虑**不被本层引入**；代价如实登记：**同一主张在两项目各记一次时提示会重复出现**。
  3. **坏行不在此报错**——点名归 `disproofs-check.mjs`（只读校验器），避免两处报同一缺陷导致「谁负责」失焦。
- **顺带把 `负知识账本.md` §九.1 从「未做」改判为「部分实现」**，并写明**仍未做**的是「聚合成一份可检索库」（去重 / 判同 / 合并 / 复用计数）——本仓判据：**未做项必须写明「未做 + 理由」**，已完成项也不得留「未做」的旧声明。
