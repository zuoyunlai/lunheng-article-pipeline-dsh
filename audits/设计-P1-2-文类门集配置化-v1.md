# 设计 — P1-2 / S2：文类 → 门集配置化（v1）

> **性质**：设计提案（尚未实现）。来源 = `audits/反哺报告-2026-10-17-全量审计九维-v1.md` §P1-2。
> **要解决的问题（有实测数字）**：33 份真实 M 门报告里 **16 份** `exit ≠ script_exit_raw`（48%），
>   根因不是门写错，而是**文类不匹配**——同一套 25 项按 IMRaD 默认档跑非 IMRaD 稿件，产出系统性假阳性，
>   再由 T8 手写四件套改判。**目标：把「人工改判」变成「脚本按文类出正确结果」**。
> **不是新机制**：`--genre` 已存在（只驱动文献下限）、`--lite-profile` 已实现「按表裁剪 results」、
>   文类档案已有 13 列真源表——本设计是把这三样接起来，**不新增闸门、不新增角色、不新增文类**。

## 一、验收指标（先定判据，再动手）

| 指标 | 现值 | 目标 | 测法 |
|---|---|---|---|
| T8 改判率（`exit ≠ script_exit_raw`） | 16/33 = 48% | **< 15%** | `run/**/final/M-Gate-Report.json` 回放 |
| 门失败中 P2 占比 | 82/118 = 69% | < 40% | 同上按 severity 聚合 |
| 单文类最小样本 | — | 每启用文类 **≥5 个历史项目** | 回放清单 |

**不做**：不以「提高通过率」为目标。若某文类在 profile 下仍有真 P0，必须照报。

## 二、核心设计判断：**黑名单 + 影子运行**，不用白名单

三种可选形态：

| 形态 | 做法 | 问题 |
|---|---|---|
| A. 白名单（只跑列出的门） | profile 列 `gates: ['M-Form-1', …]` | **新增门默认永不运行**——未来加 M-Exist-13 时，所有文类静默跳过它。这是最危险的形态 |
| B. 黑名单（默认全跑，显式列 N/A） | profile 列 `gate_na: ['M-Form-2', …]` | 新增门默认**照跑**（fail-closed）；缺点是 N/A 表需要人维护 |
| C. B + 影子运行 | 被列 N/A 的门**照样跑**，但结果不计入 exit，单列 `shadow_fail` | 多花一点计算，换来「N/A 判断是否正确」的持续证据 |

**选 C。** 理由：

1. **fail-closed**：新门默认生效，不会因为没人更新 profile 而静默失效——这与本仓「静默降级 = 缺陷」的既定立场一致。
2. **可证伪**：`shadow_fail` 回答一个关键问题——「这条门在本文类上到底命中过几次真缺陷？」。若某门在某文类的 `shadow_fail` 长期为 0，N/A 才有据；若**天天命中 P0**，说明 N/A 列错了，机器会自己叫。
3. **可回滚**：影子数据先跑一阶段（不改变 exit），确认无副作用后再启用——避免一次性改掉 25 项的聚合语义。

## 三、数据模型（单一真源）

新增 `skills/lunheng-article-pipeline/scripts/_lib/genre-profiles.json`：

```json
{
  "profile_version": 1,
  "default": "academic-cn",
  "genres": {
    "kaiti": {
      "minL": 10,
      "structure": "kaiti-nine",          // 驱动 structure-check（取代 --kaiti）
      "endnoteSections": 3,               // 文末节数量（M-Form-2/7 的判据输入）
      "gate_na": ["M-Form-2", "M-Form-7", "M-Exist-12"],
      "na_reason": {
        "M-Form-2": "开题报告文末节 = 3（参考文献/数据来源/案例来源），五节口径不适用",
        "M-Form-7": "同上：五节顺序不适用",
        "M-Exist-12": "开题报告不要求正文贡献陈述"
      }
    },
    "report-3rd": { "minL": 1, "structure": "off", "endnoteSections": 5, "gate_na": ["M-Form-8"], "na_reason": {} }
  }
}
```

**约束（写进校验）**：

- `gate_na` 的每一项**必须在 `GATE_IDS` 里**（防拼错成一条永不生效的 N/A）。`GATE_IDS` **不手写**：由测试对一份夹具跑一次全量门，取 `results[].gate` 的前缀集合派生（`_lib/mgate-gates/gate-count.mjs` 只导出**计数**派生，不导出清单，故清单在测试侧派生一次即可）。
- `na_reason` 必须**逐条覆盖** `gate_na`（无理由的 N/A 不允许）。
- `minL` 与 `structure` 与 `文类档案.md` 的两列**必须一致**（新增一致性规则；见 §六）。
- **默认值缺省**：`genres` 里没有的 code → 走 `default` 的全量门集 + `minL=3`（向后兼容，等价今天的行为）。

## 四、消费者改造（四处，均不改变既有退出码族）

### 4.1 `m-gate-check.mjs`

1. 读完 `--genre` 后加载 profile；非法 code 仍 exit 10（现有行为保留）。
2. **照常跑全部 25 门**（不做前置裁剪——这就是影子运行）。
3. 聚合前应用 profile：把 `gate_na` 命中的 result 改写为
   ```js
   { gate, pass: true, na: true, severity: 'NA',
     detail: `N/A（${genre}）：${na_reason}`,
     shadow: { pass: 原pass, severity: 原severity } }   // 影子值，只进报告不进 exit
   ```
4. 聚合面改动（**唯一需要动 exit 的地方**）：
   - `p0/p1/p2/soft/skips` 只统计 `!na` 的项；
   - `anyFail` / `softOnlyCount` 只看 `!na`；
   - `exit` 公式**不变**——只是输入集变小。
5. 报告新增字段：`genre`、`genre_profile_version`、`gates_na: [{gate, reason}]`、`shadow_fail: [{gate, severity}]`。

### 4.2 `structure-check.mjs`

把 `--kaiti` / `--humanities` 保留为**别名**，新增 `--genre <code>` 读同一份 JSON 的 `structure` 列
（`imrad` / `imrad-alt` / `kaiti-nine` / `off`）。`off` → 输出「N/A：本文类结构门不适用」（exit 0，不是 3——
N/A 与「需复核」是两件事，这条要在实现时明确）。

### 4.3 `final-check.mjs`

已经读 `M-Gate-Report.json`；新增两件事：
- 报告含 `gates_na` 时，在 `notes` 记一行（**不改变 exit**）；
- 报告 `genre` 与任务简报文类不一致 → 记 note（防「换文类重跑」造成口径漂移）。

### 4.4 `--adjudicate` 的交互（关键）

启用 profile 后，**多数改判不再需要裁定**。保留裁定通道，但收紧入口：报告里已有 `gates_na` 覆盖的失败项时，
`--adjudicate` 拒绝对该项写裁定（exit 30，理由「该项在本文类已 N/A，无需人力兜底」）——防止「用裁定绕过 profile」。

## 五、分三阶段灰度（每阶段独立回滚）

### 阶段 1 · 影子（不改变任何 exit）— 0.5 天

- 落 JSON + 加载器 + 报告字段（`gates_na` / `shadow_fail`），**聚合逻辑不动**。
- 用 `run/` 33 份历史报告回放：统计「若启用，会有多少项从失败变 N/A、其中多少是影子 P0」。
- **交付判据**：一份读数表（每文类 × 每门 × shadow_fail 次数）。此阶段**零行为变化**，可先合并。

### 阶段 2 · 开 `kaiti`（单文类）— 0.5 天

- profile 对 `kaiti` 生效（聚合面按 §4.1 改）；其它文类仍全量。
- 回放 5 个 kaiti 项目（`腐败资产外逃` 等）：期望 `exit ≠ raw` 从 2/2 降到 0/2，且**无新增通过的真 P0**（以影子值为准人工抽查）。
- **交付判据**：改判率下降 + shadow_fail 逐条有解释。

### 阶段 3 · 开「不跑结构门」的五文类 — 1 天

- `report-3rd` / `biz-review` / `industry` / `wechat` / `book-review`（按文类档案「结构门=不跑」）。
- **交付判据**：这五类的 T7/T8 不再为结构门写改判。

> 学术三类（`academic-cn/-hum/-case`）**本设计不动**：它们是 IMRaD，25 项本就适用；它们的改判主要来自
> M-Form-2/7 的「9 节 vs 5 节」口径，属另一条线（`endnoteSections` 参数化），可在阶段 3 之后单独出。

## 六、测试矩阵（缺一不可）

| 类型 | 用例 | 钉住什么 |
|---|---|---|
| 表完整性 | 遍历 profile：每个 `gate_na` ∈ `GATE_IDS`；每个 `gate_na` 有 `na_reason` | 防「拼错的 N/A 永不生效」 |
| 一致性 | `genre-profiles.json` 的 `minL`/`structure` == `文类档案.md` 同名两列 | 防两份真源漂移（新增规则编号） |
| 行为·N/A | `--genre kaiti` 跑一个 kaiti 夹具 → `M-Form-2` 为 `na:true`、`exit` 不含它 | 主路径 |
| 行为·影子 | 同上但夹具**故意缺五节** → `shadow.pass=false` 且 `shadow_fail` 有值、`exit` 仍 0 | 影子不泄漏到 exit，但可见 |
| 行为·默认 | 不传 `--genre` → 行为与今天**逐字段相同**（对比旧报告 JSON） | 向后兼容 |
| 反例·裁定 | 对已 N/A 项 `--adjudicate` → exit 30 | 防裁定绕过 profile |
| 元门 | 统计「某门在某文类 N/A 且 shadow_fail 长期为 0」→ 出提示 | 让 N/A 可被复审 |

## 七、风险与反制

| 风险 | 反制 |
|---|---|
| **N/A 变成逃逸口**（为了让稿子过而标 N/A） | ① `gate_na` 只在 JSON 里，改它要过 review + 一致性规则；② `shadow_fail` 全程可见；③ 元门提示「N/A 但常命中」；④ `--adjudicate` 拒绝对 N/A 项裁定 |
| 历史报告不可比 | 报告记 `genre` + `genre_profile_version`；旧报告无该字段 → 视为「全量档」 |
| 新增门被漏配 | 黑名单形态天然 fail-closed：新门默认跑；测试「GATE_IDS 新增项必须在所有 profile 的 `gate_na` 之外（或显式登记）」 |
| 计算量翻倍 | 影子运行不额外跑门（本来 25 项就都跑了，只是**不裁剪**）；成本≈0 |

## 十、阶段 2 实现要点（已完成，供 review）

1. **聚合按 `na` 过滤**：新增 `counted`（`naEnforced` 为空时 `counted === results`，保证未启用文类逐字段不变），
   `skips/pass/fail/soft/hard/errors/unchecked/hardRedLineHits/anyFail` 全部从 `counted` 派生；**exit 公式一字未改**。
2. **总数可对账**：`total` 仍是本次跑的门数（契约 `total = pass+p0+p1+p2+soft+skips` 不变），
   另给 `evaluated_total` 与 `na_count`，满足 `total = evaluated_total + na_count`。
3. **结果项标记**：N/A 项带 `na: true` + `na_reason`，**保留原 `pass`/`severity`** 作为影子值（可复核 N/A 表是否合理）。
4. **裁定守卫**：`--adjudicate` 的 `refutations` 若点名 N/A 项 → **exit 30**（防「用裁定绕过 profile」）。
5. **文案**：stderr 明确区分「已生效（不影响判定）」与「未启用（仅影子）」，不再出现「阶段 1 不改变 exit」的误导句。
