**三条口径（防假绿 / 防刷分）**：① 分数只反映**硬失败**（P0/P1 与结构缺项），P2 软提示单列不扣分；② N/A 分量不进分母但**必须连着 `coverage` 读**（<0.8 给 `coverageWarning`；体例不适用如实标 N/A，**不给 0 分**；`g-audit` 的 SKIP 项按缺输入降权，**SKIP ≠ 通过**）；③ **分数不影响退出码**——挂成闸门会立刻产生「为过门而刷分」的压力，而各分量都允许 N/A，一旦分数决定放行，**N/A 就是最省事的刷分路径**。

## 四、本批的操作事故（如实标注）

**同一坑踩了两次**：编辑 `cite-coverage-check.mjs` 时又用了 `pwsh` 的 `Get-Content … | Set-Content -NoNewline`，把文件压成一行（`//` 注释吞掉全文 → SyntaxError）。
- 第一次（v18.23.0，`g-audit-check.mjs`，未跟踪新文件）→ 无 git 可回滚，靠「按已知内容重写 + 去换行后逐字符比对」恢复。
- 第二次（本批，`cite-coverage-check.mjs`，**已跟踪**）→ `git checkout --` 直接恢复，再逐处重做**第三、四层**改动。

**教训**：该禁令**已在 MEMORY.md 里**（v18.23.0 事故后写下），本批仍复发——说明「记住」不等于「不犯」，**操作层的强制**才有效：**改任何源码文件只用 `edit`/`write` 工具或 Node `writeFileSync`**，`pwsh` 只用于读（`Get-Content`）与跑命令。两次事故的损失面差异也值得记：**已跟踪文件可秒级回滚，未跟踪新文件只能靠上下文重建**——故新增文件落盘后应尽快 `git add`。
