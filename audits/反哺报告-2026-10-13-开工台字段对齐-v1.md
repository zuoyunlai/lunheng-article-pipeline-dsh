## 1. 一句话结论

开工台原本有 **25 个 `WB_DEFAULT` 键（22 个在界面上有控件）**，其中：

- **3 项直接撞门**（照填必红，且其中 2 项填了也关不掉）；
- **3 项静默失效**（消费点格式对不上 ⇒ 脚本跳过检查并 **exit 0**，属**假绿**）；
- **5 项真死字段**（值无人读）；
- **3 项被第一版误判为「零消费者」**，复核证明**真源与机器载体都存在**，病灶是**表单在真源之外造了第二个开关且无仲裁规则**。

**根因两条**（比逐条症状更重要）：

1. **判档方法错**：第一版只 grep「字段名有没有出现在脚本里」，没追「这个值最后落到哪个真载体」。字段名不在脚本里 ≠ 没机制（可能落在简报的机器行）、字段名在脚本里 ≠ 有机制（可能只是同名的别的东西）。
2. **表单造第二真源**：文类档案（`references/_shared/文类档案.md`）已经把「结构门 / `--qlt` / 补扫 / 文风档 / T9 视角 / 期刊匹配 / 文献下限」等 11 列写成**预置映射**，面板又给每一项一个可编辑开关，**且没有任何仲裁规则**说明「面板值与档案预置冲突时听谁的」。

**本批处置纪律（一句话）**：**机器可读的真载体只能有一个，面板不造第二个。** 能派的派给它（`A11` / 素材池 `§11.2` / 简报机器行），派不了的降为**只读或删除**，仍缺落点的**补齐真落点**（`README.md` §定稿引用规范）。

## 4. 三类病灶逐条（含证据）

### 4.1 直接撞门 3 项

**① `citeStyle = ieee / mixed`** —— 照填必红，且**本仓从设计上就没有这两个模板**。
`scripts/cite-format.mjs:63-67` 白名单只有 `gbt`/`apa`，其余 `exit 10`；`references/_shared/引用格式.md:57`「本契约没有 IEEE 模板」、`:59`「任何文档不得声称支持 IEEE」。
**处置**：删掉这两个选项（`WB_CITE_STYLE` 余 `['', 'gbt', 'apa']`），并把「IEEE 暂缓」的既有依据写进 WB-13 登记的 `why` 里，防止下次有人「顺手加回来」。

**② `structure = off`** —— 不只是撞门，而是**它根本关不掉**。
`references/_shared/文类档案.md:7` 逐字禁止新增档位（「如『文献下限=0』『结构门=跳过』」）；且 `_lib/mgate-gates/mexist-gates.mjs:720-731` ＋ `_shared/规范-机械门对照表.md:91` 要求 **T7.5 记录必须提到 `structure-check` / `methodology-check` / `cite-coverage`**，不提 → **P1**。故「关掉结构门」这句话在机制侧没有对应实现。
**处置**：删 `off` 档；v19.4.0 更进一步把它**降为文类派生值**（只读徽标，值来自档案「结构门」列），详见 §7.3。

**③ T2 / T3 编号印反** —— 面板告诉主人的角色编号与真源相反。
`lib/client.js`（改前 `:407`）打印「T1 文献=／T2 案例=／T3 数据=」，而真源 `SKILL.md:97`「T1 文献 / T2 数据 / T3 案例」、`:157`、`references/dispatch-cards.md:34,40` 均为 **T2 = 数据、T3 = 案例**；界面 checkbox（改前 `:1996`）也按错序排。
**处置**：整套「三勾选」删除，换成 `retrieval` 两档（`全网检索` / `仅本地素材`）＋ `素材池.md` §11.2 逐字派发话术。**角色一个都不减**——档位只改来源，不改角色（`_shared/素材池.md:166-169`）；案例线唯一合法减法是 Phase 0 显式 `cases=0` 且仍 spawn T3 出空卡（`agents/03-案例检索-case-scout.md:116`），直减会撞 M-Form-8（`_lib/mgate-gates/mform-gates.mjs:456` 每论点必含 `[L]`）。

### 4.2 静默失效 3 项（**假绿**，比撞门更危险）

**④ 篇幅行字面串过不了 `LINE_RE`** —— 改前开场白写 `- 篇幅上限: 8000 汉字`；`_lib/target-chars.mjs:30` 的正则是
`/(?:目标篇幅|篇幅)[\s*_`]{0,4}[:：][\s*_`]{0,4}([^\n]{0,24})/`——**「上限」二字落在字段名与冒号之间，字符类里没有它**。

**处置**：改为模板标签形态 `- **目标篇幅**：8000 汉字`（`_lib/target-chars.mjs:19-20` 的 `MIN_TARGET=300` / `MAX_TARGET=200000` 一并核过），并加**格式敏感断言**（WB-13 ④）钉住它。

**⑤ `minLit`（文献下限）是纯死字段** —— `_lib/mgate-gates/mform-gates.mjs:88-102` 的 `GENRE_MIN_L`（缺省 3）与 `THRESHOLDS.mform1MinL` 只认 **`--genre` CLI 旗标**，从不读面板值；`_shared/文类档案.md:94` 同证。

**⑥ `lang = en` 会在字数门上连环炸** —— `scripts/count-chars.mjs:9-15` ＋ `scripts/_lib/han.mjs:3` 只数 `\u4E00–\u9FFF`，非中文稿 `hanChars = 0` ⇒ `_shared/字数判定表.md:36-48`（不足 >10% = P0 须扩写）必触发。`wbValidate` 不拦 `lang`；`SKILL.md:128` 有「非中文请换工具」的散文提醒但**无脚本兜底**。

**处置**：取值改 `WB_LANG = ['中文', 'English', '中英混']`（逐字对齐模板）＋ 新增 `wb.langHint` 明写「非中文稿汉字数恒 0 ⇒ 必触 G8 P0」。

## 5. 实跑发现（本版新增，A 级证据）：`引用模式 = 内联` 的名实不一

### 5.1 测法与矩阵

探针一次跑 **11 个文类 × 2 个变体**（`m-gate-check.mjs <draft> <ev> --genre <code>`）：变体 `inline` 按档案预置写（正文纯内联 `（机构，年份）`、文末条目不编号），变体 `num` 正文仍带 `[L01]` / `[D01]` / `[C01]` 编号。

| 文类 | 档案「引用模式」列 | `inline` 变体 | `num` 变体 |
|---|---|---|---|
| `academic-cn` / `academic-hum` / `academic-case` / `course` / `lit-review` / `book-review` | **编号**（`book-review` 为「GB/T / 内联」） | ✅ M-Form-1 / M-Form-8 / M-Exist-1 全通过 | ✅ 同 |
| `policy` / `report-3rd` / `biz-review` / `industry` / `wechat` | **内联** | ❌ **`exit 2`：`M-Form-1 = P0`（detail 逐字「正文无任何引用标注」）＋ `M-Form-8 = P0`；而 `M-Exist-1 = 通过`（漏引 0 / 硬孤儿 0，即空转）** | ✅ 三项全通过 |

**⇒ 11 个文类里有 5 个的档案自带预置写不出合规稿**；唯一能过门的写法是**违背该预置**、正文仍带 `[Lxx]`。
**该拦的没拦**（内联引用的可回溯性没人查），**不该拦的全拦**（编号缺失直接 P0）。

### 5.2 文档承诺 vs 实现现实

`references/_shared/M-Gate-Algorithm.md:789-818` 逐字承诺了 `2B. 内联模式（v2.2.4）` 分支（提取内联引用 → 把 5 项依赖编号的检查改为可回溯性检查 → 全部可回溯才通过），`_shared/M-Gate-Algorithm-appendix.md:105` 记「内联引用 ≠ 无引用」、`:122` 记 v2.2.5「已覆盖全部 5 项」。`:127` 更把它列为已闭环的实战成绩「内联模式空转 → v2.2.4 覆盖 24 条引用 ✅」。

**实测：`grep` `引用模式|机构，年份|内联模式|inlineRef|inline_ref` 在整个 `scripts/` 下 `No matches found`**——该分支**零实现**，上述三处声明全部不成立。这正是本仓自己命名过的病：**「会被机检、但没有检查在跑」= 假绿**（`M-Gate-Algorithm.md:124`，v18.2.6-B 教训）。

### 5.3 结论与依据（为什么选「改文档」而不是「实现它」）

**甲案（已采纳）：把「引用模式」正名为交付形态，文档对齐实现。**
三条依据：

1. **本仓既有先例**：`_shared/M-Gate-Algorithm.md:902` 逐字「**对齐方式：改文档以匹配实现**（而非新增检查）——补一个未经实战校准的 P0 门会立刻在既有项目上产生误报，风险高于收益」（v18.2.6 同名实对齐批）。
2. **乙案（真实现 2B）与既有架构冲突**：证据包与四类卡片（文献卡 / 数据卡 / 案例卡）**全以 `[Lxx]` / `[Dxx]` / `[Cxx]` 为键**（M-Form-6 信任级别段、M-Exist-3 引用闭环皆然），且 `agents/05-写作-writer.md:301-303` 明令写手做「正文编号 ↔ 文末四节」双向闭环 ⇒ **稿内本来就是编号**。
3. **真源本来就把内联定位成交付形态**：`agents/05-写作-writer.md:298` 逐字「终稿若面向公众号/非学术读者，正文引用标注**应在交付阶段由主控转换**为 `（机构，年份）` 内联形式 + 文末『引用来源』清单」；`agents/07-审计-auditor.md:217` 亦记「**保留 `[Lxx]` 编号兜底**」。

## 6. 开场白 → 简报 → 机制 全链对账
