## §一 触发背景

**主人提问原文（2026-10-16）**：

> 「对于论衡插件而言，出来数据卡，案例卡，文献卡，还有哪些可以建立卡片作为论据素材？作为专业的论文写作与评审专家，你有更多更好的建议吗」

**核实后的重述**：问题不是「还能建哪些卡」，而是**「现有三卡覆盖了哪几条轴、哪条轴上的消费者在空转」**。

三卡的轴是**来源（L）/ 数值（D）/ 事件（C）**——即回答「这事有没有人研究过 / 这事多大 / 这事怎么发生的」（真源 `skills/lunheng-article-pipeline/README.md:89-93`）。

核实下来，缺的是**第四条轴：这份证据是怎么产生的（研究设计 / 方法学）**。而这条轴上的消费者**已经存在四个**，只是**全部在别处碰运气**：T9-m 的 M1/M2/M3、以及 `meta-synthesize.mjs`。其中一个（M3）甚至已经把一个**全库不存在的制品名**写进了自己的数据源列——这是本报告最硬的一条实据（§2.2 F1）。

### 2.2 核实明细（逐条实据，不以报告自述为准）

#### F1｜「方法卡」是一个**被下游当真源指望、却从未被生产**的制品

- 全库 `grep "方法卡"` **仅 2 处命中，两处都是把它当「输入」引用**：
  - `skills/lunheng-article-pipeline/references/agents/09-审稿-peer-reviewer.md:333` —— T9-m 清单 **M3「因果推断合法性」** 的「数据源 / 引用」列原文含「+ 方法卡」；
  - `skills/lunheng-article-pipeline/references/pipeline-readme.md:580` —— 同一条的对上摘录「M3 因果推断合法性（初稿 + 方法卡）」。
- **无模板**（`references/templates/` 无对应项，该目录清单真源见 `SKILL.md` §模板 行）、**无产出角色**（T1–T9 无一以它作产物）、**无门消费**。
- 结论：M3 的数据源列里，`drafts/初稿-vN.md 方法节` 与 `analysis/分析大纲.md`「识别策略与反事实」段都是真实存在的产物，**只有「方法卡」不存在**。

#### F2｜`[L00]` 的机检判据被记在**一个不管它的门**名下（同一句错判据写在两处）

- 两处原文均称：「终稿正文引用方法但文末缺 `[L00]` → **M-Exist-3** 判漏引」——
  - `references/_shared/机检硬格式.md:31`（**§二 文献卡专属 [L00] 行**的「违反后果」列）；
  - `references/agents/01-文献检索-literature-scout.md:58`。
- 而 **M-Exist-3 的实装只认 `[Dxx]`**：`scripts/_lib/mgate-gates/mexist-gates.mjs:1804` 段头即「M-Exist-3 **[Dxx]** 正文↔数据卡 引用闭环」，`:1810-1811` 取 `refsOf(bodyProse, 'D')` 与 `dataCardIds(dataCard)`。**它不看 `[Lxx]`，更不看 `[L00]`。**
- 真正会报的是 **M-Exist-1（文末四节双向对比）**：`scripts/_lib/refs.mjs:20` 载明 `refRe` = `L|D|C-主|C|先`，`:31` 的 `refRegex('L')` = `/\[L\d+\]/`，故 `[L00]` **会被命中**——但前提是**该编号真的出现在正文与文末节里**。
- 关键补充：`[L00]` 的规范位置是**文献卡索引段**（`机检硬格式.md:31` 明写「索引段顶部增 … 行」），而 `scripts/_lib/mgate-gates/mform-gates.mjs:1055` 的 `SPECIAL_INDEX_ONLY = new Set(['L00','L99','L-cross'])` 把它**双向豁免**出「索引 ↔ 正文条目」对账（注释原文：「它们是索引段独有行 … 正文不会有 `### [L00]` 条目」）。
- **净结论**：「正文声称用了某方法、但文献卡里没有对应方法论依据」这件事，在**机械面零覆盖**；唯一防线是 `01-文献检索-literature-scout.md:58` 前段的 **T7 人工判 P1**。
- 同型先例（说明这不是新问题类别）：该仓 v18.0.3 已因「M-Exist-3 名实不符」做过一次更名对齐（`mexist-gates.mjs:1807-1808` 留痕：「本项旧名『信任级别一致性』，但它**只做引用闭环**」）。

#### F4｜规范效力：`policy` 是正式档，但没有对应的证据形态

- `references/_shared/文类档案.md:22` 的 `policy`（政策分析报告 / 咨政报告）是**正式文类**（文献下限 2、`--qlt` off）。

- 数据卡字段（`机检硬格式.md` §一/§三 + `agents/02-数据检索-data-scout.md` §数据卡格式）：数值 + 单位 + 口径 + 来源 + 年份 + URL + 信任级别 + 时效 —— **非数值对象无处放**。

#### F5｜`meta-synthesize.mjs` 的触发条件读 A 卡族、产物所需字段住在 B 卡族

- 触发真源：`agents/04-分析-analyst.md:185` —— 「T4 检测到 `run/<项目名>/data/数据卡.md` 中 **≥10 张同质数据卡**时，主控必跑」。
- 实现：`scripts/meta-synthesize.mjs:53-58` **只读** `data/数据卡.md`（`dataCardPath` 写死，无第二输入路径）。
- 字段提取：`:75` 用 `/(?:样本量|n|N)[：:=]\s*(\d+)/` 抓 `sampleSize`；`:76` 用 `/(RCT|队列研究|横断面|case-control|meta-analysis|experiment|survey|interview)/i` 抓 `studyType`；`:122-136` 的**效应量候选**分支在 `:128` 依赖 `studyType ∈ {rct, 队列研究, case-control}`。
- 而**数据卡的机检硬格式里没有 `studyType` 与 `sampleSize` 字段**（§一/§三 表 + §二 通用「头部条数声明」行可逐字核对）→ 一张**完全合规**的数据卡上，二者恒为 `null` → 效应量候选退化。
- 索引段兜底更直白：`:84-98` 的兜底分支**显式写死** `sampleSize: null, studyType: null`（`:97`）。
- 病根（一句话）：**元分析的效应量来自「研究」，而研究设计属性住在文献侧；脚本去数据卡里找研究设计，是因为两卡都没有这个字段。**

#### F6｜负知识不进池，跨项目不复用

### 3.1 动议 A（P1）：方法学轴落进文献卡 —— 修幽灵引用

> **来源**：F1（`agents/09-审稿-peer-reviewer.md:333` + `pipeline-readme.md:580`）+ F2（`机检硬格式.md:31`）+ F5（`meta-synthesize.mjs:75-76`）

> **改动（两案，建议甲案）**：
>
> **甲案（推荐，零新编号族、零新文件）**——在**文献卡条目的可选字段块**落地方法学四字段，仅对「类型 = 方法论文」的条目要求：

> - `**本文是否满足**`（+ 依据 / 或如实写「不满足，故降格表述」）
> - `**已知失效情形**`（替代解释、边界）

> `[L00]` 索引行**格式不变**（仍是索引段独有行，仍不计入总条数），只要求它**指向**对应的 `[Lxx]` 条目。同批把 M3 的数据源列由「方法卡」改写为「`literature/文献卡.md` 的 `[L00]` 行 + 其指向的 `[Lxx]` 条目方法学字段块」。

> **乙案（新族，成本高，仅在甲案字段确被证实溢出后启用）**——`literature/方法卡.md` + 新编号族。**编号不得用 `[Mxx]`**（F7）；用 `[L-方NN]` 形态会**像 `[L-pre]`/`[L-cross]` 一样天然不进 M-Form-10 对账**（正则 `\[([LDC])(\d+)\]` 要求字母后紧跟数字），即**「未核」而非「已核」**——须同批改 `机检硬格式.md` + `scripts/handoff-check.mjs` 的 `PATH_SPECS`/A3 + `build-evidence-bundle.mjs` 源清单 + `素材池` type。
