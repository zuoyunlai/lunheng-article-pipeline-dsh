## 发现、机制与修复

### P0-1 裁定被拒，控制台声称已落盘，实际保留旧报告【实测】

`skills/lunheng-article-pipeline/scripts/m-gate-check.mjs:595-611` 在硬 P0 或证伪材料不足时 `process.exit(30)`；真正 `writeReport` 在 `:632`。旧报告若曾为 `exit=0`，本次正文已命中 P0，磁盘文件仍显示 0。现有 `tests/adjudicate.test.mjs:62-105` 先落盘本轮机械报告再测拒绝，因此未钉“旧绿→新红”。**修复**：拒绝前用既有安全写接口写入本次机械值，写盘失败转 70，成功后退出 30；新增旧绿→新红、拒绝前后指纹/exit/时间戳三方断言。

### P1-1 审计视图滞后于最新 M 门【代码时序】

`final-check.mjs:78-80` 先执行 `build-evidence-bundle --summary`，再执行 `m-gate-check --report`；`build-evidence-bundle.mjs:433-446` 读取磁盘 `final/M-Gate-Report.json` 写审计视图。因此存在旧报告 exit 0、新 M 门 exit 2，而视图仍显示旧值的时序窗口。`final-check` 自己的 steps 能看到新退出码，不能将整个终检说成 exit 0 假绿。**修复**：证据卡刷新→M 门→审计视图刷新分为独立步骤；测试旧绿→新红和旧红→新绿，并核对视图的报告指纹。

### P1-2 发布前 gates 漏跑子技能测试【配置事实】

`.github/workflows/publish.yml:59` 仅 `"tests/**/*.test.mjs"`；`package.json:59-60` 和 `.github/workflows/ci.yml:178` 还包含 `"skills/*/tests/**/*.test.mjs"`，其中 `skills/lunheng-commands/tests/route.test.mjs` 为内嵌子技能测试。CI 主路径会跑，发布 gates **自身**不跑，不能误称“所有 CI 均不跑”。**修复**：统一三个入口与 `skills/lunheng-article-pipeline/AGENTS.md` 的命令，加跨工作流测试范围一致性断言；作为下一版发布前检查。

### P1-3 G8 字数豁免误识别否定句【代码与独立交叉复核】

`g-audit-check.mjs:168,183-186` 用无上下文子串匹配；简报“**不允许字数不作硬规定**”也会触发 `G8-CharCount` 的 SKIP。该项是候选判据，T7 才最终判级；不能声称“整套门直接通过”。**修复**：改成简报专属结构化肯定式字段；覆盖否定句、引用、代码围栏及合法豁免的成对用例。

### P1-4 两种 dry-run 输出误导【代码与独立交叉复核】

`apply-diff.mjs:228-234` 在 `--dry-run` 尚未写盘前以“原地覆盖” exit 10，但实际写盘在 `:314` 已用 `!dryRun` 限定。将守卫条件限定为真实写盘分支并写非写盘试算测试。`apply-revision-cycle.mjs:62-64,87-89,113` 干跑不复制也不应用 diff，仍优先 measure 已存在的 vN 占位文件，可能把历史文件当本次“改后”字数；应明确报告未执行或以 pre 为干跑基线，区分预测与实测。

### P2 机器字段与可观测性

- `apply-compression-cycle.mjs:137-140` 用 `verdict.split(' ')[2]` 取“低于阻塞线 1710 字”的缺口，实际取到 `字（P0，须扩写）`；应结构化保留整数并由字段渲染推荐。
- `quality-score.mjs:143-155` 有证据与无证据时 M-Gate 分量权重分别 38/40，名称为 23/22 机械项；统一分量权重、口径及 N/A 表示，否则 baseline 可比性受损。
- `handoff-check.mjs:475-488` 报告 B 组在 total 只计 1，但可能产生多个 B1-B4 失败，pass 数字与实际检查数不一致；退出码不受影响，需明确定义计量单位。
- `lib/index.js:340-352` 无 `tools.guard` 时可能静默不装机制保护；应明确记录降级。其保护仅作用于被识别的工具调用，`pwsh` 和任意子进程不经此门。

### P2 路径和文档边界【命令/报告临时目录复现 + 代码】

`lib/commands.js:17-22,66,81-92` 的 `/lunheng-status ../outside` 可读 `run/` 外固定文件名 `status.md` / `进展-主人版.md`；命令只读、由交互方发起，不是任意文件读取。限制参数为项目直接子目录，并用 realpath 验证符号链接边界。

`_lib/destructive-write.mjs:231-254` 的 `writeReport` 防覆盖 protect 源文件并备份，却不约束 `--report` 必须位于项目根；在临时目录实测 `m-gate-check --report <项目外绝对路径>` 可落盘。`SECURITY.md:29` 关于项目内写盘的说法不能当成已执行的强制沙箱。原生 `lunheng_m_gate` 工具并未暴露 `--report`，CLI 调用者若可运行 `pwsh` 本就具有相应写权限，故这里不按新增 P0 远程越权定级。先修正文档；若确需项目内强约束，再设计带例外的 `requireIn`，避免破坏合法的临时报告路径。
