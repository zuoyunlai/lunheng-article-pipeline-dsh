## 二、证据与修订任务书

### R-01｜M-Form-8 覆盖判定口径分裂（P1）

**证据**：

1. 现行实现按 H2 切节，分别统计 `[L]`、`[先]`、`[D]`、`[C]`、`[S]` 五类；`cov=0 → P0`，`cov=1 → P1`，`cov≥2` 且无文献族时为 P2；ACCEPTED-GAPS 可豁免，承重墙与幽灵编号另有独立 P1。
2. `M-Gate-Algorithm.md` 旧段只列部分类别，漏掉「仅 L 文献 = P0」；`glossary.md`、`pipeline-readme.md`、`SKILL.md` 又分别要求「三类全齐」「每段 L+D / L+C」「至少两项」，与脚本不一致。

**影响**：同一正文可能同时被描述为通过、P0、P1 或 P2；写手与审计员无法预判 T8 结果。

**修订**：以脚本语义为唯一真源，统一规约、词汇表、流程说明和主技能摘要；保留「覆盖率是布局检查，不代替证据质量判断」的边界。

**验收**：五类单覆盖、双覆盖、无文献族、ACCEPTED-GAPS、承重墙及幽灵编号用例与规约逐项对应；定向 M 门回归通过。

### R-02｜M-Exist-1 漏引 / 孤儿严重度旧口径残留（P1）

**证据**：`mexist-gates.mjs` 现行行为为：普通漏引、LDC 硬孤儿或缺口漏引任一存在即 `pass=false`；合计 1–10 为 P1、超过 10 为 P0；扩展未闭环为 P1；仅先孤儿为软 P2。旧文档仍写「不超过 3 条 P2 可过」或「全部 P0」。

**影响**：旧口径会诱导主控把真实引用断链当成可放行软提示，与硬 P0 红线冲突。

**修订**：统一分类、阈值、软硬边界与「不得靠删除证据改善结果」原则；所有复述只保留同一真源语义。

**验收**：普通漏引、LDC 硬孤儿、缺口漏引、扩展未闭环、仅先孤儿及 10/11 条边界均有行为断言；文档不再出现旧「可过」口径。

### R-03｜默认阻塞阶段与通知制漂移（P1）

**证据**：现行主控扩展职责规定 Phase 0 / 5 默认阻塞，Phase 2.5 / 3.5 默认通知后继续；`pipeline-readme.md`、审计角色卡和 `主人确认-template.md` 仍要求四门确认、Phase 2.5 提问或等待回复。

**影响**：主控会在本不应等待的阶段停住，或把通知误写成授权门；自动运行与模板实际行为相反。

**修订**：保留 Phase 0 / 5 的默认阻塞与显式例外；Phase 2.5 / 3.5 改为通知制，主人主动暂停、配置改变或命中风险条件时才进入确认。同步派发话术、角色卡和确认模板。

**验收**：四个阶段在文档中仅有一种默认行为；模板不再生成强制 Phase 2.5 提问；相关交互测试通过。

### R-04｜A / B / G 三环与双轨旧称并存（P2）

**证据**：主流程已采用 A / B / G 三环，但 `SKILL.md`、`glossary.md`、`deliverables.md` 和主控扩展职责仍有「双轨」；`SKILL.md` 还将 G14 错归 B 轨。

**修订**：统一为 A（对齐）、B（论证）、G（闸门）语义及编号归属；保留必要历史名称时只作沿革，不用于当前指令。

**验收**：G14 仅归 G 环；当前操作段不再以「双轨」指代三环；链接与一致性检查通过。

### R-05｜M-Form-7 五节与九节冲突（P2）

**证据**：`sections.mjs` 与 `deliverables.md` 已采用「必需五节 + 可选四声明」九节白名单及固定顺序；`M-Gate-Algorithm.md` 一处仍写五节固定顺序。

**修订**：旧段改为九节口径，明确四声明可选、必需五节不可缺、白名单外节禁止、顺序适用于实际出现节。

**验收**：非学术五节稿与学术九节稿均通过；缺必需节、白名单外节及顺序错误仍分别触发既定等级。

### R-06｜运行时写能力与默认值披露漂移（P1）

**证据**：

1. `tools.js`、`index.js`、快速事实、介绍文档和 `SKILL.md` 仍称工具均只读，但 `m_gate report` 可写报告。
2. `panel.mjs` 头注释称不写盘、默认关；实现会写诊断状态，且配置默认开启。架构说明也遗漏诊断写盘例外。

**影响**：用户会低估文件系统与本地 HTTP 暴露面；安全披露与实际行为相反。

**修订**：不改产品行为，只修声明：普通读取工具只读，`m_gate report` 是明确写入例外；面板默认开启、只监听本机，并在需要时写诊断状态；同步所有用户入口和安全边界。

**验收**：配置默认值、工具清单和文档逐项对账；相关声明面测试与插件入口测试通过。

### R-07｜历史堆叠与语义契约缺口（P3）

**证据**：若干规约同时保留旧伪代码、现行算法和多版补丁说明；部分镜像有真实下游消费者，不能一概删除。现有机检较擅长字面一致，较少直接验证文档所述输入到等级映射。

**修订**：当前规约只保留现行判据，沿革由 CHANGELOG / git / 审计报告承接；有消费者的多宿主副本保留并标真源；为 R-01/R-02/R-05 增加语义契约测试。

**验收**：测试直接构造边界输入验证行为，而非只检查字符串；无消费者的重复段移除，有消费者的链接与镜像检查不回归。

### R-08｜Windows 测试可靠性（P2）

**证据**：全量基线为 1439 例：1428 通过、9 失败、2 跳过；`command-enum` 单独运行 4/4 通过，提示全量运行隔离问题。`publish-ci-gate` / `publish-latest-step` 六个功能用例仅失败于临时目录 `rmSync` EPERM；两项 `bash -n` 因 Windows 路径未转 POSIX 失败，功能断言本身未失败。

**修订**：将传给 bash 的脚本路径转为 POSIX；临时目录清理采用有限重试并保留真实错误；检查共享目录、环境变量及并发状态，消除测试间污染。

**验收**：相关文件单独与全量运行结果一致；Windows 不因路径格式或短暂句柄占用产生假红；POSIX 行为不回归。

## 三、执行顺序与验证计划

1. **核心门与交互**：R-01 → R-02 → R-03，先统一行为真源附近的规约，再修复述层。

3. **契约与可靠性**：R-07 → R-08，增加边界行为测试并修 Windows 假红。
4. **逐批验证**：受影响 M 门测试、交互与入口测试、发布 workflow 测试；最后运行 `consistency-check`、`derive-facts --check`、`repo-hygiene-check`、`link-check` 及全量测试。
5. **收口**：按 `maintainers.md` §七执行差集与反向核验；对 R-01–R-08 逐项回代码和文档实测，不以「报告提及」代替「已经修复」。

### 验证边界

- 本批是文档、声明和测试可靠性修订，不主动改变 M 门等级算法、面板默认值或发布产品行为。
