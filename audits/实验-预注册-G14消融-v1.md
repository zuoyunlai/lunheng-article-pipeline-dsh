# 实验预注册 — G14 机制的文本效应（v1，冻结）

> **性质**：**预注册（pre-registration）**——判据在看到任何结果之前冻结。写完本文件后，任何判据变更都必须以「偏离登记」形式追加，且**不得**覆盖原判据。
> **来源**：`audits/反哺报告-2026-10-17-全量审计九维-v1.md` §十三（三轮测量：G14↔修订轮反向、大纲↔初稿不重合、规范无消费者）。
> **要回答的唯一问题**：**G14 机制是否让「成稿的 AI 痕迹更少」？** 不回答「论衡整体值不值」，也不回答 T4/T6/T9 的边际收益。
> **为什么现在能问**：G14 是全仓唯一有**独立检测器**（`references/checkers/中文AI痕迹-checker.md` + `gates/14-中文AI痕迹-gate.md`）的机制，也是唯一能用**同一把尺**量两臂输出的机制。

---

## 一、假设

- **H0**：去掉 G14（写手自检 + 终闸触发修订）后，成稿的 G14 命中类别数**不变**。
- **H1**：去掉 G14 后，成稿的命中类别数**上升**（G14 有效）。
- **H2**：去掉 G14 后，命中类别数**下降**（G14 有反效果——例如写手为规避检测而过度改写）。

结论只能三选一，**不允许**事后改问「是否更好读 / 更像人」。

---

## 二、设计

| 项 | 取值 |
|---|---|
| 类型 | 双臂、配对、**写手层**消融（不是全流水线） |
| 样本 | 5 个项目（见 §三），每项目 **2 次重复/臂** |
| 臂 A（对照） | 现行 `05-写作-writer.md`（含 G14 自检铁律）+ 现行 G14 终闸（命中 ≥ 阈值则触发修订） |
| 臂 B（处理） | **同一张卡删去 G14 自检铁律与终闸**；其余（字数、结构、引用、反方段、禁做清单）**逐字不变** |
| 输入 | 冻结的 `01-任务简报.md` + 文献/数据/案例卡 + `analysis/分析大纲.md`（含 §11）。**不提供原初稿**（避免锚定） |
| 输出 | `drafts/初稿-v1.md`（等长目标），由同一模型生成 |
| 度量 | 用**同一份**检测器文件（记录 sha256），对两臂输出各跑一次 G14 评分 |

**为什么只做写手层**：T9/B 轨只影响「要不要再改」，不影响单次成稿的文本；把它们混进来会把「机制效应」和「轮数效应」搅在一起。**G14 的文本效应**只能在「同样一次生成」上比较。

**为什么不做全流水线**：一次完整项目数小时 × 20 次 ≈ 数十小时机时，且混杂因素（检索质量、批判轮数）无法控制。写手层消融把这个成本压到 ~1/5，代价是**不能**外推到「G14 对整个流水线」。

## 三、样本（预选，冻结）

## 四、度量与盲评

1. **主指标**：G14 检测器的「命中类别数 / 8」（检测器对该稿输出 Warning/Fail 的类别计数）。
2. **次指标**：M 门 P0/P1 数、正文汉字数、目标字数偏离、生成耗时、token 成本。
3. **盲评**：检测阶段**不告诉**评分者（人或模型）稿件属于哪一臂；两臂输出混排、随机顺序，文件名为随机 id。
4. **同一把尺**：检测器文件内容 sha256 记入结果表；两臂必须用同一 sha。

## 五、判据（先定，后看）

设 `d_i = cats(臂A_i) − cats(臂B_i)`（正数 = 对照更好 = G14 有效），n = 10 对（5 项目 × 2 重复）。

| 结论 | 条件（同时满足） |
|---|---|
| **降级为按需** | 均值 `d̄ < 1.0` **且** 90% 置信区间上界 `< 2.0` **且** 没有任何项目出现 `d ≥ 3` |
| **保持默认必跑** | 均值 `d̄ ≥ 1.0` **或** 区间下界 `> 0.5` |
| **不确定，不动** | 其余全部情形（含 n 不足、检测器不可用、两臂字数偏离 >20%） |

> **为什么是 1.0 个类别**：G14 共 8 类，1 类约等于「一项可感知的文风缺陷」。低于 1 类的差异落在检测器自身的波动范围内（同一稿两次检测的类别数并不稳定）。
> **为什么加「无项目 d≥3」**：均值会被单点拉高；若只有一两个项目受益，说明 G14 是**项目相关**的，应改「按文类/按需」而不是全量默认。

**预先声明的无效情形**：① 任一族出现「检测器不可用 / 类别数解析失败」；② 两臂字数偏离 >20%（说明干预改变了篇幅而非文风）；③ 完成配对 < 8。以上任一 → 结论记「不确定」，**不得**据部分数据宣布降级。

## 六、成本与执行

| 项 | 估算 | 依据 |
|---|---|---|
| 写手轮 | 20 次（5×2×2） | 每次 6–15k 字 |
| 单次成本 | ≈ $1–2（写手 + 检测各一次） | 历史全项目均值 $5.06 含检索/审计，写手层约占 1/4 |
| 总成本 | **≈ $30–50** | 不含人工 |
| 机时 | 10–20 h（可夜间跑） | 每次 30–60 min |

**执行协议**：
1. 先跑 **pilot**：`生成式AI` 一项目、两臂各 1 次，验证「同一输入 → 两臂都能产出合规初稿」＋检测器可用。
2. pilot 通过才扩到 5 项目 × 2 重复；**任一步失败即停**，把失败写进结果表，不静默跳过。
3. 结果落 `audits/消融/G14-AB-v1/`：`README.md`（冻结信息 + 偏离登记）+ `results.csv` + 每篇稿与检测报告。
4. **偏离登记**：任何与本节不符的动作（改样本、改判据、少跑重复）逐条记入 `README.md §偏离`，并注明「判据未变 / 判据已变」。
