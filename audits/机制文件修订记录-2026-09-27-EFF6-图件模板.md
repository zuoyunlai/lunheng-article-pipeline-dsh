## 三、实测发现①：**刻度数字会被 M-Form-9 判「无出处」**（本批亲测，非推理）

`mform-gates.mjs:714` 的判据是 `unmatched = 图上数字 where 长度 ≥ 2 && 不在数据卡∪正文 && 不可由两数加减推得`。探针（`%TEMP%\eff6-ticks-probe.mjs`）实测：一张只含 `0/25/50/75/100` 刻度与一个正文出现过的 `42%` 的图，M-Form-9 读数：

```
图位 1 个 / 图件 1 个 ｜ 无缺图 ｜ 软提示: 图1 图上数字 25,50,75,100,01 在数据卡/正文中找不到出处
severity: P2, pass: false
```

**两点结论**：
1. 区间刻度（`25/50/75`）不属于任何项目的数据卡，**天然对不上** → 每张带区间刻度的图都会带一条 P2。这是**既有行为**，不是本模板引入的；如实写进模板 §五 第 7 条并给两条正当做法（刻度取自数据卡里出现过的数字 / 只标 `0` 与最大值——`0` 是单字符，不在对账范围）。
2. 由此推出模板的**设计约束**：**块内 `<text>` 一个阿拉伯数字都不放**。理由有两条，缺一不可——① 防「照抄示例数字」= 编造数据；② 防 M-Form-9 噪声（模板数字必然对不上）。坐标（属性值）不受此限：它们不是可见数字。

## 四、实测发现②：`analyzeSvg` 的宽高判定是**全文级**，不是根标签级（反向自证时抓到）

反向自证的第一个变体是「抹掉某块的根 `viewBox`」——**门没红**。查因：`_lib/svg.mjs` 的

```js
const hasWH = /\bwidth\s*=/i.test(raw) && /\bheight\s*=/i.test(raw)
if (!hasViewBox && !hasWH) problems.push('既无 viewBox 也无 width/height …')
```

是在**全文**里找 `width=`/`height=`，而任何图里都必然有 `<rect width=… height=…>` → 「**根上既无 viewBox 也无宽高**」这种真会渲染塌缩的形态被判 `ok=true`。

**处置（刻意保守）**：**不动共享校验器**——它同时服务 `md2html`（exit 40）与 M-Form-9，放宽或收紧都是**另一批**的语义变更。改为在**本批的测试里**补一条**根标签**断言（`<svg …>` 开标签自身必须带 viewBox 或 width+height）。补完后同一变体立刻红。
**判据**：发现共享门偏松时，先问「收紧它会不会改变别人的判定语义」——会，就用自己的层兜，并把偏松这件事**写下来**（本记录即留痕）。

## 八、与报告的两处差异（如实）

1. **报告写「提供 3–4 类常用图型」，本批交付 5 类**。理由：文件原有 5 类（柱状/折线/饼→占比条/散点→矩阵/关系→流程），**删掉一类 = 能力回退**；模板化的目标是把已有图型做成可落盘形态，不是削减图型。少给一类并不省 token（按节取用，未选中的节根本不读）。
2. **报告写「模型只填数据与文案」，本批多了一条约束**：几何量（条宽/折线点/圆心）也必须**跟着数值一起改**，因为没有任何门在看「比例 vs 数值」是否一致（§五 铁律第 6 条如实声明）。这是把「模板化可能引入的新错误形态」提前写到纸面上，而不是假装填空就够了。

## 九、边界（如实，未做）

- **几何量↔数值一致性无门**：M-Form-9 只抽 `<text>` 可见数字。属启发式边界，已写进模板与铁律；若要机械化需从 SVG 反解几何量并与标签比对，那是新族工作，不在 EFF-6 范围。
- **模板不预置刻度数字**（§三 的两条理由）；因此选「数据卡里没有的区间刻度」时仍会得到一条 P2 软提示——**这是门在提醒人复核，不是缺陷**。
- **未改 `_lib/svg.mjs`**（§四 的偏松判定保留原状），故 `md2html` 与 M-Form-9 的行为本批**零变化**。
