## 一、实施摘要（先读这段）

本仓**自保机制质量显著高于同类 DSH 插件**——三层路径收口（词法→结构→realpath 物理层）、guard「只收紧不放宽」、降级必须可观察（warn 永不静音）、fail-open 必留痕、深冻 result / 字段白名单投影 / `additionalContexts` 唯一副通道等宿主契约全靠真探针实证（R1/D1/D2），这些是**教科书级**的工程纪律，本轮不打折扣地认可。

**但本轮发现的核心问题，恰好是本仓自己在 MEMORY / 审计里反复声讨、如今落到自己头上的同一模式**：「『已修 / 已硬化』的记载只覆盖了它当时盯住的那一处」。具体有三处铁证：

1. `destructive-write.mjs` 的 `.bak` 回收 tiebreak（历史上已为它修过 v18.14.0 CI flaky、MEMORY 里立了 critical 条目），`seqOf` 正则仍把时间戳 `-HHmmss` 误当序号——**排序主键错误仍在**。
2. `panel.mjs` 头注释（113-147 行）反复宣称「F-6 安全线已实测」，但同文件的跨项目对比循环（698-699 行）**恰恰漏掉了那一层 realpath 物理层围栏**。
3. `round-ledger.mjs` 的 `else` 分支不可达，把「推断失败兜底」伪装成存在。

**结论：综合 7.5/10**。正确性与安全边界是加分项，但「文档严谨度领先于代码一致性」是扣分项。本轮 P0 共 4 处，其中 2 处是**数据丢失**（append 截断丢块、.bak 误删），1 处**围栏缺口**（reportFile 读面未收口），1 处**正确性**（--report 文本被当路径）。

## 二、P0（真实缺陷，必须修）

### P0-1 `runScript` 的 `append` 截断丢块 —— 数据丢失〔亲测〕

**位置**：`lib/tools.js:163-168`

```js
const append = (cur, d) => {
  const s = String(d)
  if (cur.length + s.length <= cap) return cur + s
  truncated = true
  return cur.slice(0, Math.max(0, cap - 1)) + '…'   // ← 把当前 chunk s 整个丢弃
}
```

**事实**：越过 `cap` 时返回的是「**已累积前缀**的前 cap-1 字符 + `…`」，**当前 chunk `s` 被整体丢弃**。首个 chunk 就超限时，输出只剩 `'…'`；即使非首块，靠近 cap 边界的本块内容也全部丢失（应部分保留）。

**建议**（一行修）：`return (cur + s).slice(0, Math.max(0, cap - 1)) + '…'`

**严重度**：P0 ｜ 数据丢失（`lunheng_m_gate` 等工具的输出截断态会静默丢尾部内容）

---

### P0-2 `.bak` 回收 tiebreak 的 `seqOf` 正则把时间戳误当序号 —— 误删较新备份〔子代·待复核〕

**位置**：`skills/lunheng-article-pipeline/scripts/_lib/destructive-write.mjs:143`

```js
const seqOf = (f) => { const m = /-(\d+)\.bak$/.exec(f); return m ? Number(m[1]) : 0 }
```

**事实**：`/-(\d+)\.bak$/` 对**无序号**备份 `bar.md.20260912-101112.bak` 会命中 `-101112.bak`，返回 `seqOf=101112` 而非注释声称的 `0`。同毫秒 mtime 并列时，无序号备份（本应最旧，见该文件 110-111、138-142 行自证）被排成「最新」，`pruneBackups` 的 `shift()` 会误删较新的 `-1/-2`、保留较旧的无序号。

**建议**：锚定完整形态再取可选序号，如 `/-(\d{8})-(\d{6})(?:-(\d+))?\.bak$/` 取第三组（可选序号），无序号归 0。

**严重度**：P0 ｜ 数据丢失（回滚点被误回收）｜ 与本仓 MEMORY critical 条目「pruneBackups 排序必须 mtime 主键 + 确定性 tiebreak」直接相关

### P0-3 `--report`（回报原文文本）被 `resolveSessionPath` 拼成路径 —— 回报侧校验失真〔亲测〕

**位置**：`lib/tools.js:472`

```js
if (args.report) argv.push('--report', resolveSessionPath(exec, args.report))
```

**事实**：工具 schema 与 `handoff-check.mjs:176,349` 均证明 `--report` 接收**回报原文文本**（`reportText = opt.report`）。但 `resolveSessionPath` 会对非绝对路径字符串执行 `resolve(cwd, p)`，把「T7 已交付，产物齐备…」这类原文拼成 `<cwd>\T7 已交付…` 假路径 → B 组回报侧六要素校验对一段被污染的路径串跑，结果失真。

**建议**：`--report` 传 `args.report` 原样（不经过路径解析）；仅 `--report-file`（真路径）走路径处理。

**严重度**：P0 ｜ 正确性（`lunheng_handoff_check` 的回报侧校验静默失真）

---

### P0-4 `--report-file`（真·读路径）未走读围栏 —— 任意文件读面〔亲测〕

**位置**：`lib/tools.js:473`

```js
else if (args.reportFile) argv.push('--report-file', resolveSessionPath(exec, args.reportFile))
```

**事实**：`reportFile` 是**读路径**（脚本 `readText()` 读它），却只做相对→绝对解析、未套用 `resolveReadablePath`（P2-7 为「工具在宿主进程内读盘」专门加的工作区∪tmpdir 围栏）。对比同函数 `project` 走了 `resolveReadablePath`，`reportFile` 是漏网——可指向工作区/tmp 之外任意文件被读取。

**建议**：`args.reportFile` 改走 `resolveReadablePath(exec, args.reportFile, 'reportFile')`。

**严重度**：P0 ｜ 安全（读面围栏缺口）

## 三、P1（有条件触发 / 语义 / 性能，建议本迭代修）

### P1-1 跨项目对比循环裸读、漏物理层围栏 —— 界外边车泄漏进 `/snapshot`〔子代·待复核〕

**位置**：`lib/panel.mjs:698-699`

```js
for (const nm of readdirSyncSafe(runDir).slice(0, 200)) { readText(join(runDir, nm, 'final', '运行报告.json')) }
```

**事实**：`readText` 裸 `readFileSync` 跟随链接，且对 `nm` 无 `isPathInsideRunDir`/lstat 任一校验——run/ 内放 junction 可把界外边车的 score/pass/p0/words 泄漏进 `/snapshot` 响应。恰是本文件 113-147 行注释宣称「F-6 安全线已实测」的同一类缺陷、此处漏改。

**建议**：循环内对 `join(runDir, nm)` 先过 `isPathInsideRunDir(runDir, …)`（与 `/file`、`/snapshot` 主路径同源）。

**严重度**：P1 ｜ 安全（读面越界）

### P1-2 地名轮无条件替换 —— 过度误报，与人名轮不对称〔亲测〕

**位置**：`lib/ethics-sanitize.js:268-278`

```js
const final = mode !== 'strict' ? '[地名-REDACTED]' : (parent === m ? m : `${parent}某地`)
```

**事实**：basic 模式对词表命中的任何地名直接替换，且 `:267` 正则无词边界（裸 `names.join('|')`），`北京时间`→`[地名-REDACTED]时间`、`和平`（常见词）等被误伤。人名轮有「低置信不改写」门、地名轮没有——不对称。本会话 H2 标记的 `place=7` 即由此而来（代码注释里的示例地名被当「替换」）。

**建议**：给地名轮补与人名轮对称的「低置信门」（无角色/上下文锚定时只登记不替换），或至少对高频普通词（和平/北京/时间等）加排除表。

**严重度**：P1 ｜ 误报面（伦理脱敏工具的过度替换）

### P1-3 非零退出码 + 有 stdout 被当 success —— 吞错〔亲测〕

**位置**：`lib/commands.js:239-242`

```js
if (r.status !== 0 && !out) { return { kind: 'error', … } }
return { kind: 'success', text: clip(out + …) }   // ← 非零退出但有输出时落这里
```

**事实**：`r.status !== 0` 但 `out` 非空时，退出码被吞、呈现为 success。ETIMEDOUT 走 `r.error` 可捕获，普通非零退出会漏。

**建议**：`r.status !== 0` 时一律归 error（把退出码与 stderr 拼进 text），或至少显式把 `exit=${r.status}` 注进 success 文本。

**严重度**：P1 ｜ 吞错（`/lunheng-stats` 失败不可见）

### P1-4 `draftName` 版本选择用字典序 —— v10+ 选错最新草稿〔子代·待复核〕

**位置**：`lib/panel.mjs:609`

```js
.sort().pop()   // 无 comparator
```

**事实**：字典序下 `v9` > `v10`，选错「最新草稿」。同文件 `verSort`/`intRep` 都是数值排序，此处漏用。

**建议**：复用既有数值排序比较器。

**严重度**：P1 ｜ 正确性

### P1-5 人名/地名巨型正则每次调用重编译 + 重排序 —— H2 热路径〔亲测〕

**位置**：`lib/ethics-sanitize.js:266-267`（地名）、`:291-295`（人名）

```js
const names = [...dicts.places.keys()].sort((a,b)=>b.length-a.length)
const re = new RegExp(names.map(...).join('|'), 'g')          // 每次 new
const surnames = [...dicts.surnames].sort((a,b)=>b.length-a.length)
const re = new RegExp(`(${roleAlt})?(${surnames…})([${HAN}]{1,2})`, 'g')  // 每次 new
```

**事实**：`loadDicts`（`:96`）已按 mtime 指纹缓存了 dicts，却**没缓存编译产物**。`sanitize` 在 H2 热路径上**每个 text 块调用一次**（`lib/index.js:581`），等于每读一个中文块就重排序 + 重编译上千地名/数百姓氏的 alternation。`roleAlt`（`:292`）完全静态却每次重建，同因。这是全库唯一能在真实会话被感知的浪费。

**建议**：把两个编译好的正则放进 `dictCache`（随 fingerprint 一起失效）；`roleAlt` hoist 到模块级。

**严重度**：P1 ｜ 性能（热路径）

### P1-6 SSE 心跳每 5s 全量重扫、无缓存 —— 同步阻塞事件循环〔子代·待复核〕

**位置**：`lib/panel.mjs:927`

**事实**：`setInterval` 无条件 `push()→lightSnapshot`，含 9 目录递归 walk + 证据/审稿/交付解析 + 最多 200 项目边车 `JSON.parse`，同步阻塞事件循环，无缓存，多客户端放大。

**建议**：快照结果按「mtime 指纹」缓存，未变则复用；或降频/增量。

**严重度**：P1 ｜ 性能
