# 论衡（lunheng-article-pipeline v18.62.6）竞品分析报告

> 分析口径：**以包内代码为准**，不信 README 营销话术。全部数字为实测。
> 样本：DSH 插件市场缓存 499 个插件中筛出 28 个同域候选 → 实拉 14 个包体解包勘察 + 1 个 GitHub-only 包 + 3 个跨 harness 参照。
> 日期：2026-10-02。论衡基线取自本机已装包与本报告同批实测。

---

## 0. 一句话结论

**论衡在一个极度拥挤但普遍「浅」的赛道里，用最重的工程换到了分发与深度双第一，但它领先的维度恰好是竞品集体缺失的那些——这既是护城河，也是它唯一的风险来源。**

- **分发**：月下载 **23,537**，是第二名的 **4.7 倍**。
- **演进深度**：**v18.62.6**，竞品普遍停在 **v0.1–v0.4**（差距 40–180 倍）。
- **中文深度**：.md 正文 **41.1 万汉字**，最接近的中文竞品 `dsh-thesis` 只有 3.5 万（**11.7 倍**）。
- **机制强度**：**24 项脚本机械门 + 28 个随包脚本**；14 个竞品里只有 4 个有机械闸门，且最强者（`dsh-openwrite`）也只是 8 个文件级 gate。
- **但**：论衡的**分发物里不带测试**（tests 在仓库、被 `files` 白名单剔除）——这一点与最认真的竞品 `dsh-thesis` **同档**（它同样把完善的测试链排除在 `files` 之外），但 `dsh-writing-studio`（GitHub 分发）证明「让用户能自证」成本极低。这是论衡口径上的自相矛盾：主打「可核验」，却不发可核验物。

## 3. 核心洞见：架构分三型，只有两家是全栈

竞品在架构上分成三型，**论衡的护城河不在功能列表，而在它选了最难的那一型**：

| 型 | 代表 | 特征 | 代价 |
|---|---|---|---|
| **① 纯工具型**（占多数） | ai4scholar(28 工具)、paper-reader(5)、paperlab(4)、industry-research(4)、research-report(3)、writing-studio(11) | 只注册 `defineTool`，把状态机与产物落盘做成工具；**推理全交给会话模型** | 每一步都花 token；无机械闸门；无角色隔离 |
| **② 技能编排型** | dsh-thesis(11 技能)、dsh-openwrite(24)、industry-research(2) | 有 SKILL.md 角色/流程，靠提示词驱动 | 约束力取决于模型自觉 |
| **③ 全栈型** | **论衡**、部分 `dsh-openwrite` | **技能 + 原生工具 + 写保护 guard + 真 spawn 子代理 + 脚本闸门** 五件齐备 | 维护成本极高（论衡自己的文档已多处自曝「旧文案与实现不一致」「幻影门」） |

**机械证据**：全量扫描 15 个包，同时具备 `guard`（写保护）与**真 spawn 子代理**的，**只有论衡与 `dsh-openwrite`**。其余 13 个包**全部不 spawn 子代理**——所谓「多 agent」在实际实现里是**提示词内联扮演**。

> 这条是本次分析最有价值的发现：**竞品市场里「多 Agent」绝大多数是话术，不是机制**。论衡是少数真的在 `subagent` 层做角色隔离与模型分档的。

## 4. 逐竞品快评（代码为准）

### 4.1 `dsh-research-report` v0.3.16 —— **证据机制最强，但不是给作者用的**

**它是什么**：领域无关的**证据账本引擎/服务层**。消费者是 sibling 插件与外部审计者，不是终端作者（`package.json:4` 自述「no deep-research loop」）。

**它比论衡强的地方（必须认账）**：

| 能力 | 它怎么做 | 论衡怎么做 |
|---|---|---|
| 内容寻址 | `objects/<sha256>` **不可变对象库** + 4 个 JSONL 账本（index/claims/verdicts/**disproofs**）；同 id 异内容直接 throw；读时重算，不符 → `integrity:'tampered'` | `manifest.json` 逐文件 sha256 —— 是**清单哈希**，不是对象寻址 |
| 逐句核验 | **字节级**：claim 里每个数字与引号串必须**逐字**出现在绑定快照；左标签后数字不同 → `disproven` | 靠 T7/G 审计的**语义判断** |
| 负知识 | `disproofs.jsonl` 强制复现已证伪项 | 无对应机制 |
| 独立外审 | `dsh-research-verify` CLI + **SARIF 2.1.0** 输出，**可脱离 DSH 审计** | **无独立审计 CLI** |

**它的硬伤**：0 个 SKILL.md（纪律只有约 3 句 systemPrompt）；**0 个人在环节点**；`package.json` 声明 9 个脚本 + README 点名的 `test/events-gate.spec.ts` **在包内全部不存在** → `pnpm test`/`verify:*` 必失败；机械闸门只在**可选 CLI 与 seal 时点**，不挂 `ctx.jobs` 时 verifier **静默 skip**。Apache-2.0，23 个版本，9 月内发 16 版（节奏极快）。

### 4.2 `dsh-plugin-academic-writing` v0.3.2 —— 薄而实，但只是「工具」

7 文件 / 34.7 KB / **548 行真逻辑**（10 个 action 全部有实现，无 TODO 桩）→ **确认非空壳**。提供大纲/摘要/引用格式化/结构诊断/术语表。

**但**：0 编排、0 角色、0 闸门、0 落盘、0 检索（自述「不读不写不检索」）。其 `academicCheck`/`analyzeStructure` 返回的 `passed` 布尔**没有任何东西消费**——「确定性检查」退化为模型可选建议。**GB/T 7714 未标版本（无 -2015）且实现不达标**：>3 作者用英文 `et al.` 而非「等」、无 `[D]/[S]/[N]` 类型标识、字段顺序与标点不符。`README.zh.md` 只列 6 个 action（英文版 10 个）、`ROADMAP.md` **断链**。

> ⚠️ **若它 ROADMAP 声称的后续版本落地（参考管理/结构 QA/期刊适配/评审流程），将在「GB/T 7714 + 结构 QA」上与论衡正面重叠，建议跟踪。**

### 4.3 `dsh-industry-research` v0.3.15 —— 中文技能最规范，但「多视角」是措辞

**强项**：2 个**全中文** SKILL.md（经 `FileSystemSkillProvider` 注册）；内置 **GB/T 4754-2017** 国民经济行业分类；`research-state.json` + `summarizeDelta` 增量摘要；数据文件带「路径 + SHA-256 + 字节 + 行数」，**数字可回溯到文件:行号**；**4 处机械闸门串在主流程内**（`validateDeliveryContract` 失败即 throw 不产半成品 / `adversarialCheck` 确定性对抗扫描、永不调模型 / `versions.ts` 读时重算 SHA-256 / skills 根缺失即 throw）。

**硬伤（重要）**：`kind:'subagent'` **名不副实**——那不是 LLM 代理，只是 `ctx.jobs.start()` 的**标签字符串**；所谓「红方魔鬼代言人」「正反方辩论」是**确定性模板渲染**（`adversarial.ts` 纯函数），**「多视角」是措辞而非独立视角**。同样 10 个声明脚本 + tsconfig + tests 全不在包内；devDep 把 `dsh-research-report` 钉在**已过期**的 0.3.10。Apache-2.0，21 版。

### 4.4 `dsh-ai4scholar` v0.3.7 —— 宣称属实，但不同抽象层

**「38 native academic tools」逐个核实为真**（需把 `semantic-scholar.js:551` 的 loop×2、`pubmed.js:219` 的 loop×2、`rxiv.js` 在 `applyServer()` 内被 biorxiv+medrxiv 各调一次展开才能数对：17+5+1+3+6+2+1+1+1+1 = 38）。**零注水，不要误判。**

**但它没有流水线**：0 SKILL.md、**无子代理**、无机械闸门（`process.exit` 零命中，全靠 `throw`）、无 sha256/manifest、**0 人在环**、状态是内存 `WeakMap` **重启即失**。

> **它对论衡构成真实威胁的唯一一点**：**真外部文献接入**——7 大库检索（Semantic Scholar/PubMed/Google Scholar/arXiv/bioRxiv/medRxiv/DOI）+ PDF 全文提取 + 跨库去重合并（同一查询只扣一次费）。论衡的检索是**通用 web 检索**，且经核实其 `外部检索源接入面.md` 自述「**能力面在、指引面缺**」——T1/T2/T3 卡默认只调 `web_search`/`web_fetch`，即便本机注册了 firecrawl/tavily/exa/AI4Scholar 也**不会主动调用**，除非卡里写明。
>
> **结论**：它是论衡 T1 层的**可选外挂**，不是同层竞品。但它也**强绑 `ai4scholar.net` 按次付费**（`auto_cite` 单次 20–90 s），存在厂商锁定与成本不可控。

### 4.5 `dsh-fund-research` v0.4.16 —— **同源机制最强者，但哲学相反**

同打「确定性计算 + 哈希溯源 + 封存版本 + 续跑 + 只读复核」，**口径比论衡更细**：

| 它怎么做 | 论衡怎么做 |
|---|---|
| **四层 sha256**（逐源 / 快照封存 / 报告清单 / 运行指纹） | 证据包 manifest 一层 |
| **数字回溯表**：`verify-bridge.ts:100-132` 用 JSON-path + 相对容差逐条核查，verdict ∈ `verified/mismatch/not-found/unverifiable` | 靠 M-Exist-2 核 sha256 完整性 |
| 数字可回溯到**文件:行号**（`company.ts:160,236`） | 论衡无此粒度 |
| `.run-state.json` 两阶段（snapshot→report）续跑，**指纹不匹配响亮拒绝** | 论衡靠 status.md + 人工 |

**但两条关键差异对论衡有利**：
1. **哲学相反**：它明示「**verification never blocks a report seal**」（`verify-bridge.ts:146`），review-note 只打 PASS/FAIL **不阻断**；论衡是「**不过门不交付**」。
2. 它 **0 个真子代理、0 个人在环节点、0 随包测试**，且 `SKILL.md:7` 的 `version: '0.1.0'` 与包 **0.4.16 漂移**。Apache-2.0，24 版。

> **这是本次分析最需要警惕的一个对手**：它的**证据密度比论衡证据包更可机械验证**。论衡的护城河在「阻断式门 + 真多角色 + 中文合规」，不在证据链精细度。

## 6. 论衡的护城河与软肋

### 6.1 护城河（同类里最深或独有，但**不是**「全市场零覆盖」）

1. **真多 Agent 角色隔离**——14 个包里，同时具备写保护 guard 与**真 spawn 子代理**的只有论衡与 `dsh-openwrite`；其余「多 Agent / 多视角 / 红方魔鬼代言人」经查全是**提示词内联扮演或模板渲染**（`industry-research` 的 `kind:'subagent'` 只是 job 标签字符串）。
2. **「不过门不交付」的阻断式门**——唯一有 7 档 exit 语义（0/1/2/3/10/30/70）的包；最强同源对手 fund-research 反而**明示核实失败不阻断封存**。
3. **中文人文合规**：**中文 AI 痕迹闸（G14 A–H 八类 + 三层防御 + 独立 spawn 检测器）是同类里最深的一档** + **内置 40 刊库**（竞品无一有）+ GB/T 7714-2015 **机检**（G15 卷期页码逐条核；`dsh-thesis` 只有要求与 LaTeX 模板、无校验器，`academic-writing` 的实现未标版本且不合规）。
   > ⚠️ **两处自查更正**：① 本条原写作「GB/T 7714-2015 是论衡独占」——实测 **`dsh-thesis` 也有**（作为必问项 + LaTeX 模板要求），已修正为「论衡独占的是**机检**那一半」。② 本条原写作「中文 AI 痕迹闸全市场独占」——实测 **`dsh-thesis` 有 `aicheck.js:15-111` 的 6 条启发式自查**（模板套话/空洞结论/自我暴露/翻译腔/句式单一/无锚点长段），我先前按 `AI 痕迹|g14` 检索故漏判。**修正后论衡真正的独占项只剩两项：内置 40 刊库、G14 的八类分级 + 三层防御 + 独立检测器。**
4. **4 个人在环节点**——竞品普遍 0。
5. **中文内容深度 41.1 万汉字**——最接近的中文竞品 `dsh-thesis` 只有 3.5 万（11.7 倍）。
6. **分发与演进**：23,537 月下载（第二名 4,707 倍差为 4.7 倍）、v18.62.6 vs 竞品普遍 v0.1–0.4。

### 6.2 软肋（必须认账，按严重度排序）

1. **证据链精细度落后于 `dsh-research-report` 与 `dsh-fund-research`**。竞品做的是**对象寻址**（`objects/<sha256>` 不可变 + 读时重算 + `tampered` 检测）、**字节级逐句核验**（claim 里每个数字与引号串必须逐字出现在绑定快照）、**数字回溯到文件:行号**、**负知识账本**（`disproofs.jsonl` 强制复现已证伪项）。论衡是**清单哈希 + 语义判断**——一档粗。
2. **分发物里不带测试**：论衡与 `dsh-thesis` **都是「仓库里有完整测试链、`files` 白名单排除」**——这是全行业习惯，论衡**不落后于同类**（`dsh-thesis` 的测试链更长）。但 **`writing-studio` 证明了把几个 smoke test 放进分发物成本极低**，而 `ai4scholar` 与 PerryLink 家族「**声明了 test/verify 却不发**」更差一档。论衡此举的真实代价是：**用户 `dsh plugin add` 之后无法自证**，对一个主打「可核验」的包，这是口径上的自相矛盾。
3. **没有独立审计 CLI**：`research-report` 有 `dsh-research-verify` + **SARIF 2.1.0**，可**脱离 DSH** 审计；论衡 24 项 M 门只能在 DSH 会话内跑，对外可审计性弱。
4. **外部文献接入薄**：论衡 T1 默认只调 `web_search`/`web_fetch`——**论衡自己的 `外部检索源接入面.md` 已诊断出「能力面在、指引面缺」**：即便本机注册了 firecrawl/tavily/exa/AI4Scholar，卡里没写明就**不会主动调**。对照 `ai4scholar` 的 7 大库真检索 + PDF 全文提取。
5. **合规分 ≠ 论证质量**：24 项 M 门管「格式/存在性/一致性」，`quality-score.mjs` 的 `validity` 字段自己声明「只支撑合规与成本，**不支撑论证质量**」；而 `openwrite` 有 37 维 × 6 域加权评分 + 阈值闸门。**论衡缺一个「稿子好不好」的量化尺。**
6. **无外部真值门**：`paperlab` 拿 `latexmk` 编译退出码当真值；论衡 24 项**全是自查脚本**。
7. **自身治理负担**（上一轮已实测）：工具层无阶段身份校验（已发生 G14 子代理覆盖 T8 的 `M-Gate-Report.json` 事故）、`--require-gates` 缺省 fail-open、guard 不拦 `pwsh`、存量历史项目不可复验。
8. **一手材料摄取为零**：`dsh-thesis` 能自研解析 docx/pdf/xlsx/pptx/代码（`pdf.js` 971 行），论衡只能靠主人投喂**纯文本**——这是当前最实的功能空白（见 §7.5）。

### 不建议做的事

- **不要跟 `dsh-openwrite` 比体量**：它 77% 是 `.map`/`.whl`/LICENSE，自研逻辑 7 千行。比的是机制密度，不是 MB。
- **不要照搬 `research-report`/`industry-research` 的发布策略**：它们**声明的 scripts/tests/tsconfig 全部不在 tarball 内**（`pnpm test` 必失败）——这是该家族（PerryLink，40+ 插件）的系统性发布缺陷，论衡若学它会毁掉自己唯一的工程质量优势。
- **不要被「38 tools / 91 tools」吓到**：工具数量与能力无关。`ai4scholar` 38 个工具**零注水但无流水线**，`openwrite` 91 个工具是网文审稿——论衡 4 个工具 + 28 个脚本是**另一种设计哲学**（见 §3）。

## 8. 一句话收束

论衡当前**没有同层竞品**——14 个包里 0 个在争夺「中文长文/学术论文多 Agent 流水线」这同一生态位。它真正的风险不是被替代，而是：**在一个平均版本 0.3、普遍不发测试、普遍不阻断的赛道里领先太久，会把「领先」误读成「没问题」**。§6.2 的七条里，前两条（证据链精细度、随包可验证性）是**已经被竞品实际超越**的，值得优先处理。
