## 二、逐条改动

### L-61 `apply-compression-cycle.mjs` — 未定义变量 `repoRoot`

**缺陷**：第 97 行 `spawnSync(nodeBin, [join(repoRoot, 'skills/lunheng-article-pipeline', 'scripts', 'build-evidence-bundle.mjs'), …])` —— `repoRoot` 在本文件**从未定义**（同族脚本 `apply-revision-cycle.mjs` 上一梯队改为 `scriptDir` 时只改了那一份）。非 dry-run 跑到这里必然 `ReferenceError` → 被 `exit-guard` 归为**内部错误 exit 70**（不是它注释里写的「以 1 退出」）→ 决策 JSON 的 `consistencyCheck` / `bundle` 两项**恒为 `exit null`**。

**为什么危险**：这两项正是主控在收尾阶段判断「一致性与证据包是否刷新」的机械证据。恒为 `null` 时主控要么白跑一轮排查，要么对「门未结算」脱敏——而**真实门值可能已经是红的**。

**修法**：
- 证据包路径改 `join(scriptDir, 'build-evidence-bundle.mjs')`（同目录同族脚本，与 `apply-revision-cycle.mjs:107` 完全同源）；
- 技能目录改 `join(scriptDir, '..')`；
- 项目参数**原样透传** `positionals[0]`（旧版传 `basename(projRoot)`，丢了 `run/` 前缀）；
- 删除从未被调用的 `writeFileSync` / `copyFileSync` 导入。

**验证**：`node --check` 通过；端到端 dry-run 用例（`tests/batch7-scan-surface.test.mjs`）断言决策 JSON 不出现 `exit null` / `exit undefined`；源码扫描用例断言**可执行代码**（剥注释后）无 `repoRoot`。

### L-63 `cite-coverage-check.mjs` — 幽灵引用检查的两处短路

**缺陷 ①（扫描面）**：`L_IN_TEXT` 与 `L_COUNT` 都扫**整篇**，而参考文献节的条目行本身含 `[Lxx]` → 每条引用都被「自己」计一次 → `decorative` **恒为空集**、`decorativeRatio` 恒 `0`。后果：07 卡的「装饰性 >20% → P1」**机械不可达**，且强度分档整体上移一档（正文只引 1 次的被算成 2 次 = 中）。

**修法**：用 `firstEndnoteIndex(text)` 切出正文区（与 `count-chars.mjs` / `m-gate-check.mjs` **同源口径**），`L_IN_TEXT` / `L_COUNT` 一律只在正文区上匹配。

**缺陷 ②（分母短路，本轮新发现）**：`decorativeRatio = totalRefs > 0 ? decorative.length / refsInList.size : 0`，而 `totalRefs = L_IN_TEXT.size`。当正文**一条 `[Lxx]` 都没有**（纯幽灵稿：清单列 5 条、正文零引用）时 `totalRefs === 0` → 比率被短路成 `0` → `cStrengthPass = true`。即**在这类最该报警的稿子上恰好静默通过**。

**修法**：分母固定为清单条数 `refsInList.size`（清单为空才是真正无引用可言，此时比率记 0）。

**验证**：3 条新用例——① 纯幽灵稿（5/5）必须判 P1 且 exit 1；② 正文 1 次 + 清单 2 条 → 弱档 `['L01']`、装饰性 `['02']`、比率 `0.50`；③ **红鲱鱼**：围栏内的伪 `## 参考文献` 不得截断正文区（引用仍计正文、围栏内示例不算幽灵）。

### L-64 `journal-fit.mjs` — `--project` 敲错路径静默放行

**缺陷**：`if (existsSync(projectPaperPath)) { … }` —— `existsSync` 为假时**静默跳过全部项目级检查**（`J-Format` 段整体消失、`checks: []`）并 **exit 0**。结论比正确传参**更宽松**，而调用方以为「已按项目核过」。

**修法**：给了 `--project` 却找不到 `final/定稿.md` → 打印可操作提示（「尚未到 Phase 5 就不要传 `--project`」/「路径敲错属参数错，不是『项目无检查项』」）→ **exit 10**。同时删掉因此变成恒真分支的旧 `if (existsSync(...))` 包裹（留着会让读者以为仍可能跳过）。

**验证**：2 条新用例——① 不存在的项目路径 → exit 10 + 报错点名 `定稿.md` + **stdout 不得出现成功 JSON**；② 项目存在 → `projectWordCount > 0` 且 `J-Format.info.checks` 非空（即项目级检查确实在跑）。

### L-65 `handoff-check.mjs` — 六要素判据改为结构判据

**缺陷**：B 组用 `norm.includes(段名)` —— 只看「这六个词出现过没有」。实测单行散文「本次检索已结束。产物在哪我还没整理，怎么验证暂缺，已知问题未记录，下一步待定，状态机更新稍后补」把首句补上「做了什么」即六词齐全 → **exit 0 放行**（而它什么都没交代）；反过来「六要素成段但产物名不全」却被判 exit 21。即该组与「是否成段」无关，与「词出现与否」有关。

**修法**：段名须以**段首形态**出现——`SEG_RE` 匹配行首 `**段名**：` / `段名：` / `### 段名` / 表格首列 `| 段名 |`。

**验证**：既有 `tests/handoff-check.test.mjs`（10 条）全绿；全量 280 项基线全绿。

### L-66 `spawnSync` 未结算口径 + `--skip-bundle` 声明无效果

**缺陷 ①**：编排脚本把子进程 `status` 拼成 `` `exit ${status}` ``。而 `spawnSync.status` 在**被信号杀死**或 **spawn 本身失败**时是 `null` → 决策 JSON 出现字面量 `exit null`：它既不是「未跑」，也不是任何已登记退出码。

**修法**：`_lib/exit-guard.mjs` 新增 `describeSpawn(result)`，把三种形态收敛为可判读口径：`exit N` / `signal SIGTERM` / `spawn-failed`。两个编排脚本（`apply-compression-cycle` / `apply-revision-cycle`）统一改用。

**缺陷 ②**：`apply-revision-cycle.mjs` 的 `if (r.status !== 0) { … exit 1 }` —— `status === null` 时也走这条，**exit 1** 在 M 门语义里是「P1 内容失败」→ 主控会据此误触发 T5 修订轮（同族事故：v18.0.5 引入 exit-guard 正是为消灭这类撞码）。**修法**：`status === null` 先分流到 **exit 70**（EX_SOFTWARE），并同步修正脚本头退出码契约注释。

**缺陷 ③**：`apply-compression-cycle.mjs` 的 `--skip-bundle` 只在 `parseArgs` 白名单里挂着、**从未被读取**——声明了却无效果的开关（主控以为跳过、实际照跑）。**修法**：与 `apply-revision-cycle.mjs` 同义实现（跳过证据包刷新；一致性门仍刷新，只读不写项目产物），跳过时决策 JSON 记 `skipped(--skip-bundle)`。

**验证**：端到端 dry-run 用例 + 源码扫描用例（断言 `flags.has('--skip-bundle')` 真被读取）。

### L-13 `build-evidence-bundle.mjs` — 项目目录名合法性机械化

**背景**：`SKILL.md` 规定项目名须匹配 `[\w\-一-鿿]{1,32}`（禁路径分隔 / `..` / 绝对路径），但那条规则**只在提示词层面**、无任何脚本校验。实测本机 `run/` 下已出现一个**乱码空目录** `绛涢€夌珵璧涚殑鍧囪　`（= `筛选竞赛的均衡` 被按 GBK 误码创建），与正常目录并存且无人发现。

**修法**：`build-evidence-bundle.mjs`（本脚本自 Phase 2 起就会跑，**零新调用**）在形态校验**之前**加判据——只查**目录基名**（不查绝对路径，否则中文盘符/用户名会误报），命中即 exit 10 并给出可操作提示（含「目录名是乱码说明创建时编码错误，请用正确名字重建」）。

**验证**：手工实测——乱码目录名 → exit 10；合法名 → exit 0。（自动化用例在本批未补：构造乱码目录名需在用例里写非 UTF-8 字节名，跨平台不稳，如实登记为待补。）
