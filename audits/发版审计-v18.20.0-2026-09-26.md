### 1.2 工具坑（如实记录）

**坑 1（write-tool script 文件已删后不能写入）**：首次尝试 `write tool _msg-docs-batch3.txt` 时被报 "file no longer exists — re-read the file, then retry"——使用文件名 `_msg-batch2.txt` 等不同名字绕过。

**坑 2（pwsh 多行命令分支解析错误）**：起初尝试用 `<<'EOF'` heredoc 给 git commit -F——PowerShell 不支持 heredoc（memory「工具坑」），解析失败且整段脚本未执行。改用 `write tool` 写消息文件。

**坑 3（pwsh $repo + $f 双路径 bug）**：bulk replace 时 `$repo` 已包含 `skills/lunheng-article-pipeline`，但 `$files` 仍以 `skills/lunheng-article-pipeline/...` 开头，导致 `Join-Path $repo $f` = `E:\...\skills\...\skills\...\...`（双重）。修正：列表里去掉前一级。

**坑 4（pwsh `$var:` 被解析为 scope）**：`$repo='E:\...'`, `Join-Path $repo $f` 中 `$repo:` 的 `:` 被误为作用域标记。改用 `${repo}` 大括号包裹。

**坑 5（pwsh 字符串内的 `${ }` 嵌套）**：多个 `"${repo}\$f"` 也偶尔失败。简化：用绝对路径 + `Split-Path -Parent` 创建目录。

**坑 6（pwsh `Get-Content -TotalCount` 显示 mojibake）**：`# ...` 注释行的中文字符在 pwsh 默认解码下显示乱码。**不**影响实际文件内容（文件本身 UTF-8 正确），仅展示问题——验证时改用 `-Encoding UTF8`。

**坑 7（WriteAllText + UTF8 无 BOM 与镜像原 BOM 字节差异 1 byte）**：bulk replace 后真源已 bump 到 v18.20.0，但镜像**仍是 v18.18.14**（因之前批 1/批 2 sync 只复制了"白名单子集"而漏了 templates 集）。同步用绝对路径 + `Split-Path -Parent` 重建目录才彻底同步。

**坑 8（双词宽全角字符在 read tool 中丢失字节）**：首次尝试印度语 README 时 `git tag v18.18.14 && git push origin v18.18.14   # एक बार में...` 行的锚点匹配失败（read 工具读了 1 字节双宽而原文件不同字符宽度）。用更窄的 anchor `git tag v18.18.14 && git push origin v18.18.14   #`（去印度语部分）成功。

### 1.3 大规模替换：56 文件 / 59 命中点位

`WriteAllText + UTF8Encoding($false)`（**无 BOM** + 行尾保真——memory「论衡仓库批量改文件的 Windows 坑」禁止 `WriteAllLines`），逐文件读 → 全文 `v18.18.14 → v18.20.0` 替换 → 写回。**零**误改（每文件命中与白名单一一对应）。

> **教训（写进本批流程）**：未来版本级联 bump，**不能用 `v18.x.x → v18.y.y` 全文替换覆盖**所有版本位——必须分两类：
> 1. `vX.Y.Z` 形态（用于叙述、引用、git tag 文档示例）——全文替换 OK；
> 2. `"X.Y.Z"` 形态（用于 JSON / YAML / frontmatter 版本字段）——需单独的 `vX.Y.Z` 与 `"X.Y.Z"` 两轮替换。
