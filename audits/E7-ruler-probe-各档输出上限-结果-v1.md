# E7 ruler-probe 各档模型有效输出上限 — 结果 v1（2026-10-11）

> **目的**：实测写手档（`subagent_strong` = MiniMax-M3）的有效单次输出上限，决定 T5 单节预算封顶。
> **方法**：因主人无独立客户端，改走 **DSH 分档 subagent（`subagent_strong`，`LUNHENG_STRONG_MODEL=MiniMax-M3`）**跑长文生成——**测的是「agent 层输出上限」，非「纯模型塌缩点」**（caveat 见下）。
> **结论**：**MiniMax-M3 有效上限 = 5000 纯汉字**（此前「未实测 → 兜底 3000」，现提升到 5000）。

---

## 一、实测数据（ruler-probe --record 输出）

| 请求字数 | 实际纯汉字 | 比率 | 判定 |
|---|---|---|---|
| 1000 | 1206 | 1.206 | ✓ 达标（略超） |
| 2000 | 1733 | 0.867 | ✗ 不达标（偏短） |
| 3000 | 2853 | 0.951 | ✓ 达标 |
| 5000 | 5388 | 1.078 | ✓ 达标 |
| 8000 | 7113 | 0.889 | ✗ 不达标（未达 8000） |

**有效上限 = 5000**（比率 ≥0.9 且不塌缩的最大档）。

## 二、两个异常（如实登记）

1. **8000 字档未达 8000**：实际产出 **7113 纯汉字**（比率 0.889 < 0.9）。subagent 生成约 7100 字后即停（只回「7100字。让我补充到接近8000字。」，正文写进了 `run/城市公交系统的历史演变/drafts/初稿-v1.md`）。这本身就是**塌缩/上限信号**：MiniMax-M3 在 agent 层请求 8000 字时，实际产出约 7100 字即到顶。
2. **2000 字档偏短**：实际 1733 字（比率 0.867 < 0.9）。subagent 自报「约 2050 字」是**含标点/数字的总字数**，而 ruler-probe 口径是**纯汉字**（countHan），两者差约 300 字。

## 三、对 T5 单节预算的影响

判据（模型路由.md §十）：**T5 单节预算 ≤ 写手档有效上限 × 80%**。

- 之前：未实测 → 兜底 3000 → 单节预算 ≤ 2400
- 现在：实测 5000 → **单节预算 ≤ 4000 纯汉字**

即 T5 单节字数预算从「≤2400」放宽到「≤4000」，长节可少拆。

## 四、caveat（如实声明）

1. **agent 层 vs 纯模型层**：本批用 `subagent_strong` 跑，测的是**「DSH agent 层能稳定产出多长」**，不是「MiniMax-M3 纯模型能吐多长」。二者可能不同（agent 层有 context 预算、可能做工具调用）。但**对 T5 单节预算的指导反而更直接**——因为 T5 也是经 `subagent_strong` 跑，agent 层上限才是 T5 实际触到的上限。
2. **8000 字档无正文**：截断结论依据 subagent 自报「7100字」，未做 countHan 复核。
3. **2000 字档偏短可能是波动**：1000/3000/5000 均达标甚至超产，2000 偏短或为单次波动，不影响「上限=5000」的结论。
