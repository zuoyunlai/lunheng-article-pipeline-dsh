## 一、立项：一次**未定位成因**的改写事故留下的需求

v18.44.0 发版前 `consistency-check` 报 `[P1 标题内嵌版本漂移] references/templates/auto_cite-补充-template.md`。事实链（详见 `CHANGELOG.md` §18.44.0 第六节与 `机制文件修订记录-2026-09-27-接口债qlt标记化.md` §六）：该文件**标题里少了一段「借鉴 Ai4Scholar v2.9.1」**，而那段括注正是 `UPSTREAM_SPEC_VERSIONS` 里**登记在案、用于豁免「标题内嵌版本」**的项；git 历史证明**任何提交都没删过它**、短形态**从未被提交** → 是**工作树**被某物改写。逐条排除 bump 规则模拟 / `consistency --fix` / 套件 / 探针脚本，**成因未定位**。

当时的「试纸」（临时脚本：对 83 个文档 + 词预算门 + SKILL.md 逐文件 sha256 快照 → 跑全量套与四道具 → 比对）实测**改写数 = 0**，即**未复现**。于是把它固化成固定动作：**下次复现时当场抓住改写者**。

**判据**：`git status` 只给**最终状态**——说不出「是谁、在哪一步改的」；**逐步快照能把改写归因到某一步**。而这一步在发布流程里**本来就是必经动作**（跑完全量套与四道具），顺手核对的边际成本 ≈ 0。它同时覆盖另一类常见风险：**测试或工具偷偷写进真仓库**。

## 二、脚本契约

`node scripts/no-write-check.mjs [--root <目录>] [--json] [-- <命令…>]`

| 模式 | 行为 |
|---|---|
| 默认 | 快照 → 跑**发布序列**（全量套 + 四道具）→ **逐步**比对（每步各自快照，便于归因） |
| `-- <命令…>` | 只跑指定命令（怀疑某个具体工具时用） |
| `--root` | 换快照根（测试夹具用） |
| `--json` | 机器可读（`steps[]` 逐步 + `total` 汇总） |

exit `0` 无改写 / `1` 有改写**或有步骤没跑起来** / `10` 参数错 / `70` 内部错误。

**快照面**：仓库根下**全部常规文件**，排除 `.git` / `node_modules` / `.dsh`（部署镜像，由 `mirror-sync` **有意**改写）/ `_backup` / `*.tgz`。

## 三、写它时被自己的用例逼出来的**三个缺陷**（每个都固化成守卫）

| # | 缺陷（首版真实存在） | 为什么危险 | 守卫 |
|---|---|---|---|
| ① | `--` 的参数被**多前置一个 `node`**（变成 `node node …`）→ 子进程 exit 1、**什么也没跑**，而检查器报「**✓ 无改写**」 | **假绿**：检查器自己成了「看起来在查、其实没查」的东西——与被它追查的那类问题同族 | spawn 失败**单独判负**（`exit 1` + 「找不到命令」），并在注释里写明「**『没跑』与『跑了没改写』在快照上一样**」 |
| ② | 快照 **0 个文件**时照常比对 → 输出「✓ 无改写」 | 「根指错」被当成「干净」 | 空根 → **exit 10** |
| ③ | 只比哈希集合的**大小** | 「新增一个 + 删掉一个」互相抵消 | 分列**新增 / 内容变 / 删除**三类并逐文件点名 |

> **可迁移判据**：**检查器也要有自己的回归网**——这三个缺陷都是**用例**（而不是 code review）抓出来的；而它们共同的形态是「**检查器给出了成功文案，但什么都没查**」。凡输出「✓ / 通过」的工具，都要问一句：**它在什么条件下会给出空转的成功？**

## 四、边界（如实）

1. **净状态语义**：「写完又复原」的瞬态写入**抓不到**（要抓它需要 fs 层审计/hook，超出本脚本范围）。本次追查的那种「内容被改掉且没复原」的形态**在覆盖范围内** ✓。
2. **排除面**：`.dsh`（镜像）不在快照内——它是 `mirror-sync` **有意**改写的对象，纳入会导致每次同步都报改写。
3. **只核本仓库根**：不核 `%TEMP%` 里的夹具——那正是测试**应该**写的地方。
4. **它不是门**：不参与 CI 的发布门，也**不阻断**任何东西；它是**发版前的固定动作**（与 `closeout-verify` 同类：仓库级、不随包、由维护者按流程跑）。

## 五之二、顺带修掉规则 ③c 的一处**作用域缺陷**（本批新增文件时撞到）

把 `scripts/no-write-check.mjs` 写进文档后，`consistency-check` 报出**两处假 P1**（`AGENTS.md` 与 `references/maintainers.md` 各一处）——**而那个文件就在盘上**。

- **根因**：规则 ③c（「文档引用的脚本必须存在」）只解析 `join(ROOT, 'scripts', s)`，而 `ROOT` = **技能根**；但 `scripts/` 前缀在文档里同时指**随包脚本**（`<技能根>/scripts/`）与**仓库级脚本**（`<仓库根>/scripts/`，**不随包**：`no-write-check` / `closeout-verify` / `bump-version` …）。旧实现**只在半个盘上找**。
- **判据（同族）**：它断言的是「引用的脚本**不存在**」，却只在一个根里解析——正是本仓反复出现的「**门在看错对象**」。
- **修法**：解析面扩到**两个根**；**判据不放宽**——反向自证：临时放一份引用 `scripts/definitely-not-here.mjs` 的文档 → **照报**（随后删除临时文件，已核验清理）。
- **关联约定（已写进规则注释）**：随包文档引用仓库级脚本时**必须写明「不随包」**（本批两处引用都标了）。
- **另一处告警按既有判据处理**：`[P2 裸「（检查）」占位符]`——我在 §十 **引述**了那个占位符字面量。按本仓既定判据（「引述被纠正内容」族）：**改写措辞，不放宽门的判据** → 改为「只做一处**占位符替换**」。
