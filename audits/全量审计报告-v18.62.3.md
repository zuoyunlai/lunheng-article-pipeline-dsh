## 2. P1 — 真实缺陷 / 门失效（12 项）

### P1-1｜`no-write-check` 在「子进程没跑起来」时给出假绿（发布门 fail-open）

- **位置**：`scripts/no-write-check.mjs:103`、`:115`、`:136`
- **实测复现**：在受限文件策略下跑 `node scripts/no-write-check.mjs`，五步**全部** `exit= -1`（子进程 spawn 被拒），脚本仍打印
  `✓ 无改写：5 步跑完，仓库 369 个文件逐一哈希未变` → **exit 0**。
- **根因**：`spawnErr` 只在 `e.code === 'ENOENT'` 时被赋值——
  `catch (e) { exit = e.status ?? -1; spawnErr = e.code === 'ENOENT' ? \`找不到命令 ${s.cmd}\` : null; }`
  EPERM/EACCES（受限沙箱、命名管道被禁）走同一分支但 `spawnErr` 为 `null` → `broken` 为空 → 判「无改写」。
- **对照实测**：`-- definitely-not-a-command-xyz`（ENOENT 路径）**正确** exit 1 并打印「有步骤没跑起来」；
  `-- <node> -e "process.exit(9)"`（步骤真跑了但失败）exit 0 —— 两者证明**只有 ENOENT 被拦截**。
- **后果**：这正是脚本头注释（`:27-28`）声称要防的形态——「『子进程没跑起来』与『跑了但没改写』在快照上完全一样，故本脚本对 spawn 失败单独判负」。**修的是 ENOENT 一种，不是这一类。** 该脚本是发版前固定动作，环境一变（CI 容器、受限 profile）就会静默给绿灯。
- **建议修法**：判负条件改为「`exit !== 0` **或** `spawnErr`` 或**子进程从未启动」——即 `const notRun = s.spawnErr || s.exit === -1 || s.exit === null`，并入 `broken`。（注意：`:102` 用 `execFileSync` + `stdio:'pipe'`，故「跑起来但退出非 0」也应记账，不能只看改写数。）

### P1-4｜`route-command.mjs` 的 CLI 入口在任何真实 `node` 调用下**必然失败**

- **位置**：`skills/lunheng-commands/scripts/route-command.mjs:39`

- **实测复现**：`node skills/lunheng-commands/scripts/route-command.mjs -lunheng -draft "写一篇论文"` →

- **建议修法**：CLI 入口改为按 `process.argv.slice(2)` 解析（`const argv = ['node', '-lunheng', ...process.argv.slice(2)]`）或在入口处剥掉前两位；并补一条**端到端 CLI 用例**（当前 `tests/route.test.mjs` 只测合成 argv，测不到这个缺陷）。

### P1-8｜`refresh-gates` 的交付说明正则过宽，可覆盖证据包逐文件指纹

- **位置**：`scripts/refresh-gates.mjs:73`
  `{ rel: 'final/交付说明.md', patterns: [/sha256[:：]\s*\`?([0-9a-f]{64})\`?/g, …] }`
- **对照该脚本自己的边界声明**（`:13-14`）：「**只替换已知形态的旧指纹**，正则锚定在『正文 sha256 / draft_sha256 / sha256:』字样附近，**不做『把所有 64 位 hex 都换掉』的危险操作（那会误伤证据包 manifest 的条目 sha256）**」。
- **实测匹配面**：该模式在 27 份真实 `交付说明.md` 中命中 **5 处**；`SKILL.md` 亦明写「**证据包仓库 manifest sha256 一律取 `final/证据包/manifest.json` 实值**」。`sha256[:：]<64hex>` 这个锚**无法区分**「被审正文指纹」与「逐文件条目指纹」——任何按模板 §9 写「逐文件 sha256：<hex>」的交付说明，都会被整体改写成正文指纹。
- **当前风险状态（如实）**：本次实测的存量项目**尚未**出现「逐文件条目写成该形态」，故是**潜在污染**而非已发生的损坏。（同批实测：闸门记录侧的 `正文 sha256` 锚是安全的——30 份记录里只有 1 份含 64-hex 实值，且确实带「正文 sha256」字样。）
- **建议修法**：把交付说明的模式收紧为**必须与正文/定稿同现**，如 `/正文[^\n]{0,40}sha256[:：]\s*\`?([0-9a-f]{64})\`?/g` 并另加 `/(被审正文|定稿)[^\n]{0,20}sha256[:：]\s*\`?([0-9a-f]{64})\`?/g`；或改为「只替换与 `M-Gate-Report.json#verdict_scope.draft_sha256` 相等的旧值」——即**用权威源反查**，而不是靠正则形态猜。
