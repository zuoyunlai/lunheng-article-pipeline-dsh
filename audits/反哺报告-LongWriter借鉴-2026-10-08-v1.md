# 反哺报告：LongWriter（THUDM, ICLR 2025）借鉴评估与修订方案 v1

> - **日期**：2026-10-08
> - **外部对象**：[THUDM/LongWriter](https://github.com/THUDM/LongWriter)（[arXiv:2408.07055](https://arxiv.org/abs/2408.07055)）及其后续 [LongWriter-Zero](https://arxiv.org/abs/2506.18841)（arXiv:2506.18841，纯 RL）
> - **评估范围**：推理侧工程（AgentWrite / Sl-Sq 双指标 / LongWrite-Ruler）。**训练侧（LongWriter-6k SFT、DPO、RL）与部署侧（vllm）不适用**——论衡不控模型权重、走 API 分流，无落地场景，本报告不设动议。
> - **性质**：改进动议（按机制文件写保护约定，agent 只出本报告；apply 须主人在 host shell 显式授权执行）
> - **建议落地版本**：v18.81.0（单批三项，均为文档+脚本小改，无 Phase 结构变动）

## 〇、结论速览

| 编号 | 借鉴点 | 判定 | 一句话 |
|---|---|---|---|
| LW-1 | AgentWrite「前文注入续写」 | **采纳（有增量）** | 论衡字数预算已到章级，但 T5 各节生成时**互不可见**；引入「兄弟节摘要注入」补连贯性 |
| LW-2 | Sl 柔性长度分 | **采纳（改造）** | 论衡字数判定是硬阈值分档；补一个**机械可算的 Sl 分**作为审计视图只读指标，不替换现有 P0/P1/P2 判级 |

## 一、现状对账：论衡已有 vs LongWriter 对应点（防重复造轮子）

评估前先对账——LongWriter 三项里有一项论衡**已经基本覆盖**，动议只针对真实缺口：

| LongWriter 机制 | 论衡现状 | 缺口判定 |
|---|---|---|
| plan.py 段落级字数预算 | **已覆盖**：T4 大纲 §11 精简段含「字数预算」；T5 卡有「篇幅按大纲字数预算执行」「逐章偏差 >±15% 须给理由」；`segment-chars.mjs --section` 逐节实测 | **无缺口**（预算粒度到章/节已够用；再下钻到自然段收益递减且机检面爆炸） |
| write.py 逐段生成时**携带已写前文** | **有缺口**：T5 按 §11 精简段各节独立成文，兄弟节内容**互不可见**（只共享大纲）；跨节连贯目前靠 T4 大纲映射表 + T6/T7 事后审计兜底 | **LW-1 动议点** |
| Sl 长度分（柔性分段惩罚） | **部分覆盖**：`字数判定表.md` §二硬阈值（≤5% P2 / >5% P1 / 不足 >10% P0）+ BUF=on 例外通道；缺一个**跨项目可横向比较的连续分数** | **LW-2 动议点** |
| Sq 质量分（GPT judge 多维） | **已覆盖且更强**：`quality-score.mjs`（QLT1）+ T9 六维评分 + G14 + M 门 25 项 | **无缺口**，不动 |
| LongWrite-Ruler 生成上限探针 | **有缺口**：`model-routing.mjs` 是**只读复算面**（读配置算路由，不真实调用模型）；各档模型**实际单次生成上限**（有效输出长度 ≠ 标称 max_tokens）无实测数据源 | **LW-3 动议点** |

## 二、LW-1：T5 前文注入续写（AgentWrite 借鉴）

### 2.1 问题

LongWriter 的 write.py 逐段生成时把**已生成的段落全文**作为上下文传入，保证 10,000+ 字的连贯。论衡 T5 写长文（≥5000 字档）时各节只见大纲不见兄弟节，实战表现为：跨节内容重叠（同一例子两节各写一遍）、承接生硬（上一节结尾抛出的问题下一节不接）、术语漂移。这些目前由 T6 批判 + T7 审计事后抓，走修订回环消耗轮次。

### 2.2 方案（改文档，不改脚本）

**改动点 1：`references/agents/05-写作-writer.md`「读」清单段**

在「优先读 `analysis/分析大纲.md` §11」条目后追加一条：

> - **前文锚注入（≥5000 字档启用）**：写第 N 节前，`read` 已完成的第 1..N-1 节**末段 + 各节一句话摘要**（自产「前文锚」，约 300-500 字，随写随更新，落盘 `drafts/前文锚.md` 供断点续写与 T6 复用）；生成时把前文锚置于素材之前。**只注入摘要不注入全文**——全文注入会把 T5 上下文撑爆（这正是 LongWriter 用小模型也敢全文注入、论衡不能照搬的原因：它每段只几百词，论衡一节可上千字）。

**改动点 2：`references/agents/04-分析-analyst.md`（§11 产出规范）**

§11 精简段的「主线」条目要求给出**节间承接句规划**（每节开头一句如何接上一节结尾）——把「承接」从写作期即兴变成大纲期设计。

**改动点 3：`references/pipeline-readme.md` T5 派发话术**

话术补一行：「≥5000 字档：开工先读 `drafts/前文锚.md`（无则从 §1 起建），每完成一节更新之」。

### 2.3 边界与刻意不做

- **<5000 字档不启用**：3000 字级各节本就少，T5 一次读全稿成本可接受，注入是纯开销。
- **不改为全顺序生成**：论衡的节级并行（各节独立成文、主控拼装）是刻意的成本结构，AgentWrite 的严格顺序仅在其「单次调用贯穿全文」前提下必要——论衡拼装后已有修订回环，注入摘要即可拿走大部分连贯收益。
- **前文锚不进 M 门**：它是 T5 的工作记忆，不是交付物；进 M 门会变成新的 P0 生产线。仅要求「≥5000 字档交接报告六要素的『产物在哪』列提及前文锚已更新」。

### 2.4 机检与测试影响

- 05/04 卡与 pipeline-readme 均为机制文件：走主人授权 apply 流程；05-写作-writer.md 现 ≈2x KB（≥12 KB），**文档若增长须同提交抬升 repo-hygiene 词预算棘轮并写理由**。
- **改前先查机械消费者**：`consistency-check.mjs` 对 05 卡与 pipeline-readme 派发话术锚点有断言——新增行不得触碰既有锚点标题字符串；「### 写手（T5…）」等锚点标题原样保留。
- 新增测试：`tests/` 下为「前文锚」加 1 条 docs-facts 级断言（≥5000 字档话术含「前文锚」关键词），防后续瘦身时被静默删掉。

## 三、LW-2：Sl 柔性长度分（LongBench-Write 借鉴）

### 3.1 问题

论衡字数判级是**离散硬阈值**：同一项目内好用，但跨项目/跨轮次不可比（「-4.9% P2」和「+0.2% 通过」在台账上看不出 severity 差异；审计视图无字数健康度一栏）。LongBench-Write 的 Sl 是连续分数（软区间不扣、超出后按偏离比例扣、封顶 5 分），天然适合做**只读观测指标**。

### 3.2 方案（扩展现有脚本，不新增脚本）

**改动点 1：`skills/lunheng-article-pipeline/scripts/segment-chars.mjs` 新增 `--budget <大纲§11路径>` 模式**

- 解析 §11 字数预算表（章级），对每节输出 `预算 / 实测 / 偏差% / Sl 分`；
- Sl 分采用 LongWriter 柔性函数的中文版变体（原版见其 `evaluation/eval_length.py`）：

```
Sl(节) = 5                                    实测 ∈ [0.9×预算, 1.1×预算]
       = 5 − 4×(偏离比例−0.1)/0.9             实测超出软区间，按线性衰减
       = 0                                    偏离 ≥ 100%（缺节/超一倍）
全文 Sl = 各节 Sl 的预算加权平均
```

- exit 语义**不变**（沿用 0/1/2/3 家族；Sl 是输出字段不是新 exit 码——**严禁新增 exit 码**，教训：exit 撞码事故家族）；Sl 低**不触发判级**，只进报告。

**改动点 2：`scripts/quality-score.mjs`（QLT1）追加 `length` 维可选列**

质量分台账增加一列 Sl（有 §11 预算文件才输出，无则 `N/A`），使「质量-长度」可在同一张表横向比较。

**改动点 3：`references/_shared/字数判定表.md` 增 §五「Sl 观测分」**

写明：Sl 是**观测指标不参与判级**（P0/P1/P2 阈值真源仍是 §二）；Sl < 3 的项目在 `audits/审计视图-v0.md` 头部「字数健康度」行高亮，供 T7 关注但不构成 P 项。**两套并行的理由**：硬阈值是验收语言（人对机器），Sl 是观测语言（项目对项目）——合并会让「-5.1% 判 P2」这类边界争议重新谈判一遍，收益为负。

### 3.3 机检与测试影响

- segment-chars.mjs / quality-score.mjs 均在随包白名单内——**脚本名不变、不加新名字，SKILL.md 白名单行（31 个）无需改动**；但两脚本头部 `version:` 契约字段须 bump（版本级联判据已覆盖此点）。
- 新增测试：`--budget` 模式 3 条用例（软区间内满分 / 缺节 Sl=0 / 无预算文件 N/A 退化为现行为），进 `tests/scripts/segment-chars.test.mjs`。
- 字数判定表.md 若因此 ≥12 KB，同提交抬棘轮。

## 四、LW-3：生成上限探针（LongWrite-Ruler 借鉴，仓库级不随包）

### 4.1 问题

`model-routing.mjs` 只读配置复算路由，**不知道各档模型真实单次输出上限**。标称 max_tokens=8192 的模型实际可能在 3000-4000 字（中文）就开始重复/塌缩——这个「有效生成上限」决定：T5 单节预算上限该封多少、修订轮「整节重写」是否可行、以及 `LUNHENG_STRONG_MODEL` 候选池排序。LongWrite-Ruler 的做法就是给模型一串递增长度的生成请求，画「请求 vs 实际」曲线找拐点。

### 4.2 方案（仓库级维护脚本 + 一次性实测落盘）

**改动点 1：新增 `scripts/ruler-probe.mjs`（仓库级，不随包）**

- 对给定 provider×model（从 `model-routing.mjs` 候选池取）发 K 个递增目标字数（1000/2000/3000/5000/8000 字）的纯生成请求；
- 每档记录：实际输出纯汉字数（复用 `count-chars.mjs` 的 `[\u4e00-\u9fff]` 口径——**口径必须同源**，否则探针数据与运行期对不上）、是否截断、是否明显重复塌缩（首尾 200 字重复率粗判）；
- 输出 Markdown 表 + 「有效生成上限」判定（实际/请求 ≥ 0.9 的最大档位）。
- **成本声明**：一次全档探针 ≈ 十几次长生成调用，跑一次几十分钟、几毛到几块钱——所以它是**维护期工具**（换模型/加候选时手动跑），不进 Phase 0 运行期。

**改动点 2：`references/_shared/模型路由.md` 增附录「§十 各档有效生成上限实测表」**

- 表结构：`档位 | 模型 | 实测日期 | 有效上限（纯汉字） | 来源（ruler-probe 输出路径）`；
- 判据行：T5 单节字数预算**不应超过**该档写手模型有效上限的 80%（留塌缩余量）；超限的节在大纲期就该拆分。
- 实测数据由主人维护期跑探针后粘贴；无数据的模型行写「未实测」，Phase 0 按保守值 3000 字兜底。

### 4.3 刻意不做

- **不做运行期自动探测**：每次 Phase 0 都真实烧 K 次长生成，与「检索便宜快」的成本结构冲突；且 bundle 部署下模型清单常不可探测（v18.79.0 已有此教训，`exit 4` 语境）。
- **不随包**：探针脚本不进 `package.json` files 白名单——运行期角色永远用不到它，随包只会扩大 pack-smoke mustNotShip 面。
- **不动 model-routing.mjs**：它是「只读复算面」的定位真源，掺入真实调用会破坏其「零成本可重跑」的性质。

### 4.4 机检与测试影响

- 仓库级脚本不受随包白名单与词预算门（skills 目录外）约束，但受 `no-write-check`（探针不得改写仓库）与 `repo-hygiene-check` 规则①（未跟踪文件）约束——**探针输出写到 `run/` 或临时目录，不写 `references/`**。
- 模型路由.md 增附录若触发棘轮，同提交抬升。
- 测试：`tests/` 给 ruler-probe 加 1 条干跑用例（`--dry-run` 只打印请求计划不真调用）。

## 七、风险登记

| 风险 | 缓解 |
|---|---|
| T5 读前文锚增加每节上下文开销（估算 +500 字/节） | 仅 ≥5000 字档；锚是摘要不是全文；断点续写本就需要类似状态 |

## 八、明确不做（登记防复评）

- 预算下钻到自然段级：机检面爆炸，收益递减。
