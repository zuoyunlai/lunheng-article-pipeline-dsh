## §三、真正未接 DSH 能力（按优先级）

### H1 · `executionMode` 显式声明 — ★★★★★

- **现状**：`lib/tools.js` 注册的 5 个原生工具（`lunheng_m_gate` / `lunheng_handoff_check` / `lunheng_char_count` / `lunheng_refresh_gates` / `lunheng_ethics_sanitize`）**全部未声明** `executionMode`
- **grep 实证**：`lib/*.js` 0 匹配
- **价值**：DSH tools.mode（parallel/exclusive）让 driver 用有界滚动池调度——T1/T2/T3 三档 subagent 现在靠主控手工派发；DSH tools mode 接管后，主控可释放同步调度负担
- **修法**：每个 `defineTool({...})` 加 `executionMode: 'parallel' | 'exclusive'`
- **建议分配**：
  - `lunheng_m_gate` → `parallel`（独立脚本调用，可与其他并发）
  - `lunheng_handoff_check` → `parallel`
  - `lunheng_char_count` → `parallel`
  - `lunheng_refresh_gates` → `exclusive`（涉及闸门记录 + 交付说明改写，独占）
  - `lunheng_ethics_sanitize` → `parallel`（纯函数，无副作用）
- **成本**：5 行声明 + 1 行注释
- **风险**：低（DSH 不消费状态，工具行为不变）

### H2 · `tools/post-execute` 接 ethics_sanitize — ★★★★★

- **现状**：v18.60.0 新增的 `lunheng_ethics_sanitize` 工具**目前只是「可调用」**，没有任何自动触发位
- **价值**：DSH `tools/post-execute` 是天然的「内容输出前自动脱敏」位 — 让 T4 分析员看到材料前自动脱敏（无需主控主动调用）
- **修法**：在 `lib/tools.js` 加监听器，监听 `tools/post-execute` waterfall，对材料类工具（如 `subagent_read`、`subagent_write`）的 result 自动调 `ethics_sanitize`
- **成本**：~30 行（监听器 + sanitized 结果回填）
- **风险**：低（ethics_sanitize 是纯函数，已有的 reviewFlags 机制确保「宁可多报不静默漏报」）
- **配套**：v18.60.0 ethics_sanitize 文档明牌「降低泄露面，不构成合规保证」——这条边界**必须**在监听器描述里转述

### H3 · `tools/post-execute` 接 G14 痕迹检测 — ★★★★

- **现状**：G14 八类痕迹检测**仍是 spawn 一次性章节**（T5 v1 自检 + Phase 4.5 终闸），不在 DSH 钩子里
- **价值**：监听 `tools/post-execute`，对模型输出（assistant/chunk 后）自动跑 G14 检测 → 把 spawn 改成 hook → **节省一次子代理**（实测 G14 单 spawn 消耗 1-3 倍 token）
- **修法**：在 `lib/tools.js` 加监听器监听 assistant/chunk 事件 → 调 G14 检测器（`references/checkers/中文AI痕迹-checker.md` 已有的 8 类判定）
- **成本**：~50 行（监听器 + 八类判定集成）
- **风险**：中（G14 8 类判定可能与「段落级 AI 痕迹」语义不符；需主控在 Phase 0 显式启用）
- **依赖**：v2.4.0 起 G14 默认 Phase 4.5 触发；改为 hook 后需要清改 trigger gate

### H4 · `system-prompt/assemble` 钩子 — ★★★★

- **现状**：论衡的 system prompt 全靠 SKILL.md 静态内容（persona + 工具使用引导 + 时间上下文），**没有按需动态扩展**
- **价值**：监听 `system-prompt/assemble`，按当前 phase（Phase 0/2.5/3.5/5）动态追加对应 persona 段 + 必读模板 + 当前可用工具清单（按已装载 subagent 工具）
- **修法**：在 `lib/index.js` 加监听器监听 `system-prompt/assemble` waterfall，按 phase 决定追加哪几段
- **成本**：~40 行（监听器 + phase 路由 + prompt 片段管理）
- **风险**：中（动态 prompt 可能与 SKILL.md 静态内容冲突 — 需要定义「动态覆盖静态」或「静态优先」）

### H5 · refresh-gates 接 patch HMR — ★★★★

- **现状**：v18.60.1 新增 `scripts/refresh-gates.mjs` 是**手动脚本**——主控跑命令才触发
