## 二、证据与修订任务书

### R-01｜一致性规则 ㉜ 取段方向写反（P1）

**证据**

1. `skills/lunheng-article-pipeline/scripts/_lib/cc-rules/content-rules.mjs:868-871` 注释写「取最近 10 段」，实现为 `[...matchAll(/^##\s+(\d+\.\d+\.\d+)\s+—/gm)].map(...).slice(-10)`。CHANGELOG 按新→旧排列，`slice(-10)` 取到的是**最旧** 10 段。
2. 实跑复现（对真实 CHANGELOG）：`first3=[19.27.15, 19.27.14, 19.27.13]`，`slice(-10)=[18.62.7 … 18.61.0]`，`maxOfSliced=18.62.7`。
3. `docs/introduction.md:147` §实战验证段最新提及 **v19.1.11**；CHANGELOG 中晚于它的版本段共 **61 个**。
4. 全仓测试 **0 处**提及「㉜」（`grep '㉜' tests/**` 无命中），即该门从未被真实触发路径验证。

**影响**：门恒为绿；所谓「实战案例章节滞后」检测自 v19.1.11 起失效 61 个版本段，文档承诺与实现相反。

**修订**：改为 `slice(0, 10)`；同步修正注释；补负向契约用例（构造新段 > 实战段 → 必须 P1）；把 `docs/introduction.md` §实战验证段的版本事实校准到当前基线（如实说明「19.x 期间无新增跑通案例，仅有复跑」）。

**验收**：负向用例红 → 修后绿；对真实树运行 `consistency-check` 0 漂移；`docs/introduction.md` 最新提及版本 ≥ 当前版本。

### R-02｜面板 Host 校验对 IPv6 回环失效（P2）

**证据**

1. `lib/panel.mjs:1031-1032`：`const host = String(req.headers?.host || '').split(':')[0]...`，白名单含 `'::1'` / `'[::1]'`。
2. 直调 `handlePanelRequest`（最小 `ctx={}` + 桩 `res`）实测：

```
127.0.0.1:8765 => 200
localhost:8765 => 200
[::1]:8765     => 403 Host 不允许：[
```

3. 测试库 **0 处** IPv6 用例。

**影响**：以 `http://[::1]:端口` 访问面板恒被拒；安全校验的意图（放行 IPv6 回环）无法达成。

**修订**：先从 Host 中正确剥离方括号 IPv6 与端口，再比对；补 `[::1]` / `[::1]:端口` 正例与 `[::2]` 反例。

**验收**：新增用例全绿；现有 127.0.0.1 / localhost 行为不变。

### R-03｜发版门强制「行为变更 ≥ 1 条」（P2）

**证据**

1. `tests/changelog-structure.test.mjs:178`：`assert.ok(expected.count > 0, 'CHANGELOG 当前段应有「行为变更 N 条」机读行（实测 0）')`。
2. `tests/batch26-contract-flow.test.mjs:139-147`：机读条数必须等于 `^- \*\*[①-⑳]` 条目数。
3. 本次对 19.27.16 的尝试：纯文档/外部插件修订（count=0）直接红；改成 1 后又被要求「只能有一个编号条目」，最终只能把「版本与派生面同步」登记为 1 条行为变更。
4. `lib/index.js:785-793` 的运行时提示在 `count=0` 时会渲染「行为变更 0 条」，语义正确，无需改动。

**影响**：诚实登记与门禁互斥；维护者被迫把非行为变更写成行为变更，历史记录失真。

**修订**：允许 `count=0`（仅拒绝 `null` / 缺失）；为「0 条 + 0 编号条目」与「N 条 + N 条目」各补一条用例；在 CHANGELOG 规范处说明 0 条的合法形态。

**验收**：`count=0` 的文档面版本段通过；`count=2` 但只有 1 条目仍红；`null` 仍红。

### R-04｜人类命令同步阻塞宿主（P2）

**证据**

1. `lib/commands.js:95`（`-status --pending`）与 `:233-254`（`/lunheng-stats`）使用 `spawnSync`，预算 15 s。
2. 宿主契约已核实：`@deepseek-ai/dsh-commands`（0.1.2-rc.1）`lib/index.d.ts:49` 明确 `handler: (invocation) => CommandResult | Promise<CommandResult>`——异步 handler 是宿主公开契约，不是未验证接线。
3. 宿主进程同时承载 Web 面板与 SSE；大 `run/` 目录下同步执行会冻结事件循环最长 15 s。

**影响**：面板心跳、其它会话请求在命令执行期间排队；极端情况下用户看到面板「假死」。

**修订**：把两个 handler 改为 `async`，用非阻塞 `spawn` + 有界输出采集 + 超时/取消实现；保持既有退出码与文本契约；保留 15 s 预算作为异步超时。补「异步返回」与「超时」用例。

**验收**：`commands.test.mjs` 既有用例全绿（它们已 `await handler(...)`）；新增超时用例；同步路径零残留。

### R-05｜超时只终止直接子进程（P3）

**证据**：`lib/tools.js:237-243` 在超时/取消时对 `child` 发 `SIGTERM`，5 s 后对同一 `child` 发 `SIGKILL`。Windows 下 `TerminateProcess` 不影响孙进程；脚本内再 `spawn` 的 node/git 可能残留。

**修订**：抽出 `killTree(child)`：Windows 用 `taskkill /PID <pid> /T /F`，POSIX 先 `SIGTERM` 再 `SIGKILL`（有进程组则发组信号）；失败不抛。

**验收**：静态检查 + 现有工具用例全绿；Windows 手测超时后无孤儿 `node` 进程（如实记录为人工验证）。

### R-06｜`/file` 的 stat → read TOCTOU（P3）

**证据**：`lib/panel.mjs:1063-1077` 先 `lstatSync`/`statSync` 判类型与大小，再 `readFileSync(abs)`；两次调用之间路径可被替换为链接或更大文件。

**修订**：改为 `openSync` + `fstatSync` + `readFileSync(fd)` + `closeSync`，类型/大小/读取基于同一 fd；打开失败走 404/403。

**验收**：现有下载用例全绿；新增「同 fd 读取」结构断言（或至少保证行为不变）。

### R-07｜`package.json` 不在机制写保护根（P3）

**证据**：`lib/index.js:825-835` 的受保护根 = 技能体 + `lib/` + `cordis.patch.yml` +（装包时不存在）`scripts/`；`package.json` 未登记。它定义 `main` / `dsh.bundle.patch` / `files`，改动等同于改变加载面。

**修订**：把 `join(packageRoot, 'package.json')` 加入受保护根；补 guard 用例（写 `package.json` 被拒，`LUNHENG_ALLOW_MECH_EDIT=1` 放行）。

**验收**：新增用例红→绿；既有 guard 用例不变。

### R-08｜每次模型装配同步读盘（P3）

**证据**：`lib/index.js:204-210` 的 `readPackageVersion()` 无缓存；`:785-793` 的 `buildPromptTail` 挂在 `system-prompt/assemble` 上，每次装配都会调用它（并再次触发 `readChangeSurface` 内的版本读取）。

**修订**：按 `mtimeMs` 缓存版本号（文件不可读时缓存 `unknown`）；保持「版本自证」语义。

**验收**：现有入口/装配用例全绿；同一 mtime 下只读一次（可用测试桩计数验证）。

### R-09｜常驻文档预算余量 442 B（核实后保留）

**证据**：卫生门实跑读数：常驻集合计 **58.6 KB / 59.0 KB（余量 442 B）**；16 个文件余量 <200 B（`07-审计-auditor.md` 1 B、`DSH-集成方案.md` 10 B、`任务简报-template.md` 19 B 等）；48/59 条上限超自述长期目标。

**保留理由**：这是**刻意的棘轮**，用于强迫每次扩张都做显式预算决策；本批不新增常驻文档，抬上限会削弱该机制。真正的问题是「常驻面已经太胖」，解决办法是一次结构性瘦身（把沿革/考据迁到 `audits/` 与按需 references），不应在审计批里草率抬数字。

**后续建议（不在本批）**：单独立项做「常驻面瘦身批」，目标把余量恢复到 ≥5 KB，并把越线 48 条的长期目标与实际值重新对齐。

### R-10｜发布 gates 现场下载并执行第三方 CLI（核实后保留）

**证据**：`scripts/plugin-surface-check.mjs:74` 默认 `dsh-plugin-guide@0.3.16`，经 `pnpm dlx` 从 registry 现场下载执行。

**保留理由**：版本已 pin；发布身份作业（`id-token` / `NPM_TOKEN`）与 gates 作业已拆分，gates 只有 `contents: read`；上游 npm 版本不可变。剩余风险是 CI runner 上的任意代码执行，属已声明的供应链取舍。若要进一步收紧，应 vendor CLI 或加 integrity 锁——这属发布工程改造，不与本批混做。
