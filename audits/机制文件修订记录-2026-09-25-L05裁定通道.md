## 二、为什么需要这条通道（审计 L-05）

M 门的 `exit` 有双字段语义：`script_exit_raw`（机械值，禁改）与 `exit`（T8 裁定值）。但**「重跑后重新裁定」此前没有正式入口**——

- 脚本只在**正文指纹未变**时才保留既有裁定；指纹一变就把 `exit` 打回机械值，且**无任何参数**能让 T8 就新版本重新裁定；
- 于是实战项目只能**自建脚本手写报告**：`run/筛选竞赛的均衡/tools/merge-m-gate-report.js` 直接 `rj.exit = 0`，
  产出 `exit=0` + `verdict_stale=true` 的**自相矛盾交付物**（报告自己写着「旧 T8 裁定不适用于本版正文」，却又把 `exit` 置 0）。

**结果**：谁都能改 `rj.exit`，而脚本无法区分「T8 读过新正文后诚实裁定」与「为了让流水线跑通而改数」。

## 三、这条通道做了什么

```
node scripts/m-gate-check.mjs <定稿.md> <证据包> --report final/M-Gate-Report.json --adjudicate <裁定.json>
```

裁定文件 schema：

```json
{ "true_p0": 0, "true_p1": 0, "verdict": "Pass（T8 裁定）",
  "llm_review": "① 逐条枚举… ② 真阳性扫描… ③ 规范冲突说明… ④ 独立复核来源…" }
```

（`true_p0`/`true_p1` 亦接受实战写法 `true_p0_count`/`true_p1_count`——L-04 的字段名兼容。）

**四道校验**（全部拒绝时**报告仍落盘机械值**，绝不丢证据）：

| # | 条件 | 结果 |
|---|---|---|
| ① | `--adjudicate` 未与 `--report` 同用 / 裁定文件缺失或非 JSON | **exit 10**（参数/路径错） |
| ② | 裁定缺 `true_p0`/`true_p1` | **exit 30**（裁定无效） |
| ③ | 本次机械运行命中**硬 P0 红线**（M-Form-2 / M-Form-7 / M-Exist-1 / M-Integrity-1） | **exit 30** —— 红线**不可兜底**（L-44 至此闭环） |
| ④ | 裁定值 ≠ 机械值，但 `llm_review` 未含**证伪四件套**的至少三项（逐条枚举 / 真阳性扫描 / 规范冲突说明 / 独立复核来源） | **exit 30** |

**通过后写入**：`exit` = 裁定值、`script_exit_raw` = 机械值（禁改）、`verdict_stale: false`、
`_t8_conclusion`（含 `true_p0`/`true_p1`/`verdict`）、`_t8_llm_review`、`_t8_adjudicated_at/_by`，
**且进程退出码 = 裁定值**——彻底消除「产物说放行、退出码说 P0」这一形态。

### 为什么新增 `30` 而不是复用 1/2/3

`1/2/3` 是**内容判定**码（P1/P0/仅 P2）；「裁定被拒」不是内容失败。本仓已有事故先例：
`exit 10` 被下游读成 P1、`handoff-check` 的 `1/2/3` 与 M 门刻意分离。故为「裁定无效」单开 **30**，
并同步登记进：`repo-hygiene-check.mjs` 的 `EXIT_CONTRACT`、`SKILL.md` §执行能力边界 的 exit 语义行、
`M-Gate-Algorithm.md` §执行模型 第 4 条、`08-终检-finalizer.md` 的 T8 必查项 ④。
