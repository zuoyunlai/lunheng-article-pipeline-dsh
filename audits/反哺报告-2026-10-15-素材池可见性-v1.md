## 1. 一句话结论

**素材池的机制是完整的，但它的「第一次显形」比「第一次被决策」晚了一个 Phase。**

池由 **Phase 0.5** 惰性创建（`pool-query.mjs:60`），而**关于它的决策发生在 Phase 0**（选检索范围档、决定要不要准备素材）。于是外部用户实际经历的是：在**从没听说过「本地素材」是什么、在哪、有没有存货**的状态下，被 Phase 0 的授权串问「检索=全网检索／仅本地素材」；选了档 B 之后，池此刻还**不存在**，第一次体验即「空池」。

**判据**：一个机制若在「它的第一个使用点」之前没有向用户显形，它在用户心智里就等于不存在——**补文档无效，必须把显形提前**。

## 4. 根因（两条，比逐条症状重要）

### 4.1 时点错配：池的创建晚于对它的决策

```
Phase 0    ← 用户在这里被问「检索=全网检索／仅本地素材」、被问「要不要准备材料」
Phase 0.5  ← 池在这里才被惰性创建（pool-query.mjs:60 ensurePoolSkeleton）
Phase 5    ← 池在这里才可能第一次有内容（pool-extract 回写）
```

用户答 Phase 0 问题时，**池目录尚未存在**。档 B（仅本地素材）的「材料不足照实报缺口」这条退路，对首次使用者等于「在一个空的池上断网」——而 `素材池.md` §11.5 第 3 条只说「档 A 下可池不足→新检索」，**没有回答「首用时池为空怎么办」**（这是本批新增缺口，见 §5.6）。

### 4.2 路径歧义：两条路读音相同、落点不同

| 轨 | 落点 | 性质 | 用户需要做什么 |
|---|---|---|---|
| **A 轨（池）** | `<工作区根>/evidence-pool/` | 跨项目、长期、只读原件 + 条目回指 | 把**长期共享**原件放进 `raw/{books,datasets,papers,misc}/` |
| **B 轨（投喂）** | `run/<项目>/materials/` + `主人投喂清单.md` | 单项目、一次性 | 每项目单独准备 |

`素材池.md` §二 第 3 条写了这两条路，但**那条写在使用者读不到的机制文件里**；用户面（面板 + 简报）只有 B 轨（`任务简报-template.md:142`「投喂入口只有一处」）。**主动把这两条路画开是本批 P1 的核心。**

### 4.3 反馈环缺失：增长不可见

Phase 5 回写**没有任何用户可见的产物**——`交付说明-template.md:83` 只有「检索证据：<文献/数据/案例卡数量与信任级别分布>」，**读的是项目内的卡，不是池**。于是「我上一篇的素材被这一篇复用了」这件事，用户**永远无从得知**，滚雪球闭环（`素材池.md` §一）在用户体验上是断的。

## 8. 边界（如实，不夸大）

2. **`POOL=` 行的机械消费者**：本报告**未**为它新增 `consistency-check` 规则（§5.1 的判据里标为可选）。理由是：该行**在 `run/**/01-任务简报.md` 里**，而本仓 `run/` 是空的、仓库树里 0 份简报 ⇒ 加规则在本仓**恒真通过**（这门「自己写了恒真断言」的形态，`CHANGELOG.md` §19.6.5 已就 `检索工具面:` 行判过一次「不做」）。**若将来 CI 拿真实工作区，可复访此条**。
3. **§5.5 高成本项的前提未决**：面板能否取得会话工作区根**本报告未实测**（属 GUI 宿主契约，`lib/client.js:2147` 的注释只证明 v19.4.0 主动删了输入框）。故该项**列为不做**，除非先有一份面板侧契约核实。
4. **本报告未在本机 v19.6.4 上验证**：本机加载的技能版本为 **v19.6.4**，而本批动议的 `文件:行` 全部按 **仓库树 v19.6.5** 记录。两者行号可能有偏移，**apply 前须以 apply 当刻的 `read` 为准**（本仓已多次踩「按旧行号改错位」）。
5. **一条真实用户路径的复现局限**：§3 的「用户面 0 命中」是**静态 grep 结论**，未做可用性试验（找外部真人实测）。它足以证明「文档/面板层面没有落点」，**不足以量化「多少人因此错过」**。
