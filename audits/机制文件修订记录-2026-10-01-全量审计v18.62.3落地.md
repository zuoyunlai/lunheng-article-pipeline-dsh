### 批次 5 的三次尝试（P1-6 改口径的完整留痕）

`P1-6` 我**改了三次**，前两次都被既有测试网抓红——这是本批最有价值的过程证据：

1. **第一版**：素材核对未执行时把整条 M-Fact-1 记 `SKIP`。→ `tests/batch16` **7 条用例全红**，实际值 `'SKIP'` 而用例里数字跨节/术语项**真的跑了也真的没发现问题**。**用「一个子检查没跑」抵消「其他子检查的干净结论」**，方向错了。
2. **第二版**：收窄为「整条记录无任何发现时才 SKIP」。→ `tests/mfact-gate.test.mjs` **4 条仍红**——其夹具沿用 `mkCase`（只造 `data/撤稿案例数据集.md`，即**素材本该存在**），而 `projectRoot` 在真实项目里正是项目根，故「未找到素材」在真实项目里本就是**素材缺失信号**，把它当「本项不适用」会掩盖它。
3. **最终版（本批）**：**不动 pass/severity**，改为把「子检查未执行」**显式计入报告顶层 `unchecked[]`**（新增字段）。这样：detail 早已写着「未执行，不是「通过」」（人读可见），而 `unchecked[]` 让**机器侧也看得见**且**不改既有语义**。判据：**新增可见性优先于新增判定**；判定语义的变更须先有反例与契约同步。

> **结论（P1-6 的最终处置，如实）**：审计报告 P1-6 的**症状**（`pass` 与 `detail` 自相矛盾）已由 `unchecked[]` 消除（同一记录里不再只有人读的一半）；但**退出码侧仍是 0**。把它改成 exit 3 需要先回答「素材缺失在本包里到底算『不适用』还是『缺陷』」——本批实测表明两种情形都存在（夹具 vs 真实项目），故**留给下一批连同 P2-7（术语近形噪声）一起做**，届时需要一条明确判据而不是一个启发式。

### ⚠️ 决策项（本批**未做**，需主人裁定）：**P2 是否应阻断交付**

P2-7 的修法引出一个**全局口径**问题，本批测得的事实：

- **三门存在「仅软提示 / 仅 P2 却 `pass: false`」的形态**：`mfact-gate.mjs`（术语近形，**已改**）、`mexist-gates.mjs:1182`（M-Exist-10 缺 §11 标题）、`mform-gates.mjs:1134`（M-Form-11：`pass: !hard && soft.length === 0`）。
- **影响面实测**：本机 26 个存量项目（有 `final/定稿.md` + 证据包）抽样统计，`pass: false` 的项按 severity 分布为 **P0 ×14 / P1 ×22 / P2 ×34** —— 即 **34 项 P2 正把项目卡在非 0**。
- **本仓文档自己两说**：M 门侧 `exit 3` 的口径是「仅 P2/soft/SKIP —— 需 LLM 复核，**不得**当作『通过』」（**阻断**）；`quality-score` 侧明写「P2 软提示单列**不扣分**」「挂成闸门会立刻产生『为过门而刷分』的压力」（**不阻断**）。
- 🔎 **批次 13 补到的决定性证据（设计真源）**：`references/_shared/M-Gate-Algorithm.md:794`
  `严重度评级：漏引/孤儿 ≤ 3 处 → **P2（可放行，由 T8 终检时主控复核）**；> 3 处 → P1（必须修订）；> 10 处 → P0（重检索）`
  —— 即**真源把 P2 定义为「可放行」**，而当前实现把它算作硬失败（`pass: false` → `anyFail` → exit 3）。
  **这与 `quality-score` 的口径一致，与 `exit 3 = 不得当通过` 那句存在张力**：后者的「不得当通过」应理解为
  「**不得当成 exit 0 的『无缺陷』**」（需人复核），而不是「必须判失败」。
  **倾向 (B)**：实现应向真源靠拢（P2 = 可放行 + 需复核）；但**对 `mexist-gates:1182`（缺 §11）这类
  「缺产物」的 P2 需另作分类** —— 它不是「软提示」，而是 SKIP（未检）的候选，二者不应混为一谈。
