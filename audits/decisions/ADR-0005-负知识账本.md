# ADR-0005 — 负知识账本：登记型校验，刻意不挂闸门

- Status: Accepted
- Date: 2026-10-03
- Version: 18.64.0
- Supersedes: 无
- Evidence: `references/_shared/负知识账本.md`（契约真源）｜`scripts/disproofs-check.mjs`（只读校验器）｜`tests/disproofs-check.test.mjs`（6 条）｜`audits/反哺报告-v5-竞品驱动.md` §v5.3-1 的 C1-b 半

## Context

论衡的机制全在积累**正向知识**（文献卡 / 数据卡 / 案例卡 / 大纲 / 审稿意见）；而**被证伪的东西**只散落在三处散文里：T6 批判报告的 C1–C7、T1 的 `[L99]` 对立证据索引行、T7 审计报告与 `final/局限性.md §四`。实测确认：**今天没有任何地方把「已证伪项」落成可复用产物**（全仓 grep `disproof|已证伪|负知识` 只命中上述三处散文，无结构化清单）。

后果：① **只记通过的、不记被证伪的** → 交付物的可核验性是**单边**的；② 同一条证伪在下一轮被重新发现/重新争论（无产物 → 靠人回忆）。

同时，原方案（竞品 `dsh-research-report` 的对象寻址 + 读时重算 + 负知识账本，三件一起）里，**只有负知识账本这一半是正交增量**：对象寻址那半要改核心证据机制（`M-Exist-2` / `build-evidence-bundle` / 存量兼容），而**实零事故**——按本仓判据「加门之前先问这解决的是哪个真实故障；故障已消失就该撤门」，那半推迟。

## Decision

1. **新增一处契约产物**：`run/<项目>/audits/disproofs.jsonl`（一行一条、append-only）。**唯一写入者 = T6 ∥ T7**（串行阶段，不并发；刻意**不分片**——账本要能被 T8/外审一次读完，分片会引入 merge 步骤）。
2. **七字段契约**：`id`（`DP-001` 递增、不复用）/ `claim`（逐字来自正文或大纲）/ `verdict ∈ disproven·weakened·unverifiable` / `basis` / `evidence`（**非空数组**）/ `reproduce`（**强制复现路径**）/ `author ∈ T6·T7`。
3. **消费者**：T5 在 `drafts/修订说明-vN.md` **逐条回应**（已证伪项不得静默消失）；T8 交付前跑校验并把结论摘录进交付说明**既有字段**（§3/§4，**不新增字段**——M-Exist-7 锁定 12 项）；T9 作为反方论证的一手材料。
4. **校验器 `scripts/disproofs-check.mjs`（只读、零 spawn、零写盘）**：`0` 合法 ｜ `1` 有非法行**或账本存在却 0 有效行** ｜ **`3` 账本不存在**（须人工确认「确实无」还是「漏记」）｜ `10`/`70`。
5. **刻意不挂 M 门、不判 P0/P1**：形状归机器，**「证伪得对不对」归 T6/T7/T8 人工**。
6. **进证据包**：`build-evidence-bundle.mjs` 的 `RULES` 加一行 → 落在 `final/证据包/disproofs.jsonl`（外审要看的正是「哪些被证伪」）。

## Regression-proof anchor

1. **行为测**（`tests/disproofs-check.test.mjs`，6 条）：合法 → `0` 且逐条回显；**缺账本 → `3`**（不得读成通过）；**空账本 → `1`**；形状不合 → `1` 且点名行号（缺必填 / `verdict` 越界 / `evidence` 空 / `id` 重复或不合规 / JSON 解析失败）。
2. **源码钉**：① 校验器**不得**出现 `spawnSync|writeFileSync|writeReport|mkdirSync|rmSync|…` 与 `child_process`（「校验」不得顺手改账本）；② `build-evidence-bundle.mjs` 的 `RULES` **必须**含 `['audits/disproofs.jsonl','disproofs.jsonl']`，且它**不得**出现在 `LATEST_REPORTS`（那是取版本号的另一套机制）。

## Consequences

### Positive
- 交付物从「单边可核验」变成**双边**：既列出证明了的，也列出证伪了的；`reproduce` 字段让每一条证伪**可被独立复核**（竞品 `disproofs.jsonl` 的立意）。
- 「已证伪项静默消失」有了落点：T5 的修订说明被要求逐条回应。
- 零新依赖、零 exec 面扩张、零 M 门编号变化（对照表 §一 登记为**登记/校验型**）。

### Negative（明确认赔）
- **新增一处需要人如实记账的产物**：它依赖 T6/T7 真的记。本账本只保证「**记下的**不会静默消失」，**不保证记全**——这是它比「无账本」强、但弱于「自动推断」的地方。
- **多了一个脚本要维护**（白名单 29 → 30、`SECURITY.md` 计数、`EXIT_CONTRACT`、对照表、测试）。
- **`exit 3` 会常态出现**（本项目确实无已证伪项时也要人显式声明），属**刻意的**「空状态不许同形」成本。
- 账本进证据包后，**无负知识的项目**会在 bundle 里多一条「跳过 1 个缺失源」的噪声——刻意保留（让「确实无」与「漏记」在交付物上可区分）。

### Neutral
- 不改 `M-Gate-Report.json`、不改交付说明 12 字段、不改 `M-Exist-*` 任何编号。

## Alternatives considered

| 备选 | 驳回理由 |
|---|---|
| **T0 主控代笔（子代理在报告里写，主控转录）** | 转录引入二次失真，且与「写者归属」纪律相悖（谁判断谁落账）。T6/T7 是**串行阶段**，共享 append-only 文件不会并发 |
| **按写者分片（`disproofs-T6.jsonl` / `-T7.jsonl`）** | 与 `sources/{T1,T2,T3}.jsonl` 同形，但**账本的读者是外审/T8，需要一次读完**；分片要加 merge 步骤与 merge 口径（谁合并、何时合并），成本大于收益 |
| **挂成 M 门 / G 项机检门（判 P0/P1）** | 挂闸门会立刻产生**「为过门补一条像样的证伪」**的刷分压力（与 `quality-score.mjs` 的既有判据同源：挂成闸门会立刻产生为过门而刷分的压力）。而本账本的价值恰恰是「只记真的被证伪的」 |
| **让 `verdict` 自动推断（从报告文字里判「已证伪」）** | 不可靠：同一段话「该研究结论相反」既可能是「证伪本文」也可能是「本文已回应」。自动推断会把语义判断伪装成机器判断 |
| **缺账本判 `0`（当作「无负知识」）** | 与「漏记」**同形**——正是本仓反复禁止的「PASS 与『没输入』同形」。故判 `3` 并要求人工一句话确认 |
| **把「门误判」也写进本账本** | 门误判（脚本判错、已用证伪四件套驳回）是**机制**问题，已归 `final/局限性.md §四`；混写会让账本失去「研究结论状态」的语义 |
| **跨项目聚合账本（一份全局负知识库）** | 当前规模下 `grep` 足够；聚合要回答「同名主张如何判同」，会引入新口径而无对应收益 |

## Contract for consumers

- **T6/T7**：攻击/证伪**成立**才落账；**未成立的不落**（那写批判报告）；**门误判不落**（那写 `局限性.md §四`）。追加，不改写既有行；改判 → 追加新 `id` 并在 `note` 写「取代 DP-00X」。
- **T5**：每轮修订说明**逐条回应**账本条目；「保留并说明理由」是允许的结论，**沉默不是**。
- **T8**：交付前跑 `disproofs-check`；`exit 3` → 在交付说明里**显式声明**「本项目无已证伪项」；**不得**用 `exit 3` 代替声明、也**不得**为了消掉 3 而建空账本。
