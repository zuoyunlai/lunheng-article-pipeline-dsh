## Context

**症状**：完成一次交付时，「证据包指纹」段该写什么，在**三份文档里有两个互斥答案**，且 `M-Gate-Algorithm.md` 的 `M-Exist-2` 算法段**自身给出三个**：

| 位置 | 说的是 |
|---|---|
| `M-Gate-Algorithm.md:825` | 主控 LLM **不能**计算 sha256 → 用 `read` 推理验证 |
| `M-Gate-Algorithm.md:826` | **DSH 例外**：主控有 `pwsh`，**可直接计算回填，不必留占位符** |
| `M-Gate-Algorithm.md:827-833` | **生成占位符**，注明「不是 agent 计算结果」 ← 与上一条**直接冲突** |
| `deliverables.md:122` | 「**agent 不执行 sha256**」 |
| `SKILL.md:31` | 「真实 hash **由主人在 host shell 回填**」 |
| `08-终检-finalizer.md:28` | 同句前半「不得留 `<…>` 占位符」＋后半「指纹**须保留**占位符」 ← **同句内自相矛盾** |

**根因重析（关键）**：这不是「有人写错了」。是 **v2.5.2-dsh.0 的「DSH 例外」只加在一处**（`M-Gate-Algorithm.md:826`），而占位符口径已**织进 19 处 / 10 文件**——包括**每个交付件都会照抄的模板本体**（`templates/交付说明-template.md:91-92`，原文「占位符**即为合规**」）与**直接决定 T8 行为的执行卡**。
**判据：例外只改一处、兄弟文档不同步，不是偶发，而是默认结局。**

**且真源早已存在**：`build-evidence-bundle.mjs:302` 逐文件算好 sha256、`:314-331` 写入 `final/证据包/manifest.json`，其 `:332` 自述「**M-Exist-2 据此复算**」，`:280` 更直言「M-Exist-7 的『证据包指纹』**只核「占位符出现了没有」**」。
→ **「交付说明 §证据包指纹」段是 `manifest.json` 的冗余载体**，而三份文档互斥争论的正是这个冗余载体该写什么。哈希**早已算好**，缺的只是「把它抄进去」被明确成口径。

## Decision

1. 「证据包指纹」段**写 sha256 实值**（逐文件）。
2. **权威真源 = `final/证据包/manifest.json`**；该段是它的**引用**，**不构成第二真源**（防「同一事实两处维护」，教训 #156）。
3. **主人不参与回填**——`[哈希校验待主人回填]` 与 `[SHA256-PENDING:HOST-VERIFY]` 两条路径**废止**，不保留为任何环境下的默认或兜底。
4. **执行口径**：T8 终检跑 `build-evidence-bundle.mjs`（**本已是必做步骤**）→ 主控从 `manifest.json` 取实值写入。
5. **机检同批收紧**（否则定案落不到机制层）：`mexist-gates.mjs` 正则不再接受占位符；占位符或缺失 → **P1**。
6. **档位收口**：原判据中的 **P5** 统一为 **P1**（本地其余门用 P0/P1/P2；且该文件阈值总表原本就写 P1——属「同一事实两处两值」的收口）。

## Regression-proof anchor

1. **行为测**：`tests/scripts.test.mjs` → 用例 `m-gate-check M-Exist-7：交付说明 12 固定字段…` 内的**新增断言 ⑥**「指纹段只剩旧占位符 → 必须报，且诊断含『实值』」。（改前该门**无此覆盖**。）
2. **源码钉**：`mexist-gates.mjs` 的 `FP_REAL_RE` 必须为**单一常量**，且被**硬检查与摘要标记两处共用**——后来者若只改一处，即复现 F-BI（见 Negative）。

## Consequences

### Positive

- 交付件的指纹**可复算**（`M-Exist-2` 据 `manifest.json` 复算），且**口径唯一**——不再出现两处互斥。
- 消灭了一个**冗余载体**：哈希不再有「写在交付说明里、又算在 manifest 里」两份。
- 主人从交付流程里**彻底退出**：无需任何手工计算或回填。

### Negative

- **【需求升级，明确认赔】** 本决策把该指纹由 v2.2.17 / 教训 #123 的「**可选验证、不阻塞交付**」升为「**必填实值**」。此后**任何未跑 `build-evidence-bundle.mjs` 就写交付说明的项目，`M-Exist-7` 判 P1（阻塞）**。原设计意图中的「不阻塞」被主动放弃——我们接受，理由是 `final-check.mjs` 的三脚本顺序契约（`08-终检-finalizer.md:46-52`，**顺序不可交换**）保证 `manifest.json` 必先产出，**写不出实值 = 真异常，应当阻塞而非静默降级**。
- **【已知连带缺陷，已修，记录防复发】** `FP_REAL_RE` 抽出之前，本批只改了**硬检查**的正则，而 `detail` 首段的「`+ 证据包指纹✓/✗`」标记仍用旧正则 → **只有占位符的项目在同一行同时输出「✓」与「缺实值」**（实测 `run/AB-共锁-A`）。**教训：同一事实若有第二个出口（摘要 / 看板 / 报告标记），必须同批改。**
- 残余风险：若某部署形态**绕过 `final-check.mjs` 手工按序跑**，顺序契约不再被强制，可能产生假 P1。

### Neutral

- 改动面 **19 处 / 10 文件**；测试新增 1 条断言（套件总数不变，因加在既有用例内）。
- 三处词预算棘轮**未同批抬升**（`SKILL.md` 余量 1,466 B 由本批跨过 1.5 KB 线；`QUICKSTART.md` 879 B / `deliverables.md` 1,249 B 属既有欠账）——门不判此约定，故非门红，留待下一批一并处理。

## Alternatives considered

- **保留占位符待主人回填** — 驳回。理由：① 主人已明确定案「**无需主人回填**」；② `manifest.json` 里实值**已经算好**，要求人工再算一遍是纯冗余；③ 两个载体并存**必然漂移**（教训 #156）。
- **占位符降为 P2 软提示（渐进取缔）** — 驳回。理由：留一条**合法路径**，定案就永远落不到机制层——正是本地教训 #139「规范从文档层到执行层断链」。
- **只改条文、不改机检** — 驳回。理由同上；且会立刻复现「条文说实值、门放行占位符」的新一轮两处两值。
- **把「证据包指纹」段整段删除，只留 `manifest.json`** — 驳回。理由：`M-Exist-7` 的 12 固定字段契约与 `M-Integrity-2` 步骤 4 都以该段为输入；删段 = 改门体系的输入契约，成本远超本决策，且会让「T8 拿到的证据包」与「T8 以为的证据包」重新失去锚点（`build-evidence-bundle.mjs:280` 记录过该风险）。

## Contract for consumers

- **不得**以任何形式恢复占位符路径（包括「仅在无 shell 环境时」——该场景已由 `manifest.json` 覆盖）。
- **不得**把实值再写到第二处而不声明权威（本 ADR 是「单载体 + 指针」的定案）。
- 改判据时，**先搜同一事实的所有出口**（摘要 / 看板 / 报告标记 / 诊断文案），**同批改**。
- 若要推翻本决策，**开新 ADR 并标 `Supersedes: ADR-0001`**，不要就地改。
