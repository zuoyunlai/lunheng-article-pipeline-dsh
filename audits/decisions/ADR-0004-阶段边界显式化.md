# ADR-0004 — 阶段边界的跨越必须显式（带 T8 裁定的报告默认拒绝被覆盖）

- Status: Accepted
- Date: 2026-10-03
- Version: 18.64.0
- Supersedes: 无（补强 `ADR-0003` 的退出码命名空间分离；不改它）
- Evidence: `m-gate-check.mjs` 的拒绝覆盖分支 + 删除后重跑的**回滚点守卫**（v18.64.0 / v18.64.2）｜`pipeline-readme.md` §阶段产物写入权清单（实测事故 14 278 B → 9 609 B）｜`tests/mgate-report-ownership.test.mjs`（**8 条**，含 v18.64.2 补入的 ⑥ 端到端与 ⑦/⑦b 回滚点守卫）｜`audits/反哺报告-v5-竞品驱动.md` §v5.0-1

## Context

`m-gate-check.mjs --report <path>` 对**任何调用者一视同仁**：工具层没有阶段身份校验，「谁有权写哪个阶段的产物」全靠协议 + 派发话术自律（`pipeline-readme.md` 的写入权表就是为此而写）。实测事故：**G14 终闸子代理用 `--report` 覆盖了 T8 阶段的 `final/M-Gate-Report.json`**（14 278 → 9 609 B）。内容后果为零（换稿后旧裁定本已 `verdict_stale`），但**阶段边界被静默破坏**，且只在 `.bak` 时间序列里才看得出来。

根因重析（**这一步决定了修法**）：原报告建议「加调用者身份校验（如 `--role T8`）」。但**身份是自报的**——愿意越界的调用方照样传 `--role T8`，于是那条判据退化成「提示词约束」，与 `SKILL.md:28` 明写的「DSH 无技能级工具白名单」是同一种无效。真正可机械判定的不是「你是谁」，而是「**你有没有把这件事说出口**」。

## Decision

`m-gate-check.mjs --report` 在**四个条件同时成立**时**拒绝写盘**并以 `exit 3`（需人工复核）收场：

1. 目标报告**已存在**且**含 T8 裁定**（`_t8_conclusion` 或 `_t8_llm_review`）；
2. **被审正文真的换了**——`prev.verdict_scope.draft_sha256 !== 本次 draftSha256`（判据**刻意收窄**）；
3. **不是** `--adjudicate` 正式通道（那条通道自带四道校验 + `exit 30`；「拒绝裁定时落盘机械值」是它刻意的行为）；
4. 调用方**未**显式声明 `--overwrite-adjudicated`。

新增 `--overwrite-adjudicated` 作为**唯一的合法越界声明**；`final-check.mjs`（唯一串联方）支持透传它。`exit 3` **不新开码**（配额 12 个已满，且 3 的既有语义正是「需人工复核，不得当作通过」）。

## Regression-proof anchor

1. **行为测**（`tests/mgate-report-ownership.test.mjs`，**8 条**）：① **反向钉**——无裁定的报告换稿后**照旧可覆盖**（判据不得扩大）；② 含裁定 + 换稿 + 普通 `--report` → `exit 3`、**报告逐字节不变**、stderr 给出两条出路；③ 显式旗标 → 放行且旧裁定段保留、`verdict_stale=true`；④ `--adjudicate` 通道不被拦；⑤ 源码钉；⑥ **端到端**（经 `final-check` 这条 T8 主管道，拒绝指引必须真的送达操作者）；⑦ **回滚点守卫**（删报告后重跑必被拒）+ ⑦b 如实登记的边界。
2. **源码钉**：拒绝分支的条件里必须同时出现 `!adjudicatePath`、`!overwriteAdjudicated`、`prevSha !== draftSha256`、`_t8_conclusion`；用法串必须印出 `--overwrite-adjudicated`（并写明与 `--adjudicate` 同给时本旗标无效）；`final-check.mjs` 必须含该旗标的透传。

## Consequences

### Positive
- 「阶段边界被静默破坏」这一形态在工具层被消灭——**越界变成一个显式动作**，出现在命令行里，可被 review、可被 `.bak` 之外的证据链看到。
- 判据挂在**可观测事实（指纹）**而非自报身份上，与 `M-Exist-2` 的「不设防『同时改文件与改清单』，防的是**静默**」（`对照表 §一`）同一条判据线。
- 零新退出码 → 不动 `EXIT_CONTRACT` / `§8` / 配额表三处契约。

### Negative（明确认赔）
- **换稿重裁路径多一步**：T8 换稿后第一次普通复跑会 `exit 3`（不写盘），必须显式加 `--overwrite-adjudicated` 才落机械值。这是**刻意的摩擦**（用一点操作成本换掉一整类静默事故）。
- **它挡不住有意带旗标的调用方**：G14 若自己加 `--overwrite-adjudicated` 仍能覆盖。本 ADR 只承诺「**静默**越界不可发生」，不承诺「越界不可发生」——后者在自报身份的世界里做不到。
- `final-check.mjs` 因此多了一个旗标面（要跟着维护、`--help` 要同步）。
- **F-AV② 那类场景不受保护**（同一稿内裁定段自述指纹写错）——判据刻意收窄，只拦「正文真换了」。
- **三条已知边界（v18.64.2 · 独立审计 A 核实后如实登记）**：
  ① **`rm` 短链**：删掉报告后**再重跑**会绕过「目标存在」这个前提。已加**回滚点守卫**（目标不存在但同目录留有**带裁定的 `.bak`** → 同样拒绝），但它只覆盖「**.bak 里还留着裁定**」的链——若裁定报告**最后一次写盘就是它自己**、旋即被删，`.bak` 里没有裁定痕迹，守卫看不到（`tests/mgate-report-ownership.test.mjs` ⑦b **钉住了这个残余**）。**明删不在「防静默」范围内**（同 `M-Exist-2` 的「不设防『同时改文件与改清单』」）。
  ② **损坏 JSON**：既有报告解析失败时走 `:599` 的 catch → 告警 + 机械值落盘（`_t8_conclusion` 随之丢失）。**有响亮告警、不做拦截**——因为「文件损坏」与「文件被换」在工具层不可分，强行拒写会让一次磁盘故障永久锁死报告路径。
  ③ **v18.0.5 之前的旧报告无 `verdict_scope`**：无法证明它绑的是哪一稿 → 不拦（旧行为 = 覆盖 + 标 `verdict_stale` + reason 写明「无指纹」）。
- **`final-check` 一侧的残余**：本次 M 门**拒绝写盘**时，`summary.mGate` 读的是**磁盘旧报告**（v18.64.2 已加 `reportIsStale` / `stableExit: null` / `stableExitApplies: false` 与专门文案，并把这些值写进报告）；但**任何**外部消费者若只读 `summary.mGate.adjudicatedExit` 而不看 `reportIsStale`，仍可能误读——判据是「**先确认本次运行真的写过该产物**」。

### Neutral
- 报告格式、`M-Gate-Report.json` 的字段面完全不变（不新增字段）；`verdict_stale` 语义不变。

## Alternatives considered

| 备选 | 驳回理由 |
|---|---|
| **加调用者身份校验（`--role T8`）** | 身份**自报**，愿意绕过的调用方照样传；等价于提示词约束，**给了一个「有门」的错觉**——比没有门更坏（本仓对「门在此却不生效」有明确态度） |
| **拒绝一切覆盖（含同稿复跑）** | T8 的正常复跑（同稿取稳定态）会被误伤；把「时点没到 / 正常复跑」判成越界，是 `handoff-check` A7 那条**已被驳回的**错误思路的重演 |
| **新开一个退出码（如 31「阶段越界」）** | 配额 12 个已满，代价是 `EXIT_CONTRACT` + `§8` 表格 + `§8` 散文 + 配额表四处同改；而 `3` 的既有语义（需人工复核）已**精确表达**本场景，新码不增信息量 |
| **只在文档里写清「别覆盖」** | 这正是现状——事故恰恰发生在文档已写明之后（`pipeline-readme.md` 的写入权表 v18.51.0 就有了）。**只靠协议的边界，会被静默跨过** |
| **把裁定段单独拆到一个文件（`M-Gate-Verdict.json`）** | 改交付物形态 → 连带 `M-Exist-2/5/7`、证据包、模板与全部消费方；与「本批只改判据」的范围不符，收益也可由本判据拿到 |
| **冻结目标报告的 mtime/权限（`readonly`）** | 跨平台不可靠（Windows ACL / POSIX 权限 / 容器挂载各不相同），且会让**正当的**换稿重裁也写不进去；把环境问题塞进机制层 |

## Contract for consumers

- **T7.5 / T7 / T9 / G14 等非 T8 角色：不得**对 `final/M-Gate-Report.json` 使用 `--report`（写入权表第一行未变）；一旦目标已含裁定，工具会拒绝并给 `exit 3`——**看到 3 不是「内容不合格」，是「你越界了」**。
- **T8：换稿重裁**必须显式 `--overwrite-adjudicated`（或直接走 `--adjudicate` 写新裁定）；**`exit 3` 不得被消费成「P2 软提示」**（它是「拒绝写盘」，磁盘报告未被更新）。
- **后续新增任何「阶段专属产物」时**：判据照本 ADR 的形状——**挂在可观测事实上、用显式旗标授权越界**，不要引入自报身份。
