# 论衡插件全量审计报告（v18.7.1）

> 审计方式：DSH 专家独立审计。入口层（lib/ + cordis.patch.yml + package.json）逐行亲审；skills 文档层、scripts 脚本层（34 个 .mjs）、tests/CI 层由三个并行子代理深扫后汇总。纯只读，未修改任何机制文件。
> 分层评分：入口层 9.0｜文档层 6.5｜脚本层 7.5｜测试与 CI 层 8.5 → **综合 7.6 / 10**。

## 一、总评

论衡是一个**由多轮真实事故反推出来的防御性工程**，工程化程度远超一般个人项目：入口的 standard-schema Config / 可逆 effect / 响亮降级，guard 的双基准 canonicalPath + mirrorRoots，destructive-write 的原子写 + 时间戳备份，CI 的四层防线（静态门 → mock apply → pack 解包真跑 → 真实 Loader verify），每一处都对着一个已记录的失效模式。它的核心弱点同样典型：**「文档即代码」的野心反噬**——版本注解沉积使四大文档膨胀近半、SKILL.md 混入维护者元信息、自家最忌讳的「同一事实多处漂移」（命令数 12/11/13、模板数 27/28）仍然发生；且**自检门自身带病**——apply-diff 存在静默损坏修订稿的致命索引错误，consistency-check 的 `--fix --write` 宣传功能 100% 不可达。

## 二、分层评分与依据

### 入口层 lib/ + cordis.patch.yml —— 9.0/10
- ✅ 无 default export、inject=['skills'] 唯一硬依赖、C 组可选能力「有则装无则退」、全部注册走 ctx.effect 带逆操作——完全符合 Cordis 插件规范，且规避了官方两起事故形态。
- ✅ 自实现 standard-schema Config（零依赖、非法配置加载期响亮失败）；CRLF/BOM 归一的 frontmatter 解析；EPERM spawn 的可操作报错；工具 output.schema 刻意避开 value-schema DSL 的 required 禁区。
- ✅ patch 的 `!!js` 执行面有 6 处如实披露 + CI 红线防守；分档工具默认不装载（P2-19 修复）。
- 扣分点：① guard 仅为同步 prompt 级之上的部分强制（pwsh 不经门，已如实声明）；② commands.js 的 `/lunheng-stats` 用 spawnSync 同步阻塞宿主命令线程（超时兜底存在，但 run/ 大时可感知）；③ 子技能注册的失败路径只 warn，`/lunheng` 命令静默缺失时用户无引导。

### 文档层 skills/ —— 6.5/10（11 条发现，见子报告）
核心问题：SKILL.md description 455 字符含版本流水（每次会话注入浪费 token）；正文 30.6KB 约 1/3 是维护者元信息；83-90KB 四大文件版本注解未按自家「注解聚合」政策回溯；命令计数三处 12/11/13 不一致；1 处严重断链（lunheng-commands/README.md 的反哺报告路径少一级）；05-写作卡「不调 shell」与「写完即跑 count-chars」自相矛盾。

### 脚本层 scripts/ —— 7.5/10（16 条发现，1 致命 3 严重）
- 🔴 **致命**：apply-diff.mjs:115-132 tail 切片索引错（应为 `L + oldPart.length`），公共前缀 > CTX 时把旧文重复注入修订稿且报告 ok:true——**静默损坏交付物**（已内存复现实证）。
- 🟠 严重：consistency-check `--fix --write` 因参数守卫不可达；normalize-trust-level.mjs 绕过 destructive-write 直接固定名 .bak 覆写；build-evidence-bundle 的信任分布与 _lib/trust.mjs 三档口径两张皮。
- 🟡 中等：md2html/lunheng-stats/handoff-check/segment-chars 未用 cli-args（拼错参数静默吞）；lunheng-stats 未装 exit-guard；pdfcheck `/Page` 匹配到 `/Pages` 计数虚高；用法错 exit 1 与 exit 10 两套并存。
- ✅ 亮点：svg 消毒、final-check spawnSync(shell:false)、destructive-write/exit-guard 设计范本级；无 eval/命令注入；性能线性。

### 测试与 CI 层 —— 8.5/10（8 条发现，无阻断）
- ✅ 四层防线 + loader-smoke 走官方 verify（真实 Loader 路径）正是对 DSH「手动挂载测不到 Loader 层」事故的补面；CI 全 pin SHA + 最小权限 + OIDC 发布。
- 扣分：scripts.test.mjs 391KB/177 用例单文件失控且同名用例标题重复；repo-hygiene-check 自身零回归用例；Loader 验证仅 ubuntu×Node24×dsh@0.1.5-rc.2 单点；CHANGELOG 313KB 拖累克隆（不随包 ✅）。

## 四、解决方案（按优先级）

1. **P0（立即，发 hotfix v18.7.2）**：修 apply-diff tail 切片（`locateStr.slice(L + oldPart.length)`）+ 补「公共前缀 > CTX」回归用例；consistency-check 守卫白名单加 `--write` + 补可达性用例；修 README 断链。此三项均为几行级改动。
2. **P1**：normalize-trust-level 改走 writeWithSafety；build-evidence-bundle 信任分布改从 TRUST_TOKENS 统计；统一命令数口径（建议「11 命令，-cite 含 3 模式」）并同步三处；写手卡 shell 边界统一为「主控跑脚本取权威值」；md2html 等四脚本接入 cli-args；lunheng-stats 装 exit-guard。
3. **P2（文档瘦身战役）**：SKILL.md 拆出 MAINTENERS.md（rank 考证/guard 缺口/更正史迁出），description 精简至「定位+何时用+何时不用」；对四大文件回溯执行「注解聚合」，历史注解压到卡头单行，目标裁 20-30%；全部版本注解迁移时同步抬 repo-hygiene-check 棘轮上限并写理由。
4. **P3（测试基建）**：scripts.test.mjs 按被测脚本拆为 `tests/scripts/<name>.test.mjs`（数量以磁盘为准，不写死数字防漂移）；repo-hygiene-check / plugin-surface-check 补最小注入用例；loader-smoke 加一个 OS 或 dsh 版本点。
5. **P4（一致性长线）**：用法错退出码统一为 10（或文档化豁免表进 glossary §十二）；CHANGELOG 裁近 2-3 个 major 归档 docs/changelog-archive/（同步改 consistency-check 规则）。

## 五、进一步优化方向

1. **从 prompt 级约束走向机制级**：渐进披露目前靠「按需查节」的文字约束，可在派发话术模板里把「必读节」固化为带锚点的注入块，或为 T7/T8 提供 M-Gate 的裁剪视图脚本（`m-gate-check --doc-section`），把 90KB 文档的读取从约定变成构造。
2. **出口统一收口**：新增 `usageExit(code)` 帮助函数收编 1/4/10 三套用法码；exit-guard 增加 stdout flush 保障（JSON 落盘优先于 console.log）。
3. **guard 补 pwsh 面**：与宿主侧 sandbox 配置联动（文档已声明这是部署级），可在 docs/installation.md 给出推荐 sandbox 配置片段，把「比机制强制弱」的缺口显式收敛为部署处方。
4. **遥测闭环**：/lunheng-stats 已有数据，可加「apply-diff 应用成功率 / M 门 P0 假阳性率」两列，让致命类静默损坏在统计面上可见。
5. **版本注解零沉积**：把「注解聚合」做成 repo-hygiene-check 新规则（每文件 v-注解行数上限），防止再膨胀——这是本次文档层失分的根因，值得机械化。
