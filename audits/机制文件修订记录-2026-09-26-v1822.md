## 六、本次批踩到的坑（v18.22.2 时记入）

1. **fixture 写入 BOM 问题**：第一次写反向自证用 `[System.IO.File]::WriteAllText`（pwsh 路径），结果文件带了 UTF-8 BOM——脚本读 JSON 解析失败 → 跳过 → `sessionsTotal: 0` → 退码 10。**修法**：测试代码用 Node 原生 `writeFileSync`（默认 UTF-8 无 BOM）。这是 v18.21.3 修订记录 §六.5 "批量改文件必须 WriteAllText + New-Object System.Text.UTF8Encoding($false)"教训的同型延伸——**测试 fixture 也得用无 BOM 的 UTF-8**。
2. **MEA-2 ⑰ 扩面与既有契约冲突**：扩面正则（含「占比 X%」「约 X%」「降低 X%」）会捕到仓库**已发布**文档里的「省 60%」/「约 85%」等历史断言 → 立刻红。**修法**：保留旧版 ⑰ 默认开启（保护既有契约），扩面作为**新规则**默认不开启 + `STRICT_PCT=1` flag 显式启用。这是 v18.21.3 修订记录 §六.2 「绝不能为了让自己写的话变绿而放宽门」的反例——**正确做法是加 gate、不放宽**。
3. **parseJson vs run(...).out 的字段不匹配**：第一次用 `parseJson(def.out)` — 实际 `def.out` 是 stdout + stderr 合并；`parseJson` 接受 `r` 对象（要求 `r.stdout` 字段）。**修法**：用 `parseJson(def)`（fixtures.mjs:74 实现的 parseJson 就是这样用的）。
4. **v18.22.0 报告 §二.3 数字已过时**：MEA-1 落地后**形式上** T7 占 31%（不再 69.1%）、真 T7 ≈11.7%（不再受主会话污染）——本批应在 CHANGELOG / 修订记录 / 反哺报告里**明示**"v18.22.0 报告原文 §二.3 数字已过时"。
