## 二、核实结论

### 2.1 宿主能力层（DSH 已具备）

DSH 当前工具面**已注册**：
- `web_search`（引擎表：bing / ddg / ddg-lite / searxng / anysearch / **exa** / **tavily** / keenable / **firecrawl** / parallel / serpbase / deepseek-official）；`web_search_test` 探测可用引擎。
- `web_fetch`。
- AI4Scholar 学术套件（计费）：`search_papers`（多平台合并去重，默认含 Semantic Scholar + PubMed，可加 arXiv / Google Scholar / bioRxiv / medRxiv）；`search_semantic` / `search_semantic_bulk` / `search_semantic_paper_match` / `search_semantic_paper_batch` / `search_semantic_snippets` / `search_semantic_authors` / `search_semantic_author_*` / `get_semantic_*` / `download_semantic` / `read_semantic_paper`；`search_pubmed` / `get_pubmed_*`；`search_arxiv` / `download_arxiv` / `read_arxiv_paper`；`search_google_scholar`（**按信用点计费**，最慢最广）；`search_biorxiv` / `search_medrxiv`；`auto_cite` / `sci_draw`。
- `free_search_test`（探测宿主实际可用的 web 引擎）。

**关键事实**（这条决定**能**不能）：
- DSH subagent 在 spawn 时**继承主会话的全部工具面**——主会话配了 firecrawl_api_key / tavily_api_key / exa_api_key / consensus_api_key，spawn 出去的 T1/T2/T3 也看得到。**这是 DSH 的 subagent 模型自带的，无需论衡做任何事**。
- `web_search` 的引擎是**路由式降级**——主会话 dsh 配置里 engine=bing 时，bing 失败自动落到 exa → tavily → keenable → firecrawl → parallel → ddg → searxng → anysearch（顺序来自 free-search 插件）。**配了 key 的引擎就会出现在降级链里**——但**不是必然被命中**，要看 bing 是否成功。

## 四、方案 1 具体落地（8 处改动 + 1 新增）

### 4.1 新增：`references/_shared/外部检索源接入面.md`（真源）

照抄 `auto_cite-integration.md` 范本 + `DSH-集成方案.md` §二 五段式，**单一真源**列出 6 个源：

| 源 | DSH 工具 | 计费 | 适用 | Key 边界 | 何时调 |
|---|---|---|---|---|---|
| **firecrawl** | `web_search` 引擎位 + `web_fetch` 端点 | keyless（无 key 仍可降级）→ 有 key 时延低 + 反爬强 | 抓取 / 反爬强场景 | `firecrawl_api_key`（可选） | web_search 链 firecrawl 失败 2 次 / T1 Phase 1.5 拆任务的跨域 URL |
| **tavily** | `web_search` 引擎位 | keyless → 有 key 时深度更强 | 时效性数据 / 快速 QA | `tavily_api_key` | T2 默认层（数据时效），主会话配 key 后自动进降级链 |
| **exa** | `web_search` 引擎位 + `exa` MCP 兼容 | keyless → 有 key 时语义更强 | 学术深检索 / 相似论文 | `exa_api_key` | T1 默认层（深度文献检索） |
| **consensus** | `web_search` 引擎位（v0.0.x 接入）；学术共识 API | key（必填） | **承重论点的学术共识验证** | `consensus_api_key`（必填） | **不放在 T1/T2/T3 默认**——写手阶段（T4/T5/T9）由 T0 显式触发（共识验证贵且慢） |
| **AI4Scholar**（`search_papers`/`search_semantic`/`search_pubmed`/`search_arxiv`/`search_google_scholar`/`search_biorxiv`/`search_medrxiv`） | 一整套学术元数据工具 | **多数按信用点计费**（Semantic Scholar / PubMed / arXiv / bioRxiv / medRxiv **免费**；Google Scholar **按信用点计费**） | 学术文献元数据 + 引用匹配 | 内置（无需 key）；GS 须积分 | **T1 默认层**——`search_papers`（多平台合并去重）+ `search_arxiv`（免费预印本） |
| **search_google_scholar** | 独立工具 | 按信用点计费（最贵最广） | 学位论文 / 会议论文 / 跨学科兜底 | 内置（积分消耗） | **不进默认**——主轮检索未饱和时由 T1 自行判断（饱和判据 v2.5.2-dsh.15 已具备） |

**§关键澄清**（避免重蹈 v18.18.x 的「门在此却不生效」）：
- ⚠️ **工具面在 ≠ 指引面在**：即使宿主开通了上述所有源，T1/T2/T3 **默认仍只会调 `web_search`**——必须**在 T1/T2/T3 卡里写明「请按 6 源可用性调用」**，才会真正触发。
- ⚠️ **引擎降级 ≠ 必然命中**：`web_search(engine=bing)` 默认走 bing，bing 成功就**不**降级；只有 bing 失败才会逐级尝试。要保证某个源被命中，要么改主会话默认 engine，要么**直接调用对应 DSH 工具**（如 `search_papers`、`search_arxiv`）——后者**可控**。
- ⚠️ **subagent 工具可见性**：subagent 继承主会话工具面——主会话配了 key，spawn 出去的 T1 也能调。**这是宿主行为**，论衡无法在插件层控制。
- ⚠️ **成本**：`search_google_scholar` **按信用点计费**——T1 主轮每跑一次 ~5-15 query，每个 ~1-5 信用点，跑满一次约 50-150 信用点。**主控在任务简报显式声明阈值**（v18.8.0 auto_cite 同型）。

**§失败熔断 / 自动降级 / 边际饱和三件套接入**（T1/T2/T3 卡已具备的 v2.5.2-dsh.7 + v2.5.2-dsh.15 不变）：
- 每个源**独立**记入"已失败源清单"——同一源连续 2 次无结果 → 第 3 次自动停止，切换 query。
- 引擎失败链：`web_search` 默认引擎 → bing → exa → tavily → keenable → firecrawl → parallel → ddg → searxng → anysearch；**keyless 也参与**（只是优先级低）。
- 首轮软预算 ≤40 步（**保持**——6 源接入不增预算，靠"**默认 3 源 + 备用 3 源**"约束；T1/T2/T3 卡里写明）。
