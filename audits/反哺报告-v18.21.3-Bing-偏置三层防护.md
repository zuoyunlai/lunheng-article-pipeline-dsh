## 一、核实结论

### 1.1 现象（T2 / T3 subagent 报告原文）

| Subagent | 来源 | 现象 |
|---|---|---|
| T2（数据检索）| `已用源` 报告 + 数据卡头部 | web_search（Bing backend）调用 5 次，命中被污染为百度百科 / B 站 / 游戏词条 |
| T3（案例检索）| 交接报告 + 案例卡头部 | bing web_search 多次返回 Baidu Baike / 通用首页，**关联度低**，熔断切学术源 |

### 1.2 实测对照（主会话亲测）

| 引擎 | 同一查询「`NEV` `China` export trade policy academic」 |
|---|---|
| Bing (默认) | 中文泛流量（Speedtest / 评测词条等噪声）|
| **tavily（keyless）** | **直接命中学术 PDF + CSIS 智库 + dieselnet 政策库**——质量远超 Bing |

### 1.3 关键事实：通用性兜底已经天然存在

> 🧠 **From Hindsight memory**（v18.21.2 接入面文档 §三.2 + v18.21.2 修订记录 §六）——「关键事实」**已实测**确认：

| 引擎 | 本机 keyless 实测 | 通用性 |
|---|---|---|
| bing | OK（中文偏置） | 通用，但质量差 |
| **exa** | **OK，2 结果** | keyless，**语义检索强** |
| **tavily** | **OK，2 结果** | keyless，**时效性强** |
| **firecrawl** | **OK，2 结果** | keyless，**反爬强** |
| anysearch | OK | keyless，**通用兜底** |
| parallel | OK | keyless，**通用兜底** |
| keenable | OK | keyless，**通用兜底** |

→ **任何宿主**（本机 / CI / 云端）至少 4 个 keyless 引擎可用；**Bing 失败时降级链一定能往下走**——**通用性不会变差**。

### 1.4 结论

- ⚠️ **不是 bug**：论衡插件从不"指定用 Bing"——`web_search` 引擎选择是 DSH 宿主行为，**插件不参与**
- ⚠️ **不是必须修复**：v18.21.2 接入面文档 §四.1 已写「默认 3 源 = `search_papers` + `search_arxiv` + `web_search`」——T1 主轮**几乎不用 Bing**（10 条文献里 0 条来自 Bing），T2/T3 也主要由 `search_papers` 提供数据
- ✅ **但值得补强**：3 层防护让"6 源接入"在**任何宿主环境**都不依赖 Bing

## 二、方案选型（A+B+C 三层防护，主人 2026-09-26 显式选定）

### A · 补文档（v18.21.2 接入面文档 §三.4 新增「Bing 偏置 + 通用性兜底」）

#### A.1 修法
在 `references/_shared/外部检索源接入面.md` §三.4 之后**新增 §三.5**：

```markdown
### 3.5 Bing 偏置 + 通用性兜底（v18.21.3 现场实测新增）

> **来源**：v18.21.2 真实项目实测（run/_v18.21.2_test/中国新能源车/）—— T2/T3 subagent 亲遇 Bing 中文流量偏置。

#### 3.5.1 现象

- **Bing backend 中文流量偏置严重**——英文专业查询（如 `"NEV" "China" export trade policy academic`）被污染为中文游戏 / 电商 / 通用词条
- 同一查询在 **tavily / exa**（均 **keyless**）上返回学术 PDF + 智库 + 政策库——**质量远超 Bing**
- **不限于论衡**——这是 DSH `web_search(engine=bing)` 的宿主行为，**任何宿主**遇到 Bing 都可能触发

#### 3.5.2 通用性兜底（实测已验证）

| 引擎 | 本机 keyless 实测 | 其他宿主 keyless 可用性 | 推荐 |
|---|---|---|---|
| **tavily** | OK，2 结果 | 几乎所有 DSH 部署 | **推荐主引擎**（时效性强）|
| **exa** | OK，2 结果 | 几乎所有 DSH 部署 | 语义检索强 |
| **firecrawl** | OK，2 结果 | 几乎所有 DSH 部署 | 反爬强 |
| anysearch / parallel / keenable | OK | keyless 通用兜底 | 兜底用 |
| bing | OK 但偏置 | 通用 | 不推荐作主引擎 |
| ddg / searxng | 本机失败 | 网络相关 | 不稳定 |

→ **任何宿主**至少 4 个 keyless 引擎可用（anysearch / parallel / keenable + 至少 1 个）；**Bing 失败时降级链必能往下走**。

#### 3.5.3 三层防护（A+B+C，主人 2026-09-26 显式授权）

| 层 | 改什么 | 影响通用性 | 谁负责 |
|---|---|---|---|
| **A · 文档** | 本节（§3.5）——把"Bing 偏置 + 通用性兜底"写进真源文档 | 0 | 论衡插件 |
| **B · 卡** | T1/T2/T3 卡**强约束**：主轮默认层**不开** `web_search`（学术源不够时**才**启用）| 0 | 论衡插件 |
| **C · 本机配置** | dsh 启动配置 `engine=tavily`（仅本机受益）| 仅本机 | DSH 宿主 |

**B 是关键**——把 `web_search` 从 T1/T2/T3 默认层降到备用层，**结构性**消除"主轮依赖 Bing"的同型病。

#### 3.5.4 反向自证

新增 1 条测试 `tests/external-source-integration.test.mjs`：

```js

    const text = read(...)
    // 主轮默认层段（前 60 行内）不得含 web_search 作为"主推"

```
```

#### 3.5.5 边界声明

- **A 不影响通用性**：文档是 host-agnostic，**任何宿主**读到的都是同一份
- **B 不影响通用性**：卡的强约束是 host-agnostic（T1/T2/T3 任何宿主下都不把 web_search 放默认层）
- **C 仅本机受益**：其他宿主不动 dsh 配置也能从降级链获益（Bing 失败 → tavily/exa 兜底）
