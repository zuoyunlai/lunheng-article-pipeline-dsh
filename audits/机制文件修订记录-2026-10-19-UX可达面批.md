## §三、契约变更登记（会改变既有输出的三处）

1. **`exit 22` 的读法变了**：从未限定「放行」→「仅软提示，不等于已验收」。凡历史交付说明写过「22 放行」的，按新口径应补一句人工确认（**历史 `run/` 不回头改**）。
2. **收件箱语义变了**：`进展-主人版.md` 里的普通 bullets **不再**进「待我决策」；已交付项目一律只报计数。本机实测：20 项 → **11 项**（减少的 9 项是阅读步骤与已失效决策）。
3. **`count-chars` 输出多了 `scopeSource`，`scope` 标签按来源派生**（无摘要稿从「摘要后…」改为「首个正文二级标题后…」）。消费方若硬编码旧标签会看到变化——仓内无硬编码消费者（已核 `tests/` 假样本用的是各自 fixture）。

## §五、差集（未做与理由）

1. **未新增 `inconclusive` 退出码**：报告 5.3 列为主人裁定项；本批按推荐路径走**渲染侧**（不牵动下游）。留作 backlog。
2. **面板未放宽 root 命中面**：`panelRoots` 只认 `workspaceRegistry`，面板层拿不到「会话工作区」；放开任意 root = 凭空扩大只读面。本批只做**可见性**（roots + warning + 403 提示）。真正解法需把会话 cwd 传进面板（涉及宿主契约，另批）。
3. **图件只带 `.mmd`，不动 `files` 白名单**：整目录随包会改变发布物形态与 `pack-smoke` 面；`.md` 版会撞词预算登记（≥12 KB）。故用 `.mmd` 扩展名（不进入 `.md` 预算扫描），并从 `docs/architecture.md` 挂指针。
4. **SKILL 首屏没挂图指针**：`SKILL.md` 余量实测 **39 B**（常驻集合计余量 85 B），任何新增行都会被 `repo-hygiene` ⑨ 判红。**先瘦身再加**，顺延。
5. **已升号/已提交/已推送**：`bump-version.mjs 19.18.1 19.19.0`（92 文件）→ CHANGELOG §19.19.0（机读行 7 条，与「改动」小节条目数由 ⑰ 门核对）→ `gen-change-surface`（version 19.19.0 / count 7）→ commit `50338826` → tag `v19.19.0` → push master/tag。**npm 发布由 tag 触发的 CI 执行**，本记录不代为宣告发布成功。
6. **未同步部署镜像**：本机 GUI 仍跑 19.18.1；改动要生效需 `dsh plugin add lunheng-article-pipeline@19.19.0` + 重启 GUI（见 `MEMORY` 既有口径）。
