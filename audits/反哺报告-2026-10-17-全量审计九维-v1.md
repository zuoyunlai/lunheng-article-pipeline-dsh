### P0-1 `count-chars.mjs --summary` 吞掉 `--report` —— 闸门实据静默丢失〔亲测·已复现〕

**问题定位**
- `scripts/count-chars.mjs:229`：`--summary` 分支在打印摘要后直接 `process.exit(0)`；
- 同文件 `:268-275`：`if (reportPath) { try { writeReport(...) } catch (e) { console.error(...) } }` —— `reportPath` 的**唯一消费点在此之后**，`--summary` 时永远到不了。
- 复现：`node count-chars.mjs 定稿.md --summary --report out.json` → **exit 0、`out.json` 不存在、stderr 无任何提示**。
- **该类事故已有真实先例**：`run/不能评估的忠诚/audits/闸门记录-T7.5.md` 第 6 条原文——「`count-chars.mjs` 无 `--report` 旗标：T7 复核报告声称落盘 `t7-review/count-chars-v2.json`，**该文件实际不存在**」。旗标后来补上了，**标准调用方式仍写不出文件**，同类事故换了形态复发。

**为什么是 P0**：`--summary` 正是 T7/T8 的标准用法；「闸门必须留机械证据」是本项目的第一承诺，而这条路径让**证据不存在却返回成功**。

**稿件侧修法（默认优先）**：闸门记录里「字数实据」一律写**命令行 + stdout 关键读数的原文**，不写「见 xxx.json」；若写了路径，必须同批附「文件存在性」实测。→ 建议沉淀到 `references/agents/07-审计-auditor.md` §闸门实据 与 `templates/闸门记录-template.md` 的「实据」列填写说明。

**工具侧修法（满足三条件之②「实现与规范不一致」——规范要求留痕、实现不留）**：
```js
// :229 之前插入（与正文区 out 复用同一份 JSON）
if (reportPath) {
  try { writeReport(reportPath, JSON.stringify(out, null, 2) + '\n', { protect: [file], label: '--report' }) }
  catch (e) { console.error(`⚠️ --report 落盘失败：${e.message}`); process.exit(70) }  // 与 m-gate-check.mjs:975 同码
}
process.exit(0)
```
（或把 `:268-275` 整段上提到 `--summary` 分支之前，二者等价，**以不改变 stdout 契约的为先**。）

**验收判据**
1. `node count-chars.mjs <定稿> --summary --report <tmp>/x.json` → exit 0 且 `x.json` 存在、可 `JSON.parse`；
2. `--report <已存在目录>` → **exit 70**（不得 0）；
3. 新增回归用例：断言 `--summary` 与默认模式产出的 JSON **逐字段相等**（除 `mode`）。

**风险**：低。唯一行为变化是「失败从 0 变 70」，与仓库既有口径一致（`m-gate-check.mjs:975` 同因同码）。

**问题定位**

**稿件侧修法**：不适用。

**工具侧修法（三条件之③「覆盖盲区」）**：

## 三、P1（本迭代内修；每条都指向「门还在，但信号失真」）

### P1-1 M-Form-11 把「软提示」记成 `pass:false` —— 92% 的常年红是噪声〔亲测〕

**问题定位**：`scripts/_lib/mgate-gates/mform-gates.mjs:1410`：`pass: !hard11 && soft11.length === 0`；`:1416` severity 在无硬问题时给 `P2`。
**证据**：25 份真实门报告逐项聚合 —— M-Form-11 通过 1 / 失败 **23**，其中 **21 次是纯 P2**；典型如「台海可预测性边界」：detail 写「已加载 59 / 引用 59，引用 ⊆ 已加载」，仅因 6 个 `[先NN]` 不在索引段（脚本自己说「已从比率对账中排除」）判失败。
**修法**：`pass` 只由硬项决定；soft 另设 `soft: true` 字段并在 detail 保留原文；`exit` 语义不变（有 hard → 1/2；仅 soft → 仍 3，但报告 `pass:true`）。
**验收**：同一夹具（soft-only）→ `pass:true && soft:true && exit:3`；hard 夹具行为不变；`--summary` 只列硬失败项（`:590` 的过滤需同步）。
**为什么不做「删掉该门」**：它是**唯一**能发现「整卡通读 vs 按需加载」的门，删掉等于放弃素材溯源；应修语义而非删门。
**风险**：低，但会改变历史对比口径，需在 CHANGELOG 记「M 门统计口径变更（pass 不再包含软提示）」。
