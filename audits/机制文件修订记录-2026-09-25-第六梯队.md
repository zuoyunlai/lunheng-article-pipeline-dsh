## 一、L-45 `exit=3` 的构造性矛盾——**已消除**（合规稿可达 exit 0）

**问题**（审计 G-14 / L-45）：两条判据**在合规稿上恒报 P2**，而 P2 项的 `pass=false` 会让 `anyFail=true` → `exit=3`；
而 `exit=3` 的语义是「需 LLM 复核、**不得当通过**」，T8 又被要求「22 项全 exit 0」→ **两条口径在构造上不可兼得**，
实测合规基线只能拿到 `pass=20 p2=2 exit=3`。

| 恒报项 | 根因 | 修法 |
|---|---|---|
| **M-Form-10「索引行信息量不足」** | 判据是「去掉编号与分隔符后**剩余 <6 字**」，与模板规定的三列形态错配——中文短主题（「综述」「规模数据」）必然命中 | 改**结构判据**：须齐「编号 + 主题 + 支撑论点」（表格三列或 ｜ 三段） |
| **M-Form-10「索引悬空」逐条刷屏** | `bodyIds` 只认 `### [Dxx]` **标题式**条目，而三卡模板规定的是**行首式** `[D01] 数值 \| 机构 \| …` → 一张完全照模板写的卡，索引里每个编号都被判「正文无对应条目」 | 补：**索引段之外**的行首式条目也计入 `bodyIds` |
| **M-Exist-1 `[先NN]` 孤儿** | 按 `glossary §12.3` 规范写法（先行者只列文末）必然产生「文末有、正文无」的对照孤儿 | 恒 P2 且 `pass=true` → **不拉 exit**（既有行为，本次确认无须改） |

**索引段边界的判定**（新增，必须与上面两条一起成立）：模板形态的卡里，索引段之后**没有新标题**（行首式条目直接跟在后面），
故边界只能按**行的形状**反推。规则：从 `## 📇 索引段` 起连续消费（空行 / 围栏块内行 / 表格行 / 行首 `[Dxx]` 行），
遇到**标题**或**「其后 4 行内出现『信任级别』的行首 `[Dxx]` 行」**即结束 —— 后者正是「条目 vs 索引行」的判据
（条目块必带信任级别行，索引行必不带）。
> **已知代价（如实）**：条目**自己漏写信任级别**时，该行会被误算作索引行 → 可能多报一条「索引缺条」；
> 但那种稿件本就该被 M-Form-6 判缺失，属「两个门同时报同一根因」，**不产生假绿**。

**实测对照**（同一份合规夹具，`$env:TEMP`）：

| 状态 | 结果 |
|---|---|
| 修复前 | `pass=20/22`，`p2=2`，**exit=3** |
| 修复后（缺 `素材加载清单`） | `pass=21/22`，`p1=1`，exit=1（仅剩一个真实 P1） |
| 修复后（补齐清单） | **`pass=22/22`，`p0=0 p1=0 p2=0`，exit=0** ✅ |

**结论**：「合规稿必然 exit=3」这一构造性矛盾消失；`exit=3` 仍保留其原语义（确有 P2/soft/skip 时需 T8 逐条裁定）。
