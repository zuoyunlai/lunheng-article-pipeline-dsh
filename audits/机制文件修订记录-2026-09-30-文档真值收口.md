## 三、A′ 批：门自身的同源缺陷（**这不是文档问题，是检查器漏了一族**）

`scripts/consistency-check.mjs` 的 ⑥b「M 门项数」分项归属表：

```js
// 旧：只列三族
const FAMILY = [['M-Form', form], ['M-Exist', exist], ['M-Integrity', integ + 1]];
```

**后果**：行内出现四族并列写法（如 `… / M-Integrity 2 项（脚本 1 + 人工 1） / M-Fact 1 项`）时，末尾的「1 项」**就近归给前一个 FAMILY 关键词 `M-Integrity`** → 报假阳性「M-Integrity 写 1 项，真源应为 2」。**实测**：`deliverables.md` 四族并列即命中（本批实际踩到）。

**修法**：`FAMILY` 补 `['M-Fact', fact]`（`fact` 早在 v18.25.0 就已在 `GATE_DERIVED` 里，漏的只是这份归属表）+ 扫描触发面补 `M-Fact`。

> **判据**：这与「`M-Fact-1` 落地时无人补登门 ID 表」是**同一类漂移**——加族时改了派生，没改**消费该派生的那几处**。AGENTS.md 已有「加族必须同批改三处」的注记（派生 / ⑳ 语族清单 / 文档同名节）；本批补第 4 处。

## 四、B 批：数字守卫（防复发）

`tests/docs-facts.test.mjs` 新增一个用例。**设计要点**：

1. **期望值从代码派生**：`mechanicalGateCount()` = `mgate-gates/*.mjs` 里 `gate:` 标签的去重个数（`M-Integrity-2` 是人工门、无标签 → 派生值天然等于机械项数；总 = 派生 + 1）。**刻意不从文档抄**——手抄的那份正是会漂的那份。
2. **断言四件事**：① 三份关键文档（M-Gate-Algorithm / SKILL / AGENTS）必须含**四族全枚举**（「数字对但漏一族」同样是漂）；② 脚本自报头必须写派生值（「自报头 ↔ 自输出」是高发矛盾点）；③ schema 示例与字段语义行必须写派生值；④ 六份锚点文档**不得留四种旧口径的精确形态**。
3. **为什么只钉「精确形态」**：宽泛地禁「22」会**误伤合法文本**（如带口径三要素的历史测值、`v18.25.0 起 23→24` 这类版本增量叙述）。故只钉 `机检 **22 项**` / `总项数 23 项` / `恒 22（机械项）` / `"total": 22,` 四种无歧义写法。
4. **反向自证（已实测）**：把旧串在内存里放回（改 `机检 **24 项**` → `机检 **22 项**`），断言确会命中；真实文件不含旧串。**证明守卫非空转**。

**为什么这一条才是有价值的守卫**：既有 M 门守卫只断言**门 ID 字符串覆盖**（它抓到过 `M-Fact-1` 漏登），**不断言数字**——而本次的漂移全部是**数字**漂移，故「22/23」这版在门体系里长期无门可响。
