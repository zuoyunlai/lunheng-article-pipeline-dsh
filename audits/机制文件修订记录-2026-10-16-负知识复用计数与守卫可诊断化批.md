## 一、⑤ `A5` 间歇失败：**未定位根因，但已让它「下次出现即自带根因」**

### 1.1 本轮排除的假设（都做了实测，不是推理）

| 假设 | 实测 | 结论 |
|---|---|---|
| `sameFile` 用 `statSync(p,{throwIfNoEntry:false})?.ino` ⇒ 两侧都不存在时 `undefined === undefined` 判同 | 读实现：`try { statSync(a); statSync(b); return dev===dev && ino===ino } catch { return false }` | **否**（实现防御正确，不存在该路径） |
| 用例自身确定性失败 | 单跑 `cross-script.test.mjs` **连跑 8 次 = 8/8 绿** | **否** ⇒ 该 flake **需要与其它测试文件交互**（`--test-isolation=none` 共享进程） |

### 1.2 真正查不下去的原因：**守卫把定位事实丢掉了**

`_lib/destructive-write.mjs` 的 `writeReport()` 原实现只打印**报告路径**：

```js
console.error(`${label} 不能与本次运行的源文件是同一文件（会不可回滚地销毁它）：${realPath(reportPath)}`)
```

⇒ 一次偶发碰撞在日志里表现为「报告撞了源文件」，却**看不出撞的是哪个源**——这正是该 flake 长期停在「未决」的原因（我此前两次失败都没拿到第二个路径）。

### 1.3 修法（**只修可诊断性，不猜根因**）

守卫现在一次打齐**全部定位事实**：

```
--report 不能与本次运行的源文件是同一文件（会不可回滚地销毁它）：
  · 报告路径 = <…>/M-Gate-Report.json
  · 撞上的源 = <…>/定稿.md
  · 判定路径：pathKey 相等=false｜dev/ino = 1152372852/5629… vs 1152372852/5629…
→ 退出码 10（参数或路径错误）：请把 --report 指向另一个路径（如 audits/xxx.json）
```

- **两个路径**（报告 / 撞上的源）
- **走的是哪条判据**（`pathKey` 相等 = 路径归一分支；否则 = 硬链接 `dev+ino` 分支）
- **两侧 `dev/ino` 实测值**

**判据（留此防复发）**：**报错信息必须包含足以定位的全部事实**——只说「撞了」等于把排查成本转嫁给下一个人。

**探针自证**（真跑）：构造 `report == protect 源` 的同一文件 → 守卫触发、四行事实齐备、`exit 10` ✓；相关回归 **57/57 通过**。

### 1.4 如实登记的状态

- **能站住的结论**：该 flake **不是本用例自身的确定性问题**（隔离 8/8 绿），**需要文件间交互**才能复现。
- **仍未做**：**根因定位**。要定位须等它在全量套里再现（届时日志自带两个路径与判据分支）。**本轮未再观察到该失败**（全量套本批读数见 §四），故**状态仍是「未定位」**——不因「本轮绿了」关闭（同批次三的既定纪律）。

## 二、④ 负知识复用计数（丁案）：**先定口径，再上计数**

### 2.1 为什么此前挂着「未做」

`负知识账本.md` §九.1 自己登记的理由是「**同名主张如何判同？**」——**口径不定的计数不可信**，所以丁案的正确顺序是**先定口径、再实现**。

### 2.2 口径（**真源 = `负知识账本.md` §九.2**，本批新增）

| 档 | 名称 | 判据 | 计入复用计数 |
|---|---|---|---|
| **1** | **同名**（**强**） | 两侧 `claim` 经**归一化**后**逐字相等** | ✅ **是**（唯一来源） |
| **2** | **同域**（**弱**） | 关键词**子串**命中（`claim` / `basis` / `reproduce` / `note` / `evidence` 任一） | ❌ **否**（只提示） |

**归一化**（唯一实现 = `pool-query.mjs` 的 `normClaim()`）：`NFKC`（全角→半角）→ 去全部空白 → 去标点符号（`\p{P}`/`\p{S}`）→ `toLowerCase()`。
⇒ 【人工智能的伦理原则已足以指导实践。】与【人工智能的伦理原则，已足以指导实践】**判同名**。

**为什么弱命中不计入（本口径的关键判据）**：同一关键词会命中**大量不同**主张 ⇒ 计数必然虚增，而**失真的统计量比没有统计量更坏**（同仓 `reuseCount` 非幂等 P1-1 的先例：**持久化的假数字不可自愈**）。

### 2.3 实现（`pool-query.mjs`）

- **`--claim "<待检验主张>"`**：走强判据 → 输出「负知识**同名**复现: N 条」+ 每条「已被 N 个项目复现」（**只读聚合**）。
- **`--project <本项目名>`**：**归属**用——判为同名时向**查询方自己**的 `run/<本项目>/audits/负知识复用.jsonl` **append** 一行（`{at, queryingProject, originProject, originId, claimNorm}`）。
  - **只写自己的项目**：**绝不改写来源账本**（跨项目写是危险动作）。
  - **不带 `--project` ⇒ 只报不记**，并**如实打印**该事实（不静默少做一步）。
- **聚合只读**：现场扫 `run/<各项目>/audits/负知识复用.jsonl` 现算，**无中心库**。
- **计数按项目去重**：同一项目重复查**不推高** N；账本本身是**查询事件流**（多行是刻意的——它是 append-only 留痕，不是去重集合）。
- **退出码不变**（0 / 10 / 70）；`--claim` 缺值 → `exit 10`（走既有 `cli-args` 严格面）。

### 2.4 功能探针（真跑，四项全过）

| 探针 | 实测 |
|---|---|
| 标点/空白差异仍判同名 | 「负知识**同名**复现: 1 条」+「已被 1 个项目复现」+ 落痕到 `projB` ✓ |
| **幂等**（同项目重复查） | 第 2、3 次仍「已被 **1** 个项目复现」——**不虚增** ✓ |
| 换 `--claim`（不同主张） | 「同名复现: **0** 条」+「弱命中**不算**复现」——**不虚报** ✓ |
| 不给 `--claim` | 「**不产生复用计数**」+ 不落痕 ✓ |
| **归属** | 账本只落 `projB`；`projA` 的 `disproofs.jsonl` **一字未动** ✓ |

### 2.5 新增回归（`tests/scripts/pool-query.test.mjs`，**7 例**）

① 强判据 + 落痕字段完整｜② **反向自证**：不同 claim 不得报数｜③ 弱命中不计入同名（**反向钉**）｜④ **幂等**（重复查不推高 N）｜⑤ **只写自己项目**（来源账本逐字未变）｜⑥ 不给 `--claim` 必须**显式声明不计数**（不静默）｜⑦ `--claim` 缺值 → `exit 10`。

> **回归网当场抓到我一处错（如实登记）**：新用例首次**加载即失败**——我起的 `mkDisproofs` 与**批次二 E-丙案**早已存在的同名 helper **撞名**（我只读了该文件首尾、没读中段）。改名 `mkReuseWs` 后 **19/19 全过**。**教训**：往既有测试文件里追加 helper 前**先扫全文的顶层 `const`**——「只读首尾够了」是错的。
