## 2. 逐条发现

### L-01 [P0] 「轮」的定义在同一文件内自相矛盾，且已被全库定案取代

**证据（同一份文件、相隔 30 行的两条定义）：**

`references/agents/00-主控-扩展职责.md:486`
> **「轮」的定义（v2.3.1 重定义，教训 #120）**：**0 轮**=主控启动 T5 出 v1；**1 轮**=T6 批判攻击 + T5 出 v2（融入主人洞察+批判反馈）；**2 轮**=T8 主控亲修出 v3（小幅修补）

同文件 `:489-490`
> **第 1 轮修订**：**T7** 审计打回 P0/P1 → **T5** 修订 → **T7** 复核 …
> **第 2 轮修订**：若第 1 轮仍有关键 P0/P1 未关闭 → **T5** 再修订 → **T7** 再复核

`:486` 把 **T6 批判**算作第 1 轮；`:489` 把 **T7 打回**算作第 1 轮。二者不可能同时成立。

而全库定案（`references/glossary.md:249-252`）明确：
> **A 轨 = 审计打回轮（硬约束 ≤2 轮）**：T7 审计打回 → T5 修订 → T7 复核为 1 轮 …
> **B 轨 = 主控触发轮（不限额…）**：主人深度洞察（Phase 3.5）/ **T6 批判反馈** / T9 审稿建议 / G14 检测修订 …**与审计打回独立计数**

即：**T6 属 B 轨，不计入 A 轨 2 轮**。

**真实项目账本证明主控用的是双轨制、`:486` 是失效定义：**
- `run/数字社交-关系重构/status.md:37`：`T7 v1 审计结论 ❌（A 轨第 1 轮）`
- `run/筛选竞赛的均衡/status.md:20`：`结论=打回修订（A 轨第 1 轮）`

另外 `:486` 连版本号都是旧的——按现行流水线，v2 来自 Phase 3.5 主人洞察、T6 攻击 v2 后产出 **v3**（`pipeline-readme.md:750`、`:777`），而 `:486` 仍写「T6 …T5 出 v2」。

**影响：** 轮次计数是「何时降级到 Acknowledged Limitations」的唯一开关（`:500-505`）。两套定义并存 → 一处多跑一轮（烧一整轮 T5 spawn + T7 复核），或一处提前 Ack 放行未关闭的 P0。这是**交付质量与成本的双向风险**。

**建议（改法具体到段）：**
1. 删 `00-主控-扩展职责.md:486` 整条「轮」的定义，替换为单行指针：`> 「轮」的定义真源 = references/glossary.md §修订回环 ≤2 轮降级（A 轨 = T7 打回轮；B 轨不计入）。本卡不重复定义。`
2. 同文件 `:489-490` 保留（与双轨制一致），但把「第 1/2 轮」显式写成「A 轨第 1/2 轮」。
3. 在 `consistency-check.mjs` 加一条最小规则：若 `00-主控-扩展职责.md` 出现「**1 轮**=T6」形态的定义行 → 判 P1。

### L-05 [P0] 没有「重跑后重新裁定」的正式入口 → 主控手写脚本把 `exit` 改成 0

**机制侧证据**：`scripts/m-gate-check.mjs:387-416` 的落盘逻辑只在 `verdict_scope.draft_sha256` 与本次正文**完全一致**时才保留既有 T8 裁定；正文一变即置 `verdict_stale=true` 并**回退为机械值**（注释 `:401-406`）。脚本本身**没有任何参数**能让 T8 就「新版本正文」重新裁定（`--report` 只能指定路径）。

**真实项目怎么绕过去的**：`run/筛选竞赛的均衡/tools/merge-m-gate-report.js`（主控在项目内手写的第 3 方脚本）
```js
// :72-73
rj.script_exit_raw = rawExit;   // 机械原值保留（禁止修改）
rj.exit = 0;                    // T8 裁定值（双字段口径）
rj._t8_conclusion = { verdict: 'Pass（T8 裁定：真 P0 = 0 / 真 P1 = 0）', true_p0_count: 0, true_p1_count: 0, … }
```
后果——交付物**自相矛盾**：`final/M-Gate-Report.json` 里 `exit = 0`（通过）与 `verdict_stale = true` 并存，而 `verdict_stale_reason` 原文是：

> 被审正文已变更（旧 sha256=95774d63…，本次=dadefdfa…）→ **旧 T8 裁定不适用于本版正文**

同一项目的 `tools/` 目录还有 **17 个 `compress-pass*.js` + 4 个 `rebuild-*.js`**（合计 25 个一次性工具，含 `debug-section-count.js`、`svg2png.js`、`generate_banner.py` …）——**一个内容项目里长出 25 个自建工具**，是机制缺环的直接度量。

**影响：** 谁都可以通过手写 `rj.exit = 0` 让 M 门「通过」，且脚本**无法区分**「T8 在读过新正文后诚实裁定」与「为了让流水线跑通而改数」。这正是文档自己担心的 `exit=0 视为伪造`（`M-Gate-Algorithm.md:74`）的形态，但**没有任何机械手段能发现**。

**建议：**
1. 给 `m-gate-check.mjs` 增加正式入口：`--adjudicate <path/to/_t8_conclusion.json>`，由脚本负责写入 `exit`/`_t8_llm_review`/`_t8_conclusion`、把 `verdict_stale` 置 false、并记录 `_t8_adjudicated_at`。**禁止手写 `exit`** 随之成为可陈述规则。
2. 修 M-Exist-5：`verdict_stale === true` **且** `exit === 0` → 直接判 P0（当前这个组合在实践中出现却无人报）。
3. 把 `apply-compression-cycle.mjs` / `apply-revision-cycle.mjs` 的覆盖范围写进 `pipeline-readme.md` §字数压缩，明确「不得在项目内自建 compress 脚本」（`tools/` 目录目前无任何规范约束）。

### L-03 [P1] 闸门记录只校验形式，用 `exit=2` 的实据标 ✓ 也能过机检

**实现证据**：`mexist-gates.mjs:375-383` 的三项校验是：① 实据列不是「已检查」类自述；② 结论词 ∈ {✓,✗,N/A…}；③ 判 ✗ 必须写失败原因。**没有任何一项读实据的内容**。

**真实反例**：`run/筛选竞赛的均衡/audits/闸门记录-T7.5.md`
| 检查项 | 实据 | 结论 |
|---|---|---|
| M 门 exit code（v4 基线） | `v4 跑过 M 门 **exit=2**（12 项 P0/P1/P2）——该项已由 Phase 4.5 主控收尾与后续编辑修订轮取代` | **✓** |
| M 门 exit code（编辑修订轮刷新，机械值） | **本项按 N/A 处理（自引用循环）**…机械判定为 exit=3 | **N/A** |

按全库退出码语义（`SKILL.md:60`）：`2` = **P0**、`3` = 不得当通过。这张表把「M 门全部 exit 0」这一项用 `exit=2` 的实据标成 ✓、把真正的机械值判成 N/A，**机检仍判 pass**（我已只读重跑确认）。

**影响：** 闸门记录的全部证据价值建立在「结论词可信」上，而结论词由被考核者自己填。机检通过 ≠ 闸门通过。
