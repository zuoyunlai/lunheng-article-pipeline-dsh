# M 门算法规约 v2.2.4（增量更新，AI安全隐患实战 + 深度长文定位）

> **背景**：v2.2.3 实战（AI安全隐患项目）暴露 2 个 M 门盲区 + 1 个流程盲区：
> - **教训（内联引用盲区）**：任务简报要求「内联（机构，年份）」引用格式（公众号/商业评论常见，正文无 [Dxx]/[Lxx] 编号）时，M-Exist-1 的标准 `[Dxx]` 双向 diff **空转**（grep 到 0 个编号即 PASS，实际未校验可回溯性）。实战中 24 条内联引用靠主控手动核对才确认无漏引。

> - **教训（修订轮独立写手）**：实战修订轮由主控代执行，削弱论衡 8 角色独立价值（详见主控卡修订回环 v2.2.4）。
>
> **解法**：本规约在 v2.2.1.2 M 门基础上**升级 2 个算法 + 1 个流程约束**，由 LLM 兜底执行。
> **设计哲学**：沿用 v2.2.0/v2.2.1/v2.2.1.2 M 门哲学——不引入 Python 脚本，主控用 `read` + `write` 工具按本规约伪代码推理执行；**实战反馈驱动升级**。

## 升级 1：M-Exist-1 内联引用模式分支（深度长文定位）

**背景**：任务简报要求「内联（机构，年份）」时，正文无 [Dxx]/[Lxx] 编号，标准 diff 空转。

**算法步骤（内联模式，当任务简报「引用格式」= 内联时触发）**：

```
1. 判断引用格式：读 01-任务简报.md「引用格式」字段
   - 「内联（机构，年份）」或「公众号/商业评论/行业分析」 → 走内联模式分支
   - 「[Lxx]/[Dxx] 编号」或「期刊/学术」 → 走标准 diff（v2.2.1.2）

2. 内联模式核验（覆盖 5 项依赖编号的检查，v2.2.5 系统化，教训 P1-3）：
   # ① 提取正文内联引用（机构，年份）—— 注意排除文末四节
   awk '/^## 引言/{f=1} /^## 引用来源/{f=0} f' final/定稿.md \
     | grep -oE '（[^（）]*[0-9]{4}[^（）]*）' | sort -u > /tmp/内联引用.txt

   # ② M-Exist-1 漏引/孤儿：每条内联引用能否在文末四节+证据包找到对应条目
   # ③ G2 数据溯源：每个正文数字能否在数据卡/文献卡找到来源（防无主数据）
   # ④ M-Exist-3 信任级别：引用机构的信任级别在数据卡/案例卡有标注
   # ⑤ G4-2 四节 diff：正文引用的机构/数据/案例在文末四节有对应

3. 判定：
   - 全部内联引用可回溯 + 所有数字有源 + 信任级别齐全 → 通过
   - 任一内联引用无法回溯 / 数字无源 → P1（触发修订任务书）
```

**论衡哲学化**：「内联引用 ≠ 无引用」——公众号/商业评论的引用是可信度，M 门必须校验其可回溯性，不能因格式不同而放行。

> ⚠️ **v2.2.5 修正（P1-3）**：内联模式下**不只 M-Exist-1 空转**，G2/M-Form-1/M-Exist-3/G4-2 等所有依赖 [Dxx]/[Lxx] 编号的机械检查都会空转。本升级必须覆盖全部 5 项，而非只修 M-Exist-1。

## 升级 2：M-Exist-1 补检索文献回填校验分支

**背景**：GAP 定向补检索（如 L18-L23）后，文末参考文献清单若未回填，正文引用即悬空。

**算法步骤（当流水线发生过补检索时触发）**：

```
1. 判断是否发生补检索：检查 run/<项目名>/literature/ 是否有「补检索-*.md」文件，或文献卡有「补检索」段

2. 回填校验（v2.2.5 修正，教训 P1-2：不可用「L总数==清单条目数」判定）：
   # ⚠️ 文末参考文献清单包含非 L 文献（法规[S]/报告[R]/标准/数据库[DB/OL]）,
   #   如 GAO/EU AI Act/中国办法/OECD/Stanford HAI/AIID，等式在实战中「23==23」只是巧合。

   # ① 提取文献卡中补检索新增的 L 编号（如 L18+，有「补检索」段标记）
   awk '/补检索/,0' final/证据包/文献卡.md | grep -oE 'L[0-9]{2}' | sort -u > /tmp/补充L.txt

   # ② 对每个补检索 L，人工检查文末参考文献清单是否有对应条目（按作者/标题/期刊匹配）
   #    例：L20 Taeihagh → 参考文献应含「TAEIHAGH A. Governing autonomous vehicles」

3. 判定：
   - 每个补检索 L 都在文末清单有对应条目 → 通过
   - 任一补检索 L 缺文末对应条目 → P1 漏引（补检索文献未回填）→ 触发修订任务书补录
```

**论衡哲学化**：「补检索是源头，回填是闭环」—— 补检索新增文献必须同步回填文末清单，否则正文引用悬空，T7 必拦。

## 升级 3：M-Integrity-2 修订轮流程约束（修订轮强制独立写手）

**背景**：v2.2.3 实战修订轮由主控代执行，既当运动员又当裁判，削弱 T5 审计独立性。

**算法约束（并入 M-Integrity-2 T5.5 闸门检查项）**：

```
T5.5 闸门新增检查项（v2.2.4）：
- 检查本轮修订是否由独立写手子代理执行（而非主控代执行）
- 证据：status.md 修订回环记录写明「spawn 独立写手 vN 执行」
- 若发现主控代执行 → 打回修订轮，强制 spawn 独立写手
- 例外：主控直接 edit 定点修复（<5 处纯校对类，v2.1.3 允许）不视为违反
```

**论衡哲学化**：「修订也需独立角色」—— 论衡 8 角色独立的核心理念应贯穿到修订轮，主控只协调不代笔。
